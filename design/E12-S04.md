# E12-S04 — Bid capture: keyed by the buyer, in the vendor's currency, never altered

**Epic** E12 · **M3** · **crud/M** · after **E12-S03** · tags: `money` (Opus review)

> **Status: settled.** The bid-replacement rules were decided by the operator on 23 Oct 2026 (see `## Decision`).
>
> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.
> **Decisions:** canvas DECISIONS 145 and 155 (the vendor's sent time, evidenced, decides lateness;
> `Keyed By Us` never changes); no vendor portal in v1. `design-system/pages/sourcing.md` §2 "Bids are
> keyed by the buyer", "The original bid is never altered", §4.5. Lateness enforcement is E12-S05.
> Back end only; UI is E12-S14.
> **Writes:** every `PATCH`/`PUT`/`DELETE` on an editable resource follows `docs/m2-conventions.md` §O (`If-Match` with the integer version, `ETag` on reads, 400 when missing, 409 `stale_version` on mismatch). `Idempotency-Key` protects **POST** commands only (the middleware ignores other methods).
> **RLS:** every new tenant table gets literal `ALTER TABLE <t> ENABLE ROW LEVEL SECURITY; … FORCE …; CREATE POLICY tenant_isolation ON <t> …` statements in the migration text, one block per table, never generated by a helper or f-string (the static gate in `tests/isolation/test_ci_guards.py` reads the text; the light check runs it).

## Requirements (inlined)

- **SRC-006** — Vendor responses must capture line prices, currency, tax, freight, lead time, validity, exceptions, attachments, and submission timestamp.
- **SRC-010** — Currency conversion used for comparison must show rate, source, and effective date and must not alter the vendor's original bid.

## Data (one migration, `migrations/<head date>_<next>_bids.py`)

Every table below has `org_id uuid NOT NULL REFERENCES organization(id)` and its own literal
ENABLE / FORCE / `CREATE POLICY tenant_isolation … USING (org_id = current_setting('app.org_id')::uuid)
WITH CHECK (…same…)` block, exactly as `migrations/20261022_0069_rfq_lifecycle.py`.

**`bid`:** `id uuid PK`, `org_id`, `rfq_id uuid NOT NULL`, `vendor_id uuid NOT NULL`,
`rfq_version int NOT NULL` (the version answered), `currency char(3) NOT NULL` (the vendor's;
validated by `modules/org/fx.py::validate_currency`), `sent_at timestamptz NOT NULL` (entered by the
buyer), `evidence_attachment_id uuid` (the vendor's email or file; see **Evidence** below; NULL
only while draft: `CHECK (status = 'draft' OR evidence_attachment_id IS NOT NULL)`), `keyed_by uuid NOT NULL REFERENCES identity(id)`,
`keyed_at timestamptz NOT NULL DEFAULT now()`,
`freight NUMERIC(18,4) NOT NULL DEFAULT 0 CHECK (freight >= 0)`,
`lead_time_days int CHECK (lead_time_days >= 0)`, `valid_until date`, `delivery_terms text`
(≤ 500), `warranty text` (≤ 2000), `exceptions text` (≤ 5000),
`status text NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','submitted'))`,
`submitted_at timestamptz` with `CHECK ((status = 'submitted') = (submitted_at IS NOT NULL))`,
`replaces_bid_id uuid REFERENCES bid(id)`, `row_version int NOT NULL DEFAULT 1` (§O: `ETag` and
`If-Match`), `UNIQUE (org_id, id)`.
Foreign keys: `(org_id, rfq_id) REFERENCES rfq(org_id, id)`; `(rfq_id, vendor_id) REFERENCES
rfq_invitee(rfq_id, vendor_id)` (only an invitee can bid; invitees are removable in draft only);
`(rfq_id, rfq_version) REFERENCES rfq_version(rfq_id, version)` (only a published version can be
answered); `(org_id, evidence_attachment_id) REFERENCES attachment(org_id, id)`.

**Evidence is a bid attachment, uploaded through the existing collaboration routes.** RFQ
attachments are write-locked after draft (`sourcing/service.py::rfq_attachments_open`, 409
`not_draft`), and bids exist only on a `published` or `closed` RFQ, so evidence cannot be an
`rfq` attachment. Register a second document type in `sourcing/service.py::register_access`:
`DocumentAccess("bid", "rfq.approve", "rfq.edit", bid_access, bid_attachments_open)`, where
`bid_access(connection, scope, id)` resolves the bid's RFQ unit exactly as `rfq_access` does (unknown
or foreign bid → 404) and `bid_attachments_open` raises 409 `not_draft` unless the bid is `draft`.
The buyer creates the draft bid, uploads with the existing
`POST /api/v1/documents/bid/{bid_id}/attachments` (same storage, scan and audit as every attachment;
no new storage path, no new upload route), then sets `evidence_attachment_id` by `PATCH`. A valid
evidence row is an `attachment` with `document_type = 'bid'`, `document_id` = this bid, and
`deleted_at IS NULL`; `PATCH` checks it (422 on `evidence_attachment_id`) and submit re-checks it.
Because the guard closes at submit, a submitted bid's evidence can get no new version and cannot be
deleted (`upload_version` and `delete` both call the write guard). The existing collaboration routes (`api/collaboration.py`) first require `record.read`, then the
registered document permission; every baseline role that holds `rfq.edit` or `rfq.approve` already holds
`record.read` (`modules/identity/models.py`), so no grant changes. A custom role needs `record.read` as well,
as for every attachment in the product; say so in the field help. Reading evidence content needs
`rfq.approve` (the registry takes one read permission, and the content holds figures; this is
narrower than the bid read rule, never wider). `write_guard` sees no actor, so any `rfq.edit`
holder on the RFQ's unit can upload onto a draft bid; only the keyer can link it (`PATCH`), and an
unlinked upload binds nothing.

**Replacement is a chain; no row changes after submit.** A corrected bid is a new row with
`replaces_bid_id` set to a submitted bid of the same RFQ and vendor (service-checked, 422). A bid is
**replaced** when a *submitted* bid names it in `replaces_bid_id`; that is derived on read, never
written to the original. Partial unique indexes:

- `bid_one_draft UNIQUE (rfq_id, vendor_id) WHERE status = 'draft'`
- `bid_one_original UNIQUE (rfq_id, vendor_id) WHERE status = 'submitted' AND replaces_bid_id IS NULL`
- `bid_replaced_once UNIQUE (replaces_bid_id) WHERE replaces_bid_id IS NOT NULL`

Each (rfq, vendor) therefore has one linear chain; its **current** bid is the submitted bid no
submitted bid replaces. This supersedes the earlier "one submitted bid per (rfq, vendor)" index, which
a replacement could never satisfy.

**`bid_line`:** `org_id`, `bid_id uuid NOT NULL`, `rfq_line_id uuid NOT NULL REFERENCES rfq_line(id)`,
`quantity NUMERIC(18,4) NOT NULL CHECK (quantity > 0)`, `quoted boolean NOT NULL`
(`Not Quoted` = false), `unit_price NUMERIC(18,4) CHECK (unit_price >= 0)`,
`tax NUMERIC(18,4) NOT NULL DEFAULT 0 CHECK (tax >= 0)` (amount for the line),
`line_total NUMERIC(18,4)`,
`CHECK (quoted = (unit_price IS NOT NULL) AND quoted = (line_total IS NOT NULL))`,
`PRIMARY KEY (bid_id, rfq_line_id)`, `FOREIGN KEY (org_id, bid_id) REFERENCES bid(org_id, id)`.
The service checks `rfq_line_id` belongs to the bid's RFQ (422).

**Quantity comes from the version answered, never from live `rfq_line`.** Amendments change
`rfq_line.quantity` in place (`lifecycle.py::_amend` → `_quantities_only`); the quantity each version
sent is `rfq_version.snapshot -> 'lines' -> <requisition_line_id> -> 'quantity'`
(`versions.py::snapshot`). When a line is written, the server copies that quantity for the bid's
`rfq_version` into `bid_line.quantity` and sets
`line_total = kernel.money.quantize(unit_price * quantity, bid.currency)`. Amendments never add or
remove lines (`lines_fixed`), so every version has every `rfq_line`.

**`bid_requirement`:** `org_id`, `bid_id uuid NOT NULL`,
`requirement_id uuid NOT NULL REFERENCES rfq_requirement(id)`, `met boolean NOT NULL`, `note text`
(≤ 1000), `PRIMARY KEY (bid_id, requirement_id)`,
`FOREIGN KEY (org_id, bid_id) REFERENCES bid(org_id, id)`. Requirements are frozen once the RFQ is
published (`put_requirements` and `waive_requirement` are draft-only), so `requirement_id` is
stable; the service checks it belongs to the RFQ and is not waived.

**Immutable after submit: `bid`, `bid_line` and `bid_requirement`.** Use the guard pattern of
`migrations/20261014_0060_vendor_questionnaire.py` (`vendor_version_guard`, `vendor_question_guard`),
`ERRCODE '55000'`:

- `bid_guard()` `BEFORE UPDATE OR DELETE ON bid`: raise on any DELETE (no route deletes a bid), and
  on UPDATE when `OLD.status = 'submitted'`. A draft may be updated, including `draft → submitted`.
- `bid_child_guard()` `BEFORE INSERT OR UPDATE OR DELETE` on `bid_line` and on `bid_requirement`:
  raise unless every parent bid the row leaves or enters (`OLD.bid_id`, `NEW.bid_id`) is `draft`.
- `raise_append_only()` `BEFORE TRUNCATE` on all three, as `rfq_version`.

**Never converted here.** No column in these tables holds another currency (SRC-010). The comparison
(E12-S06) converts.

## API (`/api/v1/sourcing/rfqs/{id}/bids`, in `apps/api/src/flo/api/sourcing.py`)

Every route uses the existing `rfq_target`, so a foreign RFQ is 404 before any permission is
weighed; a `bid_id` of another RFQ is 404. Each write locks `rfq` `FOR UPDATE` first, then the `bid`
row, in that order only.

| Method and path | Permission | Behaviour |
|---|---|---|
| `POST /` (Idempotency-Key) | `rfq.edit` | Body `BidCreate` (`extra="forbid"`: `vendor_id`, `rfq_version`, `currency`, `sent_at`; evidence is attached afterwards, see **Evidence**). `keyed_by` = caller. 201 draft, `ETag` = `row_version`. 409 `not_open` unless the RFQ is `published` or `closed`; 422 if the vendor is not an invitee or the version does not exist; 409 `bid_exists` (with the existing bid's id in the problem detail) when the vendor already has a submitted original for this RFQ: a second capture goes through `/replace`, never a new original. The check runs under the RFQ row lock (`SELECT … FOR UPDATE`), before the insert; 409 `draft_exists` on `bid_one_draft`. |
| `PATCH /{bid_id}` (`If-Match`) | `rfq.edit`, keyer only | Body `BidPatch` (`extra="forbid"`, every field optional): **patchable on a draft:** `sent_at`, `currency`, `rfq_version`, `evidence_attachment_id`, `freight`, `lead_time_days`, `valid_until`, `delivery_terms`, `warranty`, `exceptions`, `lines` (replaces the draft's lines whole), `requirements` (replaces the answers whole). **Fixed at create, never patchable:** `vendor_id` (the invitee FK and the one-chain-per-(rfq, vendor) indexes key on it; a wrong vendor is a new bid), `replaces_bid_id` (set only by `/replace`), and the server fields `keyed_by`, `keyed_at`, `status`, `submitted_at`, `row_version`. Any of those in the body is 422 (`extra="forbid"`). `rfq_version` and `currency` are safe to patch before submit because nothing outside the draft depends on them yet; a patch that changes either recomputes every existing line in the same transaction (`quantity` from the new version's snapshot, `line_total = quantize(unit_price * quantity, currency)`), so no line ever carries another version's quantity or another currency's rounding. A changed `rfq_version` must exist (422). 403 if the caller is not `keyed_by`; 409 `not_draft` if submitted; §O otherwise. Bumps `row_version`. |
| `POST /{bid_id}/submit` (Idempotency-Key, `If-Match`) | `rfq.edit`, keyer only | Body `BidSubmit` (`extra="forbid"`, no fields yet). Validates every RFQ line has a row, quoted lines have a price, every non-waived requirement is answered, and the evidence is valid (set, a `bid` attachment of this bid, not deleted): one 422 `VALIDATION_FAILED` listing every problem in `errors` (`lines/<rfq_line_id>`, `requirements/<id>`, `evidence_attachment_id`). Then `status = 'submitted'`, `submitted_at = now()`. **Seam for E12-S05:** one private method `BidService._before_submit(rfq_row, bid_row, body)`, called after validation and before the status update inside the lock, that does nothing in this story. E12-S05 fills it with the late check and adds `accept_late_reason` to `BidSubmit`. Do not create `sourcing/sealing.py` or call anything from it. |
| `POST /{bid_id}/replace` (Idempotency-Key) | `rfq.edit` | Body `BidReplace` (`reason` 1..500, required; `sent_at`, required; `extra="forbid"`). Inside one transaction, `SELECT … FOR UPDATE` on the RFQ row, then the original bid row, **before** any check. Refuse 409 `deadline_passed` unless `now() < rfq.deadline_at` (strictly before the bidding stop time); then, as a second, independent check, refuse 409 `rfq_awarded` if the RFQ is `awarded` (this story creates `BidService._assert_not_awarded(rfq_row)` checking status only; E12-S08 adds its award-record check there). 409 `not_submitted` unless the original is `submitted`; 409 `already_replaced` on `bid_replaced_once`. Body also takes `sent_at` (required; the replacement's own sent time). Creates a **draft** with `replaces_bid_id` = the original, `keyed_by` = caller, the original's `vendor_id`, `currency`, `rfq_version`, `freight`, `lead_time_days`, `valid_until`, `delivery_terms`, `warranty`, `exceptions`, lines and answers copied, `sent_at` from the body, and `evidence_attachment_id` NULL (the correction's own evidence is uploaded to the new bid and set by `PATCH`); the replacement is submitted through `/submit` like any bid, and its lateness is judged on its **own** `sent_at` (E12-S05). The original row is never touched. Audited `bid.replace` with `after = {bid_id, replaces_bid_id, vendor_id, reason}`. |
| `GET /` and `GET /{bid_id}` | `rfq.approve`, or the bid's keyer | **`GET /{bid_id}`:** `rfq.approve` holder or the bid's `keyed_by`, else 403. **`GET /` applies the same rule per row:** an `rfq.approve` holder gets every bid of the RFQ; a caller with `rfq.edit` but not `rfq.approve` gets only bids where `keyed_by` = caller (200 with an empty list when there are none, never 403); a caller with neither is 403. The filter is in the SQL (`WHERE keyed_by = %(actor)s`), not applied after the fetch. `BidRead`: the columns above, `lines`, `requirements`, `replaced_by_bid_id` (derived) and `current: bool`; `ETag` on `GET /{bid_id}`. E12-S05 replaces this read rule with sealing; until then no other route returns a bid figure. |

Audited (`target_type = 'rfq'`, `target_id` = the RFQ), ids only plus the one decided exception:
`bid.create` and `bid.submit` with `after = {bid_id, vendor_id}`; `bid.replace` with
`after = {bid_id, replaces_bid_id, vendor_id, reason}` (the reason is audited by operator decision,
23 Oct). `PATCH` is not audited (a draft is the buyer's working copy). Never a figure (price, tax,
freight, total, quantity) in `before` or `after` of any event (figures stay in the bid tables, which
E12-S05 seals until the deadline).

## Decision (operator, 23 Oct 2026; was Blocked)

1. **When `replace` is allowed:** only while the RFQ's bidding stop time has not passed (`now() < rfq.deadline_at`), and, as a secondary check, only if the RFQ has not been awarded. Both are checked under the RFQ row lock.
2. **Lateness of a replacement:** judged on the replacement's own `sent_at`, like any bid (E12-S05 enforces it).
3. **Reason:** required, 1..500 characters, audited.
