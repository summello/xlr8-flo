# E23-S05 — `flo start` refuses a story with no packet pre-flight record

**Epic** E23 · **MT** · **chore/S** · tags: none · backlog item T6 · no dependency

> MT stories ship by a pull request to `main`, as E21-S01 did (PR #18).
> **No new dependency** (AGENTS.md §0.6).

## Requirement (inlined)

- **SUP-005** — Administrator and operator documentation must be updated in the same PR as the feature it describes (UX-010).

## Why

Checking a design packet against the real code before an author starts has caught real gaps cheaply: qwen found E08-S03's resolver wiring and an import-contract break on M1 (`project-memory.md`, "Latest handoff" item 6). It is applied when whoever drives the session remembers. A packet that skips it sends an author into a gap, and the cost is a blocked or reworked story.

## Pre-flight findings (Opus, 22 Oct 2026, traced against `799797d`)

- **The backlog's wording cannot be built as written.** It says `flo start` should refuse "without a pre-flight record in `task.json`". `task.json` is created *by* `flo start` (`cmd_start`, ~line 346, inside the new worktree), so no record can exist before the first start. The record has to live where `cmd_start` can read it first. This packet puts it in `.scratch/`, the runner's local state directory (already used for `.author.pid`, `.ci-red`, logs, prompts). Note: the committed `.gitignore` has **no** `.scratch/` entry (`git status` shows it untracked), so the runner must exclude it some other way; see decision 3.
- `cmd_start` already refuses on three conditions (`st != todo`, unmet deps, missing `design/<id>.md`). Add the fourth in the same place, before the worktree is created.
- The supervisor starts stories through `agents/scripts/begin.sh`, which calls `flo start`. The supervisor source is not in this repository. A refused start makes `begin.sh` fail; what the supervisor does with a failing `begin` is not visible from here. See Design decisions.
- Packets get amended after pre-flight (`## Pre-flight amendments N (Opus, <date>)` sections exist in `design/E08-S04.md` and `E07-S01.md`). An amendment must invalidate an earlier record, or the check proves nothing.

## Design

### Record

`.scratch/<STORY>.preflight.json`, written only by the new command below:

```json
{"story": "E23-S05", "packet_sha256": "<hex of design/<id>.md bytes>",
 "reviewer": "qwen", "verdict": "pass", "at": "2026-10-22T12:00:00+0530",
 "findings": 0}
```

### `flo preflight <STORY_ID> --reviewer NAME --verdict pass|fail [--findings N]`

- Computes `packet_sha256` from `design/<STORY_ID>.md` **at the time of the call** (the file in the runner checkout). `--reviewer` is required and must be a key of `agents.yaml` `agents`. Writes the file atomically (write temp, rename).
- `--verdict fail` is recorded and does not unlock the start.

### `cmd_start` check (before `git worktree add`)

1. The record exists, parses, `verdict == "pass"`.
2. `packet_sha256` equals the SHA-256 of the packet **as it is now**. A packet edited after pre-flight is refused with "packet changed since pre-flight, run it again".
3. On success, copy the record into `task.json` as `preflight` so the story carries it (and so E23-S01 and later stories can read it).
4. Message on refusal names the story, the missing or stale condition, and the command to run.

### What this does and does not prove

It proves a pre-flight was *recorded* against *this* packet text. It does not prove the pre-flight was good. Add a `ponytail:` comment in `cmd_start`: "the record proves a pass was filed for this packet text, not its quality; measure amendment rate after start before adding more". Do not build quality scoring here.

## Design decisions (confirm on review)

1. **No bypass flag.** A `--skip-preflight` would become the default path. A genuinely trivial packet is pre-flighted by the planner like any other (one command). Recommended: no bypass.
2. **Keep refused stories out of the supervisor's queue.** `cmd_facts` (`agents/scripts/flo`, ~line 2166) emits `"next": [...]`, the todo stories whose deps are met and whose packet exists, and that list is what the supervisor starts from. Filter `next` to stories with a valid record (same two checks as `cmd_start`) and add a top-level `needs_preflight: [ids]` list for the ones filtered out. Then a supervisor that follows `next` never attempts a start that will be refused, and nothing retries every tick. **Verified 22 Oct 2026 from the supervisor source:** `plan()` starts `facts["next"][0]`, so it follows `next`. It **ignores `needs_preflight`**, so if every ready story lacks a record the fleet idles silently; E23-S11 adds a notification for that case. The refusal in `cmd_start` stays regardless, as the backstop for a manual start.
3. **Add `.scratch/` to `.gitignore`** (one line). Records, prompts and logs live there and the backup config already treats it as local state; today only the runner's local excludes keep it out of a commit. Recommended: include.
4. **In-flight stories are not touched.** Only a `flo start` after this merges needs a record.

## Acceptance criteria

- [ ] `flo start` on a todo story with no record exits non-zero, creates no worktree and no branch, and names the fix.
- [ ] With a `pass` record whose hash matches, `flo start` proceeds and `task.json` contains `preflight`.
- [ ] Editing one byte of the packet after pre-flight makes `flo start` refuse again.
- [ ] A `fail` record does not unlock the start.
- [ ] `flo preflight` with an unknown `--reviewer` exits non-zero and writes nothing.
- [ ] `flo facts` omits a todo story without a valid record from `next` and lists it in `needs_preflight`; with a valid record it is in `next`.
- [ ] `.scratch/` is in `.gitignore`.
- [ ] Usage text and one docs paragraph updated (find where `flo start` is documented: `grep -rn "flo start" docs/ agents/`).

## Plants

1. Delete the record: start refused. A start that merely warns fails the test.
2. Append a line to the packet after writing a `pass` record: start refused (stale hash). A check that tests only for existence fails.
3. Write `verdict: fail`: start refused.
4. Write a record for story A and start story B: refused.
