## Requirements (inlined)

- **SRC-017** — Cancelling or superseding an RFQ/award must preserve the complete history and reconcile its downstream budget effect.
- **WF-005** — cancelled documents stay readable.

## Design (fixed)

`Cancel RFQ` (Destructive) and `Supersede Award` dialogs: intro, consequence rows for invitees, bids,
the requisition's open quantities and the budget, a required reason, the safe button focused, and a
confirm named for the action. The cancelled RFQ stays readable with a banner. Server errors are shown
in words with the reason kept.

**Budget rows are fixed by the merged E12-S09 code (DECISIONS 212, 213); copy states exactly this:**
- Cancel RFQ moves no money (`sourcing/lifecycle.py` cancel): row reads that the requisition's reservation is kept and its lines return to the approved-lines pool.
- Supersede Award reverses the award's committed quantities (the lines reopen for sourcing) and, per requisition, moves back **only** the amount that award's approval returned to the main project (`requisitions/sourcing.py` `restore_unawarded`; nothing when the award used the whole scope). No figure is shown: `AwardRead` does not carry that amount, so the row states the effect in words, never `budget_total`. Refusals are the dialog's error state with the reason kept: `insufficient-budget` (main project no longer has the amount) and 409 `po_exists` (a PO was created from the award).

**Consequence rows come from data the server already returns; no new endpoint.** RFQ: `RfqRead.invitees` (count) and `RfqRead.lines`; bid count from `GET /rfqs/{id}/bids` as `components/sourcing/bids/BidsCard.tsx` reads it (only when `can_edit || can_approve`). Award: `GET /rfqs/{id}/awards` (`AwardRead.lines`, `budget_total`, `currency`). Money per MASTER (tabular, currency code).

**Endpoints (existing, E12-S09):** `POST /api/v1/sourcing/rfqs/{id}/cancel` and `POST /api/v1/sourcing/rfqs/{id}/award/supersede`, body `ReasonBody {reason: 1..2000}`, `ApproveContext` (show the action only when `rfq.can_approve`). Send headers with `mutationHeaders(key)` from `components/requisitions/api.ts`, which carries the CSRF header via `writeHeaders()`; never build headers by hand. MFA is enforced globally by middleware; the dialog only renders its problem detail.

**Which states show `Cancel RFQ`:** `published` only, per `design-system/pages/sourcing.md` §4 item 4. The API also accepts cancel from `draft`, `closed` and `under_evaluation`; exposing it there is an operator question, not this story's (record nothing in the diff; it is in the planner's log). `Supersede Award` shows when the RFQ's latest award is `approved`. On success the server sets the award `superseded` and the RFQ back to `under_evaluation`: the dialog calls the detail route's `changed` with a fresh RFQ read and reloads the awards, versions and history loads (`routes/sourcing/rfqs/detail.tsx`).
