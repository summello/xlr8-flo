## Requirements (inlined)

- **SRC-017** — Cancelling or superseding an RFQ/award must preserve the complete history and reconcile its downstream budget effect.
- **WF-005** — cancelled documents stay readable.

## Design (fixed)

`Cancel RFQ` (Destructive) and `Supersede Award` dialogs: intro, consequence rows for invitees, bids,
the requisition's open quantities and the budget, a required reason, the safe button focused, and a
confirm named for the action. The cancelled RFQ stays readable with a banner. Server errors are shown
in words with the reason kept.

**Budget rows are fixed by the merged E12-S09 code (DECISIONS 212, 213); copy states exactly this:**
- Cancel RFQ moves no money (`sourcing/lifecycle.py` cancel): row reads that the requisition's reservation is kept and its lines return to the approved-lines pool.
- Supersede Award reverses the award's committed quantities and returns the award's `budget_total` to the requisition's funding (`sourcing/awards.py` supersede). A 409/422 problem whose code is `insufficient_budget` is the dialog's error state, reason kept.

**Consequence rows come from data the server already returns; no new endpoint.** RFQ: `RfqRead.invitees` (count, bid state per invitee) and `RfqRead.lines`. Award: `GET /rfqs/{id}/awards` (`AwardRead.lines`, `budget_total`, `currency`). Money per MASTER (tabular, currency code).

**Endpoints (existing, E12-S09):** `POST /api/v1/sourcing/rfqs/{id}/cancel` and `POST /api/v1/sourcing/rfqs/{id}/award/supersede`, body `ReasonBody {reason: 1..2000}`, `ApproveContext` (show the action only when `rfq.can_approve`). Send headers with `mutationHeaders(key)` from `components/requisitions/api.ts`, which carries the CSRF header via `writeHeaders()`; never build headers by hand. MFA is enforced globally by middleware; the dialog only renders its problem detail.

**Which states show `Cancel RFQ`:** `published` only, per `design-system/pages/sourcing.md` §4 item 4. The API also accepts cancel from `draft`, `closed` and `under_evaluation`; exposing it there is an operator question, not this story's (record nothing in the diff; it is in the planner's log). `Supersede Award` shows when the RFQ's latest award is `approved`.
