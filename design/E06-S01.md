# E06-S01 — Project entity, scoped numbering sequence, department and ledger account

**Epic** E06 · **M1** · **crud/M** · after **E05-S03** · tags: 

> **Conventions:** read `docs/m1-conventions.md` (authorization outcomes, scope targets, wire formats). It applies unless this packet says otherwise.

## Requirements

- **PROJ-001** — Projects must be creatable manually or through a validated import.
- **PROJ-014** — Every project expense must carry a department and ledger account code.
- **PROJ-019** — Project identifiers must be unique within their configured scope.
- **SEQ-001** — Project, requisition, RFQ, award, PO and asset numbers must be unique within their configured organization/BU/OU scope (PROJ-019, PO-006).
- **SEQ-002** — Numbering must be **monotonic but not gapless**; gaps from rolled-back transactions are acceptable and must be documented for auditors. Gapless numbering would require a serialized counter and is not worth the contention.
- **SEQ-003** — The format must be configurable per scope (prefix, year segment, width) and must not be reinterpreted retroactively.
- **SEQ-004** — Number allocation must be concurrency-safe and must not reuse a number after a rollback.

## Design decisions (confirm on review)

- **D-M1-14 Document numbers are allocated outside the caller's transaction.** SEQ-004 forbids reusing a number after a rollback, and SEQ-002 explicitly accepts gaps. A counter row updated inside the caller's transaction rolls back with it and the number is handed out again. So allocation runs in its **own short committed transaction on a second connection**: `UPDATE numbering_counter SET last_value = last_value + 1 WHERE ... RETURNING last_value`. A later rollback of the caller leaves a harmless gap. Counters are per (org, scope unit, document type, year segment when the format has one). The same service serves requisitions, RFQs, POs and assets later (SEQ-001).
- **D-M1-15 Project re-parenting is not supported in M1.** `parent_id` is set at creation and immutable (removes cycle risk and roll-up recomputation). A mistaken parent is fixed by abandoning and recreating.

## Behaviour

1. `number` = `prefix` + (`-YYYY-` when `include_year`) + zero-padded counter, using the format row in effect on the creation date for the project's `bu_id` (falling back to the org-wide format, then the built-in `PRJ`, year, width 4).
2. `department_code` and `ledger_account_code` are validated through `org.service.assert_usable` (E05-S03) — PROJ-014 (every project expense carries both; they default onto its ledger entries).
3. `currency` must be a valid ISO 4217 code from the bundled data; it fixes the project's currency (a ledger posting in another currency is rejected, E07-S02).
4. The project creator becomes its default `owner_id` when none given. `bu_id` must belong to the caller's org and the caller must hold `project.create` on that BU/OU scope.
5. Creating a project also registers it as a `project` authorization scope in the same transaction: `identity.service.register_scope(scope_type='project', scope_id=<project id>, parent=<its parent project, else its BU/OU as a 'bu' scope>)`, so grants at a BU/OU or ancestor project cover it (conventions B).
5b. Creating a project also creates its zero `project_balance` row (same transaction), so E07 locks always find a row.
6. Audit `project.create|update`.
7. `projects.service.get_status(project_id) -> str` (read-only, scoped) is added here for E07-S03's funding check; E06-S03 later replaces its callers with the full guard functions.

## Acceptance criteria

- [ ] 20 concurrent creates in one scope yield 20 distinct, increasing numbers; a creation that then rolls back leaves a gap and the next create does not reuse that number (SEQ-002, SEQ-004)
- [ ] A new `numbering_format` row changes only numbers allocated afterwards; existing numbers are unchanged (SEQ-003)
- [ ] Same number cannot exist twice in one (org, BU); the same number may exist in two BUs (PROJ-019, SEQ-001)
- [ ] Missing or inactive department/ledger codes → 422 with field errors naming the code
- [ ] `PATCH` with a stale `If-Match` → 409; immutable fields change is rejected once a ledger entry exists
- [ ] Foreign-tenant ids → 404 on GET/PATCH, and a foreign `bu_id` or `parent_id` on POST → 404 (isolation gate entries)
- [ ] A user with `project.create` on BU A only cannot create under BU B (403)
- [ ] Replayed `Idempotency-Key` → first response, one project, one number consumed
- [ ] Migration up/down/data-preservation; the new FKs do not break E07 tests
