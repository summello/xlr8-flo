# E06-S01 — Project entity, scoped numbering sequence, department and ledger account

**Epic** E06 · **M1** · **crud/M** · after **E05-S03** · tags: 

## Requirements

- **PROJ-001** — Projects must be creatable manually or through a validated import.
- **PROJ-014** — Every project expense must carry a department and ledger account code.
- **PROJ-019** — Project identifiers must be unique within their configured scope.
- **SEQ-001** — Project, requisition, RFQ, award, PO and asset numbers must be unique within their configured organization/BU/OU scope (PROJ-019, PO-006).
- **SEQ-002** — Numbering must be **monotonic but not gapless**; gaps from rolled-back transactions are acceptable and must be documented for auditors. Gapless numbering would require a serialized counter and is not worth the contention.
- **SEQ-003** — The format must be configurable per scope (prefix, year segment, width) and must not be reinterpreted retroactively.
- **SEQ-004** — Number allocation must be concurrency-safe and must not reuse a number after a rollback.

> **Conventions:** read `docs/m1-conventions.md` (authorization outcomes, scope targets, error labels, imports, file scope). It applies unless this packet says otherwise.

## Design decisions (confirm on review)

- **D-M1-14 Document numbers are allocated outside the caller's transaction.** SEQ-004 forbids reusing a number after a rollback and SEQ-002 accepts gaps. A counter bumped inside the caller's transaction would roll back and be handed out again, so allocation runs in its **own short committed transaction on a second connection** (`psycopg.connect` from `Settings`, tenant scope set with `SET LOCAL`, committed immediately). A later rollback of the caller leaves a harmless gap. The numbering service is generic (`doc_type`) because requisitions, RFQs, POs and assets reuse it later (SEQ-001).
- **D-M1-15 No re-parenting, and in this story no parents at all.** This story creates **root projects only**. `parent_id` exists as a nullable column and the create schema accepts it, but a non-null value is a **422** (`VALIDATION_FAILED`, field error on `parent_id`, label `parenting_not_supported`). E06-S02 enables hierarchy, depth limits and the parent authorization rules. Structural fields are **immutable** once created, so no authorization scope is ever re-parented.

## Contract

**Migration** (reversible, RLS forced and tenant policy on every new table, `org_id uuid NOT NULL REFERENCES organization(id)`): the next revision after the current head (revision id `20260826_<next 4-digit number>`, `down_revision` = the head that `python -m flo.kernel.migrate --check` validates today; stories merge one at a time). Tables:

- `numbering_format(id uuid pk, org_id, scope_id uuid not null, doc_type text not null check (doc_type in ('project','requisition','rfq','award','po','asset')), prefix text not null default '', include_year boolean not null default true, width smallint not null default 4 check (width between 1 and 9), effective_from date not null, created_at, UNIQUE (org_id, scope_id, doc_type, effective_from))`. `scope_id` is the **org unit id**, or the **organization id** for an organization-wide format (never NULL). Formats are versioned by `effective_from` and **never edited**: a change inserts a new row (SEQ-003).
- `numbering_counter(org_id, scope_id uuid not null, doc_type, year int not null, last_value bigint not null default 0, PRIMARY KEY (org_id, scope_id, doc_type, year))`; `year` is `0` when the format has no year segment.
- `project(id uuid pk, org_id, bu_id uuid not null, parent_id uuid null, number text not null, name text not null, description text, status text not null default 'draft' check (status in ('draft','approval_pending','active','deferred','completed','abandoned')), owner_id uuid not null, sponsor_id uuid, department_code text not null, ledger_account_code text not null, currency char(3) not null, planned_start date, planned_end date, created_by uuid not null references identity(id), created_at timestamptz not null default now(), version bigint not null default 1, UNIQUE (org_id, bu_id, number), UNIQUE (org_id, id), UNIQUE (org_id, id, bu_id), FOREIGN KEY (org_id, bu_id) REFERENCES org_unit(org_id, id), FOREIGN KEY (org_id, parent_id) REFERENCES project(org_id, id), CHECK (planned_end IS NULL OR planned_start IS NULL OR planned_end >= planned_start))`.
- Permissions inserted into the global `permission` table: `project.create`, `project.read`, `project.update`.

**Endpoints** (router parses and authorizes only; logic in `modules/projects/service.py`; targets per conventions B: create targets the new project's **BU/OU scope** named by `bu_id`, record routes target the project's own `project` scope, the list targets the organization scope with `project.read`, and the list is filtered to projects the caller can read):

- `POST /api/v1/projects` body `{bu_id, parent_id?, name, description?, department_code, ledger_account_code, currency, planned_start?, planned_end?, owner_id?, sponsor_id?}`, `Idempotency-Key` → 201 `ProjectRead` | 403 | 404 | 409 | 422
- `GET /api/v1/projects?q=&status=&bu_id=&sort=&direction=&cursor=&page_size<=50` → 200 keyset-paged page of `ProjectRead`. `sort` is one of `number|name|status|created_at` (default `number`), `direction` `asc|desc`, the cursor encodes the sort key plus id. `q` is a case-insensitive prefix match on number and name.
- `GET /api/v1/projects/{id}` → 200 | 404
- `PATCH /api/v1/projects/{id}` with header `If-Match: <version>` (missing header → 400 `BAD_REQUEST`, label `if_match_required`). **Only** `name`, `description`, `owner_id`, `sponsor_id`, `planned_start`, `planned_end` are editable. A body containing `number`, `bu_id`, `parent_id`, `currency`, `department_code` or `ledger_account_code` is a **422**, label `immutable_field`. → 200 | 409 (label `stale_version`) | 404 | 422

`ProjectRead` carries id, number, name, description, status, bu_id, parent_id, owner_id, sponsor_id, department_code, ledger_account_code, currency, planned dates, version, created_at. It has **no health, no balances and no percent complete** (added by later stories).

## Behaviour

1. `number` = `prefix` + (`-YYYY-` when `include_year`) + zero-padded counter of the format's `width`, using the format row with the greatest `effective_from <= today` for the project's BU scope, falling back to the organization-wide format, then to the built-in default (`PRJ`, year included, width 4). `YYYY` is the **calendar year** of the creation date.
2. `department_code` and `ledger_account_code` are validated through `org.service.assert_usable('department'|'ledger_account', code, today)` (E05-S03); a failure is 422 with a field error naming the code and the reason (PROJ-014).
3. `currency` must be a valid ISO 4217 code from the bundled data (`kernel/data/iso4217.json`) and is fixed for the project's life.
4. `owner_id` defaults to the creator. A supplied `owner_id` or `sponsor_id` must be a user of the caller's organization, checked with the new `identity.service.user_exists` (below); otherwise 422 with a field error. `bu_id` must be an organization unit of the caller's organization; one the caller cannot see is a 404.
5. In one transaction the service allocates the number (independent transaction, above), inserts the project, and registers its authorization scope through the identity wrapper `register_project_scope(connection, scope, project_id, parent_kind='bu', parent_id=<bu_id>)`, then audits `project.create`. Updates audit `project.update`.
6. `projects.service.get_status(project_id) -> str` is a read-only, scoped function used by E07-S03's funding check.
7. A non-null `parent_id` is rejected as stated in D-M1-15.

**Identity edits authorized in this story (the only ones):** add to `modules/identity/service.py` (a) `register_project_scope(connection, scope, project_id, parent_kind, parent_id) -> None`, a thin wrapper over the existing `register_scope` with `ScopeType.PROJECT` and `parent_kind` in `'bu'|'project'`, so projects never import `identity.models`; and (b) `user_exists(connection, scope, user_id) -> bool`, read-only and scoped to the caller's organization. Each needs one test under `tests/identity/`.

## Acceptance criteria

- [ ] 20 concurrent creates in one scope return 20 distinct numbers in increasing order; a create that fails after allocating a number leaves a gap and the next create does not reuse it (SEQ-002, SEQ-004)
- [ ] Inserting a newer `numbering_format` row changes only numbers allocated afterwards; existing project numbers are unchanged (SEQ-003); a format row cannot be updated through the service
- [ ] The same number cannot exist twice within one (org, BU) (database constraint, tested directly); the same number may exist in two BUs (PROJ-019, SEQ-001)
- [ ] An unknown, inactive or not-yet-effective department or ledger account code → 422 with a field error naming the code and reason
- [ ] A non-null `parent_id` on create → 422 `parenting_not_supported`
- [ ] `PATCH` with a stale `If-Match` → 409 `stale_version`; without `If-Match` → 400 `if_match_required`; with any immutable field → 422 `immutable_field`; two concurrent PATCHes with the same `If-Match`: exactly one succeeds
- [ ] Authorization (conventions A): a caller whose grants do not cover the BU gets **404** on create under it; a caller with a grant covering the BU but without `project.create` gets **403**; a caller with `project.create` on BU A cannot create under BU B (404); a foreign-tenant `bu_id` → 404; foreign-tenant project id → 404 on GET and PATCH (add all three project routes with real named tests to `tests/isolation/test_route_coverage.py`)
- [ ] Replayed `Idempotency-Key` on create → the first response, one project row, one number consumed
- [ ] The creator becomes `owner_id` by default; an `owner_id` from another organization → 422
- [ ] The project's authorization scope exists after create and a grant on its BU covers the project (resolver test)
- [ ] List: keyset paging with `page_size=50` over 120 projects never repeats or skips an id for each `sort` value and both directions
- [ ] Migration up, down, and a data-preservation assertion; the migration-chain check passes
