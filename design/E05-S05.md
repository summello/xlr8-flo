# E05-S05 — FX: ECB daily rate ingest, rate table, effective dating, missing-rate block

**Epic** E05 · **M1** · **engine/M** · after **E03-S06** · tags: `money`

> **Conventions:** read `docs/m1-conventions.md` (authorization outcomes, scope targets, wire formats). It applies unless this packet says otherwise.

## Requirements

- **FX-001** — Each organization must declare a base currency; documents retain their original currency (FIN-002).
- **FX-002** — Rates come from the ECB daily reference feed, stored with rate, source, and effective date, retained permanently.
- **FX-003** — A conversion shown to a user must display rate, source and effective date, and must never mutate the source document (SRC-010, FIN-003).
- **FX-004** — A missing rate for a required date must block the conversion with an actionable error, never fall back to a stale rate silently.
- **FIN-003** — A transaction must not mix currencies unless its exchange-rate policy, rate, source, and effective date are recorded.

## Design decisions (confirm on review)

- **D-M1-8 FX source and failure behaviour.** ECB daily reference rates (EUR base) are fetched by a job, parsed and stored as rates against EUR; a cross rate between any two currencies is derived as `rate(to)/rate(from)` at read time using `Decimal`, rounded through `kernel/money.py` only at the final conversion (never intermediate). If the feed is unreachable the job records a failed run and **does not fabricate or carry forward** a rate (FX-004). Weekend/holiday dates have no ECB publication: a lookup for such a date uses the **most recent prior published date within 7 days** and returns that effective date to the caller so it is displayed (FX-003); older than 7 days is a block. This is the single place a prior-date rate is permitted, and it is explicit.
- No network from tests: the fetcher takes an injected HTTP callable and tests use a recorded ECB XML fixture.

## Contract

Migration (reversible): the next revision after the current head at story start (revision id `20260826_<next 4-digit number>`, `down_revision` = the head `python -m flo.kernel.migrate --check` validates today); stories merge one at a time, so there is no gap or fork: `fx_rate(id bigserial pk, base char(3) not null default 'EUR', quote char(3) not null, rate numeric(18,8) not null check (rate > 0), effective_date date not null, source text not null default 'ECB', fetched_at timestamptz not null, UNIQUE (base, quote, effective_date, source))`. **Not tenant data** (reference data shared by all orgs); no RLS, but writes are restricted to the migration role and the job; the table is append-only by trigger (corrections are a newer `fetched_at` row is not allowed - rates are retained permanently, FX-002).
`fx_ingest_run(id, started_at, finished_at, status in ('ok','failed'), rows_inserted, error_class)`.

Service (`modules/org/fx.py`, imported by other modules via `service`): `convert(amount: Decimal, from_ccy, to_ccy, on_date) -> Conversion{amount, rate, source, effective_date, from_ccy, to_ccy}` raising `FxRateMissing(from, to, on_date)` with an actionable message; same-currency returns rate 1 with `source='identity'`.

Endpoints: `GET /api/v1/fx/rates?base=&quote=&on=` → 200 `{rate, source, effective_date}` | 422 with `FxRateMissing` problem type (permission `fx.read`); `GET /api/v1/fx/status` (last run status, newest rate date) permission `fx.read`.

Job: registered with the existing Postgres job queue, daily; fetch URL is `settings.fx_feed_url` (default the ECB `eurofxref-daily.xml`), HTTPS only, 10 s timeout, response size cap 1 MiB, XML parsed with `defusedxml`-equivalent safety — **no new dependency**: use `xml.etree.ElementTree` after rejecting any `<!DOCTYPE` or `<!ENTITY` in the payload.

## Behaviour

1. Ingest is idempotent: re-running for an existing date inserts nothing.
2. A conversion never mutates a source document (FX-003): the service returns a value object; recording the rate on a transaction is the caller's job (FIN-003).
3. Quote precision: rates stored `NUMERIC(18,8)`; conversion rounds once to the target currency's exponent via `kernel/money.py`.
4. `FIN-003`: provide `fx.service.assert_single_currency(*currencies)` and a `Conversion.as_record()` dict (rate, source, effective_date) that callers persist.

### 3. The fetcher and the parser, exactly
- **HTTP client: `urllib.request` from the standard library.** `httpx` is a dev-only dependency and is not in the production image; add no dependency. `fetch(url) -> bytes`: refuse any URL whose scheme is not `https`; `urlopen(request, timeout=10)`; after redirects confirm the final URL is still `https`; read at most `1 MiB + 1` bytes and fail with `error_class='too_large'` above 1 MiB. Failures map to `error_class` in `{'network','http_status','too_large','doctype','parse'}`; never store a URL, header or secret in `error_class`, in logs or in the problem body.
- **Reject before parsing**: if the bytes contain `<!DOCTYPE` or `<!ENTITY` (case-insensitive), fail with `'doctype'` and do not call the XML parser.
- **Parse with `xml.etree.ElementTree`.** The feed is namespaced: elements are `{http://www.ecb.int/vocabulary/2002-08-01/eurofxref}Cube`. The structure is `Cube > Cube[@time] > Cube[@currency][@rate]`. Take `time` as an ISO date (`date.fromisoformat`), `currency` as three uppercase ASCII letters, `rate` via `Decimal(rate_text)` (never `float`), finite and `> 0`, quantized to 8 decimal places. Any malformed value fails the whole run with `'parse'` and inserts nothing (all rows in one transaction).
- Store **every** currency the feed publishes, whether or not the bundled `iso4217.json` knows it. The exponent table is only needed at conversion time.
- `INSERT ... ON CONFLICT (base, quote, effective_date, source) DO NOTHING`; `rows_inserted` counts rows actually inserted, so a second run reports 0. `fetched_at` comes from an injected `now: Callable[[], datetime]` (UTC).
- EUR is the base and is never in the feed: treat `rate(EUR) = 1` in code; store no EUR row.

### 5. Lookup rule (restates the earlier amendment, with the dates the tests use)
Exact date, or for a Saturday or Sunday the preceding Friday. Nothing else: any other date with no row is blocked. Both legs must have a row at that same effective date. Tests: Friday 2026-10-02 returns itself; Saturday 2026-10-03 and Sunday 2026-10-04 return Friday 2026-10-02 as `effective_date`; **Monday 2026-10-05 (no row) raises `FxRateMissing`**; so does 2026-10-10 (replaces the old "8 days after" case). A currency absent from the feed raises `FxRateMissing`.

### 6. Service surface and error mapping (the error taxonomy is closed)
All in `modules/org/fx.py`, exported through **`org.service`** (add them to `org/service.py`'s `__all__`).
- `FxRateMissing` is a `ProblemError` subclass built with `ErrorCode.VALIDATION_FAILED` (HTTP 422) and `checks={"problem": "fx_rate_missing"}`; detail names the pair and date and says what to do ("No ECB rate for USD to GBP on 2026-10-05. Rates exist for business days after the first ingest. Choose a published date, or ask an administrator to check the FX feed status.").
- An unsupported currency code (`currency_exponent` raises `ValueError`) becomes `ProblemError(VALIDATION_FAILED, checks={"problem": "unknown_currency"})` with a field error on the offending parameter.
- `assert_single_currency(*currencies)` raises `ProblemError(VALIDATION_FAILED, checks={"problem": "currency_mismatch"})`. Do not reuse `kernel.money.CurrencyMismatch` (a bare `ValueError`).
- `Conversion` is a frozen dataclass of `Decimal`s and strings; `as_record()` returns `{"rate": str(rate), "source": ..., "effective_date": iso, "from": ..., "to": ...}`. Same-currency returns rate `Decimal(1)`, `source='identity'`, `effective_date=on_date`.
