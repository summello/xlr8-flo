# E13-S23 — PO lock order: withdrawal instance-first, change-order submit award-first

**Epic** E13 · **M3** · **concurrency/S** · after **E13-S07** · tags: `concurrency` (Opus review)

> Found by Codex pre-flights 12 and 15 of E13-S07 (30 Oct 2026). Raised by the operator as its own story; part 2 added by the operator the same day.

## Requirements (inlined)

- **PO-007** — a PO that needs approval goes through the approval workflow; its creator may withdraw it while pending.
- **PO-010/PO-011** — an issued PO changes only through a numbered, approved change order.

## Problem

### 1. `PurchaseOrderService.withdraw`

`PurchaseOrderService.withdraw` (`apps/api/src/flo/modules/purchasing/service.py:859-876`) locks the PO
(`self._row(id, lock=True)`) and **then** calls `approvals.service.withdraw`, which locks
`approval_instance` (`approvals/decisions.py:362`). A final approval decision takes the opposite order:
`approval_instance` first (`decisions.py:226`), then the outcome adapter locks the PO
(`purchasing/service.py:880`). A creator withdrawing while an approver decides the same PO can deadlock;
Postgres aborts one side with 40P01, which reaches the client as a 500.

### 2. `ChangeService.submit`

`ChangeService.submit` (`purchasing/changes.py:512-543`) locks the PO (`self.po._row(po_id, lock=True)`,
:516) and then calls `approvals.service.start`. When the published `po_change` workflow auto-approves at
start (`approvals/engine.py:~700-740`), the outcome callback runs synchronously and `_apply` calls
`ChangeService._lock` (:576, :610-625), which locks the **award**, balances and requisition while the PO
is already held. Every other writer (E13-S07 cancel, `_apply` from a decision, PO `_draft`) locks the
award before the PO, so an auto-approving submit can deadlock with them.

## Design

### 1. withdraw

Copy `ChangeService.withdraw` (`purchasing/changes.py:545-569`): read the PO **unlocked**, check
creator-only and `status == 'approval_pending'` (409 `invalid_transition`) on that read, then call
`withdraw(document_type='po', ...)` holding no PO lock. The adapter's `settle` locks the PO and moves it
to `draft` under the instance lock, so the order is instance → PO on every path. A decision that
finishes first makes `withdraw` raise 409 `task_closed`; let it through unchanged. No API, schema or
migration change.

### 2. submit

Replace the PO lock at changes.py:516 with `self._lock(po_id)` (award, line-project balances in id
order, requisition, PO), so an auto-approved apply's own `_lock` only re-takes rows already held.
Everything after it is unchanged. E13-S07's `/reduce` already takes `_lock` first and needs no change.

## Acceptance

- [ ] `withdraw` takes no PO lock before `approvals.service.withdraw` (unit test asserting no `FOR UPDATE` on `purchase_order` before the instance lock, or a code-level assertion the reviewer can read).
- [ ] **Concurrency (real Postgres):** withdraw and a final approve racing on one PO, many iterations: no 40P01; exactly one of PO `draft` (withdrawn) or `approved`, the loser 409 `task_closed` or `invalid_transition`.
- [ ] Existing withdraw tests still green (creator-only 403, non-pending 409).
- [ ] `submit` takes the award lock before the PO lock (a second connection holding the award `FOR UPDATE` makes `submit` wait, `SET LOCAL lock_timeout = '1s'` → lock timeout, before any PO row is locked).
- [ ] **Concurrency (real Postgres):** a `submit` whose `po_change` workflow auto-approves, racing E13-S07's cancel on the same PO, many iterations: no 40P01; one wins, the other a 409.
- [ ] Existing change-order tests still green.

## Plants

1. Restore `self._row(id, lock=True)` before `withdraw`: the concurrency test sees a deadlock and fails.
2. Restore `self.po._row(po_id, lock=True)` in place of `self._lock(po_id)` in `submit`: the award-first test locks the PO first and fails.

## Files

`apps/api/src/flo/modules/purchasing/service.py` (`withdraw` only), `modules/purchasing/changes.py`
(`submit` only), their tests. Out of scope: every other withdraw path, `ChangeService.withdraw`, E13-S07's
cancel and `/reduce` (they already lock in order).
