# E23-S11 — Track the fleet supervisor in the repo, with tests for its decision rules

> **No new dependency** (AGENTS.md §0.6): the supervisor is stdlib only.

## Requirement (inlined)

- **SUP-005** — Administrator and operator documentation must be updated in the same PR as the feature it describes (UX-010).

## Why

The supervisor decides which step runs next for every story, within the Claude and Codex windows. It lives in `~/.claude/fleet/fleet.py`, outside this repository, so nothing about it is reviewed, tested or versioned, and E23-S07 and E23-S10 cannot be built. The operator chose **option A**: the repository holds the reviewed source; the user-scoped file becomes a deployed copy.

## Pre-flight findings (Opus, 22 Oct 2026, from the uploaded file)

- Source: the operator's upload, `fleet.py`, **441 lines, sha256 `f22da510cb99b030eb2733f6774632f4745272352c53260f89d6213d24ad684d`**. Stdlib only, Python 3.11+ (`tomllib`), macOS-specific in two places (`osascript` notifications, `launchctl`/launchd).
- Everything project-specific is already in `agents/fleet.toml`. The code is project-agnostic and keeps one state directory per project (`~/.claude/fleet/state/<project>/`).
- The decision rules are **pure functions**: `capacity`, `can`, `author_can`, `opus_account`, `decide`, `plan`, `heavy_slots`. `tick()` and `launch()` do the I/O. So the rules can be tested without launchd or a network.
- `tick()` is single-flight: a `mkdir` lock in the state directory, treated as stale after 1200 s.
- The supervisor never writes `task.json`. It reads `rounds` from `flo facts`, which counts round files.
- **Hazard of tracking it in the repo:** launchd runs the script from wherever it lives. If that is the runner checkout, a merged story can change the supervisor between two ticks. So the repo is the **source of truth** and `~/.claude/fleet/fleet.py` stays the **deployed copy**, updated by a deliberate `cp` after review.
- Two gaps that are real after E23-S04 and E23-S05, closed here because both are output-only (no change to what is launched):
  1. `plan()` silently skips a start when a Claude account has a free slot but no "start" headroom, even if the story will be authored by another agent. Nothing records that it happened.
  2. `flo facts` now keeps stories without a pre-flight record out of `next` and lists them in `needs_preflight`, which the supervisor ignores. If every ready story lacks a record, the fleet idles and nothing tells the operator.

## Design

### 1. `agents/fleet/fleet.py`

A copy of the uploaded file with exactly the two additions below and no other change. State the sha256 of the original in the commit message so a reviewer can diff against it.

### 2. Two output-only additions

- **Skipped-start note.** In `plan()`, when `facts["next"]` is non-empty, nothing else blocks a start (not `line_stopped`, `in_flight < max_in_flight`, `allow_start` true), and the Claude start condition fails (`facts["free_accounts"]` non-empty and `room` empty), append `{"note": "start blocked: no Claude account has room (next: <id>)"}` to the actions. `tick()` routes entries with a `note` key into `status["notes"]` (they reach `status.json` and `tick.log`) and never into `status["actions"]`, never to `launch()`. `heavy_slots` already passes entries without a `step` through.
- **Pre-flight need.** In `plan()`, when `facts["next"]` is empty, `facts.get("needs_preflight")` is non-empty and a start would otherwise be allowed (same three conditions), append `{"need": "nothing can start: <first id> and others have no pre-flight record; run flo preflight", "story": "<first id>"}`. The text carries no count so the existing de-duplication in `notified.json` does not re-notify on every change.

### 3. Deploy by copy

Document in `docs/ops/fleet-tooling.md`: edit and review in the repo; after merge run `cp agents/fleet/fleet.py ~/.claude/fleet/fleet.py`; check for drift with `cmp agents/fleet/fleet.py ~/.claude/fleet/fleet.py`. Do **not** point launchd at a path inside the runner checkout. Update the header comment of `agents/fleet.toml` to say the same.

### 4. Tests: `apps/api/tests/gates/test_fleet_supervisor.py` (new)

Load `agents/fleet/fleet.py` with `importlib` under a name other than `fleet`. Cover:

- `capacity`: no snapshot allows work; a stale account row is ignored (unknown, not 0%); the `start` and `continue` thresholds; `disabled_accounts`; Codex windows.
- `can`, `author_can` (Codex by its windows, Claude by account), `opus_account` (most five-hour headroom; none when no account may continue).
- `decide`, every branch: a running or busy story waits; merged with red CI fixes; blocked asks the operator; author `limit` or `none` resumes only when the account may continue; author `failed` asks the operator; red CI on the submitted head fixes, and **a fix that committed nothing asks the operator instead of looping**; an unsubmitted head submits, and a failed submit asks; a malformed verdict asks; missing or stale reviewers are launched (Codex only if its windows allow, Opus on the roomiest account); `changes` runs a round, and at `max_rounds` asks for arbitration; a stopped line waits; a gated story waits for green CI; finish, and a failed finish asks.
- `plan`: starts at most one story, with `room[0]`; nothing when the line is stopped, the fleet is full, or `allow_start` is false; the two additions above (the note appears exactly when specified; the need appears exactly when specified; neither appears otherwise).
- `heavy_slots`: drops heavy steps beyond the limit, keeps the rest.
- `tick`: a held `tick.lock` makes a second tick return "another tick is running" without launching; a dry run with a fake `facts` command returns the expected actions and launches nothing. Use a temporary `STATE` directory.
