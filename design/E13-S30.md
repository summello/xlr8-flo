# E13-S30 — Issue refuses to queue a PO email the sending domain cannot send

**Epic** E13 · **M3** · **engine/M** · after **E13-S10**, **E13-S21** · tags: —
Origin: M3 Opus milestone review (finding 2, 8 Nov 2026).

> **UI authority:** `design-system/MASTER.md`, `tokens.css`, `design-system/pages/purchase-orders.md`.

## Requirements (inlined)

- **EML-001** — The sending domain must publish SPF, DKIM and DMARC, verified by an automated check before first customer send (operator narrowed: SPF and DKIM automated, DMARC manual).
- **PO-012** — Duplicate clicks, retries, worker retries, and integration retries must not issue or transmit a PO more than once unintentionally.
- **UX-005** — errors say what happened, what was preserved and how to recover.

## Finding

The EML-001 gate holds: `kernel/email.py` `po_domain_gate` refuses a `po-*` email until the latest check has
SPF and DKIM `pass`. But the dispatcher (`kernel/outbox/dispatcher.py:114`) raises `PermanentOutboxError`, so
each PO email issued before verification goes **dead**. The issue itself still commits the budget and marks
the PO issued, and the Issue dialog (`components/purchasing/issue/IssueDialog.tsx`) never reads
`po_email_allowed`, so on a new tenant the buyer is told the vendor will be emailed and learns otherwise only
from a dead row in the transmission log. When the domain later passes nothing re-sends; each PO needs a manual
Resend.

## Decision (operator, 8 Nov 2026)

(b) **Refuse at issue.** With `po_email_allowed` false the Issue dialog says "Purchase order email is held
until the sending domain is verified" and offers **issue without email** (download the PDF and send it
yourself) or **cancel**; nothing is queued, nothing goes dead.

## Design

**Server is the authority; the dialog only reflects it.**

- **One gate reading.** In `purchasing/transmission.py`, a function `po_email_allowed(conn, settings) -> bool`
  = `po_domain_gate(settings, latest status)(TEMPLATE) is None`, the expression `sending_domain` (~486) already
  uses; `sending_domain` calls it. No second implementation.
- **Issue body.** `POST /api/v1/purchase-orders/{id}/issue` accepts an optional body
  `PoIssue {send_email: bool = true}` (`extra="forbid"`); no body means `send_email: true`, so every existing
  caller and test keeps working. The route passes `settings` (`Depends(get_auth_settings)`, as `sending_domain`
  ~475 does) and `send_email` to `issue()`.
- **In `purchasing/issue.py` `issue()`**, inside the transaction, after the retry/status/version checks
  (~70-73) and **before** any write (the recipients update ~82, `issue_lines`, `transition`):
  - `send_email` and not `po_email_allowed` → `409` problem, `checks.problem = "po_email_held"`, detail
    "Purchase order email is held until the sending domain is verified. Nothing was issued." Nothing is
    written: no ledger entry, no status change, no outbox row.
  - `send_email` false → issue exactly as today **except** `enqueue_transmission` is not called; write one
    audit row through `kernel` `audit_event` (action `purchase_order.issue_without_email`, the actor, the PO) in
    the same transaction. Recipients are still resolved and stored as today (a later Resend uses them); the
    `NO_RECIPIENTS` rule is unchanged.
  - A retry of the same issue (the `status == "issued"` early return, PO-012) returns before this check, as now.
- **Dialog read.** `VendorCopyRead` (`purchasing/pdf.py` ~204, already loaded by the dialog) gains
  `po_email_allowed: bool`; `GET .../vendor-copy` takes `settings` and fills it from the one function.
- **`IssueDialog.tsx`:** when `copy.data.po_email_allowed` is false, the dialog body shows the held message
  (above the facts, a `Signal tone="warning"` with that text; text carries it) and the primary button reads
  **Issue Without Email**, which POSTs `{send_email: false}`; the secondary is Cancel. "Download PDF" stays
  available as today. When allowed, the dialog is unchanged and POSTs no body. If an Issue press gets
  `409 po_email_held` (the domain lapsed after the dialog opened), the dialog switches to the held state with
  the same key cleared (a new operation) and focus moves to the message.
- **After issue without email:** the issue result page / transmission log (`routes/purchase-orders/issue.tsx`)
  for an issued PO with **no** transmission rows shows "Issued without email. Download the PDF and send it to the
  vendor yourself." in place of the empty log. Derived (an issue with email always writes attempt 1 in the same
  transaction), no new field.
- Regenerate the client (`openapi.json`, `schema.ts`); no hand-written types.
- Follow-up, not this story: a cancel notice for a PO issued without email is still gated by the same domain
  check; record it in `notes.followup`.

## Acceptance

- [ ] pytest (real Postgres, `email_provider="resend"` settings override, no passing domain check): issue with no body → 409 `po_email_held`; afterwards the PO is still `approved`, no `ledger_entry`, no `po_transmission`, no outbox row, `recipients` unchanged.
- [ ] pytest: same state, `{send_email: false}` → 200, PO `issued`, commitment posted as in the existing issue test, **no** outbox row and no `po_transmission`, one `purchase_order.issue_without_email` audit row.
- [ ] pytest: with SPF and DKIM `pass`, issue with no body behaves exactly as today (one attempt-1 transmission queued); `{send_email: false}` also works there.
- [ ] pytest: a retried issue (same `If-Match`, PO already issued) returns the PO without the 409, held domain or not (PO-012).
- [ ] pytest: `GET .../vendor-copy` reports `po_email_allowed` false/true across the two domain states; `sending_domain` still reports the same value.
- [ ] Playwright (`po-issue.spec.ts`; stub): `po_email_allowed: false` shows the held message and **Issue Without Email**, which sends `{"send_email": false}`; Cancel closes with focus back on Issue; a `409 po_email_held` on a plain Issue switches the dialog to the held state; the result page with an empty transmission list shows the "Issued without email" line. Keyboard-only path through the held dialog; axe both themes.
- [ ] `flo check --light` green.

## Plants

1. Move the held check after `issue_lines`: the "no ledger entry" assertion fails.
2. Call `enqueue_transmission` when `send_email` is false: the "no outbox row" assertion fails.
3. Make the dialog ignore `po_email_allowed`: the Playwright held-state case fails.
