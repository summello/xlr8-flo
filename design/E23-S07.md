## What changed since the first version of this packet

The first version was blocked because `fleet.py` was not in the repository. The operator uploaded it on 22 Oct 2026 and chose to track it in the repo (E23-S11). Reading it **disproves the backlog's premise**:

- T5 said `plan()` takes "the first eligible account" instead of ranking by headroom. `plan()` does take `room[0]` (`fleet.py`, `plan`), but `room` is built from `facts["free_accounts"]`, which `flo` sorts by **current worker load, least loaded first** (`free_accounts` in `agents/scripts/flo`). So `room[0]` is the least-loaded account that passes the start thresholds, not an arbitrary one. A headroom ranking is a different criterion, and nothing measured says it would help. **The headroom ranking is dropped.**
- What the source does show is a coupling that matters more after E23-S04 routes ungated work to nemotron: `plan()` starts a story only if `room` is non-empty **or** `facts["free_accounts"]` is empty. The supervisor cannot tell who will author the next story ("never picks a model"). When a Claude account has a free worker slot but is below the start thresholds, **no story starts at all**, even one that `flo assign` would give to nemotron or Codex.

## Design

### 1. `flo facts` says who would author each startable story

`cmd_facts` adds `next_authors`: a map from each id in `next` to the author `assignment_for` would choose. If `assignment_for` exits for a story (nobody qualifies), the value is `null`; the command must not fail. `next` itself is unchanged.

### 2. `plan()` requires Claude room only for a Claude author

For `facts["next"][0]`, let `author = facts.get("next_authors", {}).get(id)`:

- `author` is `null` or `"sonnet"` (or `next_authors` is absent): today's rule, unchanged.
- `author` is `"codex"`: start only if `cap["codex"]` allows it; no Claude room needed; `account` is `""`.
- any other author (nemotron): start; `account` is `""`.

The skipped-start note from E23-S11 stays for the Claude case.
