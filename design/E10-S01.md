# E10-S01 — Workflow definition schema, versioning, active-document version pinning

**Epic** E10 · **M2** · **migration/L** · after **E03-S04** · tags: `migration`

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md` (G–N) and `docs/author-traps.md` apply unless this packet says otherwise. Decisions D-M2-n: `docs/m2-decisions.md`.

## Requirements

- **APR-011** — Workflow definitions must be versioned; active documents must retain the workflow version used at submission.
- **ACC-007** — Editing a workflow does not alter the routing or decision history of documents already submitted.
- **AUD-001** (configuration events) — Create, update, transition, approval, rejection, override, import, export, transmission, configuration, and deletion/retirement events must be audited.

## Contract

New module `modules/approvals/` (convention G). Routers in `apps/api/src/flo/api/workflows.py`, registered where the other routers are.

| Route | Permission (target) | Success | Notes |
|---|---|---|---|
| `POST /api/v1/workflows` (Idempotency-Key) | `workflow.manage` (organization; or the BU/OU when `scope_type = bu`) | 201 `WorkflowRead` | body `{document_type, name, scope_type: "org"\|"bu", scope_id?}`; a live definition already bound to the same `(document_type, scope)` is 409 `CONFLICT`, `checks.problem = "workflow_scope_taken"` |
| `GET /api/v1/workflows?document_type=&cursor=` | `workflow.read` (organization) | 200 `{rows, next_cursor}` | keyset on `(created_at, id)`, 50 per page |
| `GET /api/v1/workflows/{id}` | `workflow.read` | 200 `WorkflowRead` with `versions: [{version, status, created_at, published_at}]` | |
| `POST /api/v1/workflows/{id}/versions` (Idempotency-Key) | `workflow.manage` | 201 `WorkflowVersionRead` | body `{graph}`; a new `draft` version numbered max+1; at most one `draft` per definition, else 409 `draft_exists` |
| `GET /api/v1/workflows/{id}/versions/{version}` | `workflow.read` | 200 `WorkflowVersionRead` (`ETag` = row version) | |
| `PUT /api/v1/workflows/{id}/versions/{version}` | `workflow.manage` | 200 | `If-Match` required (convention O: 400 without it, 409 `stale_version` on mismatch); only a `draft` is editable, else 409 `version_immutable` |
| `POST /api/v1/workflows/{id}/versions/{version}/publish` (Idempotency-Key) | `workflow.manage` | 200 | structural validation only here (the graph parses); E10-S03 adds semantic validation to this same endpoint. Publishing supersedes the currently published version in the same transaction |
| `POST /api/v1/workflows/{id}/retire` (Idempotency-Key) | `workflow.manage` | 200 | sets `retired_at`; documents already pinned keep their version (ACC-007) |

`document_type` is one of `project`, `requisition`, `budget_change`, `vendor`, `rfq`, `award`, `po` (APR-003; only the first three have adapters in M2, the rest are registered by M3 stories). `scope_type = org` requires `scope_id` absent (it is the organization); `bu` requires an org unit of this tenant, else 404.

**Graph format** (Pydantic in `approvals/schemas.py`, stored as `jsonb`; E10-S02/S03/S05 consume it, so freeze it here):

```json
{
  "nodes": [
    {"id": "start", "kind": "start"},
    {"id": "c1", "kind": "condition", "name": "Large request?"},
    {"id": "a1", "kind": "approval", "name": "Finance",
     "approvers": {"type": "role", "role_code": "finance_approver"},
     "mode": "any", "due_days": 5, "allow_repeat": false},
    {"id": "end", "kind": "end"}
  ],
  "edges": [
    {"from": "start", "to": "c1"},
    {"from": "c1", "to": "a1", "when": {"field": "amount", "op": "gt", "value": {"amount": "250000.00", "currency": "USD"}}},
    {"from": "c1", "to": "end", "default": true},
    {"from": "a1", "to": "end"}
  ],
  "layout": {"a1": {"x": 320, "y": 140}}
}
```

- `approvers.type` is `role` (`role_code`), `users` (`user_ids`, 1..50) or `permission` (anyone eligible under E10-S04).
- `mode` is `"any"`, `"all"` or `{"quorum": n}` with `n >= 1`.
- `due_days` (1..365, optional), `escalate_after_days` and `escalate_to` (optional, consumed by E10-S08) are stored but not acted on here.
- `when` is a condition expression (E10-S02 defines its grammar; this story stores it as opaque JSON that must be an object).
- `layout` is presentation only (E10-S11) and never affects routing.
- Structural rules enforced at save and publish: exactly one `start`, at least one `end`, unique node ids (`^[a-z0-9_-]{1,40}$`), every edge endpoint names a node, at most 200 nodes and 400 edges, graph JSON at most 256 KiB. Violations are 422 `VALIDATION_FAILED` with `errors[].field` as a JSON pointer (`/nodes/3/id`).

## Behaviour

1. **Tables** (one migration, reversible, next revision after the head at story start):
   - `workflow_definition(id uuid PK, org_id uuid NOT NULL, document_type text NOT NULL CHECK (...the seven values...), name text NOT NULL, scope_type text NOT NULL CHECK (scope_type IN ('org','bu')), scope_id uuid NOT NULL, created_by uuid NOT NULL, created_at timestamptz NOT NULL DEFAULT now(), retired_at timestamptz)`; `UNIQUE (org_id, document_type, scope_type, scope_id) WHERE retired_at IS NULL`; for `org` scope, `scope_id = org_id`.
   - `workflow_version(id uuid PK, org_id, definition_id uuid NOT NULL REFERENCES workflow_definition, version int NOT NULL, status text NOT NULL CHECK (status IN ('draft','published','superseded')), graph jsonb NOT NULL, row_version int NOT NULL DEFAULT 1, created_by, created_at, published_by uuid, published_at timestamptz)`; `UNIQUE (definition_id, version)`; `UNIQUE (definition_id) WHERE status = 'published'`; `UNIQUE (definition_id) WHERE status = 'draft'`.
   - **Immutability trigger** (ACC-007): a `BEFORE UPDATE` trigger raises unless the old row is `draft` (any column may change, `row_version` must increase), or the only change is `status` from `published` to `superseded`. `BEFORE DELETE` raises unless the row is `draft`. Follow the `raise_append_only()` precedent's style and SQLSTATE.
   - RLS (`FORCE ROW LEVEL SECURITY`, the `tenant_isolation` policy every tenant table uses) on both.
   - Permissions `workflow.read`, `workflow.manage` (convention I) in a **separate permissions-only migration** `<next+1>_workflow_permissions.py`; baseline grant of both to `organization-administrator`, granted to existing tenants' system roles by role code; downgrade removes `role_permission` rows, then `permission` rows.
2. **Resolution** (the function E10-S05 calls; nothing else picks a version): `approvals.service.resolve_version(conn, scope, document_type, bu_id: UUID | None) -> WorkflowVersionRead | None` returns the published version of the live definition bound to `bu_id` if one exists, otherwise the organization-level one, otherwise `None` (D-M2-11). It never returns a draft, superseded or retired version.
3. **Pinning** (APR-011, ACC-007) is the combination of (a) E10-S05's instance row storing `workflow_version_id NOT NULL REFERENCES workflow_version` and (b) the immutability trigger here: once published, a version's graph can never change, so an instance pinned to it can never be re-routed. Publishing v2 supersedes v1 without touching v1's graph.
4. **Publish** locks the `workflow_definition` row `FOR UPDATE`, checks the version is `draft`, sets the previous published version to `superseded` and this one to `published` in one transaction. Two concurrent publishes of two drafts cannot both win, which the partial unique indexes guarantee.
5. **Audit** (AUD-001): create, version create, version update, publish (with superseded version id), retire, each with the before and after of the changed fields, in the same transaction.
6. Every new route gets a `COVERED` entry with a real foreign-tenant test (convention C).

## Acceptance criteria

- [ ] Publishing v2 leaves v1's `graph` byte-identical and marks it `superseded`; `resolve_version` then returns v2.
- [ ] `UPDATE workflow_version SET graph = ...` on a published row fails in the database, issued as the application role (not only through the service).
- [ ] `DELETE` of a published or superseded version fails in the database; deleting a draft succeeds.
- [ ] A BU/OU-bound published version wins over the organization-level one for a document in that BU/OU; a document in another BU/OU gets the organization one; with neither, `None`.
- [ ] Two concurrent publish calls on one definition: exactly one version ends `published`.
- [ ] Editing a draft without `If-Match` is 400 `BAD_REQUEST`; with a stale one 409 `stale_version`; editing a published version is 409 `version_immutable`.
- [ ] Every structural rule above produces a 422 with a JSON-pointer field.
- [ ] Every route: unauthenticated 401, no grant 404, wrong permission in scope 403, foreign tenant 404.
- [ ] Each write produces exactly one audit row with before and after.

## Required tests

`apps/api/tests/approvals/test_workflow_definitions.py` (real app, real Postgres): one test per acceptance criterion, plus a migration test in `tests/kernel/test_migrate.py` (append the revision, convention F) proving down then up preserves a definition with a published and a draft version.

## Plants (reviewer runs each, watches the named test fail, restores)

1. Drop the immutability trigger in the migration: the published-graph update test fails.
2. Make `resolve_version` ignore `bu_id`: the BU-override test fails.
3. Remove the `FOR UPDATE` on publish and the partial unique index on `published`: the concurrent-publish test fails.
4. Skip the audit write on publish: the audit test fails.
