> (this packet overrides its "Never: a new dependency" line, see §5 and **Resolved**).

## Requirements (inlined)

- **PO-014** — Generated PO PDFs must be reproducible from the stored PO snapshot and template version.
- **DATA-005** — Historical documents must retain snapshots of mutable referenced data needed to reproduce their legal/business meaning.

## Design

### 1. `VendorCopy` — the whitelist (`modules/purchasing/vendor_copy.py`)

Pydantic models, `model_config = ConfigDict(extra="forbid")`; every leaf is `str`, `int`, `date` or
`None` (amounts are the already-quantized strings `PoRead`/`PoLineRead` carry; no `float`):

- `VendorCopyAddress`: `line1`, `line2`, `city`, `region`, `postal_code`, `country`.
- `VendorCopyLine`: `line_no`, `description`, `quantity`, `uom_code`, `unit_price`, `price`, `tax`, `freight`, `line_total`.
- `VendorCopyNote`: `body: str`, `created_on: date`.
- `VendorCopy`: `number`, `revision`, `issued_on: date | None`, `needed_by: date | None`, `currency`,
  `vendor_trading_name`, `vendor_legal_name`, `bill_to: VendorCopyAddress`,
  `ship_to: VendorCopyAddress | None`, `terms: str | None` (the PO's own `purchase_order.terms`),
  `letterhead_address: str | None`, `standard_terms: str | None`, `lines: list[VendorCopyLine]`,
  `price_total`, `tax_total`, `freight_total`, `total`, `notes: list[VendorCopyNote] = []`.

No field holds a chartfield, a project id, a budget amount, the rate or converted totals, the
requester, recipients, eligibility, an internal note or a file. **`notes` ships here, always `[]`
in this story**; E13-S11 fills it through `collaboration.service.external_notes_for` and adds no
field (its packet forbids it). Any field added later must have a default, and none is ever removed
(stored snapshots must keep validating).

`vendor_copy(conn, scope, po_id) -> VendorCopy` builds it from live data in the caller's
transaction, taking **no lock**:

- header, lines and totals from `PurchaseOrderService(conn, scope).get(po_id)` (`service.py:164`) —
  `PoRead`/`PoLineRead` fields of the same names (`schemas.py:95-147`); vendor names from
  `vendor_snapshot["trading_name"]` / `["legal_name"]` (written at create, `service.py:451-460`);
- `issued_on`: `purchase_order.issued_at` (not in `HEADER`, `service.py:72-76`; one
  `service.repo.execute` SELECT) as its UTC date, `None` before issue;
- `bill_to`: the six keys above from the `purchase_order.bill_to` jsonb (an `OrgAddressRead` dump,
  `service.py:358-365`, that also holds ids, dates and `created_by`, all dropped);
- `ship_to`: `None` when `ship_to_address_id` is null; else for each unit of
  `OrgService.unit_chain(unit_id)` (`org/service.py:210`) try
  `OrgService.get_address(unit, address_id)` (`org/service.py:465`; it raises
  `ProblemError(NOT_FOUND)` when the address is not on that unit: catch it and try the next). It has
  no date filter, so an address closed since the draft still resolves. This is DATA-005's snapshot of
  a mutable reference. Not found on any unit → `ProblemError(ErrorCode.CONFLICT, checks={"problem": "ship_to_missing"})`
  (unreachable: `update` only accepts an address on the chain, `service.py:725-734`);
- `letterhead_address`, `standard_terms`: `OrgService.effective_setting(unit_id, key).value`
  (`org/service.py:428`) for the two keys of §2.

`email_summary(copy: VendorCopy) -> str`: plain text built **only** from a `VendorCopy` (number,
revision, vendor trading name, needed-by, line count, total with currency, then "The purchase order
is attached as a PDF."). E13-S09 sends it as the email body.

### 3. Snapshot table — `po_version`

Migration `migrations/20261030_0085_po_version.py`, `revision = "20261030_0085"`,
`down_revision = "20261029_0084"` (renumber if another lane merges a migration first):

```
po_version (
 org_id uuid NOT NULL REFERENCES organization(id),
 po_id uuid NOT NULL,
 version int NOT NULL CHECK (version >= 1),
 template_version text NOT NULL,
 snapshot jsonb NOT NULL,
 pdf_sha256 text NOT NULL CHECK (pdf_sha256 ~ '^[0-9a-f]{64}$'),
 created_at timestamptz NOT NULL DEFAULT now(),
 PRIMARY KEY (org_id, po_id),
 FOREIGN KEY (org_id, po_id) REFERENCES purchase_order(org_id, id)
)
```

One row per `purchase_order` row, ever. `version` is the row's `purchase_order.version` right after
its `issue` transition: the value `enqueue_transmission` receives (`issue.py:153` passes
`version + 1`, `changes.py:696` passes `2`). It never moves when the row is later superseded,
cancelled or closed. `(po_id, version)` is the "document snapshot id" E13-S09 records (EML-006).

Plus the literal RLS block and append-only triggers on the existing `raise_append_only()`
(`20260825_0005_audit_log.py:22`), as `ledger_entry` does (`20260826_0019_ledger.py:58-61`): one
`BEFORE UPDATE OR DELETE … FOR EACH ROW`, one `BEFORE TRUNCATE … FOR EACH STATEMENT`. Down drops the
triggers and the table under an `# irreversible:` comment (snapshots are lost). No backfill: no PO has
been issued in production (M3 has not reached `main`). `purchase_order` gets no column, so
`purchase_order_immutable` (`20261029_0084_po_change.py:57`) is unchanged.

### 4. Freeze at issue — `pdf.freeze(conn, scope, po_id) -> None`

`copy = vendor_copy(conn, scope, po_id)`; `snapshot = copy.model_dump(mode="json")`;
`data = render(VendorCopy.model_validate(snapshot), TEMPLATE_VERSION)` (render the **round-tripped**
snapshot, the path `pdf_for` takes, so the stored hash is the one a later read reproduces); insert
`(po_id, version, TEMPLATE_VERSION, snapshot, sha256(data).hexdigest())` with `version` read from
`PurchaseOrderService(conn, scope)._row(po_id)["version"]` (already past the `issue` transition).

Call it in exactly two places, in the caller's transaction, after the issue stamp and **before
`enqueue_transmission`** (E13-S09 reads the snapshot there):

- `issue.py` `issue()`: between the `UPDATE purchase_order SET issued_at …` (`issue.py:146-150`) and
  `mark_completed` (`:151`).
- `changes.py` `ChangeService._write_revision`: after its `issued_at` stamp (`changes.py:827-831`),
  before `return new_id` (`:832`), with `po_id = new_id`. `_apply` calls `enqueue_transmission`
  after it returns (`changes.py:694-696`). E13-S07's reduce applies through this path. E13-S07 is in
  flight and edits both files (a `lock_award` call at the top of `issue`, the `_root` move): put each
  call after the stamp wherever it sits after that merge.

Once per row: an issue replay returns at `issue.py:59-60`, a retried approval decision at
`changes.py:578-579`, a retried non-material apply at `changes.py:597-598`, all before `freeze`. The
primary key turns any second call into a unique violation, never a second snapshot. Cancel writes no
revision and no snapshot; a cancelled, closed or superseded row keeps its PDF.

**Locks:** `freeze` takes no row lock. Its reads (`get`, `effective_setting`, `unit_chain`,
`get_address`, the `issued_at` SELECT) are plain SELECTs. Its INSERT takes FK `KEY SHARE` locks on
(a) the `purchase_order` row, which this transaction already holds `FOR UPDATE` (issue's PO lock;
the new revision row it inserted itself), and (b) the `organization` row. (b) is taken last, after
every lock of issue (E13-S05; award → balances → requisition → PO once E13-S07 merges) and of change
apply (approval instance when through `decide`, then `ChangeService._lock`: award → balances →
requisition → PO, `changes.py:610-625`). `_write_revision`'s own `purchase_order` INSERT already takes
the same `KEY SHARE` on that path. Every `organization FOR UPDATE` taker is in the org module
(`org/models.py:22-24`, called from `org/service.py` and `org/fiscal.py`) and locks only org-module
rows after it (the only setting guard, `budget/service.py:280`, only reads; `fiscal.py:291` creates
a missing fiscal year inside a posting, after that posting's balance locks). So a concurrent settings write can make `freeze` wait, never
deadlock. A setting committed during an issue is either in that snapshot or not; both are correct.
A render error rolls the whole issue back.
`# ponytail: renders inside the issue transaction with its locks held; move the render out if issue latency shows it.`

### 5. Renderer — `modules/purchasing/pdf.py`

`pdf.py` imports `vendor_copy.py`, never the reverse. It holds `TEMPLATE_VERSION = "po-v1"`,
`render`, `freeze`, `frozen`, `pdf_for` and `vendor_copy_read`. `issue.py` and `changes.py` import
`pdf.freeze`.

`render(copy: VendorCopy, template_version: str) -> bytes` takes **no connection**, so the PDF can
only contain what `VendorCopy` holds. An unknown `template_version`, or `copy.issued_on is None`,
raises `ValueError`. `po-v1` is frozen once merged: a layout change adds `po-v2` beside it and
never edits v1 (the golden test enforces it).

- **Library: `fpdf2`** (operator, 30 Oct 2026, option A; see **Resolved**). No PDF library is
  installed (`apps/api/pyproject.toml` `[project] dependencies`, `uv.lock`). Pin `fpdf2==<current>`
  and its subsetter `fonttools==<the version uv resolves>` with `==` in `pyproject.toml` (the bytes
  depend on both; every other dependency keeps the repo's range style), and lock with uv. Runtime
  additions: `fpdf2`, `fonttools`, `defusedxml`, `Pillow`, all wheels, no `apt` package, no change
  to `apps/api/Containerfile`. PR body (AGENTS.md §0.6): "fpdf2 — replaces nothing (no PDF library
  installed) — stdlib cannot write PDF; pure Python, no system packages, same bytes on macOS and
  Linux; LGPL-3.0, used unmodified as a library." Why not `reportlab`: its flowing-text API
  (`platypus.Paragraph`) parses inline markup, so every vendor-supplied string would need escaping to
  stay verbatim; fpdf2's `multi_cell`/`table` draw text as given and break pages themselves. Both pull
  Pillow, so neither is cheaper to install. If `mypy --strict` needs an override for the library,
  scope it to `fpdf.*` and name it in the PR body.
- **Deterministic bytes:** `set_creation_date(datetime.combine(copy.issued_on, time(), UTC))` (the
  default is `now()`, and the `/ID` hash includes it); `set_compression(False)` (keeps zlib out of the
  byte path); `set_producer("XLR8 FLO po-v1")`; no other metadata. One committed Noto Sans TTF
  (regular, plus bold if the layout uses it; SIL OFL 1.1, `OFL.txt` beside it) in
  `modules/purchasing/fonts/`, loaded with
  `importlib.resources.files("flo.modules.purchasing").joinpath("fonts/…")`, and added to
  `[tool.setuptools.package-data]` beside `kernel/data/*.json` (the runtime image copies
  `apps/api/src/` whole, `Containerfile:46`, so the font ships either way). A character the font lacks
  is skipped or drawn as the missing glyph; it never raises (an issue must not fail on a vendor name).
  Upgrading `fpdf2` or `fonttools` changes bytes and therefore every stored hash check: the golden
  test fails on it, so such an upgrade needs a new template version, never a silent bump.
- **Layout:** monochrome document (MASTER §7.16 `.pdf-page` is E13-S17's **browser preview** frame,
  drawn with CSS tokens; it is not a PDF value source). Letterhead block, Bill To, PO number and
  revision, issued and needed-by dates, vendor, Ship To, lines (amounts right-aligned, currency code
  shown), totals with tax and freight apart (PO-016), PO terms, notes (when `notes` is non-empty),
  standard terms. Every string, amount strings included, is drawn verbatim from the snapshot: no
  HTML, no Markdown (`markdown=False`), no locale formatting. Pages break as needed.

`frozen(conn, scope, po_id) -> PoVersion`: one scoped SELECT of the `po_version` row; none →
`ProblemError(ErrorCode.NOT_FOUND)`. `PoVersion` is a frozen dataclass `(version, template_version,
pdf_sha256, copy: VendorCopy)` with `copy = VendorCopy.model_validate(snapshot)`.

`pdf_for(conn, scope, po_id) -> bytes`: `pv = frozen(...)`; `data = render(pv.copy,
pv.template_version)` (the module global, so a test can monkeypatch it); `sha256(data).hexdigest()
!= pv.pdf_sha256` → `logger.error("po_pdf_hash_mismatch po_id=%s", po_id)` and
`ProblemError(ErrorCode.INTERNAL_ERROR)`. Never serve bytes that differ from what was issued.
E13-S09 and E13-S24 attach these bytes.

`vendor_copy_read(conn, scope, po_id) -> VendorCopyRead {vendor_copy: VendorCopy, email_summary:
str, template_version: str, issued: bool}`: the stored snapshot when a `po_version` row exists
(`issued: true`, its `template_version`); otherwise, when the row's status is `draft`,
`approval_pending` or `approved`, a live `vendor_copy()` (`issued: false`, current
`TEMPLATE_VERSION`) for E13-S15's confirmation; any other status → `ProblemError(NOT_FOUND)`.

### 6. Routes — `api/purchasing.py` (parse, authorize, call, serialize)

| Route | Permission | Response |
|---|---|---|
| `GET /api/v1/purchase-orders/{id}/pdf` | `purchase_order.view` (`ViewContext`, `api/purchasing.py:52`) | 200 `application/pdf` body `pdf_for(...)`; 404 when the row has no `po_version` |
| `GET /api/v1/purchase-orders/{id}/vendor-copy` | `purchase_order.view` (`ViewContext`) | 200 `VendorCopyRead` from `vendor_copy_read(...)` |

`{id}` is one revision's `purchase_order.id`; `po_target` (`api/purchasing.py:38-40`) is already 404
for a foreign, deleted or unknown id before the permission check. PDF headers, as the attachment
download precedent (`api/collaboration.py:204-213`): `Content-Disposition: inline; filename*=UTF-8''`
+ `quote(name, safe="")` with `name` = `{number}.pdf`, or `{number}-rev{revision}.pdf` when
`revision > 0` (E13-S09's attachment name), from `frozen(...).copy`; `X-Content-Type-Options:
nosniff`; `Cache-Control: private, no-store`. Declare `responses={200: {"content":
{"application/pdf": {}}}}` and `response_class=Response`. Both are GETs: no `Idempotency-Key`, no
`If-Match`. Regenerate the web client (`npm run generate:api` in `apps/web`).

(No shareable note here: E13-S11 makes those appear.)
- [ ] **Letterhead:** with both settings set, the PDF text contains the address and the standard terms; an address `<script>alert(1)</script>` appears verbatim in the text; with both unset neither appears; a unit override → 422 `org_only_setting`; 601 characters or 9 lines → 422 `invalid_setting_value`.
- [ ] **Snapshot, not live:** after issue, change both settings and close the Ship To address (`close_address`) → `GET …/pdf` is 200, its sha256 equals the stored `pdf_sha256`, its text has the old values; `GET …/vendor-copy` returns the old values with `issued: true`.
- [ ] **Per revision:** apply a non-material change order that edits `terms` (`ChangeService.apply`) → revision 0's PDF is unchanged (same hash, old terms); revision 1 has its own `po_version` row with `version = 2` and the new terms; revision 0's row has `version` = its version right after issue. - [ ] **Golden:** a committed fixture snapshot (two lines, a `ship_to`, both settings, one note) renders with `po-v1` to a sha256 literal in the test; green on macOS (`flo check --light`) and Linux CI.
- [ ] **Hash check:** monkeypatch `flo.modules.purchasing.pdf.render` after issue to return other bytes → `GET …/pdf` is 500 `internal-error` and the log has `po_pdf_hash_mismatch`.

- [ ] **Once:** an issue replay (`If-Match` = version - 1), `ChangeService.settle` called twice with `APPROVED`, and a retried `apply` each leave exactly one row per `purchase_order` row; calling `freeze` twice for one row raises a unique violation.
