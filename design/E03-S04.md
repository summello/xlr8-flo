# E03-S04 — Audit trail: append-only table, triggers, before/after, correlation id

**Epic** E03 · **M0** · **security/L** · after **E03-S02** · tags: `security`, `migration`

## Requirements

- **AUD-001** — Create, update, transition, approval, rejection, override, import, export, transmission, configuration, and deletion/retirement events must be audited.
- **AUD-002** — Each audit event must record when, where, who, what, target, action, outcome, reason, correlation identifier, and before/after values where appropriate.
- **AUD-003** — Audit timestamps must be stored in UTC with sufficient precision and displayed in the viewer's timezone.
- **AUD-004** — Audit records must be append-only for application users and protected from unauthorized modification or deletion.
- **AUD-006** — Secrets, passwords, raw tokens, session identifiers, sensitive banking data, and unnecessary personal information must not be written to logs.
- **AUD-010** — System clocks must be synchronized, and event correlation identifiers must span API and background processing.

## Model

```sql
CREATE TABLE audit_log (
  id              BIGSERIAL PRIMARY KEY,
  org_id          UUID        NOT NULL,
  bu_id           UUID,
  occurred_at     TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),  -- UTC, microsecond
  actor_id        UUID,                       -- null only for system actions
  actor_kind      TEXT NOT NULL,              -- user | system | job | import
  action          TEXT NOT NULL,              -- 'project.approve', 'role.grant', …
  target_type     TEXT NOT NULL,
  target_id       UUID,
  outcome         TEXT NOT NULL,              -- success | denied | error
  reason          TEXT,
  correlation_id  TEXT NOT NULL,
  before          JSONB,
  after           JSONB,
  ip_prefix       TEXT,                       -- truncated /24 or /48, never full
  user_agent      TEXT
) PARTITION BY RANGE (occurred_at);
```

Monthly partitions. Per §2.9 of the plan, partitions older than 90 days export to R2 as JSONL and detach — Neon's 512 MB is the binding constraint and audit is the fastest-growing table.

## Behaviour

1. **Append-only is enforced by the database (AUD-004)**, not by convention:
   ```sql
   CREATE TRIGGER audit_log_immutable BEFORE UPDATE OR DELETE ON audit_log
     FOR EACH ROW EXECUTE FUNCTION raise_append_only();
   ```
   The application role additionally holds no `UPDATE`/`DELETE` grant on the table.
2. **Redaction is a allow-list, not a deny-list (AUD-006).** `before`/`after` are built by naming the fields to include. A field never explicitly included is never written. Deny-lists fail the moment someone adds a column. A test asserts that a model carrying `password_hash`, `token_hash`, `bank_account` and `tax_id` produces an audit payload containing none of them.
3. **Correlation (AUD-010)** — the `correlation_id` from E03-S03 propagates into background jobs and the outbox, so an emailed PO traces back to the click that caused it. A job that loses the id fails a test.
4. Writes happen **in the same transaction** as the business change. An audited action that commits without its audit row, or vice versa, is a bug — there is no fire-and-forget audit path.
5. Timestamps are `TIMESTAMPTZ` in UTC at microsecond precision. Display-timezone conversion happens in the UI only; nothing stores local time.
6. `ip_prefix` is truncated at write time (PRIV-001). The full address is never stored.
7. Reading the audit log requires `audit.read` and **is itself audited** (AUD-005, enforced from E02-S05's permission set).

## Acceptance criteria

- [ ] `UPDATE audit_log` and `DELETE FROM audit_log` both raise, as the application role and as the owner
- [ ] A business change and its audit row commit or roll back together — a forced failure after the business write leaves neither
- [ ] A model containing `password_hash`, `token_hash`, `bank_account`, `tax_id` produces before/after payloads containing none of them
- [ ] Adding a new sensitive column does **not** cause it to appear in audit output (allow-list proof)
- [ ] A correlation id set on an API request appears on the audit row written by the background job it enqueued
- [ ] Timestamps are UTC `TIMESTAMPTZ`; no local-time column exists
- [ ] Stored `ip_prefix` is truncated; the full IP appears nowhere
- [ ] Reading the audit log writes an audit row naming the reader
- [ ] Monthly partitions are created automatically and a 91-day-old partition detaches cleanly
