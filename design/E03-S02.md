# E03-S02 — Tenancy kernel: session org_id, RLS SET LOCAL, scoped repository base

**Epic** E03 · **M0** · **security/L** · after **E01-S02** · tags: `security`, `auth`

## Requirements

- **SEC-008** — Authorization must prevent cross-organization, cross-BU/OU, cross-project, and object-identifier access.
- **ACC-004** — A user cannot access another BU/OU's record by guessing an identifier or changing a request.
- **D-06** (decision log) — Pooled multi-tenant: one deployment, one database, `org_id` on every business row, Postgres RLS plus application scope checks.

## Deliverable

Three independent layers of tenant isolation. Any one failing must not leak data — that is the whole design, because this is the failure mode that ends the company.

## Behaviour

### Layer 1 — `org_id` from the session, never from input

Resolved by middleware from the authenticated session into a request-scoped context. **No route may accept `org_id` as a path, query, body, or header parameter.** A CI check greps the OpenAPI schema and fails if any operation declares one.

### Layer 2 — Postgres RLS

```sql
ALTER TABLE <t> ENABLE ROW LEVEL SECURITY;
ALTER TABLE <t> FORCE ROW LEVEL SECURITY;      -- applies to the table owner too
CREATE POLICY tenant_isolation ON <t>
  USING (org_id = current_setting('app.org_id')::uuid);
```

At transaction start: `SET LOCAL app.org_id = :org`. **`SET LOCAL`, never `SET`** — `SET LOCAL` is transaction-scoped, which is what makes this correct under Neon's PgBouncer transaction pooling. A session-scoped `SET` would leak the previous tenant's value to the next borrower of the pooled connection. This is the single most important line in the story.

`FORCE ROW LEVEL SECURITY` matters because the application connects as the table owner, and owners bypass RLS by default.

### Layer 3 — scoped repository

```python
class ScopedRepo(Generic[T]):
    def __init__(self, session: Session, scope: Scope) -> None: ...
```

`Scope` is a required constructor argument carrying `org_id` and, for BU-scoped modules, `bu_ids`. A repository **cannot be constructed without one** — `mypy --strict` rejects it at type-check, so an unscoped query never reaches review. No `.unscoped()` escape hatch exists; if one is ever needed it must be a new story with an explicit decision-log entry.

### Not-found, not forbidden

A record belonging to another tenant returns **404**, never 403. A 403 confirms the identifier exists, which is a free enumeration oracle. This applies to every route, including admin.

## Acceptance criteria

- [ ] Tenant A authenticated, requesting tenant B's record by exact id → **404**
- [ ] Same for list, search, export, and every `PATCH`/`DELETE` path
- [ ] With the application-layer scope deliberately disabled in a test, RLS alone still returns zero rows — proving the layers are independent
- [ ] With RLS deliberately disabled in a test, the repository still returns zero rows
- [ ] `SET LOCAL` is used, never `SET` — asserted by a test that reuses a pooled connection across two tenants and finds no bleed
- [ ] `FORCE ROW LEVEL SECURITY` is set on every business table; a migration adding a table without it fails a CI check
- [ ] Constructing any repository without a `Scope` fails `mypy --strict`
- [ ] No OpenAPI operation declares an `org_id` parameter — asserted in CI
- [ ] The TEN-010 isolation suite is created here with these cases and runs on every merge
