# E22-S09 — Show people by name, with the email as secondary text

**Epic** E22 · **M3** · **ui/M** · tags: ui

> Operator decision, 21 Oct 2026: canvas DECISIONS **232** (amends D-M2-16). Depends on **E22-S07**,
> which returns a `*_name` beside every person's email. Read `design-system/MASTER.md` before
> starting; the canvas boards that show email only are stale on this point.

## Requirements (inlined)

- **A11Y-004** — Information is never carried by colour alone.
- **UX-007** — Locale-correct display with canonical values preserved (the email stays the canonical identifier).

## Design

**One component.** `apps/web/src/components/ui/Person.tsx`: props `{ name: string | null; email: string }`.
With a name: the name as the primary text and the email as secondary text (MASTER's secondary
text token) on the same line where width allows, below it at 375; the `title` attribute carries the
email too. Without a name: the email alone, exactly as today. No avatar, no initials.

**Adoption.** Replace every place a person is rendered by email with `<Person>`: approver pickers
(the option label and the selected chip), requester and "on behalf of" fields, decision trails and
explanations, delegation lists, vendor contacts linked to an identity, user administration lists, and
the account menu (`GET /me`). Find them with `grep -rn "_email" apps/web/src --include=*.tsx`.
Search inputs keep matching email and, through the API, name.

## Acceptance

- [ ] `Person` vitest: name + email renders both with the name first; null name renders the email only; long names truncate with the full text in `title`.
- [ ] Every screen in the adoption list renders `Person` (a vitest or e2e per screen, or one grep-based test that no `.tsx` renders a `*_email` field directly outside `Person`).
- [ ] Playwright happy path on the approval inbox and the requisition detail with a named and an unnamed person; keyboard-only path through the approver picker; axe clean on both routes in light and dark.
- [ ] MASTER §8 checklist; `flo check` green.
