# E03-S01 — Money primitives: Decimal, NUMERIC(18,4), central rounding, float lint ban

**Epic** E03 Application kernel · **M0** · **ledger/M** · after **E01-S01** · tags: `money`

## Requirements

- **FIN-001** — Monetary values must use fixed-precision decimal arithmetic; persisted money must not use binary floating point.
- **FIN-002** — Every monetary amount must carry an ISO 4217 currency code.
- **FIN-009** — Rounding mode, currency precision, and line-versus-document rounding rules must be centrally defined and consistently used.

## Deliverable

One `Money` type and one rounding function, used by every module that touches an amount. This story is small and its blast radius is the entire product.

## Contract

```python
@dataclass(frozen=True)
class Money:
    amount: Decimal          # NUMERIC(18,4) in the database
    currency: str            # ISO 4217, uppercase, validated against a bundled list

    def __add__(self, other: "Money") -> "Money"   # raises CurrencyMismatch
    def __sub__(self, other: "Money") -> "Money"   # raises CurrencyMismatch
    def __mul__(self, qty: Decimal) -> "Money"     # quantity, never another Money
    def allocate(self, ratios: list[int]) -> list["Money"]   # remainder-preserving split

def quantize(amount: Decimal, currency: str) -> Decimal      # to the currency's exponent
```

## Behaviour

1. `Decimal` end to end. **Constructing `Money` from a `float` raises** — not a warning, an exception. `Money(Decimal("10.50"), "USD")` is the only legal form.
2. **`Money + Money` across currencies raises `CurrencyMismatch`.** There is no implicit conversion anywhere in the type (FIN-003 governs explicit conversion, and that lives in E05-S05).
3. **Storage is `NUMERIC(18,4)`** — four decimal places, not two. Unit prices and FX-converted values need more precision than the presentation currency; rounding to two happens at document totals, not at storage.
4. **Rounding (FIN-009)** — one function, `ROUND_HALF_UP`, the accounting convention. `round()`, `//`, `%` and float division are forbidden on money. Currency exponent comes from a bundled ISO 4217 table: most currencies 2, JPY 0, BHD 3.
5. **Line-versus-document rounding is decided here and never re-decided**: each line is quantized to the currency exponent, then the document total is the **sum of quantized lines** — not the quantized sum of raw lines. This makes the printed total always equal the sum of the printed lines, which is what a vendor will check.
6. `allocate()` splits an amount by ratio without losing or inventing cents; the remainder is distributed one minor unit at a time to the earliest buckets. Used by tax apportionment and split awards.
7. **The float ban is enforced by CI**, already wired in `.github/workflows/ci.yml`: any `float(` or `: float` annotation under `modules/{budget,purchasing,sourcing,requisitions}` fails the build.
8. SQLAlchemy type decorator maps `Money` to two columns (`*_amount`, `*_currency`) so a currency can never be separated from its amount by a schema change.

## Acceptance criteria

- [ ] `Money(10.50, "USD")` raises; `Money(Decimal("10.50"), "USD")` succeeds
- [ ] `USD + EUR` raises `CurrencyMismatch`
- [ ] `Money(Decimal("0.1"),"USD") * 3 == Money(Decimal("0.3"),"USD")` exactly — the test that fails under float
- [ ] `quantize` rounds `2.5 → 3` and `3.5 → 4` (HALF_UP), and `-2.5 → -3`
- [ ] JPY quantizes to 0 places, BHD to 3, USD to 2
- [ ] `allocate(Money("100.00"), [1,1,1])` returns `33.34, 33.33, 33.33` — sums exactly to the original
- [ ] Document total equals the sum of quantized lines for a 37-line fixture with repeating decimals
- [ ] Adding `x: float` to `modules/budget` fails CI; removing it passes
- [ ] Round-trip through Postgres preserves 4 decimal places and the currency code
