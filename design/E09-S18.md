# E09-S18 — Expired master codes: flag, substitute at approval, block downstream; no code changes by amendment

**Epic** E09 · **M2** · **engine/L** · after **E09-S13** · tags: `money`, `auth`, `ui`

> **Conventions:** as E09-S13. Decisions: E09-S13 packet, 8 and 10 (D-M2-23, D-M2-25).

## Why
`department_code` and `ledger_account_code` are validated when a document is saved and submitted
(`OrgService.assert_usable`, `modules/org/service.py:623`, reasons `unknown`/`inactive`/`not_effective`), but
never again: approval copies them onto the generated project and every ledger entry, and nothing flags a
code that has since expired. Amendments can also change them, leaving the reservation on the old code.

## Requirements
- **D-M2-25** — during approval, the current approver must substitute an expired code to approve, or may reject without substituting; after approval, M3 sourcing and purchasing documents are blocked until a Project Manager substitutes; expired codes are flagged on project screens and wherever such a project is selected.
- **D-M2-23** — code, account and project changes by amendment are blocked.
- **AUD-001** — every substitution is audited with before and after values.

## Design
- **Status:** a `code_status` helper in `org.service` returns, per code, `usable` or the `assert_usable`
  reason, evaluated at `today()` (UTC). Exposed as `codes: {department: {code, status}, ledger_account: {...}}`
  on `RequisitionRead` and `ProjectRead`, and as a `codes_expired: bool` on project lookup rows
  (`requisitions/lookups.py`) and project list rows.
- **At approval:** `DecisionWrite` gains optional `substitutions: {department_code?, ledger_account_code?}`.
  On `approve` (any step), if a requisition code is not usable, the decision is refused 409 `code_expired`
  (naming the code) unless a usable substitution for it is supplied; a substitution for a usable code is 422.
  Applied substitutions update the requisition inside the decision transaction (audited
  `requisition.code_substitute`, before/after), and the **live reservation is left on its original code**
  (ledger is append-only; re-reserving is M7). `reject`, `return` and `comment` need no substitution.
- **After approval:** `assert_current_upstream` (`requisitions/links.py`, E09-S09) refuses 409 `code_expired`
  while the requisition's or its sub-project's codes are unusable, so M3 documents cannot be raised.
- **Substitution after approval:** `POST /api/v1/projects/{id}/codes` and
  `POST /api/v1/requisitions/{id}/codes` (Idempotency-Key), permission `master_code.substitute` on the
  record's scope (Project Manager), body `{department_code?, ledger_account_code?, reason}`; only an
  unusable code may be replaced, only with a usable one. Audited. A requisition's substitution also updates
  its generated sub-project, and vice versa.
- **Amendments:** `amendments.py` refuses any change to `department_code` or `ledger_account_code` with
  422 `codes_change_blocked` ("Codes cannot be changed by amendment. Raise a transfer or adjustment request.");
  `project_change_blocked` already exists.
- **UI:** an "Expired code" badge (icon + text, never colour alone) on project list/detail, requisition
  detail, the project picker and the approval decision panel; the panel shows code fields to substitute
  when blocked; a Substitute codes action for Project Managers on project and requisition detail.

## Acceptance
- [ ] Approve with an expired code and no substitution → 409 `code_expired`; with a usable substitution → approved, requisition updated, audit row; reject without substitution → allowed.
- [ ] Substitution of a usable code → 422; with an unusable replacement → 422.
- [ ] After approval, `assert_current_upstream` refuses while a code is expired, passes after a Project Manager substitutes; without `master_code.substitute` → 403; foreign tenant 404 (TEN-010).
- [ ] Amendment changing a code → 422 `codes_change_blocked`.
- [ ] Lookups and list rows carry `codes_expired`; UI badge shows on all listed screens (Playwright + axe + keyboard path).
- [ ] Plants: skip the approval check; allow a code change in an amendment — tests fail.
