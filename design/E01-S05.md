# E01-S05 — Deploy API to Cloud Run and SPA to Cloudflare Pages from CI

**Epic** E01 · **M0** · **chore/L** · after **E01-S04** · tags: `security`

## Requirements

- **SEC-003** — All external traffic must use authenticated TLS; insecure transport must redirect or fail closed as appropriate.
- **SEC-005** — Secrets must not be stored in source code, browser bundles, logs, or ordinary configuration files.
- **COMP-004** — Deployments must externalize configuration and avoid environment-specific code branches.

## Deliverable

`main` deploys itself. This is the story that turns the repository into a running product at a real domain.

## Behaviour

1. **Authentication to GCP uses Workload Identity Federation.** No service-account JSON key is created, downloaded, or stored — a long-lived key in a GitHub secret is exactly what SEC-005 forbids. CI holds only `GCP_WIF_PROVIDER`, `GCP_DEPLOY_SA`, `GCP_PROJECT`.
2. Deploy order is **migrate, then serve** — never the reverse:
   - `gcloud run jobs execute flo-migrate --wait` runs Alembic and must exit 0
   - `gcloud run deploy flo-api --min-instances 0 --concurrency 80`
   - a failed migration aborts the deploy and leaves the previous revision serving
3. Secrets reach the container through Secret Manager references (`--set-secrets DATABASE_URL=flo-database-url:latest`), never as literal `--set-env-vars`.
4. The SPA builds and deploys to Cloudflare Pages via `wrangler`. **The bundle must contain no secret** — only `VITE_API_BASE_URL` is injected, and CI greps the built assets for `sk-`, `-----BEGIN`, and the project id before publishing.
5. TLS and HSTS terminate at Cloudflare; the Cloud Run service rejects plain HTTP. Cloudflare is configured Full (strict).
6. Rollback is one command against the previous Cloud Run revision, documented in `infra/SETUP.md`.

## Acceptance criteria

- [ ] A push to `main` deploys both API and SPA with no human step
- [ ] No service-account JSON exists in any secret, file, or log
- [ ] A deliberately failing migration aborts the deploy and the prior revision keeps serving
- [ ] `curl http://<domain>` redirects to HTTPS; HSTS header present
- [ ] Built SPA assets contain no `sk-`, no `-----BEGIN`, no GCP project id — asserted in CI
- [ ] `/readyz` returns 200 against Neon from the deployed revision
- [ ] Rollback to the previous revision succeeds and is documented

## Files

`.github/workflows/ci.yml` (deploy job), `infra/SETUP.md`, `apps/web/.env.production`, `apps/api/Containerfile`
