# E22-S15 — Requisition lookups admit a unit-scoped requester

**Epic** E22 · **M3** · **security/S** · after **E22-S14**, **E09-S02** · tags: `auth`, `security`
Origin: ACC-008 automated keyboard run 2, 23 Nov 2026 (`.scratch/acc-008-run2/notes.md`, step 3). Run 1 missed it
because its database workaround gave the Requester an organization-wide role for the whole run. Operator,
23 Nov 2026: fix before the human walkthrough round.

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.

One route and its tests. No migration, no service change, no API shape change, no frontend change.

## Requirements (inlined)

- **USR-003** — Access must support organization, BU/OU, module, record, and action scopes.
- **ACC-004** — A user cannot access another BU/OU's record by guessing an identifier or changing a request.
- **ACC-008** — A complete project-to-PO workflow is operable without a mouse.
- **DECISIONS 234 / 243** (operator): a permission held at any scope admits the caller; rows narrow to where it is
  held. E22-S14 applied this to `GET /org/units`.

## The defect

`GET /api/v1/requisitions/lookups/{kind}` (`api/requisitions.py` ~161-189) is gated by `OrgCreateContext`,
`require("requisition.create", organization_target)`. A requester whose roles are granted on a business unit (the
seeded walkthrough Requester; every unit-scoped project manager) gets **403 on every kind**, so the requisition
form loads no unit, project, department, ledger account, unit of measure, delivery address or person, and **a
unit-scoped project manager cannot raise a requisition**.

The rows are already narrowed per row by point checks inside `LookupService` (`modules/requisitions/lookups.py`):
projects by `requisition.create` on each project (~61-91), units by `project_request.create` on each unit
(~93-109, D-M2-18), delivery addresses by `requisition.create` on the chosen unit (~127-140). Only the route gate is
organization-only.

## Fix

In `api/requisitions.py` only. Replace `OrgCreateContext` on `lookups` with two dependencies,
`create: Annotated[GrantedScopes, Depends(require_granted("requisition.create"))]` and
`request_: Annotated[GrantedScopes, Depends(require_granted("project_request.create"))]` (`kernel/authz.py` ~186).
If neither is truthy, raise `ProblemError(ErrorCode.FORBIDDEN)` before calling the service: a caller who may raise
nothing anywhere gets **403 as today** (this is a form helper, not a list route; its behaviour for such a caller does
not change). Otherwise call `LookupService` exactly as now; its per-row point checks are the narrowing. Delete
`OrgCreateContext` if nothing else uses it.

Master codes (department, ledger account, UOM, currency) and `user` stay organization reference data, as now:
any admitted caller sees them.

## Acceptance

- [ ] **Unit-scoped requester:** a user holding `requisition.create` and `project_request.create` only on unit A
      (role granted with `AuthorizationTarget(ScopeType.BU, A)`), with an active project P_A under A and P_B under B:
      `lookups/project` → 200 with P_A, without P_B; `lookups/bu` → A only; `lookups/department`, `ledger_account`,
      `uom`, `user` → 200 with rows; `lookups/delivery_address?bu_id=A` → 200; `?bu_id=B` → 404 (unchanged service rule).
- [ ] **Project-scoped requester** (`requisition.create` on P_A only): `lookups/project` → P_A; `lookups/bu` → empty
      (no `project_request.create`); `lookups/department` → 200.
- [ ] **Neither permission anywhere** (e.g. `requisition.view` only): every kind → **403**, as today.
- [ ] **Organization-wide** grants: unchanged (existing `tests/requisitions/test_lookups.py` cases green).
- [ ] **TEN-010:** a foreign tenant's project, unit or address never appears (existing
      `test_lookups_never_return_another_tenants_rows` green); route coverage keeps the lookup mapped.
- [ ] `flo check --light` green.

## Plants

1. Restore `OrgCreateContext`: the unit-scoped requester case answers 403.
2. Admit everyone (drop the 403): the neither-permission case answers 200.
3. Pass `create` alone (drop `project_request.create` from the gate): a caller holding only `project_request.create`
   on A gets 403 on `lookups/bu` (add that case).
