# E03-S03 — RFC 9457 problem details, error taxonomy, no internal disclosure

**Epic** E03 · **M0** · **api/M** · after **E01-S01** · tags: `security`

## Requirements

- **ARCH-007** — APIs must be versioned, documented with OpenAPI, and return RFC 9457-compatible problem details.
- **SEC-011** — User-visible errors and API errors must not expose secrets, queries, stack traces, filesystem paths, or internal topology.
- **UX-005** — Errors must state what happened, what was preserved, and how the user can recover.

## Contract

```json
{
  "type": "https://xlr8flo.app/errors/insufficient-budget",
  "title": "Insufficient available budget",
  "status": 409,
  "detail": "The project has 12,400.00 USD available and this request needs 18,000.00 USD.",
  "instance": "/api/v1/requisitions/8f2a/approve",
  "correlation_id": "01JB2K7Q9XN4",
  "recovery": "Reduce the requested amount, transfer funds into the project, or request an override.",
  "errors": [{"field": "lines[2].amount", "message": "exceeds remaining line budget"}]
}
```

`recovery` is a non-standard member and is **required on every 4xx** — UX-005 asks what the user can do, and an error that only says what broke is half an error.

## Behaviour

1. A closed `ErrorCode` enum. Every raised error maps to exactly one code, one HTTP status, one stable `type` URI. Adding a code without a taxonomy entry fails a test.
2. **A single exception handler produces every error response.** No route builds one by hand, so the shape cannot drift.
3. **SEC-011 is enforced by construction, not discipline**: unhandled exceptions are caught, logged in full server-side with the correlation id, and returned as a generic 500 carrying *only* `correlation_id`. The client never receives a stack trace, SQL, path, hostname, driver message, or dependency version. A test asserts a deliberately raised `ZeroDivisionError` yields a body containing none of those.
4. `correlation_id` is generated per request, returned in the body and the `X-Correlation-ID` header, and attached to every log line for that request (AUD-010, OBS-006). It is the only thing a user can paste to support.
5. Validation errors return 422 with a `errors[]` array keyed by JSON-pointer-ish field paths the form kit (E04-S04) maps to inputs.
6. `title` and `recovery` are user-facing prose: plain, no apology, no blame, no jargon. `detail` may name concrete values the user is allowed to see.
7. FastAPI's default handlers are replaced — its stock 422 body leaks input echoes and internal locations.

## Acceptance criteria

- [ ] Every 4xx and 5xx response validates against the RFC 9457 media type `application/problem+json`
- [ ] A deliberately raised `ZeroDivisionError` returns 500 whose body contains no traceback, no file path, no module name, no SQL
- [ ] The same request logs the full traceback server-side under the same correlation id
- [ ] Every 4xx carries a non-empty `recovery`
- [ ] `X-Correlation-ID` is present on every response, including 500s
- [ ] Adding an `ErrorCode` without a taxonomy entry fails a test
- [ ] A 404 for a foreign-tenant record is indistinguishable from a 404 for a nonexistent one
- [ ] OpenAPI documents the problem schema for every operation
