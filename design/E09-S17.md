# E09-S17 — Block governed actions until their approval workflow is published

**Epic** E09 · **M2** · **engine/M** · after **E09-S13**, **E09-S15** · tags: `money`, `auth`

> **Conventions:** as E09-S13. Decision: E09-S13 packet, 6 (D-M2-21).

## Why
With no published workflow, a project auto-activates (`api/projects.py:186`, reason `no_approval_applies`)
and budget transfers and adjustments post at once (`budget/change_requests.py:83`); manual and imported
allocations never go through approval at all (`api/budget.py:78`, `imports/templates/budget_allocations.py:171`).
The operator wants these blocked until an administrator publishes the workflow.

## Requirements
- **D-M2-21** — with no published workflow, refuse: Project Requests (already), project activation, budget transfers, adjustments and allocations.
- **BUD-007 / WF-001** — governed budget changes route through approval.

## Design
- One helper in `modules/approvals/service.py`: `require_workflow(conn, scope, document_type, bu_id)` → raises
  409 `workflow_not_set_up` with detail "No approval workflow is published for {label}. Ask an administrator
  to set one up." Uses `resolve_version`.
- **Projects:** `api/projects.py:186` calls it instead of auto-activating. (Routers hold no logic: move the
  check into `ProjectService.transition`.)
- **Budget changes:** `request_change` (`change_requests.py:70`) refuses instead of posting immediately.
- **Allocations:** `POST /projects/{id}/budget/allocations` becomes a `budget_change` request of kind
  `allocation` (extend `budget_change_request.kind` CHECK; reuse the dry-run-then-pending path and
  `BudgetChangeAdapter.on_outcome`, which calls `allocate` on approval). The import template creates one
  pending request per row (batch result lists request ids). Response 202 with the request, as transfers do.
- **Bootstrap:** `infra/SETUP.md` / onboarding doc: a new tenant publishes `project`, `requisition`,
  `project_request` and `budget_change` workflows before first use; the seed script may publish a
  one-step default per type if the operator wants (flag in `notes.followup`, do not do it unasked).

## Acceptance
- [ ] Each gated action with no published workflow → 409 `workflow_not_set_up`, nothing written; after publishing → routes for approval.
- [ ] Allocation request approved → allocation posted once (idempotent replay); rejected → nothing posted.
- [ ] Import of N allocation rows creates N pending requests, none posted.
- [ ] Existing tests that relied on auto-activation or immediate posting publish a workflow in their setup (list them in the report).
- [ ] Plants: bypass the helper for projects; post allocations directly — each gated test fails.

## Files

## Out of scope
Direct project creation with budget (E22-S01); UI beyond surfacing the 409 message (existing problem rendering).
