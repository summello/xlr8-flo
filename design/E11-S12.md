## Requirements (inlined)

- **VEN-001** — The system must maintain a simplified, searchable vendor list for sourcing and PO generation.
- **VEN-002** — Each vendor must support billing and service/delivery contacts; additional typed contacts may be added.
- **VEN-003** — documents stored as protected attachments. **VEN-011** — issue date, expiry date, verification status, reviewer, expiry notifications.
- **VEN-013** — Vendor changes must not rewrite the vendor snapshot stored on historical RFQs, awards, or POs (Linked Records says so).
- **OBS-004** — expired vendor documents are visible.
- **UX-004** — loading, empty, partial and error states. **UX-005** — errors say what happened, what was kept, how to recover. **PERF-005** — server-filtered, never a full dataset.

## Screens

**`/vendors`** (pages/vendors.md §3.1). Tabs `Active`, `Pending Approval`, `Needs Attention`,
`Inactive` and `All`, each with a server count. Search by name or number (never a tax id). Filters
for availability and documents. Columns, server paging, `Request Vendor` as the one Primary (it
links to `/vendors/new`, E11-S14; hide it until that route exists, behind the route registry), and
`Export` (sensitive fields excluded; if no export endpoint exists, omit the button and record a
follow-up). The `Eligible Here` column uses `Eligibility variant="cell"` (E11-S11) for the user's
default unit. The `Documents` column is a `Signal` that looks ahead (`1 Expiring in 12 Days` before
`1 Expired`). Below 900px card width, the stacked columns follow §3.1.

The `Needs Attention` tab and the documents filter need server filters: add `?documents=expired|expiring|missing|rejected` to `GET /vendors` in this story if E11-S03 did not, reusing `document_state`.

**`/vendors/:id`** (§3.2). The header has the names, the status pill (E11-S09 map) and
`Eligibility variant="header"`. Cards in the dashboard layout rule: `Profile` (with the closed
`Onboarding Record` fold, score and threshold, visible to approvers only, as the server says),
`Availability` (units, local disables with who, when and why), `Contacts`, `Documents` (table, a
`Missing` row per missing required type, `Open` per row), `History` (from `GET
/vendors/{id}/changes` and the audit trail), and `Linked Records` (empty state now: "RFQs and
purchase orders that use this vendor appear here. They keep the vendor as it was when they were
made." VEN-013). `Tax and Banking` is E11-S13's card, and `Performance` is E11-S18's. Leave their
grid slots to those stories; do not render placeholders. Action buttons (`Edit`, and the status
actions) render only when the server says the user may act. The dialogs themselves are E11-S16, so
until then the status actions are absent.

**Document sheet** (§3.6): a side sheet with file, scan state (reuse `DetailFiles`' states), issue
and expiry, verification, reviewer and earlier versions, and `Verify`, `Reject` (reason required)
and `Replace File` for holders of the permissions. Focus is trapped; Escape closes and returns
focus to the opener.

A pending vendor viewed by its requester is read-only and says where it is in approval.

## States (§4)

Loading skeletons at final height; empty per tab; partial (one card fails, the rest stay); error
(what happened, what was kept, how to recover); all five widths; `Missing` document; vendor
disabled in the viewer's unit; long legal name at 375; document expiring today.
