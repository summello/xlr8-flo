## Requirements (inlined)

- **VEN-006** — Administrators must be able to configure onboarding questionnaires with typed fields, required answers, weights, and scoring.
- **CUS-007** — Changing a definition must not reinterpret historical values silently.
- **A11Y-003** — every drag interaction has a keyboard alternative in the same story *(here, move buttons are the only reorder path)*.

## Screen `/admin/vendor-questionnaires`

Under the existing admin shell (`org.setting.manage`). A versioned list (`Draft`, `Published`,
`Retired`, with numbers and dates) and an editor for the draft:
- Per question: prompt, type (text, number, yes or no, single choice, multiple choice, date, file), required, weight, and points per answer (choice options, yes/no, number bands).
- **Reorder with `Move Up` and `Move Down` buttons per row**, named with the question (`Move "Insurance held?" up`). No drag. After a move, focus stays on the moved row's button.
- A live `Weights total N of 100` `Signal` (ok at 100, warn otherwise), computed by the server on each save, never in the browser.
- `Publish` opens a dialog: "A published version never changes. Requests keep the version they were answered against." A refusal (409 `weights_total`) shows a focused summary with the total, and the draft is kept.
- A published version opens read-only with `Copy to New Draft`.
- `Preview of the Request Form` is a closed fold that renders the questions as the requester sees them (no weights).
- Threshold field (0..100) on the version.
