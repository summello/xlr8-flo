# E09-S15 — Project Requests: their own document type, workflow, permission and name

**Epic** E09 · **M2** · **engine/L** · after **E09-S13** · tags: `money`, `auth`, `ui`, `migration`

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.
> Decisions: E09-S13 packet, "Operator decisions" 3, 7, 9 (D-M2-18, D-M2-22, D-M2-24). User guide:
> `design/E09-S13.md` "How budget works". Design system: MASTER.md and `design-system/pages/requisitions*.md`.

## Why
A standalone requisition today is any requisition raised without a project, by anyone with
`requisition.create`, approved through the same `requisition` workflow
(`modules/requisitions/approval.py:45`; `fields()` returns only `amount`, so a workflow cannot even branch
on it). The operator wants it to be a separate, role-gated **Project Request** with its own approval route.

## Requirements
- **REQ-004** — a standalone request's approval creates a project, unless an authorized approver assigns it to an existing one.
- **D-M2-18** — Project Requests: own document type, own workflow, own UI name; created only with `project_request.create`.
- **D-M2-22** — its project is created only on full approval; cancelled after approval → project `abandoned`, excluded from budget totals into an Abandoned category.
- **D-M2-20 (part)** — sponsors: one or more, named on the request, carried to the project.
- **D-M2-21** — submit is refused until a `project_request` workflow is published (already true: `engine.start` raises `no_workflow`).

## Design
- **Storage:** Project Requests stay rows in `requisition` with `standalone = true` (no new table). The approval
  instance uses `document_type = 'project_request'`. `requisition.kind` is not added; `standalone` already says it.
- **Document type:** add `project_request` to `DocumentType` (`modules/approvals/schemas.py:32`) and to the
  `document_type` CHECK (migration 0037's constraint; new migration, reversible). Register a
  `ProjectRequestAdapter` (subclass or sibling of `RequisitionAdapter` in `requisitions/approval.py`) with
  `document_type = "project_request"`, permission `requisition.approve`, and `fields()` exposing `amount`
  and `bu` so its own workflow can branch. `on_outcome` reuses `_approved`'s standalone branches.
- **Routing at submit:** `lifecycle.submit` starts the instance with `document_type="project_request"` when
  `standalone`, else `"requisition"`. Existing standalone drafts in non-production data: none expected; the
  migration needs no backfill (assert no `approval_instance` with `document_type='requisition'` points at a
  standalone requisition, or migrate them).
- **Permission:** `create_target` (`api/requisitions.py:~56`) requires `project_request.create` on the unit for
  a standalone create, `requisition.create` on the project otherwise. 403 otherwise; foreign unit 404.
- **Sponsors:** new table `requisition_sponsor(org_id, requisition_id, user_id)` (PK on the triple, RLS,
  tenant FK); `RequisitionCreate`/`Patch` accept `sponsor_ids: list[UUID]` (1..10, distinct, active users of the
  org) for Project Requests only (422 on a regular requisition). On approval, the created project gets the
  sponsors: new `project_sponsor` table (same shape), and `ProjectRead.sponsor_ids`; the existing single
  `sponsor_id` column stays for compatibility and is set to the first sponsor. Submission check:
  a Project Request without a sponsor is `submission_invalid` (`sponsors` problem).
- **Abandon on stop:** `stop_approved` (`lifecycle.py:379`) also abandons the project a Project Request
  created (`source_requisition_id` = the requisition, `generated_by_requisition_id` NULL), via a new
  `ProjectService.abandon_requested(project_id, actor, reason)` that mirrors `abandon_generated`
  (`projects/service.py:748`) but allows a remaining allocation (the reservation is released first;
  allocation stays, per D-M2-22). Audit row `project.abandon` with `source=requisition`.
- **Budget summary:** `budget_summary` (`budget/service.py:273`) and `aggregate_balance` exclude abandoned
  projects whose `source_requisition_id` is set and `generated_by_requisition_id` is NULL from the totals and
  return them as a separate `abandoned` group (per currency: allocated, reserved, committed, actual). Schema:
  `BudgetSummary.abandoned`.
- **UI** (`apps/web`): the create screen shows "New Project Request" only to holders of
  `project_request.create` (read from the session's permissions); regular users see only the requisition
  form with a required project. List gets a "Project Requests" filter/tab; detail and list labels say
  "Project Request" for standalone rows; sponsors multi-select (people picker from the existing user lookup);
  Budget summary shows the Abandoned group as its own card with a table equivalent. Copy per the user guide.

## Contract
| Route | Change |
|---|---|
| `POST /api/v1/requisitions` | standalone body needs `project_request.create` on `bu_id`; `sponsor_ids` required (1..10) for standalone, refused (422) otherwise |
| `PATCH /api/v1/requisitions/{id}` | `sponsor_ids` editable on a draft Project Request |
| `GET /api/v1/requisitions?kind=project_request|requisition` | filter |
| `GET /api/v1/budget/summary` | adds `abandoned` |
| `GET /api/v1/projects/{id}` | adds `sponsor_ids` |

## Acceptance
- [ ] Without `project_request.create`, a standalone create is 403; with it, 201. Foreign unit 404. TEN-010 case.
- [ ] A Project Request submits only when a `project_request` workflow is published (else 409 `no_workflow`); a regular requisition is unaffected by it.
- [ ] A workflow condition on `bu` routes a Project Request (builder lists the type).
- [ ] Approval creates the project with the request's sponsors; regular requisitions cannot carry sponsors.
- [ ] Cancel after approval: project `abandoned`, allocation kept, reservation released once; budget summary excludes it from totals and lists it under `abandoned`. Concurrency: cancel vs approve, exactly one wins.
- [ ] UI: Playwright happy path + axe on the changed routes + keyboard-only path; the option is hidden without the permission.
- [ ] Plants: drop the permission check (403 test fails); count abandoned in totals (summary test fails).
- [ ] Migration up/down/data preservation.
