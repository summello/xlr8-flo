# E12-S27 — A declared conflict outlives removal from the evaluator list

**Epic** E12 · **M3** · **engine/S** · after **E12-S07**, **E12-S26** · tags: `security`, `auth`
Origin: operator audit of PR #22 (15 Nov 2026), left open by decision on 16 Nov. Operator, 17 Nov 2026: fix it.

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.

One backend change in one function. No migration, no API shape change, no frontend change, no new helper.

## Requirements (inlined)

- **SRC-011** — Evaluators must be able to score qualitative and quantitative criteria with comments and conflicts-of-interest declarations where configured. E12-S07: no bid content is returned to an evaluator until they declare; a declared conflict recuses them, **permanently** (409 `recused`). E12-S07 also lets an RFQ editor remove a recused evaluator who has no submitted scores (operator, 25 Oct 2026). Both stay true.

## The defect

`modules/sourcing/evaluation.py` `assert_may_see_bids` (~244-259) finds the declaration **through** the caller's `rfq_evaluator` row and returns at once when there is no such row. `remove_evaluator` (~505-540) deletes that row. `rfq_evaluator_declaration` is append-only with no key to `rfq_evaluator` (`migrations/20261022_0076_rfq_evaluation.py` ~47-67), so the conflict declaration is still stored, and nothing reads it: a person who declared a conflict, once removed from the list by any `rfq.edit` holder, reads the comparison, the bids and the award as an ordinary `rfq.view` holder.

## Fix

In `assert_may_see_bids` only. Read the two facts separately, in one statement, for `(org_id, rfq_id, identity_id)`:

- `is_evaluator`: a `rfq_evaluator` row exists;
- `conflict`: `bool_or(d.conflict)` over `rfq_evaluator_declaration` for that RFQ and identity, **not** joined through `rfq_evaluator` (NULL when there is no declaration).

Then, in this order:

1. `conflict` is true → 409 `recused`, the message as today, whether or not the caller is still an evaluator.
2. `is_evaluator` and `conflict` is NULL → 409 `declaration_required`, as today.
3. anything else → return.

`identity_id` may be `None` (the signature allows it); both lookups then find nothing and the function returns, as today.

Do **not** change `remove_evaluator`: a recused evaluator with no submitted scores may still be removed (E12-S07). Do not change `tally` (~221) or `_evaluators` (~318): completion and the evaluator list keep counting current evaluators only. Do not change `declare`: a removed person who is added again and had declared a conflict is recused at once by rule 1, and `already_declared` still refuses a second conflict row.

Every caller of the gate (`bids.py` ~352/~374, `comparison.py` ~661/~679, `awards.py` the two public reads, and any other `grep assert_may_see_bids` finds) gets the fix with no edit. Read each to confirm none of them pre-checks `rfq_evaluator` itself before calling; if one does, report it in `notes.blocked` with the file and line.

## Tests

`apps/api/tests/sourcing/test_evaluation.py` ~470-505 (the route-level gate test) today **asserts the defect**: after the conflict declaration it deletes the `rfq_evaluator` row by SQL and expects 200 on all six reads. Change that case so it proves the opposite, and get the "ordinary viewer reads" case from a person who never declared a conflict.

## Acceptance

- [ ] **Removed after a conflict (authorization test, through the routes):** an evaluator declares a conflict, an editor removes them with `remove_evaluator` (the service call, not SQL), and with `rfq.view` + `rfq.edit` the six reads (`/comparison`, refresh-rate, bid list, bid by id, `/award`, `/awards`) are still 409 `recused`; with `rfq.view` + `rfq.approve` likewise, refresh-rate 403 as before.
- [ ] **Removed before declaring:** an evaluator who never declared is removed → the six reads are 200 for `rfq.view` + `rfq.edit` (the gate never applies to a non-evaluator with no conflict on record).
- [ ] **Removed after a clear declaration:** declared no conflict, removed → 200.
- [ ] **Added again:** the recused person is added back with `add_evaluator` → 409 `recused` on the reads and on `save_scores`, and `declare(conflict=False)` is 409 `already_declared`.
- [ ] **Removal itself unchanged:** removing a recused evaluator with no submitted scores still succeeds and is audited (`rfq.evaluator.remove`); the existing `evaluator_has_scores` test stays green.
- [ ] A person who was never an evaluator and has no declaration → 200, as today (existing cases green).
- [ ] The service-level award test (`test_award.py` ~355-371) and every existing `declaration_required` / `recused` case stay green unchanged.
- [ ] TEN-010: no new endpoint; the declaration lookup carries `org_id = %(org_id)s` like every other statement in the file. `flo check --light` green.

## Plants

1. Restore the early `return` when there is no `rfq_evaluator` row: the removed-after-conflict assertion fails.
2. Apply `declaration_required` without the `is_evaluator` condition: the removed-before-declaring 200 fails.
