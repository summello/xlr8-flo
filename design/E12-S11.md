## Requirements (inlined)

- **SRC-004** — RFQs must support Draft, Published, Closed, Under Evaluation, Awarded, and Cancelled states.
- **SRC-015** — All RFQs, responses, comparisons, and awards must remain linked to the requisition.
- **UX-004 / UX-005 / PERF-005** — loading, empty, partial and error states; recoverable errors; server paging.

## Server (all in `apps/api/src/flo/api/sourcing.py` and `modules/sourcing/`)

1. **`GET /api/v1/sourcing/rfqs`** (new). Self-scoped list on the requisition-list precedent
   (`api/requisitions.py::list_requisitions`): `Depends(require_member())` and
   `granted_scopes(…, "rfq.view")`, rows filtered to the units where the caller holds `rfq.view`
   (org-wide grant = no filter). Query: `tab` in `drafts` (`draft`), `open` (`published`),
   `evaluating` (`closed`, `under_evaluation`), `awarded` (`awarded`), `all` (default); `q`
   (number or title prefix, case-insensitive); `cursor`; `page_size` 1..50 (default 50); order
   `deadline_at, id`. Response `RfqPage { rows: RfqListRow[], next_cursor, counts: {drafts, open,
   evaluating, awarded, all} }`, counts over the same visible scope and `q`.
   `RfqListRow`: `id, number, title, status, unit_id, owner_email, deadline_at, deadline_tz,
   invitee_count, requisition_numbers: list[str]` (distinct, from `rfq_line`). No bid field.
2. **`GET /api/v1/sourcing/rfqs/{id}/history`** (new, `ViewContext`). `list[RfqEvent { action, at,
   actor_email | null, reason | null }]` from `audit_log` where `target_type = 'rfq'` and
   `target_id = id` and `action LIKE 'rfq.%'`, newest first, on the precedent in
   `modules/approvals/versions.py` (join `identity` for the email; `reason` is `after->>'reason'`).
   Return only these four fields, never `before`/`after` whole.
3. **Capability flags on `RfqRead`**, computed in the `GET /rfqs/{id}` route with
   `kernel.authz.permits(request, …, rfq_target(id, connection))`, on the `can_substitute_codes`
   precedent (`api/requisitions.py::get_requisition`): `can_edit: bool = False` (`rfq.edit`),
   `can_approve: bool = False` (`rfq.approve`). The UI shows `Extend Deadline` only when
   `status == 'published'` and `can_edit`; the server stays the authority (403 otherwise). Owners of
   later actions use the same flags.
4. **Correct the RFQ tone in the link provider.** `modules/sourcing/service.py::_TONES` has
   `"closed": "neutral"`; MASTER §2.3 (binding) says `closed: 'info'`, and
   `apps/web/src/components/status/map.ts` already agrees with MASTER. Change `_TONES["closed"]` to
   `"info"` and assert it in `apps/api/tests/sourcing/test_rfq.py` (the requisition's Linked Records
   card shows RFQ rows through this provider). MASTER wins over the code.

Add both routes to `tests/isolation/test_route_coverage.py::COVERED` with a named foreign-tenant
test, and regenerate the client (`npm run generate:api`).

## Screens

**Route wiring.** Routes are selected by hand in `apps/web/src/routes/__root.tsx`; a file under
`routes/` alone exposes nothing. Add `"/sourcing/rfqs"` to `ROUTE_PATHS` (`routes/route-paths.ts`)
and its entry in the static route table (`activeHref: "/sourcing"`, `phase: "commit"`, title
`RFQs`); add `RFQ_PATH = /^\/sourcing\/rfqs\/([0-9a-f-]{36})$/` to `routeFor` and the render switch,
as `VENDOR_PATH` does. The `/sourcing` nav item keeps its href; its page renders the RFQ list.
Screens are `apps/web/src/routes/sourcing/rfqs/list.tsx` and `detail.tsx` (the `routes/vendors/`
layout).

**`/sourcing/rfqs`:** tabs `Drafts`, `Open`, `Evaluating`, `Awarded`, `All` with the server counts
(arrow, Home and End keys). Columns per §4.1 without `Bids`: `Number`, `Title` (requisition numbers
beneath), `Status` (pill from `components/status/map.ts`, icon plus words), `Invited` (`4 of 5`:
`invitee_count` of the cap of 5, decision 106), `Deadline` (date in the user's locale and the
relative phrase, `in 2 days` or `closed 3 days ago`, computed from the server's `deadline_at`),
`Owner`. Server paging with the cursor; the grid is the shared server-driven grid.

**`/sourcing/rfqs/:id`:** the lifecycle `Draft → Published → Closed → Under Evaluation → Awarded` as
an ordered list with `aria-current="step"` on the current step and done steps said in words;
`Cancelled` is a banner, not a step. Cards:

- `Request`: `RfqRead.lines`, each with a link to its requisition (`/requisitions/<requisition_id>`).
- `Versions`: `GET /rfqs/{id}/versions`; each diff as words with a struck `was`.
- `Invitees`: per invitee the latest version sent, the email state per contact (`deliveries`), and
  `Not yet told of version N` from `not_told_of`. On a `bounced` delivery, `Change Contact`
  (`PATCH /rfqs/{id}/invitees/{vendor_id}` with `If-Match` = the RFQ `ETag`, then
  `POST …/resend` with an `Idempotency-Key`), shown when `can_edit`.
- `History`: `GET /rfqs/{id}/history`.
- `Linked Records`: the distinct requisitions of `RfqRead.lines` (number, link). SRC-015.

Each card fetches and fails on its own (partial state, §5).

**`Extend Deadline`** (header, published and `can_edit`): a dialog with date and 24-hour time
fields in the RFQ's `deadline_tz`, an optional reason (1..500), and two actions, the safe one focused
first. **The new deadline must be strictly later than the current one**: the server refuses an equal
instant as well as an earlier one (`lifecycle.py::_amend`, `deadline_at <= current` →
422 `deadline_earlier`), so the field refuses both before sending. Submit
`POST /rfqs/{id}/extend-deadline` with an `Idempotency-Key`; a 409 `deadline_passed` or a 422 is shown
on the field with the input kept (UX-005).

## Acceptance

- [ ] Playwright (seeded or stubbed): list tabs and counts; open an RFQ; extend its deadline; see the new version and `Not yet told of version 2` until the outbox marks it sent.
- [ ] Extend Deadline refuses an earlier **and an equal** date-time at the field, and shows the server's 422 on the field.
- [ ] A user with `rfq.view` but not `rfq.edit` (the purchasing user) sees no `Extend Deadline` and no `Change Contact`.
- [ ] `GET /sourcing/rfqs` returns only RFQs in units where the caller holds `rfq.view`; counts match; a foreign tenant's RFQ never appears.
- [ ] No action from the "does not draw" table is in the DOM.
- [ ] The requisition Linked Records shows a `closed` RFQ with the `info` tone.
- [ ] axe on both routes in both themes; keyboard path through tabs, list to detail, Extend Deadline dialog (safe button focused, Escape returns focus to the opener).
- [ ] MASTER §8 checklist; tokens only.
- [ ] `flo check --light` green.

## Plants

1. Render the lifecycle without `aria-current`: the a11y assertion fails.
2. Let the field accept the current deadline unchanged: the equal-instant assertion fails.
3. Drop the `rfq.view` scope filter from the list query: the scope test fails.
