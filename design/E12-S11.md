## Requirements (inlined)

- **SRC-004** — RFQs must support Draft, Published, Closed, Under Evaluation, Awarded, and Cancelled states.
- **SRC-015** — All RFQs, responses, comparisons, and awards must remain linked to the requisition.
- **SRC-007** — bids confidential (the list and detail show counts only before the deadline).
- **UX-004 / UX-005 / PERF-005** — states, recoverable errors, server paging.

## Screens

**`/sourcing/rfqs`:** tabs `Drafts`, `Open`, `Evaluating`, `Awarded` and `All` with server counts;
columns per §4.1 (`Bids` is a count or `3 Received, sealed`, **never a figure**); `Deadline` with
the relative phrase from the server's timestamp in the user's locale; `New RFQ` as the one Primary
(links to E12-S12's route; hidden until it exists). Server paging. Add a `GET /sourcing/rfqs`
list endpoint with `?tab=&q=&cursor=` and counts if E12-S01..S03 did not.

**`/sourcing/rfqs/:id`:** the lifecycle as an ordered list (`aria-current="step"`; Cancelled shown as
a banner). Cards are `Request` (lines with requisition links), `Bids` (sealed state or a link to the
comparison after the deadline), `Versions` (diffs as words with a struck `was`), `Evaluators`,
`Invitees` (version sent, email state, bid state; `Not yet told of version 3`; `Change Contact` on a
bounce; `Record Bid` opens E12-S14's sheet, hidden until it exists), `History` and `Linked Records`.
Header actions by state and permission: `Edit` (draft), `Extend Deadline` (a two-action dialog:
date and time, reason, confirm; never earlier), `Amend` (E12-S13), `Cancel RFQ` (E12-S18; hidden
until it exists), `Open Comparison`, `View Award`.

`Start RFQ` on the requisition detail (§4.10) for a requisition in `sourcing_in_progress`, linking
to the new-RFQ route with the requisition preselected (hidden until E12-S12 exists).
