# E22-S05 — Replace MinIO with SeaweedFS in the local stack

**Epic** E22 · **M3** · **chore/S** · tags: none

> Operator decision, 15 Oct 2026. `quay.io/minio/minio` and `quay.io/minio/mc` now return 401 to
> anonymous pulls and `minio/minio` is gone from Docker Hub, so `flo up` cannot start the R2
> stand-in on a fresh machine. PR #20 made the object store optional as a stopgap; this story
> replaces it.

## Requirement (inlined)
**OPS-007** — A single command must reproduce the full stack locally (Postgres, object store, mail
catcher) with no cloud account.

## Design
1. **`compose.yaml`:** delete the `minio` and `minio-init` services and the `minio-data` volume.
   Add one `seaweedfs` service:
   - image `chrislusf/seaweedfs:4.48@sha256:4e61d15fd35994cb1e43e1e553dff106794841fd9a99ade2fc8c8bfce4d7872d`
     (multi-arch index: amd64, arm64; pulled and verified 15 Oct)
   - `command: server -dir=/data -s3 -s3.port=9000 -s3.autoCreateBucket=false` (single process:
     master, volume, filer and the S3 gateway). `autoCreateBucket=false` makes a missing bucket fail
     the way R2 does, instead of being created silently on the first upload.
   - credentials: `AWS_ACCESS_KEY_ID: ${S3_ACCESS_KEY_ID:-flo}` and
     `AWS_SECRET_ACCESS_KEY: ${S3_SECRET_ACCESS_KEY:-flo-local-secret}`. SeaweedFS uses these as admin
     credentials when no `-s3.config` file is given (`weed help s3`). Do not add a config file.
   - port `127.0.0.1:9000:9000` only. There is no console port.
   - volume `seaweedfs-data:/data`
   - a healthcheck that uses a binary that exists in the image. Check with
     `docker run --rm --entrypoint ls <image> /bin /usr/bin` before you write it. Do not assume curl.
2. **Bucket via the S3 API, no `mc`, no init container:** add
   `ensure_bucket(settings: Settings) -> None` to `flo/kernel/storage.py`. It reuses
   `_configured_s3_client(settings)`, calls `head_bucket`, and calls `create_bucket` only on a
   404/`NoSuchBucket`. It is idempotent, and any other error propagates. Expose it as
   `python -m flo.kernel.storage ensure-bucket`.
   `flo up` runs that module with `apps/api/.venv/bin/python` after the stack is healthy, with the
   `.env.example` storage values as defaults. If the venv is missing, it dies with a message naming
   `uv sync --frozen`.
3. **The object store is required again.** In `agents/scripts/flo`, `cmd_up` brings up `postgres`,
   `seaweedfs` and `mailpit` in one call, waits for all three to be healthy, then ensures the bucket.
   Remove the `optional=` path, the `OBJECT_STORE_SERVICES` constant and the `minio-init` logic that
   PR #20 added. OPS-007 says *full* stack: a missing store must fail loudly. Print
   `Object store: http://localhost:9000` in place of the two MinIO lines.
4. **Rename the provider, not the contract:** `adapters/minio.py` becomes `adapters/s3_local.py`, and
   `MinioStorage` / `create_minio_storage` become `LocalS3Storage` / `create_local_s3_storage`.
   `storage_provider: Literal["r2", "local"]`. Production sets `STORAGE_PROVIDER=r2` (`ci.yml:471`) and
   is untouched. Update `adapters/__init__.py`, `storage.py` and the `S3Client` docstring in `r2.py`.
5. **`.env.example`:** drop `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` and `MINIO_BUCKET`, change the
   section header to "Local S3-compatible storage (SeaweedFS)", and set `STORAGE_PROVIDER=local`.
   Keep the `S3_*` values as they are.
6. **Docs, in the same commit (SUP-005):** README line ~302 and AGENTS.md §6 (`flo up` line) say
   "SeaweedFS (R2 stand-in)". Do **not** edit the OPS-007 text in `docs/claude-plan.md` or
   `docs/requirements.md` (AGENTS.md §0.4). Record in `notes.followup` that its parenthetical still
   says MinIO.

## Dependency note (AGENTS.md §0.6, copy into the PR body)
**SeaweedFS `chrislusf/seaweedfs:4.48` (digest-pinned) replaces MinIO `quay.io/minio/minio` +
`quay.io/minio/mc`.** MinIO's images are no longer anonymously pullable, so the R2 stand-in is
unobtainable. Stdlib and the existing dependencies cannot serve S3 locally. SeaweedFS is
Apache-2.0, ships one multi-arch image, takes credentials from environment variables, and serves
the S3 API we already use through boto3. That replaces two images with one and removes `mc`
entirely. It is a dev-only container image: no Python or npm package is added, and production
stays on R2.
