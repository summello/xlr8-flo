# E01-S06 — Neon + R2 + Secret Manager wiring, infra/SETUP.md, registry pruning

**Epic** E01 · **M0** · **chore/M** · after **E01-S05** · tags: `security`

## Requirements

- **SEC-005** — Secrets must not be stored in source code, browser bundles, logs, or ordinary configuration files.
- **OPS-001** — Every free-tier limit in §2.2 must have an automated headroom metric with 60/80/90 % alerts.

## Deliverable

The free tier made real and observable. Per §2.9 of the plan, the two constraints that actually bind are **Neon storage (512 MB)** and **Resend email (100/day)** — not compute. This story instruments both before they can surprise anyone.

## Behaviour

1. **Neon** — connect via the **pooled** endpoint (PgBouncer, transaction mode). This matters: RLS in E03-S02 uses `SET LOCAL`, which is transaction-scoped and therefore correct under transaction pooling. `SET` (session-scoped) would leak across pooled clients and is forbidden.
2. **R2** — S3-compatible via `boto3` behind the `Storage` port. Bucket `flo-attachments`, private, no public access. Credentials from Secret Manager.
3. **Secret Manager** — one secret per value, referenced by Cloud Run. The application never reads a secrets file.
4. **Headroom monitors**, exposed on `GET /internal/health/quota` and checked by the cron worker:
   | Metric | Source | Alert at |
   |---|---|---|
   | Neon storage | `pg_database_size()` | 60 / 80 / 90 % of 512 MB |
   | Cloud Run requests | Cloud Monitoring | 60 / 80 / 90 % of 2M/mo |
   | R2 storage | bucket listing | 60 / 80 / 90 % of 10 GB |
   | Artifact Registry | image listing | 80 % of 0.5 GB |
   Each alert names the pre-agreed action and its cost from §7 of the plan.
5. **Registry pruning** keeps the last 3 images (0.5 GB free tier fills silently otherwise). Already scripted in the deploy job — verify it runs and actually deletes.
6. `infra/SETUP.md` documents every console step so the environment is reproducible by a second operator: GCP project + WIF, Neon project + pooled connection string, R2 bucket + token scope, Cloudflare zone + Pages project, DNS records, and the rollback procedure.

## Acceptance criteria

- [ ] Deployed API reads and writes Neon through the pooled endpoint
- [ ] An object round-trips to R2 through the `Storage` port
- [ ] No secret value appears in any log line, env dump, or error body
- [ ] `/internal/health/quota` reports all four metrics with current values and percentages
- [ ] Crossing a threshold in a test fixture emits an alert naming the action and cost
- [ ] After four deploys, Artifact Registry holds exactly 3 images
- [ ] A second operator can reproduce the environment from `infra/SETUP.md` alone
