# E13-S10 — Deliverability: SPF/DKIM/DMARC check, bounce and complaint ingestion, suppression list

**Epic** E13 · **M3** · **engine/M** · after **E13-S09** · tags: `security` (Opus review)

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.
> **Decisions:** D-17 (one origin; the webhook is under `/api/*`), invariant 6 (outbound calls go
> through kernel ports: the `module-external-effects` import-linter contract forbids `httpx` in
> modules), project memory (secrets: Secret Manager in production, keychain locally; never in a
> file). `design-system/pages/purchase-orders.md` §4.11. Back end only; the admin screen is E13-S21.
> **Writes:** every `PATCH`/`PUT`/`DELETE` on an editable resource follows `docs/m2-conventions.md` §O (`If-Match` with the integer version, `ETag` on reads, 400 when missing, 409 `stale_version` on mismatch). `Idempotency-Key` protects **POST** commands only (the middleware ignores other methods); where a packet says "(Idempotency-Key)" on a non-POST route, read §O instead.
> **RLS:** every new tenant table gets literal `ALTER TABLE <t> ENABLE ROW LEVEL SECURITY; … FORCE …; CREATE POLICY tenant_isolation ON <t> …` statements in the migration text, one block per table, never generated by a helper or f-string (the static gate in `tests/isolation/test_ci_guards.py` reads the text; the light check runs it).

> **Scheduling (planner, 16 Oct, from Opus on E11-S03):** production runs internal work only from the Cloudflare worker's `runScheduledWork` (`apps/web/worker/api-proxy.ts`): `tickJobs` on every trigger, and daily jobs at minute 30 of a mapped UTC hour (2, 3, 7, 16, 18 and 4 are taken). A job that is only registered in `api/internal.py` **never runs**. Add `email-domain-check` to the hour map at a free hour (for example 5). Extend `apps/web/src/api-proxy.test.ts` to assert it.

## Requirements (inlined)

- **EML-001** — The sending domain must publish SPF, DKIM and DMARC, verified by an automated check before first customer send.
- **EML-002** — Bounces and complaints must be ingested, stored against the vendor contact, and surfaced on the PO transmission record.
- **EML-003** — A hard-bounced or complained address must enter a suppression list and must not be retried silently; the PO must show as undelivered and be actionable (PO-015).
- **EML-006** — Every send must record provider message id, recipient, template version, document snapshot id, and result (PO-004).

## Design

**Domain check (EML-001):** extend the kernel email port with `domain_status() -> DomainStatus(spf,
dkim, dmarc: pass|fail|unknown, detail)`. The Resend adapter calls the provider's domain endpoint;
the SMTP adapter (local) returns `unknown` with "Local mail catcher". A daily job `email-domain-check`
(registered in `api/internal.py`) stores `email_domain_status(checked_at, spf, dkim, dmarc,
detail)`. **Gate:** the outbox email handler refuses to send a PO email (template name starting `po-`;
today `po-issued-v1`) while the latest status is not all `pass` **in production**. Implementation:
`email_handler(sender, *, domain_gate: Callable[[str], str | None] | None = None)` in
`kernel/outbox/dispatcher.py`; before `sender.send` it calls `domain_gate(template)`, and a returned
reason raises `PermanentOutboxError(reason)` (no provider call, outbox row goes `dead` with
`last_error = reason` via the existing `_record_dead`). `api/internal.py` passes the gate when it
builds the handler. Other templates (password reset, MFA, invitations) are never gated. There is no environment setting: the gate is
`settings.email_provider == "resend"` (only production sends through Resend; local and CI use
`smtp`). The transmission then reads `failed` (existing `READ_STATE`: outbox `dead` → `failed`) with
`result_reason = "Sending domain not verified"`, derived on read (below); the kernel never writes
`po_transmission`.
Locally and in tests, `unknown` is allowed. **Reason storage:** the migration adds
`po_transmission.result_reason text NULL` and `PoTransmissionRead` gains `result_reason: str | None`,
read as `COALESCE(t.result_reason, CASE WHEN o.state = 'dead' THEN o.last_error END)`. Fixed strings
(constants in `transmission.py`), written with the result in the same statement:
- `bounced`: `"Hard bounce: the address does not accept mail"`
- `complained`: `"The recipient marked the email as spam"`
- `failed` (provider `email.failed` event): `"The email provider could not deliver the email"`
- `address_suppressed` (at send): `"Address is on the suppression list"`
- domain gate: `"Sending domain not verified"` (outbox `last_error`, see above)
`delivered` and `sent` carry no reason (NULL). Provider free text is never stored in the reason.

**Webhook (EML-002):** `POST /api/v1/webhooks/email` (new `api/webhooks.py`,
`router = APIRouter(prefix="/api/v1/webhooks", tags=["webhooks"])`, mounted in `api/health.py`
with `app.include_router(webhooks_router)` beside the others; the endpoint is decorated
`@public_route` from `kernel/authz.py` like the auth routes, and keeps the app-wide
`require_origin_secret` dependency, so it is only reachable through the proxy). Path handling is the
same as every other `/api/v1/...` router: the proxy's `/api` handling (`cloudRunRequest`) is shared
and not changed here; the proxy test asserts the upstream path for the webhook equals what it
asserts for any other route. It is **unauthenticated by session but
signature-verified** (Resend signs with Svix: `svix-id`, `svix-timestamp`, `svix-signature`).
The secret is a new setting `resend_webhook_secret: SecretStr | None` (alias
`RESEND_WEBHOOK_SECRET`) in `kernel/config.py`, never logged; when unset the webhook fails closed
(401 on every call). Production binds it like `RESEND_API_KEY`: add
`"RESEND_WEBHOOK_SECRET": "flo-resend-webhook-secret:latest"` to
`apps/api/scripts/check_deploy_resources.py` and a keychain/Secret Manager step to `infra/SETUP.md`
beside the Resend API key (creating the secret is an operator step: `notes.followup`).
**CSRF and Idempotency-Key:** follow the worker precedent in `infra/cron-worker/jobs-tick.ts`. The
Cloudflare proxy (`apps/web/worker/api-proxy.ts`), for `POST /api/v1/webhooks/email` only,
synthesizes the double-submit pair (`Cookie: flo_csrf=<uuid>` and `X-CSRF-Token: <uuid>`) and sets
`Idempotency-Key` to the incoming `svix-id`; it forwards the body and Svix headers unchanged. No
exemption is added to the CSRF middleware or `IDEMPOTENCY_KEY_EXEMPT_PATHS`. Extend
`apps/web/src/api-proxy.test.ts`: the webhook path gets the pair and `Idempotency-Key == svix-id`;
any other path does not get them synthesized. **Signature (stdlib `hmac`, `hashlib`, `base64`; no new dependency):** the secret is
`whsec_<base64>`; key = base64-decode of the part after `whsec_`. Signed content =
`f"{svix_id}.{svix_timestamp}.".encode() + raw_body` (the raw request bytes, read before any JSON
parsing). Expected = base64(HMAC-SHA256(key, signed content)). `svix-signature` is a
space-separated list of `v<n>,<base64>`; accept if any `v1,` entry matches by
`hmac.compare_digest`. Missing header, non-integer timestamp, or `|now - timestamp| > 300 s` → 401.
Tests build vectors with the same algorithm from a fixed test secret (no recorded fixtures needed);
one fixed known-answer vector (secret, id, timestamp, body, expected signature computed once and
pasted into the test) guards the algorithm itself. **Payload (Resend):** JSON
`{"type": "email.delivered"|"email.bounced"|"email.complained"|"email.failed"|..., "created_at",
"data": {"email_id": <provider message id>, "bounce": {"type": "Permanent"|"Transient"|...}}}`.
`email.bounced` with `data.bounce.type == "Permanent"` is a hard bounce; anything else is soft.
Other `type` values → 200, stored nowhere. It rejects a bad
signature with 401 and replays older than 5 minutes with 401. It is idempotent per provider event
id: `email_event(id uuid PK, org_id uuid NOT NULL REFERENCES organization(id), provider_event_id
text NOT NULL (the `svix-id`), type text NOT NULL, transmission_id uuid NOT NULL, vendor_contact_id
uuid NULL, received_at timestamptz NOT NULL DEFAULT now(), UNIQUE (provider_event_id),
FOREIGN KEY (org_id, transmission_id) REFERENCES po_transmission(org_id, id))`, with the literal
`ENABLE`/`FORCE`/`tenant_isolation` block; it is inserted after the org is set from the route, so
ordinary tenant isolation applies (`INSERT ... ON CONFLICT (provider_event_id) DO NOTHING`; zero rows
inserted → 200, no further change). Append-only in practice (no update path). It maps `delivered`, `bounced` (hard only;
soft → keep `sent`), `complained` and `failed` to `po_transmission.result` by `provider_message_id`.
The org is resolved **from `email_message_route`** (below), never from the payload (invariant 4). An
unknown message id → 200 and ignored (no oracle).

**Tenant routing (Q-T1, decided by the operator 1 Nov 2026: option (b)).** The webhook has no session,
and `po_transmission`/`outbox` have forced RLS, so the message id is resolved through a narrow
non-tenant table, never through the payload:
- Migration: `email_message_route(provider_message_id text PRIMARY KEY, org_id uuid NOT NULL,
  outbox_id uuid NOT NULL, created_at timestamptz NOT NULL DEFAULT now())`. Literal statements, one
  block: `ENABLE` + `FORCE ROW LEVEL SECURITY`; `CREATE POLICY tenant_isolation` (same text as
  `outbox`); `CREATE POLICY email_route_jobs_insert ... FOR INSERT WITH CHECK
  (current_setting('app.worker', true) = 'jobs')`; `CREATE POLICY email_route_webhook_select ... FOR
  SELECT USING (current_setting('app.worker', true) = 'webhook')`. No UPDATE/DELETE worker policy.
  Downgrade drops it.
- Write: the provider message id only exists after the provider call, so "at send time" means the
  moment it is recorded: `WorkerOutboxStore.sent()` (`kernel/outbox/store.py:230`) inserts the route row
  (`ON CONFLICT (provider_message_id) DO NOTHING`) in the **same transaction** as the outbox
  `state = 'sent'` update, under the dispatcher's existing `app.worker = 'jobs'` flag, for every
  email topic with a non-null `org_id`. Kernel-generic (no `purchasing` import).
- Read: the webhook handler, in one transaction, sets `SET LOCAL app.worker = 'webhook'`, selects
  the route by `provider_message_id`; no row → 200 ignored. Then `SET LOCAL app.org_id` to the
  route's `org_id` (via `set_config(..., true)`, bound parameter),
  and finds the transmission by `outbox_id` under ordinary `tenant_isolation`. Everything after that
  is tenant-scoped; the `webhook` flag grants nothing on any other table.
- Isolation test (TEN-010): with neither flag, a tenant session sees only its own route rows; with
  `app.worker = 'webhook'` an INSERT/UPDATE is refused; with `app.worker = 'jobs'` a SELECT returns
  nothing. A forged `org_id` in the payload of an event whose route belongs to org A updates only
  org A's transmission.

**Contact attribution (EML-002):** `po_transmission` stores only recipient name and email, and the
send path drops the contact id. The migration adds `CREATE UNIQUE INDEX vendor_contact_org_id ON vendor_contact(org_id, id)`,
`CREATE UNIQUE INDEX po_transmission_org_id ON po_transmission(org_id, id)` (for `email_event`'s FK) and
`po_transmission.vendor_contact_id uuid NULL` with `FOREIGN KEY (org_id, vendor_contact_id)
REFERENCES vendor_contact(org_id, id) ON DELETE SET NULL (vendor_contact_id)` (Postgres 15+ column
list). `modules/vendors/schemas.py` `Recipient` gains `contact_id: UUID`; `document_recipients()` in
`modules/vendors/service.py` selects `id` too; `_dedupe()` in `transmission.py` keeps `contact_id`
(first contact wins for a duplicate address, the existing order) and `_send` writes it. Existing
rows stay NULL. `email_event` stores `transmission_id` and `vendor_contact_id` (copied
from the transmission), so a later contact email edit does not re-attribute the event.

**Suppression (EML-003):** `email_suppression(id uuid PK, org_id, email_normalised, reason, source_event_id,
created_at, UNIQUE(org_id, email_normalised))` (literal RLS block). `email_normalised =
lower(trim(email))`, nothing more (no dot or plus stripping), the same key `_dedupe` uses; one
helper `normalise_email()` in `transmission.py` used by insert, `_suppressed()` and `_dedupe()`, which a hard bounce or a complaint adds. The vendor contact (E11-S02) gains a computed
`suppressed: bool` on read. E13-S09's `_send` already calls `_suppressed()` (a stub returning `False`); this story makes it
query `email_suppression`. Removal is an
admin action (`DELETE /admin/email-suppressions/{id}`, `org.setting.manage`, reason, audited).

## Acceptance

- [ ] Webhook: a valid signature updates the transmission; a bad signature → 401; a replay → 401; the same event twice → one row; an unknown message id → 200 with no change; the org comes from the transmission (a forged org in the payload is ignored).
- [ ] Hard bounce → `bounced` + suppression; complaint → `complained` + suppression; soft bounce → stays `sent`.
- [ ] A suppressed contact on resend → `address_suppressed` without an outbox email.
- [ ] Production gate: with a failing domain status, a PO send fails with the reason; in test mode it sends.
- [ ] The signing secret never appears in logs (log-capture assertion); with the secret unset every call → 401.
- [ ] Proxy test: the webhook path gets the synthesized CSRF pair and `Idempotency-Key == svix-id`; other paths do not.
- [ ] Failed, bounced, complained and suppressed transmissions return `result_reason`; the event row carries `vendor_contact_id`.
- [ ] `DELETE /admin/email-suppressions/{id}` removes by the suppression `id`.
- [ ] `email_message_route` is written in `WorkerOutboxStore.sent()`'s transaction; the webhook resolves the org only through it; the flag isolation test passes.
- [ ] TEN-010 on the admin routes; `flo check` green.

## Plants

1. Accept the org id from the payload: the forged-org test fails.
2. Skip the signature check: the 401 test fails.
3. Grant the `webhook` flag SELECT on `po_transmission` (or drop `FORCE` on `email_message_route`): the isolation test fails.
4. Write the route row outside the `sent()` transaction (separate commit): the test that a failed `sent()` leaves no route row fails.
