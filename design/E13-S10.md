## Requirements (inlined)

- **EML-001** — The sending domain must publish SPF, DKIM and DMARC, verified by an automated check before first customer send.
- **EML-002** — Bounces and complaints must be ingested, stored against the vendor contact, and surfaced on the PO transmission record.
- **EML-003** — A hard-bounced or complained address must enter a suppression list and must not be retried silently; the PO must show as undelivered and be actionable (PO-015).
- **EML-006** — Every send must record provider message id, recipient, template version, document snapshot id, and result (PO-004).

## Decided

**(operator, 1 Nov 2026) DMARC is dropped from the automated production gate: SPF and DKIM only.**
Resend's domain endpoint returns SPF, DKIM and tracking records and nothing about DMARC. The gate
refuses PO email unless `spf` and `dkim` are both `pass`. No `dmarc` column, field or gate input
exists. DMARC stays a **documented manual step** in `infra/SETUP.md` (publish a DMARC record, verify
it by hand with a DNS lookup). This narrows EML-001's "verified by an automated check"; add a
`notes.followup` for a later automated DMARC check (DNS lookup, new-dependency decision). The roadmap
title and `purchase-orders.md` §4 item 11 still say DMARC: `notes.followup`, do not edit them.

**(operator, 1 Nov 2026) Tenant routing of webhook events: option (b),** the `email_message_route`
table below.

**(operator, 7 Nov 2026) Domain-check credential: option (a).** A second, **full-access** Resend key
is used **only** by the domain check; the send key (`RESEND_API_KEY`, `infra/SETUP.md:183`, "restricted
to sending mail") stays send-only. Already created by the operator: keychain
`FLO_PROD_RESEND_DOMAIN_API_KEY`, Secret Manager `flo-resend-domain-api-key` (project `xlr8flo-prod`;

### 2. Domain check (EML-001)

**Port** (`kernel/ports/email.py`): `DomainStatus` frozen dataclass `(spf: Literal["pass","fail","unknown"],
dkim: Literal["pass","fail","unknown"], detail: str)` and a `DomainChecker` Protocol with
`domain_status() -> DomainStatus`. A separate port from `EmailSender`: it holds a different key.

**Resend adapter** (`kernel/adapters/resend.py`): `ResendDomainChecker(api_key, domain_id,
from_address, *, timeout_seconds, requester)`. The existing `_request` (`:24-35`) is POST-only; add a
GET requester beside it (stdlib `urllib.request`, same `(status, body)` shape, injectable for tests
exactly like `requester=` on `ResendEmailSender`). Call `GET https://api.resend.com/domains/{domain_id}`
with `Authorization: Bearer <domain key>`. HTTP 408/425/429/5xx or a network error →
`TransientEmailError`; any other non-2xx or an unparsable body → `PermanentEmailError` (messages
fixed, never the key or body). Mapping from the response (`{"name", "status", "records": [{"record":
"SPF"|"DKIM"|..., "type", "name", "status": "verified"|"pending"|"failed"|"not_started"|"temporary_failure"}]}`),
per record kind K in {SPF, DKIM}, over the records whose `record == K`:
- `pass`: at least one record, and every one `verified`;
- `fail`: any one `failed`;
- `unknown`: otherwise (none, or any pending/not_started/temporary_failure).

If the response `name` is not the domain of `from_address` (`settings.email_from`, the part after
`@`, compared lower-case), both are `fail`: the check would otherwise verify a domain the app does
not send from. `detail`: for every SPF/DKIM record not `verified`, `"<record> <type> <name>:
<status>"`, joined with `"; "`, plus `"EMAIL_FROM is not on <name>"` on a mismatch; empty when both
pass; cut to 500 characters. `create_domain_checker(settings)` in `kernel/email.py` (beside
`create_email_sender`, `:9-14`): `email_provider == "resend"` → `ResendDomainChecker` (a missing
`resend_domain_api_key` or `resend_domain_id` → `RuntimeError("Resend domain check is not
configured")`); otherwise `SmtpDomainChecker` in `kernel/adapters/smtp.py`, returning
`DomainStatus("unknown", "unknown", "Local mail catcher")`.

**Table** `email_domain_status(id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY, checked_at
timestamptz NOT NULL DEFAULT now(), spf text NOT NULL CHECK (spf IN ('pass','fail','unknown')), dkim
text NOT NULL CHECK (dkim IN ('pass','fail','unknown')), detail text NOT NULL)`. **Global**: no
`org_id`, no RLS (the guard at `kernel/tenancy/guards.py:124-133` only treats a table with an
`org_id` column as a tenant table). Append-only in practice; latest = `ORDER BY checked_at DESC, id
DESC LIMIT 1`. Helper `latest_domain_status(connection) -> DomainStatus | None` in `kernel/email.py`.

**Job:** `POST /internal/jobs/email-domain-check` in `api/internal.py`, `include_in_schema=False`,
`@public_route`, response `EmailDomainCheckReport(spf, dkim)`, docstring "Require origin secret and
Idempotency-Key; never replayed; a repeat appends another status row". `_run_email_domain_check(settings)`
(pattern `_run_fx_ingest`, `:641-651`) calls `create_domain_checker(settings).domain_status()` **before**
opening the database, then inserts one row on `psycopg.connect(...)` in one transaction. A
`TransientEmailError` or `PermanentEmailError` writes **no row** and raises
`ProblemError(ErrorCode.SERVICE_UNAVAILABLE, checks={"problem": "email_domain_check_unavailable"})`
(the fx precedent, `:648-651`): the last stored status stays in force, so a provider blip at 05:30
does not stop PO email; the worker reports the failed run. Wired at hour 5 in `api-proxy.ts:83-87`.

**Gate (production only).** `email_handler(sender, *, domain_gate: Callable[[str], str | None] | None
= None)` in `kernel/outbox/dispatcher.py:91`: before `sender.send` (`:113`), a non-None reason from
`domain_gate(template)` raises `PermanentOutboxError(reason)`: no provider call; the row goes `dead`
with `last_error = reason` through the existing `_record_dead` (`:194-198`) and `_safe_error`
(`:233-236`). `kernel/email.py` gains `DOMAIN_NOT_VERIFIED = "Sending domain not verified"` and
`po_domain_gate(settings, status: DomainStatus | None) -> Callable[[str], str | None]`: returns
`DOMAIN_NOT_VERIFIED` when `settings.email_provider == "resend"` **and** the template starts with
`po-` (today `po-issued-v1` and `po-cancelled-v1`) **and** (`status is None` or `status.spf != "pass"`
or `status.dkim != "pass"`); otherwise `None`. Password reset, MFA, invitations and every non-`po-`
template are never gated. With `smtp` (local, CI) nothing is gated.

**Where the gate reads the status (transaction safety).** `_run_jobs_tick` (`api/internal.py:342-391`)
uses a non-autocommit connection (`:349`) and the dispatcher calls the handler **outside** any
transaction (`dispatcher.py:174`). A bare SELECT there would open an implicit transaction, turn the
later `connection.transaction()` blocks into savepoints, and `connection.close()` (`:377`) would roll
back `sent`, the route row and the audit. So the status is read **once per tick**, before the
dispatcher is built: `with connection.transaction(): status = latest_domain_status(connection)`,
then `email_handler(create_email_sender(settings), domain_gate=po_domain_gate(settings, status))`
(`:371-375`). The handler itself never touches the database.

**Reason on the transmission (EML-003).** The migration adds `po_transmission.result_reason text NULL`;
`PoTransmissionRead` (`modules/purchasing/schemas.py:383-397`) gains `result_reason: str | None`
**after** `result_at` (`list_transmissions` zips `model_fields` order, `transmission.py:224`), and the
SELECT at `:213-218` gains, last: `COALESCE(t.result_reason, CASE WHEN o.state = 'dead' THEN CASE
WHEN o.last_error = %(gate)s THEN o.last_error ELSE %(failed)s END END)` — only fixed strings ever
reach the API, never `last_error` free text or an exception name. Constants in `transmission.py`:
- `BOUNCED_REASON = "Hard bounce: the address does not accept mail"`
- `COMPLAINED_REASON = "The recipient marked the email as spam"`
- `FAILED_REASON = "The email provider could not deliver the email"` (provider `email.failed` /
  `email.suppressed`, and any dead outbox row other than the gate)
- `SUPPRESSED_REASON = "Address is on the suppression list"` (written at send with `address_suppressed`)
- the gate's `DOMAIN_NOT_VERIFIED` (imported from `kernel/email.py`).
`delivered` and `sent` read NULL. The kernel never writes `po_transmission`.

### 3. Tenant routing table (operator option (b))

Migration: `email_message_route(provider_message_id text PRIMARY KEY, org_id uuid NOT NULL REFERENCES
organization(id), outbox_id uuid NOT NULL, created_at timestamptz NOT NULL DEFAULT now())`, one literal
block: `ENABLE` + `FORCE ROW LEVEL SECURITY`; `CREATE POLICY tenant_isolation` with the `outbox` text
(`migrations/20260825_0007_jobs_outbox.py:98-100`); `CREATE POLICY email_route_webhook_select ON
email_message_route FOR SELECT USING (current_setting('app.worker', true) = 'webhook')`. No worker
INSERT/UPDATE/DELETE policy.

**Write:** `WorkerOutboxStore.sent()` (`kernel/outbox/store.py:230-238`), after the `_transition`,
inserts `(provider_message_id, row.org_id, row.id)` `ON CONFLICT (provider_message_id) DO NOTHING`
**only when** `row.org_id is not None`, `row.topic == "email"` and `str(row.payload.get("template",
"")).startswith("po-")` (the payload on the claimed `OutboxRecord` is intact; only the stored copy is
blanked). Same transaction: the dispatcher's `_delivery_transaction` (`dispatcher.py:200-205`), which
for an org row is `tenant_transaction` (`kernel/tenancy/rls.py:48-53`, sets only `app.org_id`), so the
insert passes `tenant_isolation` with the row's own `org_id`. Every other email (approvals,
invitations, imports, sourcing, vendor expiry) gets **no** route row, so its provider events are
"unknown message id" below; every route row therefore has a `po_transmission` (written with the
outbox row in `_send`). Kernel-generic: no `purchasing` import.

**Read:** `email_route(connection, provider_message_id) -> tuple[UUID, UUID] | None` (org, outbox id)
in `kernel/outbox/store.py`, in its own `with connection.transaction():` — `SET LOCAL app.org_id =
'00000000-0000-0000-0000-000000000000'` first (`tenant_isolation` calls `current_setting('app.org_id')`
without missing-ok; same as `store.py:203`), then `SET LOCAL app.worker = 'webhook'`, then the SELECT.
The flag dies with that transaction. All later work runs in a separate `tenant_transaction` for the
route's org, so the `webhook` flag never coexists with a tenant write.

### 4. Webhook (EML-002)

`POST /api/v1/webhooks/email` in new `api/webhooks.py`: `router = APIRouter(prefix="/api/v1/webhooks",
tags=["webhooks"])`, mounted in `api/health.py` beside the others (`:109-129`). The endpoint is
`include_in_schema=False`, `@public_route` (`kernel/authz.py`, as the auth and internal routes), and
keeps the app-wide `require_origin_secret` dependency (`health.py:107`), so it is reachable only
through the proxy. It reads the raw body (`await request.body()`) before any JSON parsing, verifies
the signature, then runs the work in `asyncio.to_thread` on its own `psycopg.connect(settings.database_url…)`
(the `_run_fx_ingest` pattern; a public route has no idempotency transaction connection).

**Proxy (CSRF and Idempotency-Key, precedent `infra/cron-worker/jobs-tick.ts:14-24`).** In
`apps/web/worker/api-proxy.ts` `cloudRunRequest` (`:38-60`), for `POST` on the incoming path
`/api/v1/webhooks/email` only: **replace** the whole `Cookie` header with `flo_csrf=<uuid>` (so no
browser session cookie can ride along), set `X-CSRF-Token: <same uuid>`, and set `Idempotency-Key` to
the incoming `svix-id` when present; body and Svix headers are forwarded unchanged; the upstream path is
whatever `cloudRunRequest` already produces for every route (`:47`, unchanged). No exemption is added to
the CSRF middleware or `IDEMPOTENCY_KEY_EXEMPT_PATHS` (`kernel/idempotency/middleware.py:33-41`). With
the key present and no tenant scope the idempotency middleware passes through without storing
(`:271-277`); with no `svix-id` there is no key and the middleware answers 400 (`:255-266`) before the
handler — accepted: nothing is written, and a genuine Resend call always carries `svix-id`.

**Signature (stdlib `hmac`, `hashlib`, `base64`; no new dependency)** — `verify_svix(secret, svix_id,
svix_timestamp, svix_signature, body, now) -> bool` in `kernel/adapters/resend.py`. `resend_webhook_secret`
unset → every call 401 (fail closed). The secret is `whsec_<base64>`; key = base64-decode of the part
after `whsec_`. Signed content = `f"{svix_id}.{svix_timestamp}.".encode() + raw_body`. Expected =
base64(HMAC-SHA256(key, signed content)). `svix-signature` is a space-separated list of
`v<n>,<base64>`; accept if any `v1,` entry matches by `hmac.compare_digest`. A missing Svix header,
non-integer timestamp, or `|now - timestamp| > 300 s` → 401 (`ErrorCode.UNAUTHORIZED`). Tests build
vectors with the same algorithm from a fixed test secret of the form `"whsec_" + base64(b"A" * 32)`
(no secret-shaped literal, author-traps), plus one known-answer vector pasted into the test.

**Payload (Resend):** `{"type", "created_at", "data": {"email_id": <provider message id>, "bounce":
{"type": "Permanent"|"Temporary"|…}}}`. Unparsable JSON or no `data.email_id` after a valid signature →
200, ignored. Event types:
- `email.delivered` → `delivered`
- `email.bounced` with `data.bounce.type == "Permanent"` → `bounced` (hard) + suppression; any other
  bounce type → soft: event stored, result unchanged
- `email.complained` → `complained` + suppression
- `email.failed`, `email.suppressed` (Resend did not send) → `failed`, no local suppression
- any other type → 200, stored nowhere.

**Flow:** `email_route(conn, email_id)` → `None` → 200, nothing stored (no oracle). Otherwise
`transmission.apply_email_event(conn, Scope(org_id), outbox_id, event_id=svix_id, type, hard)` in
`modules/purchasing/transmission.py`, inside `tenant_transaction(conn, scope)`:
1. find the transmission by `outbox_id` (`WHERE org_id = %(org_id)s AND outbox_id = %(o)s`); none → return.
2. `INSERT INTO email_event … ON CONFLICT (provider_event_id) DO NOTHING`; zero rows → return (a duplicate delivery).
3. update `result`, `result_at = now()`, `result_reason` under the **transition rule** below.
4. hard bounce or complaint: `INSERT INTO email_suppression … ON CONFLICT (org_id, email_normalised)
   DO NOTHING`, and, when a row was inserted, `audit_event(actor=AuditActor(ActorKind.SYSTEM),
   action="email.suppression.add", target_type="email_suppression", target_id=<id>, outcome=SUCCESS,
   after={"email": <normalised>, "reason": "bounced"|"complained"})`.
The handler returns 200 with an empty body.

**Transition rule for `po_transmission.result` (derived from EML-003, not a new business rule):**
providers deliver events out of order, and EML-003 requires an undelivered PO to stay visible, so a
later event may never hide `bounced`, `complained` or `failed`. `delivered` is the only result that
moves (an asynchronous bounce or a complaint arrives after delivery). One guarded UPDATE:
`… WHERE org_id = %(org_id)s AND id = %(t)s AND (result IS NULL OR (result = 'delivered' AND
%(new)s IN ('bounced','complained')))`.
| current | `delivered` | `bounced` | `complained` | `failed` |
|---|---|---|---|---|
| NULL (`sent`/`queued`) | set | set | set | set |
| `delivered` | — | set | set | — |
| `bounced` / `complained` / `failed` / `address_suppressed` | — | — | — | — |
The event row is stored either way; suppression (step 4) does not depend on the transition.

**`email_event`**: `(id uuid PRIMARY KEY, org_id uuid NOT NULL REFERENCES organization(id),
provider_event_id text NOT NULL (the svix-id), type text NOT NULL, transmission_id uuid NOT NULL,
vendor_contact_id uuid NULL, received_at timestamptz NOT NULL DEFAULT now(), UNIQUE
(provider_event_id), FOREIGN KEY (org_id, transmission_id) REFERENCES po_transmission(org_id, id))`,
literal RLS block. `vendor_contact_id` is copied from the transmission, so a later contact edit does
not re-attribute the event. No update path.
