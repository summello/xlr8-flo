# E09-S01 — Requisition header, scoped numbering, project-linked and standalone

**Epic** E09 · **M2** · **crud/M** · after **E06-S03** · tags: `migration`

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md` (G–O) and `docs/author-traps.md` apply unless this packet says otherwise. Decisions D-M2-n: `docs/m2-decisions.md`. UI is E09-S11; this story has none.

## Requirements

- **REQ-001** — A requisition may be created against an existing project or as a standalone capital request.
- **REQ-003** — A requisition must not be created against a sub-project that was itself generated by a requisition. *(The marker column and guard land here; E09-S06 sets the marker.)*
- **REQ-010** — A requisition must capture requestor, justification, needed-by date, project/BU/OU, department, ledger account, estimate, currency, lines, attachments, and delivery location. *(Header fields here; lines E09-S02; attachments E09-S10.)*
- **SEQ-001** — Project, requisition, RFQ, award, PO and asset numbers must be unique within their configured organization/BU/OU scope.
- **SEQ-002/004** (inherited from `NumberingService`) — monotonic, not gapless; a number is never reused after a rollback.
- **D-M2-7** — A requisition's currency is always its project's currency (the organization's base currency for a standalone request). Derived, never entered.

## Design decisions (this packet)

- **A draft may be incomplete.** Only `title` and the mode (`project_id` xor `bu_id`) are needed to create one; every other REQ-010 field is nullable on the row and required at submission (E09-S04).
- **Project-linked:** `bu_id` is copied from the project, and `department_code` and `ledger_account_code` default to the project's when the body omits them. **Standalone:** `bu_id` comes from the body and `project_id` stays `NULL` until approval assigns one (E09-S06, D-M2-5); `standalone` records the origin and never changes after creation.
- **`estimate` is derived** (sum of the lines, maintained by E09-S02), starts at `0` and is never accepted from a body.
- **The number is allocated at creation**, so drafts carry one (the page spec shows `Draft REQ-00431`): `NumberingService(settings, scope).allocate(bu_id, "requisition", today)`. The numbering scope is the requisition's BU/OU.
- **List visibility mirrors the project list:** `GET /requisitions` needs `requisition.view` at the organization. `# ponytail:` a user granted only at a BU/OU cannot list (they open records by link and see them in E10's inbox); upgrade path is a resolver `granted_scopes(identity, permission)` filter, add it when a tenant runs BU-only grants. Record this in `notes.followup`.

## Contract

New module `modules/requisitions/` (convention G). Router `apps/api/src/flo/api/requisitions.py`, included in `api/health.py` beside the others.

**Authorization targets** (convention A/B): a project-linked requisition targets `AuthorizationTarget(ScopeType.PROJECT, project_id, "requisition", requisition_id)`; a standalone one targets `AuthorizationTarget(ScopeType.BU, bu_id, "requisition", requisition_id)`. Create targets the project (project-linked) or the BU/OU (standalone) without a record id, exactly like `api/projects.py::create_target`/`parent_target`. Put the builder in `api/requisitions.py::requisition_target(id, connection)`.

| Route | Permission (target) | Success | Errors |
|---|---|---|---|
| `POST /api/v1/requisitions` (Idempotency-Key) | `requisition.create` (project or BU/OU) | 201 `RequisitionRead`, `ETag: "<version>"` | 422 field errors; 422 `requisition_generated_project` on `project_id`; 404 unknown/foreign project or unit |
| `GET /api/v1/requisitions?status=&project_id=&bu_id=&requester=me&q=&sort=&direction=&cursor=` | `requisition.view` (organization) | 200 `{rows, total, next_cursor}` | 403 without an org grant |
| `GET /api/v1/requisitions/{id}` | `requisition.view` (record) | 200 `RequisitionRead`, `ETag` | 404 |
| `PATCH /api/v1/requisitions/{id}` | `requisition.edit` (record) | 200 `RequisitionRead`, new `ETag` | 400 no `If-Match`; 409 `stale_version`; 409 `not_editable` (status ≠ `draft`); 422 |

- **Create body** (`RequisitionCreate`, `extra="forbid"`): `title` (1..200), exactly one of `project_id` / `bu_id`, optional `justification` (≤ 4000), `needed_by` (date), `department_code`, `ledger_account_code`, `delivery_address_id` (uuid). Both or neither of `project_id`/`bu_id` → 422 on `project_id`. A body carrying `currency` or `estimate` → 422 naming the field (`checks.problem = "derived_field"`), not the generic extra-field error.
- **PATCH body** (`RequisitionPatch`): the same optional fields, but **mode is immutable**: `standalone`, `bu_id` and the standalone/project-linked choice are fixed at create, and a PATCH carrying `bu_id`, or `project_id` on a standalone requisition, is 422 `immutable_field` (`checks.problem = "immutable_field"`). The one allowed switch is a **project change within a project-linked requisition** (a returned draft may be moved, see E09-S05 amendment 4): the caller must also hold `requisition.create` at the **new** project (checked with `kernel.authz.permits`, 403 otherwise), REQ-003 applies, and `bu_id`/`currency` re-derive. `currency`, `estimate`, `number`, `status`, `requester_id` → 422 `immutable_field` (the `ProjectPatch.reject_immutable` precedent).
- **`RequisitionRead`**: `id, number, title, status, standalone, project_id, project_number, project_name, bu_id, bu_name, requester_id, requester_email (people are shown by email, convention Q / D-M2-16), justification, needed_by, department_code, ledger_account_code, delivery_address_id, estimate (decimal string), currency, version, submitted_at, decided_at, created_at, updated_at`.
- **List:** filters as named; `requester=me` filters on the caller; `q` matches number prefix or title substring (case-insensitive); `sort` ∈ `number|title|estimate|needed_by|updated_at`, keyset on `(sort key, id)`, 50 per page; `total` is the filtered count.
- Validation on create and PATCH (values present must be valid; absence is fine for a draft): `department_code`/`ledger_account_code` through `org.service.assert_usable(conn, scope, kind, code, today)` (422 with the reason, the `ProjectService.create` precedent); `delivery_address_id` must be an address of kind `ship_to` belonging to the requisition's BU/OU **or an ancestor unit**, effective today (422 otherwise; a foreign id is a 422 on the field, never a hint of existence); `needed_by` is any date here (the past is rejected at submission, E09-S04).

## Behaviour

1. **Migration** (reversible; revision = the head's date prefix + next number at story start, convention C):
   - `requisition(id uuid PK, org_id uuid NOT NULL REFERENCES organization(id), number text NOT NULL, title text NOT NULL, standalone boolean NOT NULL, project_id uuid, bu_id uuid NOT NULL, requester_id uuid NOT NULL REFERENCES identity(id), justification text, needed_by date, department_code text, ledger_account_code text, delivery_address_id uuid, estimate NUMERIC(18,4) NOT NULL DEFAULT 0 CHECK (estimate >= 0), currency char(3) NOT NULL, status text NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','approval_pending','sourcing_in_progress','sourced','awarded','open_for_purchase','completed','rejected','withdrawn','cancelled','expired')), version int NOT NULL DEFAULT 1, submitted_at timestamptz, decided_at timestamptz, created_by uuid NOT NULL, created_at timestamptz NOT NULL DEFAULT now(), updated_at timestamptz NOT NULL DEFAULT now())` — the full status CHECK now (convention J); `UNIQUE (org_id, id)`; `UNIQUE (org_id, bu_id, number)`; `CHECK (standalone OR project_id IS NOT NULL)`; `FOREIGN KEY (org_id, project_id) REFERENCES project(org_id, id)`; indexes on `(org_id, project_id)`, `(org_id, requester_id, updated_at)`, `(org_id, status, updated_at)`. RLS: `ENABLE` + `FORCE` + the `tenant_isolation` policy.
   - `ALTER TABLE project ADD COLUMN generated_by_requisition_id uuid` with `FOREIGN KEY (org_id, generated_by_requisition_id) REFERENCES requisition(org_id, id)` and a partial unique index `(org_id, generated_by_requisition_id) WHERE generated_by_requisition_id IS NOT NULL` (one generated sub-project per requisition).
   - No new permission: `requisition.create`, `requisition.edit`, `requisition.view` already exist in the catalogue and the baseline roles (convention I).
2. **Projects additions** (authorized edits to `modules/projects/{models,schemas,service}.py`): `generated_by_requisition_id: UUID | None` on `ProjectRead` (and `COLUMNS`), and `projects.service.is_requisition_generated(connection, scope, project_id) -> bool` (404 for an unknown or foreign id). Add it to the service's exports.
3. **Create** runs in one `tenant_transaction`: resolve the project (`ProjectService.get`, 404 on foreign) or unit (`OrgService.get_unit`); reject a requisition-generated project with 422 `requisition_generated_project` ("REQ-00277 created this project. A requisition cannot be raised against it; choose its parent project."); derive `bu_id` and `currency` (project's; for standalone the organization's base currency, a 409 `CONFLICT` `base_currency_unset` with a WF-006 detail if the organization has none); allocate the number; insert; audit `requisition.create` with the after-image.
4. **PATCH** locks the row `FOR UPDATE`, checks `If-Match` (convention O), checks `status = 'draft'`, applies the changes, bumps `version`, sets `updated_at`, audits `requisition.update` with before and after of the changed fields only.
5. Every route gets a `COVERED` entry pointing at a real foreign-tenant test.

## Acceptance criteria

- [ ] A project-linked requisition takes the project's `bu_id`, `currency`, department and ledger account (when omitted); a standalone one takes the body's BU/OU and the base currency; `project_id` is null.
- [ ] Two creations in one BU/OU get distinct numbers; the same format in two BU/OUs may repeat a number (SEQ-001 scope); a rolled-back create does not reuse its number.
- [ ] A body with `currency` or `estimate` → 422 naming the field; both or neither of `project_id`/`bu_id` → 422.
- [ ] A project whose `generated_by_requisition_id` is set → 422 `requisition_generated_project`, on create and on a PATCH that switches to it.
- [ ] An inactive ledger account → 422 with reason `inactive`; a `bill_to` address, a closed address, or an address of an unrelated unit → 422 on `delivery_address_id`.
- [ ] PATCH: no `If-Match` → 400; stale → 409 `stale_version`; non-draft → 409 `not_editable`; moving a project-linked draft to another project without `requisition.create` on the new one → 403; a PATCH carrying `bu_id`, or `project_id` on a standalone requisition → 422 `immutable_field`; `currency` in body → 422 `immutable_field`.
- [ ] `estimate` reads `"0.0000"` on a new requisition and is a decimal string on the wire.
- [ ] Each route: unauthenticated 401; no grant on a record → 404; wrong permission with a grant in scope → 403; foreign tenant → 404. The list without an org-level `requisition.view` → 403.
- [ ] Each write produces one audit row with before/after.
- [ ] Migration up, down, up preserves a requisition and a project's `generated_by_requisition_id`.

## Pre-flight amendments (11 Oct 2026, Opus; binding, they override anything above)

Each item below was found by reading the code this story touches. A block on any of them is a packet defect, not an author failure.

1. **Numbering has no `requisition` default.** `NumberingService.allocate` falls back to `("PRJ", True, 4, scope_id)` for every `doc_type` when the tenant has no `numbering_format` row (`modules/org/numbering.py`, the `row or (...)` line). An unconfigured tenant's first requisition would be numbered `PRJ-2026-0001`. Replace the single fallback with a per-type default map: `project` → `("PRJ", True, 4)` (unchanged), `requisition` → `("REQ-", False, 5)` (the page spec's `REQ-00431`; `numbering.py` adds no separator when `include_year` is false, so the separator lives in the prefix, and a tenant-configured prefix carries its own separator), and for the other `DocumentType` members `("RFQ"|"AWD"|"PO"|"AST", False, 5)`. A configured format still wins. Counter scope is unchanged. Acceptance: a tenant with no formats gets `PRJ-<year>-0001` for a project and `REQ-00001` for a requisition (the default prefix is `"REQ-"`, so `("REQ-", False, 5)` renders `REQ-00001`); a configured requisition format wins. Add `modules/org/numbering.py` and the existing numbering test file under `tests/org/` to Files.
2. **No ancestor-chain helper exists in `org.service`** (only the settings recursion inside `effective_setting`). Delivery-address validation here and the catalogue scope in E09-S03 both need "this unit and its ancestors". Add `OrgService.unit_chain(unit_id) -> list[UUID]` (the unit first, then parents nearest first; 404 for an unknown or foreign unit) and a module-level wrapper beside `assert_usable` (`org/service.py` has the pattern). Export it. E09-S03 reuses it; do not write a second recursion. Add `modules/org/service.py` to Files with a unit test (three-level tree, foreign unit → 404).
3. **`NumberingService.allocate` commits on its own connection** (that is how SEQ-002 "never reused after rollback" holds). A create that fails after allocating leaves a gap on purpose. The acceptance criterion "a rolled-back create does not reuse its number" is proved by forcing a failure after `allocate` and asserting the next number is higher by two, not one.
4. **Audit.** Use the existing writer exactly as `ProjectService._audit` does (`kernel/audit/writer.py`, `ActorKind.USER`). Do not invent an audit helper.
