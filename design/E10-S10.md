## Requirements

- **APR-020** — The system must provide inbox, pending, overdue, completed, and delegated approval views.
- **APR-013**, **APR-014**, **APR-016**, **APR-017**, **APR-021** — through the decision panel and the availability page (texts in E10-S06, S07, S08, S09).
- **WF-006** — Users must receive a clear, actionable explanation when a workflow action is blocked.
- **A11Y-004**, **A11Y-006**, **UX-004**, **UX-005** — status never by colour alone; forms with labels, field errors, an error summary and preserved input; distinct loading, empty, partial and error states; errors say what happened, what was preserved and how to recover.

## Contract

**Backend added by this story** (`api/approvals.py`, `modules/approvals/inbox.py`):

`GET /api/v1/approvals/tasks?view=pending|overdue|completed|delegated&type=&q=&sort=due|amount|decided&direction=asc|desc&cursor=` → 200 `{rows: [InboxRow], total, next_cursor}`, 50 per page, server-filtered and sorted (PERF-005).

- `pending`: open tasks where the caller is a current member (convention K, including as an active delegate).
- `overdue`: the subset of `pending` with `due_at < now`.
- `completed`: tasks the caller decided, as themselves or on someone's behalf.
- `delegated`: tasks the caller covers for someone ("Covering For") and tasks of the caller now passed to a delegate ("Passed To Others").

`InboxRow = {task_id, instance_id, document_type, document_id, number, title, requester_name, document_version, amount: {amount: str, currency} | null, step: {index, of}, due_at, decided_at, status_word, on_behalf_of_name, href}`. Number, title, amount and requester come from the adapters' batch `summaries()` (frozen in E10-S05), one call per document type per page, never per row. `q` matches number, title or requester name (prefix, case-insensitive). The `total` row in the spec ("Total waiting … USD") is a server figure: add `total_amount` per currency to the response; the UI never adds money.

The decision panel uses E10-S06's `POST /api/v1/approvals/tasks/{id}/decisions` (the spec's `/decision` path is illustrative; **the packets' routes win**), E10-S09's explanation and E10-S06's decision list. The availability page uses E10-S08's delegation routes.

## Behaviour (screens; the page spec is the layout and copy reference)

1. **`/approvals`** (spec §1): tabs Pending, Overdue, Completed, Delegated with counts, the tab in the query string, arrow-key tab navigation. Search and Type filter; server sort on Amount and Due with `aria-sort`; a total row from `total_amount`; every state (loading skeleton at final height, empty per tab with the spec's words, no match, error with filters kept and a reference id, partial). Overdue shows "N days overdue" in words with an icon and a start-edge rule. Status pills use the existing `StatusPill` (E04-S05): icon and words, never colour alone.
2. **Decision panel** (spec §2), a side sheet (`role=dialog`, `aria-modal`, focus to Close, trapped, Escape and the scrim return focus to the row), in the operator's order: notices, key facts with `Open the full requisition`, **Decision Trail**, the comment, then **Why It Reached You** folded `for audit`, with its own error and `Try again`. Buttons `Close`, `Post Comment`, `Return for Changes`, `Reject`, `Approve`, never disabled to signal an error; for a task you cannot decide, the decision buttons are absent and a notice says why (WF-006).
   - **Reject asks the approver to choose** "Return to the requester to fix" or "Reject permanently" (D-M2-1), a required radio group with a field error. The spec predates D-M2-1; add the choice where the spec's reject flow is, using MASTER radio components.
   - **Refusals** focus the alert and keep the typed comment: reason missing; `This requisition changed` (the 409 `stale_version`) with `Load Version N`; `Already Decided` (`task_closed`).
   - **After a decision** the result `role=status` with the 260 ms tick (reduced motion shows the finished tick), `Back to Inbox` and `Next: <number>`.
   - **Final approval of a standalone requisition** (`accepts_project_assignment`): an optional "Assign to an existing project" combobox (project-linked, eligible projects only) feeding `assign_project_id`; when empty the copy says a new project will be created and funded with the approved amount (D-M2-5).
3. **`/approvals/availability`** (spec §5): the out-of-office form (Starts, Ends as native date inputs converted per D-M2-14, Pass Approvals To from `eligible-delegates`, Covers as all types or a chosen subset), the error summary pattern, the delegations table with statuses, revoke `alertdialog` with focus on `Keep Delegation` and the canvas-80 wording, "Decided on Your Behalf", and the organization tab for `approval.admin` (revoke only).
4. **Stale spec copy, overridden** (record each in `notes.followup` for the design session): `Group Fixed … snapshotted` becomes live membership ("Members are checked when a decision is made", D-M2-2); the withdraw rules in spec §3 belong to E09 (canvas 78, until sourcing starts); any copy saying a pending requisition holds a reservation is stale, since budget is reserved on approval (REQ-002, D-M2 "raised with the operator").
5. Tokens only; no value from the canvas (AGENTS.md). Money cells: tabular, right-aligned, currency code visible, from server strings, never `Number` (the E06-S07 `Money` component).

## Acceptance criteria

- [ ] Each tab lists exactly the tasks its rule defines (fixture: one user as member, as delegate, as delegator, with an overdue and a completed task); counts equal the server totals.
- [ ] The list never requests more than 50 rows; sort and filter are server-side.
- [ ] Reject without choosing a mode shows the field error and sends nothing; with a mode it sends `reject_mode`.
- [ ] A 409 `stale_version` shows `This requisition changed` with the reload action and keeps the comment.
- [ ] A keyboard-only path: open the inbox, move between tabs with arrows, open a row, type a comment, approve, reach `Next`.
- [ ] Axe passes on `/approvals` (every tab, panel open) and `/approvals/availability` in light and dark.
- [ ] Every UX-004 state renders: loading, empty per tab, no match, error, partial.
- [ ] The availability form keeps typed values on a failed save and focuses the summary.
- [ ] The MASTER §8 checklist is ticked in the PR body.
