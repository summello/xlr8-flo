# E10-S12 — Workflow list, version history and diff, route preview

**Epic** E10 · **M2** · **ui/L** · after **E10-S11**, **E10-S05** · tags: `ui`

> **Re-scoped in the M2 design pass (10 Oct 2026).** The roadmap called this "Keyboard/list workflow editor with identical capability to the canvas". AGENTS.md invariant 8 and the page spec put that Outline in the same story as the canvas, so it ships in **E10-S11**. This story takes the builder parts no other story covered: the workflow list, version history with a diff, and Route Preview.
>
> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`. **UI authority:** `design-system/MASTER.md` and `tokens.css`, then `design-system/pages/approval-workflow-builder.md` (§1 list, §5 route preview, §6 states), then canvas boards `ApprovalWorkflows`, `WfList*` for layout and copy only.

## Requirements

- **APR-011** — Workflow definitions must be versioned; active documents must retain the workflow version used at submission.
- **ACC-007** — Editing a workflow does not alter the routing or decision history of documents already submitted.
- **APR-021** — Approval routing must be explainable: authorized users can see which rule matched and why an approver was selected.
- **UX-004**, **UX-005**, **A11Y-006**, **PERF-005** — states, recoverable errors, forms, server-side paging.

## Contract

Backend added by this story (`api/workflows.py`, `modules/approvals/{versions,preview}.py`):

1. `GET /api/v1/workflows` (E10-S01's list) gains, per row: `applies_to` (document type and bound scope name), `published_version`, `draft_version`, `in_flight` (count of `running` instances pinned to a version other than the published one), `edited_at`, `edited_by_name`.
2. `GET /api/v1/workflows/{id}/versions/{version}/route-preview?amount=&currency=&bu_id=` (`workflow.read`) → 200 `RoutePreview`, the same shape E10-S05's `preview_route` returns (steps, conditions with traces, current eligible members and exclusions per approval step). It is evaluated on **that version's graph, draft included**, with a synthetic attribute set `{amount: Money(amount, currency)}`. `amount` must match `^[0-9]{1,14}(\.[0-9]{1,4})?$` (422 field error otherwise). Factor E10-S05's route walk into a pure `walk(graph, attributes)` used by both `start` and this preview; do not copy it. Read-only, a `GET`, no key.
3. The version diff is computed **in the browser** from two `GET .../versions/{v}` responses (graphs are presentation-safe JSON with no money arithmetic): added, removed and changed steps; changed conditions; approver changes.

## Behaviour

1. **`/admin/approval-workflows`** (spec §1): search; a server-paged table with Workflow (name, "Edited <date> by <who>"), Applies To, Published pill, Draft pill, In Flight and Versions; `New Workflow` (document type, scope, name, which creates the definition and its first draft, then opens the builder); every state, including partial ("In-flight counts delayed").
2. **Version History** side sheet: version lineage with state pills, dates, authors, in-flight counts, then "Draft N Compared With Published N−1" as a `.diff` (the inbox spec §4 pattern). Published versions are read-only, with no edit affordance anywhere (ACC-007).
3. **Route Preview** side sheet (spec §5), from the builder header: an Estimate field (required tag, field error on a bad amount, typed value kept), a BU/OU picker (default the workflow's bound scope), then numbered steps, each with the rule that matched in the decision panel's words, the group rule and the current approvers (with exclusions, as in E10-S09). The canvas numbers the path's steps and draws its lines heavier (numbers and weight, not colour alone). The sheet says the preview uses the estimate only (the M2 catalogue, D-M2-4).
4. Money in the preview and list: server strings in the `Money` component; never `Number`.

## Acceptance criteria

- [ ] `in_flight` counts only running instances on non-published versions (server test with real instances).
- [ ] Route preview on a draft returns the draft's route, not the published one's; an amount below and above a condition boundary routes differently; a bad amount is a 422 field error.
- [ ] `walk()` is shared: a server test asserts `start` and `route-preview` produce the same steps for the same graph and amount.
- [ ] The diff sheet lists an added step, a removed step, a changed condition value and a changed approver set for a fixture pair.
- [ ] Keyboard-only: open the list, open Version History, close it, open a workflow, run Route Preview, and read the steps.
- [ ] Axe passes on the list, both sheets, light and dark; all UX-004 states render.

## Plants

1. Give the preview its own copy of the route walk with the default-edge rule changed: the shared-walk test fails.
2. Count all running instances as in flight: the in-flight test fails.
3. Make the preview read the published version: the draft-preview test fails.
