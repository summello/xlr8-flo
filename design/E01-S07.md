# E01-S07 — Gate self-tests: every CI gate proves it fails on a planted violation

**Epic** E01 Platform & delivery · **Milestone** M0 · **chore/M** · after E01-S04

## Requirements

- **SEC-012** — Dependency scanning, secret scanning, static analysis, dynamic testing, and an
  SBOM must be part of release controls.

A gate that cannot fail is not a release control. This story makes "it fails on a real
violation" a permanent, re-executed property of every gate rather than a claim in a commit
message.

## Why this story exists

Three gates shipped in M0 reported green while enforcing nothing. Each was found by a reviewer
reading the implementation, which does not scale:

1. **RLS migration guard (E03-S02)** — captured the `CREATE TABLE` body with a non-greedy match
   to the first `)`, so any table declaring `NUMERIC(18,4)` truncated the body, was never
   recognised as tenant-scoped, and skipped every RLS requirement. Blind to exactly the tables
   AGENTS.md §3.1 mandates that column for.
2. **Money float ban (E01-S04)** — the regex caught `x: float` but not `-> float`,
   `list[float]`, or `int | float`.
3. **Identity port contract (E02-S01)** — `source_modules = flo` against its own descendant is a
   pair import-linter skips, so the contract passed with a direct adapter import present.

## Deliverable

One pytest module that runs inside the existing `flo check` and CI. No new job, no new tool.

```
apps/api/tests/gates/__init__.py
apps/api/tests/gates/test_gates_bite.py     # one case per gate
apps/api/tests/gates/fixtures/              # the planted violations
```

Each case: copy a violating fixture into an isolated temporary tree, run the gate's **real**
command, assert a non-zero exit **and** that the output names the violation; remove the fixture,
assert clean exit. Both halves matter — a gate that always fails is as useless as one that never
does.

## Gates that must be covered

| Gate | Command | Planted violation |
|---|---|---|
| Money float ban | `check_money_floats.py` | `def total() -> float:` in a money module |
| Module boundaries | `lint-imports` | `flo.modules.a` importing `flo.modules.b` |
| Identity adapter | `lint-imports` | `flo.api` importing `flo.kernel.identity.local` |
| Tenancy RLS | `check_tenancy.py` | `CREATE TABLE t (amount NUMERIC(18,4), org_id uuid)` with no RLS statements |
| Tenancy policy | `check_tenancy.py` | `CREATE POLICY tenant_isolation ON t USING (true)` |
| Tenancy OpenAPI | `check_tenancy.py` | an operation declaring an `org_id` parameter |
| Secret scanning | `gitleaks detect` | a realistic fake AWS key in a source file |
| Strict typing | `mypy --strict` | an untyped function body |
| Roadmap drift | `flo roadmap --check` | a hand-edited rendered table |
| Scorecard drift | `flo score --check` | a hand-edited SCORECARD.md |

## Also in scope — two silent-skip holes

1. **`run_check` treats exit 127 as a pass** (`agents/scripts/flo`, prints
   `? not installed (M0 not complete)` and continues). A missing tool is indistinguishable from
   a passing one. Make 127 a failure, with an explicit, named opt-out list for tools M0 has not
   delivered yet, so the exemption is visible and shrinks.
2. **The money Postgres round-trip test skips when `DATABASE_URL` is unset**, so the
   `NUMERIC(18,4)` persistence criterion is only ever verified in CI. `flo up` exists as of
   E01-S02 — point `flo check` at it, or fail rather than skip when it is absent.

## Acceptance criteria

- [ ] Every gate in the table above has a case that fails on its planted violation and passes once removed
- [ ] Each case asserts the gate's output *names* the violation, not merely that the exit code is non-zero
- [ ] Deliberately reverting the E03-S02 guard to its non-greedy `(.*?)` body match makes the RLS case fail
- [ ] Deliberately reverting the float ban to its old regex makes the `-> float` case fail
- [ ] Deliberately setting `source_modules = flo` makes the identity-adapter case fail
- [ ] `run_check` returns non-zero when a gate's tool is missing, unless that tool is on the named opt-out list
- [ ] The opt-out list is documented in `docs/ops/ci-gates.md` with the story that will remove each entry
- [ ] `flo check` is green with all of the above in place

## Files

`apps/api/tests/gates/*`, `agents/scripts/flo` (run_check only), `docs/ops/ci-gates.md`,
`AGENTS.md` §4 (add the Definition of Done line below).

**AGENTS.md §4 addition, exact wording to add as item 10:**

> 10. Any gate, contract or guard the story adds or edits ships a test that plants a real
>     violation and proves the gate fails on it. A gate nobody has seen fail is not a gate.

## Out of scope

New gates of any kind. Changing what existing gates check. Deploy (E01-S05), infra (E01-S06).
This story only proves the gates already agreed on actually bite.
