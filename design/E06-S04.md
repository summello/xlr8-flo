# E06-S04 — Roll-down and roll-up funding modes, set per BU/OU and inherited

**Epic** E06 · **M1** · **ledger/L** · after **E06-S02**, **E07-S02** · tags: `money`

## Requirements

- **PROJ-006** — A BU/OU setting must select roll-down funding or roll-up aggregation, applied consistently at every level.
- **PROJ-007** — In roll-down mode, a child allocation must not exceed the parent’s available budget.
- **PROJ-008** — In roll-up mode, a parent budget must aggregate descendants without duplicating their funds.

## Design decisions (confirm on review)

- **D-M1-17 Funding mode semantics** (setting key `funding_mode`, values `roll_down` default | `roll_up`, resolved per project at its BU/OU through E05-S01's precedence; **the mode of a project's top-level ancestor's BU/OU governs its whole tree**, so a tree never mixes modes).
  - **Roll-down:** money is held at nodes. A root project is funded from outside the hierarchy (`allocate`, E07-S03). A child is funded **from its parent**: allocating X to a child posts a transfer pair (parent `allocated −X`, child `allocated +X`, one `transfer_group_id`, `source_type='transfer'`). PROJ-007 follows directly: the parent's leg is subject to its `available`, so a child allocation can never exceed the parent's available budget.
  - **Roll-up:** a parent's budget is the **aggregate of its descendants** and is never stored twice (PROJ-008): the parent's own `allocated` counts once, plus each descendant's. No ancestor legs are ever posted in this mode.
- Direct `allocate` on a child in roll-down mode is rejected (409 `FundFromParent`) — it would create money from nothing.

## Contract

- `modules/budget/funding_policy.py` completes the hook left by E07-S03/S08: `plan_allocation(project, amount) -> Direct | FromParent(parent_id)`; `allocate` follows the plan. The E07-S03 endpoint is unchanged; for a roll-down child it now returns the two-leg transfer result (same `entries` shape) — adjust that story's response model to a union documented in OpenAPI.
- `GET /api/v1/projects/{id}/balance/aggregate?period=...` (permission `ledger.read` at the project's scope) → 200 `{mode, own: BalanceRead, descendants: BalanceRead, total: BalanceRead, node_count}`: in roll-up mode `total = own + Σ descendants` per bucket, computed by one recursive CTE over `project_balance` (life-to-date) or over `ledger_entry` for date ranges; in roll-down mode `total = own` and `descendants` is informational only, never summed into `total` (the funds are already in the children's holdings).
- Setting changes: switching `funding_mode` on a BU/OU that already has allocated projects is a 409 (`FundingModeLocked`) — modes are fixed once money exists under the scope.

## Behaviour

1. Mode resolution is one query per request, cached for the request only.
2. In roll-down mode a child's allocation is validated under the parent's `FOR UPDATE` lock (lock order ascending `project_id`, as E07-S07).
3. Roll-up totals and drill-down (RPT-003) reconcile: `total.allocated` equals the sum of the `allocated` ledger entries of the subtree, tested against the ledger, not against `project_balance`.
4. A child of a project in a different currency than the parent is rejected for funding (409), not converted.

## Acceptance criteria

- [ ] Roll-down: parent allocated 100; allocating 60 to child A then 50 to child B → the second returns 409 `InsufficientBudget` (parent available 40), nothing written; allocating 40 succeeds and the parent's `available` is 0 (PROJ-007)
- [ ] Roll-down: direct `allocate` on a child → 409 `FundFromParent`
- [ ] Roll-up: parent own 10, children 30 and 20 → aggregate `total.allocated = 60`, and a cross-hierarchy transfer between two leaves of this tree changes no ancestor's `own` and keeps `total` constant (PROJ-008, no duplication)
- [ ] The aggregate reconciles to the ledger for every bucket on a seeded random tree (golden + property test)
- [ ] Concurrent child allocations racing for the last 40 of a parent: exactly one succeeds
- [ ] Changing `funding_mode` after allocations exist → 409; before any → allowed; precedence from E05-S01 (BU overrides org) is honoured for the tree's top-level BU
- [ ] Foreign-tenant project → 404 (isolation gate entries)
