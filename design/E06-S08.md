# E06-S08 — Project dashboard with hierarchy visual and drill-down to ledger entries

**Epic** E06 · **M1** · **ui/L** · after **E06-S07**, **E07-S06** · tags: `ui`

> **Conventions:** read `docs/m1-conventions.md` (authorization outcomes, scope targets, wire formats). It applies unless this packet says otherwise.

## Requirements

- **PROJ-009** — Project dashboards must visualize hierarchy and drill down to items, services, documents, and ledger entries.
- **PROJ-021** — Project risk indicators should incorporate requirements, milestone/delivery adherence, budget variance, and manually recorded risks while showing the facts behind each indicator.
- **RPT-002** — Dashboards must support organization → BU/OU → project → sub-project → document → transaction drill-down.
- **RPT-003** — Project reporting must show allocation, reservation, commitment, actual, available balance, variance, and consumption percentage.
- **A11Y-009** — Charts must have names, descriptions, and equivalent tabular or textual data.

**Read first (UI story):** `design-system/MASTER.md` and the chart rules in it. Tokens only.

## Contract

Route `/projects/$projectId/dashboard` (linked from the detail page) and the organization/BU roll-up at `/budget` (replacing its placeholder). Data: `GET /api/v1/projects/{id}/balance`, `.../balance/aggregate`, `.../tree`, `.../ledger`, `.../balance/reconcile` (E07-S06, E06-S02, E06-S04) and the risks list (E06-S06), all through the generated client.

New read endpoint for the computed risk indicator (small, in this story): `GET /api/v1/projects/{id}/risk-indicators` (permission `project.read`) → 200 `{indicators: [{code, level: 'low'|'medium'|'high', facts: [{label, value}]}]}` with exactly these indicators, **each showing the facts behind it** (PROJ-021):
- `budget_variance`: `high` when `(reserved+committed+actual)/allocated >= 0.95`, `medium` at `>= 0.80`, else `low`; facts: allocated, consumed, percent. `allocated = 0` → `low` with the fact "no budget allocated".
- `schedule`: `high` when any milestone is overdue by more than 14 days, `medium` when any is overdue, else `low`; facts: each overdue milestone name and days late.
- `recorded_risks`: `high` when any open risk has `score >= 15`, `medium` at `>= 8`, else `low`; facts: top three risks by score.
Requirements adherence is not computable until requisitions exist; the response includes `{code:'requirements', level:'unknown', facts:[{label:'Not available', value:'Requires requisitions (M2)'}]}` rather than inventing a value. **These thresholds are a documented default (D-M1-18, confirm on review).**

## Behaviour

1. **KPI strip:** allocation, reservation, commitment, actual, available, variance, consumption percentage (RPT-003), money formatted per MASTER (tabular, currency code, parenthesised negatives), each with a text label.
2. **Hierarchy visual:** an accessible tree (`role="tree"`, arrow-key navigation, expand/collapse by keyboard) of the project and descendants with each node's status pill and consumption; selecting a node navigates to its dashboard (organization → BU/OU → project → sub-project drill-down, RPT-002). Truncation from the API (`truncated: true`) is stated in words.
3. **Chart:** a bar chart of the buckets per project (children of the selected node) — **with an equivalent data table rendered beside it and a name and description** (A11Y-009, RPT-013). Colour never carries meaning alone: bars are labelled and patterned; chart colours come from tokens.
4. **Drill-down to ledger entries:** every figure links to the ledger list filtered to that bucket (ACC-003); the ledger list is keyset-paged, shows source type/id, actor, reason, reversal/release links, and a "Reconciles to the ledger" status from `reconcile` that states a non-zero difference plainly if one exists.
5. **Risk indicators panel** shows each indicator's level (icon + text) and its facts.
6. Loading, empty (no allocation yet), partial and error states exist; reduced motion respected; transitions at most 300 ms.

## Acceptance criteria

- [ ] Playwright: open a seeded project dashboard, see the seven KPIs, expand the tree with the keyboard, drill from a KPI to the filtered ledger, and see "Reconciles"
- [ ] The chart has an accessible name, description and a data table with the same numbers (test compares them)
- [ ] `@axe-core/playwright` clean on both new routes in both themes; keyboard-only path covers the tree and drill-down
- [ ] A planted drift (test fixture inserts a bypassing row) makes the UI show the non-zero difference in words
- [ ] Risk-indicator unit tests pin each threshold boundary (0.79/0.80, 0.94/0.95, 7/8, 14/15 days) and the `unknown` requirements row; every indicator returns its facts
- [ ] Foreign-tenant project → 404 on `risk-indicators` (isolation gate entry); no money value is rendered with a float conversion (decimal strings formatted with `Intl.NumberFormat` from a string-safe path or a decimal helper; a vitest pins `0.1 + 0.2` style cases)
- [ ] `tsc`, `eslint`, `vitest`, colour gate and Playwright pass; MASTER §8 checklist in the PR description
