## Requirements (inlined)

- **PO-014** — PDFs reproducible from the snapshot and template version.
- **PO-017 / EML-005** — internal-only content (chartfields, budget figures, internal notes, uploaded files) is never
  included in what the supplier receives; covered by an automated test.
- Decision 170: the supplier receives one email (a high-level summary) and one PDF, and nothing else; no chartfield
  (project, department, ledger account), no budget information, no internal note. Decision 171: uploaded files stay
  internal in M3 (`Not sent until scanning is available`).

The server already enforces all of this (E13-S08, E13-S11; `apps/api/tests/purchasing/test_vendor_copy.py:111`
`test_chartfields_budget_figures_and_internal_notes_never_reach_the_vendor`, `:238`
`test_each_revision_has_its_own_snapshot_and_the_old_one_never_moves`). This story **shows** it, and proves the screen
adds nothing the server withheld.

## Why the PDF is not embedded (settled; do not change it)

Every API response carries `frame-ancestors 'none'` and `X-Frame-Options: DENY`
(`apps/api/src/flo/kernel/session/middleware.py:16`, `:23`), and the SPA's CSP has `object-src 'none'`
(`apps/web/public/_headers:5`, asserted by `apps/web/src/security-headers.test.ts`). An `<iframe>`, `<embed>` or
`<object>` of the PDF is therefore blocked, and no PDF renderer is a production dependency
(`apps/web/package.json:16-27`). **Do not change any security header, do not add a dependency.** Instead, per MASTER
§7.16 item 4, the page **draws** the vendor copy as a `.pdf-page` from `vendor_copy` (the same snapshot the PDF is
rendered from, PO-014), and offers `Open PDF`, a plain link to the real PDF in a new tab — the pattern `View PDF`
already uses at `detail.tsx:34` (top-level navigation is not framing).

## Design

### Route `/purchase-orders/:id/vendor-copy`

In `__root.tsx`, beside `PO_PATH`:

- `const PO_VENDOR_COPY_PATH = /^\/purchase-orders\/([0-9a-f-]{36})\/vendor-copy$/;`
- `routeFor`: `activeHref: "/purchase-orders"`, `phase: "commit"`, `title: "Vendor Copy"`,
  `description: "What the supplier receives: one email and one PDF."`, breadcrumbs Organization → Purchase Orders →
  Purchase Order (`href` = the path without `/vendor-copy`) → Vendor Copy (same shape as `RFQ_AWARD_PATH` at `:283`).
- Extract the id and render `<PurchaseOrderVendorCopy key={id} id={id} navigate={navigate} />` from a new
  `apps/web/src/routes/purchase-orders/vendor-copy.tsx`, which imports the same style files as `detail.tsx`.

The page fetches **only** `GET …/{id}/vendor-copy`. It does not call `GET /purchase-orders/{id}`, the notes, the
attachments or the budget summary: everything it shows comes from `VendorCopyRead`. That is the structural guard the
leak test checks.

### Shared component `apps/web/src/components/purchasing/vendor-copy/VendorCopyView.tsx`

Props `{ copy: VendorCopyRead; poId: string }`. Renders, in this order:

1. **Status line in words:** `issued` true → `Version v{revision + 1} as issued on {formatDate(issued_on)}, template
   {template_version}`; `issued` false → `Not issued yet. This is what the supplier will receive when it is issued; the
   PDF is generated at issue.`
2. **The email** (heading `Email`): `To` is not shown (recipients are on Transmissions); the body is `email_summary`
   verbatim in a block with `white-space: pre-line`, then `Attachment: PDF` (only when `issued`).
3. **The PDF** (heading `PDF`): `Open PDF` link (`href="/api/v1/purchase-orders/{poId}/pdf"`, `target="_blank"`,
   `rel="noreferrer"`, Phosphor `FilePdf` regular, as `detail.tsx:34`) **only when `issued` is true**; then a
   `.pdf-page` drawing of `vendor_copy`: letterhead address, number with `Revision n` when `revision > 0`, issued and
   needed-by dates, vendor legal and trading name, Bill To, Ship To (omitted when null), terms, a lines table
   with the PDF's eight columns in its order (`pdf.py:93`): `#`, `Description`, `Qty` (one cell, `{quantity} {uom_code}`,
   as `pdf.py:100`), `Unit price`, `Price`, `Tax`, `Freight`, `Total`; amounts through
   `Money` with the currency, tabular, right-aligned), totals (price, tax, freight, total), notes shared with the
   vendor (body and date), standard terms. Omit any block whose value is null or empty, as the PDF does.
4. **"Never sent to the vendor"** (heading): a static list of category names only, citing decisions 170/171 in a code
   comment — `Chartfields (project, department, ledger account)`, `Budget figures`, `Internal notes`,
   `Uploaded files: not sent until scanning is available`. No values, no counts. (The earlier draft asked for this list
   from the server; `VendorCopyRead` has no such field and the categories are fixed by decision, so a constant is the
   correct source. A server field would be a constant too.)

### Sheet on the detail

`apps/web/src/components/purchasing/vendor-copy/VendorCopySheet.tsx` (pattern above): title `Vendor Copy`, a visually
hidden description, loads `…/vendor-copy` when opened, renders `VendorCopyView`, and a link `Open full page` to
`/purchase-orders/{id}/vendor-copy`. In `detail.tsx` add one button `Vendor Copy` (Phosphor `Envelope`, regular) to
`vendor-head-actions` for every status, `cancelled` included (a PO cancelled after issue keeps its frozen copy,
`pdf.py:211`; one cancelled before issue gets the 404 sentence below in the sheet); it opens the sheet and focus returns to it on close. Keep the
existing `View PDF` link. Change nothing else on the detail (E13-S18 and E13-S19 also edit this header: add one
element, do not reorder).

### States (pages/purchase-orders.md §5, UX-004, UX-005)

Loading: a `req-card-skeleton` at the final height (as `detail.tsx:26`). 404: `This purchase order has no vendor copy:
it does not exist, you cannot see it, or it was cancelled before it was issued.` plus `Back to purchase orders`. Other
error: `failure(error, "Loading the vendor copy")` with `Try again` (`reload`). Nothing to keep: the page holds no input.

### Styles

Add to `apps/web/src/styles/purchase-orders.css` only, tokens only:
`.pdf-page { background: var(--surface); border: 1px solid var(--border-strong); border-radius: var(--radius-card);
padding: var(--space-6); display: grid; gap: var(--space-4); }` and `.po-email { white-space: pre-line;
padding: var(--space-4); border: 1px solid var(--border); border-radius: var(--radius-card); }`. Never a literal white
or a value from `design-system/canvas*` (MASTER §7.16: `--surface` and `--border-strong`). Every token named here
exists in `tokens.css` (`--surface` :6, `--border-strong` :12, `--space-4` :136, `--space-6` :138, `--radius-card`
:144; `--border` is used by `purchase-orders.css:5`). The `1px` border width is MASTER's hairline (§1 principle 1,
"1px lines"; `tokens.css` has no border-width token and every existing rule, e.g. `purchase-orders.css:5`, writes
`1px`): it is the one literal allowed. No new `@media` rule: on a 375px viewport the lines table scrolls inside its own container, never
the page.
