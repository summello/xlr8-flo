# E23-S13 — Scorecard rounds come from the round files; void rounds are not charged; older records are marked

**Epic** E23 · **MT** · **chore/S** · tags: none · new story (planner agreed option A, 22 Oct 2026, with two refinements) · **land after E22-S12** (a roadmap dependency; no file overlaps, the order is the planner's)

## Why

Routing decisions are made from `agents/SCORECARD.md` (`agents/claude.md` §5), and its author columns ("Clean merge", "Mean rounds", the score) rest on each record's `rounds`. That number cannot be trusted:

- In this repository the only code that has ever written `task.json["rounds"]` is `flo escalate` (since the initial commit), and the scorecard records that value plus 1. No skill, script or the supervisor increments it.
- Six records carry the per-reviewer review count that `record_score` has stored since 21 Oct. All six say `rounds: 1`; their reviewers actually ran 2, 2, 2, 1, 7 and 6 times (E22-S10: 7, E22-S04: 6). They agree in 1 of 6.
- Every Sonnet record with `rounds` above 1 predates that change, and their values have no known writer.
- Some of those review runs are reviewer failures (a Codex review that hit its call cap and left a draft), which must not be charged to the author. Example: E22-S02 round 3 sent the author an empty findings list.

The supervisor already counts the right thing: `flo_facts.rounds_done()` over `.scratch/<STORY>.roundN.md`, one file per `changes_requested` round, used to cap rounds at 3. The scorecard should use the same source.

## Design

### 1. `rounds` comes from `flo_facts.rounds_done()`

In `record_score` (`agents/scripts/flo`), compute from `.scratch` (names listed once):

- `done = rounds_done(names, sid)` (reuse it; do not write a second counter).
- `void = void_rounds(texts)` over the story's round files.
- `rounds = max(1, done - void + 1)`. A story with no round files has `rounds: 1`.

New record fields (alongside the existing ones, which do not change):

| Field | Meaning |
|---|---|
| `rounds` | rounds that sent itemised findings back to the author, plus 1 |
| `void_rounds` | round files with no itemised findings; not charged |
| `escalations` | `task.json["rounds"]`, which from now on means **`flo escalate` runs only** |
| `review_runs` | `{reviewer: n}`, the existing per-reviewer `reviews` count, exposed at the top level |
| `rounds_basis` | the string `"round_files"`; marks a record whose `rounds` is trustworthy |

`flo escalate`'s message reads "escalation N", not "round N"; its code comment says what the key now means. The key name in `task.json` stays `rounds` because `flo_delivery.py` copies it to the delivery snapshot; the snapshot field is out of scope here.

### 2. Void rounds (`agents/scripts/flo_facts.py`)

- `is_void_round(text)`: true when the file has no numbered finding line (`^\d+\. \(`, multiline), which is exactly what `round_file()` writes for an empty findings list. `void_rounds(texts)` counts them. Both pure.
- **A `changes_requested` verdict with no findings can no longer start a round.** `verdict_state` returns `"malformed"` for it (it returns `"changes"` only when `findings` is non-empty). Not `"missing"`: the planner suggested relaunching the reviewer, but the supervisor has no attempt counter for reviews, so a reviewer that keeps writing an empty verdict would be relaunched every tick, burning the Codex cap. `"malformed"` is a state both the deployed supervisor and the tracked copy already handle: it asks the operator ("a verdict file is malformed: fix the JSON or rerun that reviewer"). The void round never happens, nothing loops, and the deployed copy needs no update to stay safe. Auto-retry once is a follow-up that needs an attempt counter in the supervisor.

### 3. Mark the older records, rewrite none

`render_scores` (and `compute_scores`):

- Each agent's author row gets a **"Rounds verified"** column: `verified/authored`, where verified means `rounds_basis == "round_files"`.
- When any authored record lacks the marker, a **Data quality** block at the top says: N of M records took `rounds` from a counter with no reliable writer (before E23-S13, 22 Oct 2026); "Clean merge", "Mean rounds" and the author score include them and are indicative only until "Rounds verified" reaches the agent's full count; the records are not rewritten. No block when every record is verified.
- The formulas do not change. "How these are computed" defines `rounds` and `void_rounds`.
- Regenerate `agents/SCORECARD.md` (`flo score`); CI fails on drift.

### 4. Docs

`docs/ops/fleet-tooling.md`: a section on what `rounds` means now, with the six-record evidence. Update `docs/ops/sonnet-round-churn.md` row 2 to say no skill or script writes `rounds`, that the 6 post-21-Oct records all say 1, and that the A/B must read `rounds_basis: "round_files"` records only.

## Acceptance criteria

- [ ] For a fixture with round files 1 and 2 (2 void), `record_score` writes `rounds: 2`, `void_rounds: 1`, `escalations` from `task.json`, `review_runs`, `rounds_basis: "round_files"`.
- [ ] With no round files, `rounds: 1`.
- [ ] `is_void_round(round_file(...))` is true for an empty findings list and false with one finding.
- [ ] `verdict_state`: `changes_requested` with findings → `changes`; with `[]` or no `findings` → `malformed`; `approve` and the stale/missing cases are unchanged.
- [ ] `render_scores` shows the Data quality block and the verified column when a legacy record exists, and shows neither block nor mismatch when all records are verified.
- [ ] Existing records in `agents/scorecard.json` are byte-identical; `SCORECARD.md` is regenerated and `flo score --check` passes.
- [ ] The existing `test_verdict_state` case for a bare `changes_requested` is changed on purpose to carry a finding, and a new case pins the empty one.

## Plants

1. Make `verdict_state` return `changes` for an empty list: the new case must fail.
2. Count void round files as rounds: the `record_score` test must fail.
3. Drop `rounds_basis` from new records: the verified-column test must fail.
4. Skip the Data quality block: the render test must fail.
5. Rewrite an old record in `record_score`: the byte-identical test must fail.
