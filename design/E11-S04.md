# E11-S04 — Tax and banking data: field-level access, masking, audited reveal

**Epic** E11 · **M3** · **security/M** · after **E11-S01**, **E02-S05** · tags: `security`, `auth` (Opus review)

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.
> **Decisions:** canvas DECISIONS 124 (6h-4) and 136, `design-system/pages/vendors.md` §2 "Tax and
> banking are masked by default". Back end only; the masked-value UI is E11-S13.
> **Writes:** every `PATCH`/`PUT`/`DELETE` on an editable resource follows `docs/m2-conventions.md` §O (`If-Match` with the integer version, `ETag` on reads, 400 when missing, 409 `stale_version` on mismatch). `Idempotency-Key` protects **POST** commands only (the middleware ignores other methods); where a packet says "(Idempotency-Key)" on a non-POST route, read §O instead.
> **RLS:** every new tenant table gets literal `ALTER TABLE <t> ENABLE ROW LEVEL SECURITY; … FORCE …; CREATE POLICY tenant_isolation ON <t> …` statements in the migration text, one block per table, never generated by a helper or f-string (the static gate in `tests/isolation/test_ci_guards.py` reads the text; the light check runs it).

## Requirements (inlined)

- **VEN-014** — Sensitive vendor data, including tax and banking information, must receive field-level access control and masking where appropriate.
- **CUS-008** — Sensitive custom fields must support field-level authorization and exclusion from exports/logs.
- **PRIV-001** — Collect only personal and sensitive data required for stated business purposes.
- **AUD-006** — Secrets, passwords, raw tokens, session identifiers, sensitive banking data, and unnecessary personal information must not be written to logs.

## Design

**One table, one door.** `vendor_sensitive` (RLS) holds `vendor_id` (PK with `org_id`),
`tax_id text NULL`, `tax_id_country char(2) NULL`, `bank_account_name text NULL`,
`bank_account_number text NULL`, `bank_routing text NULL` (IBAN/SWIFT/sort code, free text ≤ 64),
`updated_by` and `updated_at`. Nothing else in the codebase selects these columns: the vendors repo
exposes exactly two readers, `masked(vendor_id)` and `reveal(vendor_id)`. Add a test that greps the
`src/` tree and fails if any other file names `vendor_sensitive` or `bank_account_number`.

**Masked form:** each value becomes `•••• ` plus its last four characters (`•••• 4821`), or `null`
when unset. Values of four characters or fewer are fully masked (`••••`). The mask is computed in
SQL (`right(col, 4)`), so the full value never enters the Python process on the masked path.

**Who may reveal (decision 6h-4):** a new permission `vendor.sensitive.reveal`, added to
`PERMISSION_CODES` and granted by migration (pattern: `migrations/20261014_0053_baseline_role_catalogue.py`)
to `vendor-manager` and `budget-finance-user` (finance). It is **not** granted to `auditor`, and
`organization-administrator` gets it only through the existing "every code" rule. `tests/authz/test_catalogue_gate.py` must pass.

**Who sees the masked form:** holders of `vendor.view`. Everyone else gets the field omitted, with
`"restricted": true`, and the response names who to ask (the vendor-manager role label, not people).

**Reveal is an audited read:** `POST /vendors/{id}/sensitive/reveal` (Idempotency-Key not needed,
since it is not state-changing, but it **is** a POST so it is never cached or prefetched), body
`{fields: ["tax_id" | "bank"], reason?: string}`. It writes an audit row `vendor.sensitive.reveal`
with the actor, the vendor, the **field names** (never values) and the time, then returns the
values with `Cache-Control: no-store`. The web re-mask timer is UI (60 s, open question 7.3).

**Write:** `PUT /vendors/{id}/sensitive` (Idempotency-Key), with `vendor.edit` **and**
`vendor.sensitive.reveal`. A user who cannot see the values cannot overwrite them blindly. The
audit row records which fields changed, never the values (AUD-006).

**Exclusion everywhere else:**
- `GET /vendors` and `GET /vendors/{id}` carry the masked form only.
- The vendor export (when built) and the import templates exclude these fields.
- Audit snapshots are allowlist-based (`kernel/audit/redact.allowlisted_snapshot`). Never add these
  columns to any allowlist. There is no log redaction layer (`kernel/logging.py`), so the defence is
  that the values never reach a logger. The log-capture assertion below proves it.
- `tax_id` is **not searchable** (pages/vendors.md §3.1). E11-S06's duplicate check compares inside
  the repo and returns only the matching vendor id.

**No encryption-at-rest change in this story.** Neon encrypts storage; per-column encryption is a
ponytail with a stated trigger: `# ponytail: plaintext columns behind one repo door; add envelope
encryption (kernel/identity/mfa.py's key handling) if a customer contract requires column-level
encryption`.

## Acceptance

- [ ] Migration up, down and data preservation, including the grants (down removes only what up added; follow the 0053 tracking-table pattern **with RLS enabled on the tracking table**, per E22-S04 item 6).
- [ ] **Masking test with a planted violation:** seed a vendor with a known tax id and account number; assert neither full string appears in the list response, the detail response, the captured log output of both requests, or the audit table. Then plant `SELECT tax_id` into the detail query and watch the test fail.
- [ ] Reveal: a vendor-manager and a finance user get values and an audit row naming the fields; an auditor, a sourcing-specialist and a requestor get 403. The response carries `Cache-Control: no-store`.
- [ ] Write: `vendor.edit` without reveal → 403; with both → 200, and the audit row has field names only.
- [ ] The repo-door grep test exists and fails when a planted second reader is added.
- [ ] TEN-010: another tenant's vendor → 404 on reveal and write.
- [ ] Authorization test per role, including that the UI-hidden reveal is refused by the server.
- [ ] `flo check` green.

## Plants

1. Return the full value on the detail route: the masking test fails.
2. Grant reveal to `auditor`: the per-role test fails.
3. Log the reveal response body: the log-capture assertion fails.

## Files
