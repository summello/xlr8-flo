# E04-S02 — App shell: nav, breadcrumbs, command palette, focus management, skip links

**Epic** E04 · **M0** · **ui/L** · after **E04-S01** · tags: `ui`

## Requirements

- **UX-001** — The UI must provide consistent navigation, breadcrumbs, page titles, action placement, and terminology.
- **XFN-010** — A command palette should provide keyboard-first navigation and permitted actions.
- **A11Y-002** — All functions must be operable by keyboard with visible, unobscured focus and logical focus order.

## Deliverable

The frame every screen renders inside, and the keyboard spine of the product.

## Behaviour

1. **Layout** per `design-system/MASTER.md` §5: 240 px sidebar, 52 px header, responsive collapse to a 56 px icon rail at 768–1023 px and an overlay drawer below 768 px. The page body **never** scrolls horizontally at any width.
2. **Sidebar groups modules by lifecycle phase** — Foundation, Plan, Demand, Commit — with the phase accent on the nav icon and the active indicator only. Never on a control, a row, or a number.
3. **Command palette (XFN-010)** — ⌘K / Ctrl+K from anywhere, **with zero open animation**. A power user presses it forty times a day; 200 ms each time is 8 seconds of waiting per day for decoration.
   - Grouped Records / Actions / Navigation, fuzzy match with highlighting, arrow-key navigation, recents when empty
   - **Only permitted actions appear** — the palette filters by the caller's permissions, so it never advertises something that will 403
   - Palette entries and keyboard shortcuts come from **one registry**, so what you see teaches the shortcut
   - Destructive commands require an explicit modifier
4. **Focus management (A11Y-002)**
   - Skip-to-content link, first in the DOM, visible on focus
   - On route change, focus moves to the main landmark and the new page title is announced (`focus-on-route-change`)
   - `Esc` closes only the topmost layer and returns focus to whatever opened it
   - No keyboard traps; tab order matches visual order
   - Focus ring is the token-defined 2 px ring plus soft glow, never removed, never clipped by `overflow: hidden`
5. **Breadcrumbs** reflect real hierarchy (organization → BU → project → sub-project → document) and every segment is a link.
6. Landmarks: `nav`, `main`, `aside`, `header`, each labelled.
7. Reduced motion honoured; nothing in the shell conveys state by motion alone.

## Acceptance criteria

- [ ] Every shell function is reachable by keyboard alone, with a visible focus ring throughout
- [ ] ⌘K opens with **no** animation — asserted by a test that the palette is interactive within one frame
- [ ] The palette omits actions the current user lacks permission for
- [ ] A shortcut shown in the palette actually performs that action
- [ ] Skip link is the first focusable element and jumps to `main`
- [ ] Route change moves focus to `main` and announces the title to a screen reader
- [ ] `Esc` inside a dialog inside a sheet closes the dialog only, then the sheet, returning focus each time
- [ ] No horizontal page scroll at 375 / 768 / 1024 / 1440
- [ ] Sidebar collapses to a rail at 768 and a drawer below it
- [ ] axe passes on the shell in both themes
