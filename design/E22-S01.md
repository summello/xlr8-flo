# E22-S01 — Create Project with budget: form and Excel, sponsors, approval

**Epic** E22 · **M3** · **engine/L** · after **E09-S17** · tags: `money`, `auth`, `ui`

> Decisions: `design/E09-S13.md` decision 5 (D-M2-20). User guide: "Where budget comes from".

## Why
Projects are created today without any budget (`ProjectService.create`, `modules/projects/service.py:224`);
allocation is a separate endpoint the UI never calls, and the import has two separate templates. The
operator wants one role-gated Create Project flow that sets the budget, names sponsors and goes through
the project approval workflow.

## Design
- `ProjectCreate` gains `budget: {amount, currency}` (optional for a draft, required to submit) and
  `sponsor_ids` (1..10, required to submit; uses E09-S15's `project_sponsor`).
- Standalone project (no parent): on final project approval, a direct `allocation` of the amount.
  Child project: on approval, a transfer from the main project (`post_legs`), funds checked under the lock.
  Both inside the approval decision transaction (`ProjectService.approval_outcome`), entries on the project
  and, for a child, on the main project.
- Permission: `project.create` to draft, `project.submit` to submit; gating by the published `project` workflow (E09-S17).
- Excel: the `projects` template gains `budget_amount` and `sponsor_emails`; a row creates a draft and
  submits it, so allocation happens on approval; `budget_allocations` stays for top-ups as allocation requests (E09-S17).
- UI: the Create Project form adds amount, main project (optional), sponsors; shows the funds check for a child.

## Acceptance
- [ ] Standalone and child projects: on approval, ledger entries as above, drift empty; rejection posts nothing.
- [ ] Child creation refuses when the main project lacks funds (nothing written); concurrency: two children against one main, one wins.
- [ ] Without `project.create` → 403; TEN-010 case; import row errors listed per row.
- [ ] Playwright + axe + keyboard path for the form.
