## Requirements (inlined)

- **SRC-002** — An RFQ must contain items/services, quantities, specifications, delivery requirements, response deadline, terms, attachments, and invited vendors.
- **SRC-011** — Evaluators must be able to score qualitative and quantitative criteria with comments and conflicts-of-interest declarations where configured.

- **`Evaluation Criteria`** on `/sourcing/rfqs/:id/edit` (draft only; on `amend` the card is
  read-only, since criteria are edited only while the RFQ is `draft`, E12-S07). Rows of `name`
  (1..120) and `weight` (1..100), add, remove and reorder (with `Move Up`/`Move Down` buttons, no

  The page shows **no** weight total: `CriteriaRead` carries none (`sourcing/evaluation.py:50`) and the
  page computes none. The server's signal is E12-S07's 422 `weights_total` at publish, shown through
  E12-S13's error summary. Record "add `weights_total` to `CriteriaRead`" in `notes.followup`.
- **`Evaluators`** on both `edit` and `amend` (so `draft` and `published`, the editor's states,
  `editor/Editor.tsx:27`; managing them while `closed`/`under_evaluation` is a `notes.followup`): the

## Decisions (operator, 27 Oct 2026; was B1)

- **Evaluator picker:** this story adds one read route, `GET /api/v1/sourcing/rfqs/{id}/evaluators/eligible`
  (`rfq.edit` on the RFQ's unit; tenant-scoped, a foreign RFQ is 404). It returns the active
  identities holding `rfq.view` on that unit and not already on the RFQ, as `{identity_id,
  display_name, email}`, paged and searchable by name (two characters minimum). It lives in
  `api/sourcing.py` and the sourcing service (a router holds no logic). The picker uses it and posts
  the chosen `identity_id`. It gets a TEN-010 isolation case and an authorization test per role.
  Regenerate the API client.

- **Inactive identities (pre-flight 27 Oct, small in-scope API change):** `POST …/evaluators`
  (`api/sourcing.py:495-507`) checks only `rfq.view` grants (`granted_scopes`), not
  `identity.status`. `EvaluationService.add_evaluator` also refuses an identity whose
  `identity.status <> 'active'` with the existing 422 `not_eligible`, in the service (the predicate
  `status = 'active'` as `approvals/eligibility.py:143`), not the router. A pytest case: a
  deactivated identity holding `rfq.view` → 422, no `rfq_evaluator` row.

## Plants

1. Render a computed weight total: the assertion that no total is shown fails.
2. Allow criteria edits on `amend`: the read-only assertion fails.
3. Drop the `identity.status` check: the deactivated-identity test fails.
4. Keep the stale `edit_revision` after a criteria save: the save-criteria-then-draft test fails 409.
