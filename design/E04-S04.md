# E04-S04 — OpenAPI to TS client generation, forms kit, a11y harness (axe + keyboard) in CI

**Epic** E04 · **M0** · **ui/L** · after **E04-S03, E03-S03** · tags: `ui`

## Requirements

- **A11Y-001** — The responsive web application must conform to WCAG 2.2 Level AA across complete supported workflows.
- **A11Y-006** — Forms must have programmatic labels, instructions, field-level errors, an error summary, and preserved input after validation failure.
- **A11Y-010** — The application must honor reduced-motion preferences; core information must not depend on animation.
- **XFN-008** — Every screen must provide contextual field help through accessible tooltips or equivalent help text.

## Deliverable

Three things that must exist before any feature story, or every feature story reinvents them badly: the type bridge across the Python/TypeScript split, the form primitives, and the accessibility gate.

## Behaviour

### 1. Generated client — the type bridge

`openapi-typescript` + `openapi-fetch`, generated from the live OpenAPI document into `apps/web/src/api/generated/`. **Hand-writing a request or response type is a review rejection.** CI regenerates and fails on any diff — already wired. Errors come back typed as the RFC 9457 problem shape from E03-S03, and `errors[]` maps to form fields automatically.

### 2. Forms kit (A11Y-006)

React Hook Form + Zod schemas derived from the generated types. Every field primitive ships with:
- a **visible** `<label>` — placeholder is never the label
- required marked with `*` **and** `aria-required`
- persistent helper text below the field that does not vanish on focus (XFN-008)
- validation **on blur**, not per keystroke
- error below the field with an icon, `aria-describedby`, `aria-invalid`, stating cause **and** fix — "Invalid input" is a defect
- on submit failure: an error summary at the top with anchor links, focus moved to the first invalid field, **and every entered value preserved**
- `inputmode` and `autocomplete` set correctly so mobile keyboards and password managers work

### 3. Accessibility harness

- `@axe-core/playwright` runs against every route in **both themes**; any violation fails CI
- A keyboard-only Playwright path per critical flow — no mouse events permitted in the test
- A reduced-motion run asserting no information is lost with motion disabled (A11Y-010)
- **The harness must fail on a seeded violation.** A test that has never failed is not a test: commit a deliberate contrast violation, prove CI goes red, revert it, prove CI goes green, and link both runs in the PR.

## Acceptance criteria

- [ ] Editing an API schema and not regenerating fails CI
- [ ] A 422 from the server maps to the correct form field without hand-written mapping
- [ ] Every field primitive has a visible label, persistent helper text, and blur validation
- [ ] Submitting an invalid form focuses the first invalid field and preserves **all** entered values
- [ ] The error summary anchors jump to their fields
- [ ] axe passes on every route, in light and dark
- [ ] A seeded contrast violation fails CI, and reverting it passes — evidence linked in the PR
- [ ] The keyboard-only test completes a full form submission with zero mouse events
- [ ] With `prefers-reduced-motion`, no information is conveyed only by motion
