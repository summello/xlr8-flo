# E04-S03 — Data grid: TanStack Table, virtualization, server filter/sort, saved views, grid semantics

**Epic** E04 · **M0** · **ui/L** · after **E04-S02** · tags: `ui`

## Requirements

- **XFN-002** — Module grids must support sorting, filtering, resizing, reordering, visibility, pinning where useful, pagination/virtualization, and saved views.
- **XFN-003** — Grid and dashboard preferences must be saved per user without altering shared records.
- **PERF-005** — Pagination, server-side filtering, and/or virtualization must prevent large datasets from being loaded into the browser unnecessarily.
- **A11Y-008** — Grids must expose meaningful table/grid semantics and offer efficient keyboard navigation.

## Deliverable

The most-used surface in the product. Eleven modules render through it, so its keyboard model and its density are the product's ergonomics.

## Behaviour

1. **Server-driven state (PERF-005)** — sort, filter, and pagination are URL search params, resolved on the server. The client never receives an unfiltered dataset. Cursor pagination, page size 50.
2. **Virtualization** via `@tanstack/react-virtual` above 50 rows. Row height is the token `--row-h` (40 px comfortable / 32 px compact), fixed so the virtualizer does not measure.
3. **Density toggle** — Comfortable / Compact, persisted per user (XFN-003) in preferences, not in the shared record.
4. **Semantics (A11Y-008)** — a real `<table>` with `<th scope="col">`, `aria-sort` on every sortable header reflecting current state, `aria-rowcount`/`aria-rowindex` correct **against the full server-side count**, not the virtualized window. A virtualized grid that reports only rendered rows lies to a screen reader.
5. **Keyboard model** per `design-system/MASTER.md` §7.3: arrows move cell, `Home`/`End` row ends, `Ctrl+Home`/`Ctrl+End` grid ends, `Space` selects, `Enter` opens the record sheet, `/` focuses filter. Focus follows the virtualizer — scrolling to a focused row must not lose it.
6. **Column controls (XFN-002)** — resize, reorder, hide, pin left. All operable from a keyboard-reachable menu, not drag-only (A11Y-003).
7. **Saved views** — named filter + sort + column + density sets. Personal by default; publishing a shared view is a separate permission (E15-S07 governs shared).
8. **Four states, all designed** (UX-004): skeleton rows at **exact** final height so there is no layout shift; empty with a phase-tinted glyph, one sentence and one action; partial (loading more); error inside the grid frame with cause and retry.
9. **Numeric columns** right-aligned, mono, tabular figures, slashed zero. Negative amounts in parentheses and coloured (`MoneyCell` arrives with E07, but the column primitive is defined here).
10. No zebra striping — a 1 px `--border` between rows, which is quieter and survives dark mode.

## Acceptance criteria

- [ ] A 10,000-row fixture renders and scrolls at 60 fps with fewer than 60 row nodes in the DOM
- [ ] Sorting and filtering issue a server request; the client never holds the unfiltered set
- [ ] `aria-rowcount` equals the **server** total, not the rendered count
- [ ] `aria-sort` reflects the true sort state on every sortable header
- [ ] Full keyboard path: reach the grid, move by cell, select, open the sheet, return focus to the originating row
- [ ] Focus survives virtualized scrolling
- [ ] Column resize, reorder, hide and pin are each achievable without a mouse
- [ ] Density toggle persists per user and changes no shared record
- [ ] Skeleton rows occupy exactly the final height — measured CLS < 0.1
- [ ] Empty, error and partial states all render as specified
- [ ] axe passes; NVDA or VoiceOver announces row and column position correctly
