- **VEN-005** — Vendor creation, activation, scope changes, suspension, and reactivation must support approval.

## Design

A **variant** of the shared decision panel (E10-S10, as reflowed by E11-S10), not a second approval
UI. For `document_type = "vendor"`, the panel inserts an **Onboarding Evidence** block between the
key facts and the Decision Trail (DECISIONS 65). It renders from the adapter's `snapshot` (E11-S06),
never from extra calls:
- **Create:** the score against the threshold as a `Signal` (`62 of 100, below the threshold of 70`, a fact; **Approve stays enabled**, decision 6h-6); the per-question breakdown behind a closed fold, with weights; the duplicate result as a link to the matching vendor with the matching identifier shown masked, and any override reason; documents with verification, and missing required documents as rows.
- **Availability, suspend, reactivate:** the change (old and new units for availability), the reason, and counts of open RFQs and issued POs (0 until E12/E13).
- `Open the full vendor` links to `/vendors/:id`.

**The footer is not touched** (E11-S10 owns it). The variant registers through the panel's existing
per-document-type extension point. If none exists, add the smallest slot in `DecisionPanel.tsx`
that renders an evidence component by `document_type`, and make no other change to the panel.

## Amendment, 22 Oct 2026 (operator; canvas DECISIONS 235)

The author found no endpoint returns the vendor evidence to the web: `VendorChangeAdapter.snapshot()` puts it in
`DocumentSnapshot.material['evidence']`, but `InstanceRead` and every `/api/v1/approvals/*` response omit it. Rule
(decided):

- Add `evidence: dict | None` to `InstanceRead` (`modules/approvals/schemas.py`), filled from the adapter snapshot's
  `material.get("evidence")` by the approvals service, not the router (AGENTS.md 3.3). `None` for adapters that
  supply none. No new endpoint, no extra call from the web.
- Guard: unchanged. `GET /api/v1/approvals/instances/{id}` already requires `adapter.read_permission` on the
  document (`vendor.view` for vendor changes). Foreign tenant or unreadable instance stays 404.
- Sensitive fields: any sensitive vendor field in `evidence.payload` is masked with the vendors module's existing
  masking (the same values `GET /vendors/{id}` returns), done inside the vendors module before the evidence leaves
  it. Never raw; revealing stays `POST /vendors/{id}/sensitive/reveal` (audited).
- Regenerate the API client; the panel reads `instance.evidence`.

**Scope change:** `modules/approvals/schemas.py`, the approvals service's instance read, `modules/vendors/changes.py`
(`evidence` masking) and the generated client are now **in** scope for exactly this. Acceptance gains: a viewer
with `vendor.view` sees evidence on the instance; a caller without it gets 404 for the instance; a create change
whose payload carries a sensitive field returns it masked, never raw; a non-vendor adapter's instance has
`evidence: null`. Plants: return the raw payload, the masking test fails; drop the read guard, the 404 test fails.
E11-S10 is merged into this story's base (`da66786`); the DecisionPanel reflow is there.
