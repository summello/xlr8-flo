# E12-S03 — RFQ lifecycle: publish, versioned amendments told to every invitee, deadline, close

**Epic** E12 · **M3** · **engine/M** · after **E12-S02** · tags: none

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.
> **Decisions:** canvas DECISIONS 154 (amended, never edited), **207 (6i-12: publishing needs no
> approval)**, **206 (6i-11: the requisition becomes `sourced` when every open line is on a published
> RFQ)**, the Resend 100/day ceiling (project memory: transactional sends go immediately; RFQ
> invitations are transactional). `design-system/pages/sourcing.md` §2 "After publication, changes
> are versions". Back end only; UI is E12-S11 and E12-S13.
> **Writes:** every `PATCH`/`PUT`/`DELETE` on an editable resource follows `docs/m2-conventions.md` §O (`If-Match` with the integer version, `ETag` on reads, 400 when missing, 409 `stale_version` on mismatch). `Idempotency-Key` protects **POST** commands only (the middleware ignores other methods); where a packet says "(Idempotency-Key)" on a non-POST route, read §O instead.

## Requirements (inlined)

- **SRC-004** — RFQs must support Draft, Published, Closed, Under Evaluation, Awarded, and Cancelled states.
- **SRC-005** — RFQ versions and changes after publication must be retained and communicated to all affected invitees.
- **REQ-005** — the requisition lifecycle includes Sourcing in Progress → Sourced (trigger per decision 206).

## State machine (this story: draft → published → closed → under_evaluation)

| From | Action | Permission | To | Notes |
|---|---|---|---|---|
| `draft` | publish | `rfq.edit` | `published` | ≥ 1 line, ≥ 1 invitee, deadline ≥ now + 1 h, every invitee has a recipient. Each failure → 422 with every problem listed. **No approval** (decision 207). |
| `published` | amend | `rfq.edit` | `published` (version + 1) | Reason required. |
| `published` | extend deadline | `rfq.edit` | `published` (version + 1) | Later only; an earlier date → 422 `deadline_earlier`. |
| `published` | (deadline passes) | system | `closed` | The cron tick (`api/internal.py`, a `rfq-close` job each minute) closes due RFQs, idempotent per RFQ. |
| `closed` | start evaluation | `rfq.edit` | `under_evaluation` | |

`awarded` is E12-S08 and `cancelled` is E12-S09. Every other transition → 409 `invalid_transition`.
A state-machine test covers every pair.

## Versions (SRC-005)

`rfq_version`: `rfq_id`, `version int`, `snapshot jsonb` (lines, content, requirements,
vendor-visible attachment ids and versions, deadline), `reason text NULL` (NULL for v1),
`diff jsonb` (field-level `was`/`now` vs the previous version, computed by the server),
`published_by`, `published_at`. Immutable (the append-only trigger set). **A published RFQ is never
edited in place:** amend takes a body of the same shape as the draft edits, applies them to a
new version under `SELECT … FOR UPDATE` on `rfq`, and records the diff. Lines in an amendment may
change quantity only through E12-S01's `source_lines` (same guard, same transaction).

## Telling invitees

On publish and on every amendment, for each invitee contact, **one outbox email** (never sent from
the request) with the version's content and the vendor-visible attachments, idempotency key
`rfq:{id}:v{version}:{contact_id}`. `rfq_invitee_version(rfq_id, vendor_id, contact_id, version,
outbox_id, state)` records who was sent which version. `state` follows the outbox (`queued`, `sent`,
`bounced`, `failed`). The detail returns, per invitee, the latest version sent and `not_told_of`
(versions with no `sent` row). A bounced contact can be changed (E12-S02 `PATCH /invitees`) and
**re-sent the same version** with `POST /invitees/{vendor_id}/resend`.

## Requisition `sourced` (decision 206)

At publish, in the same transaction: for each requisition on the RFQ, if every non-cancelled line has
`sourced_qty = quantity − cancelled_qty` **and** every RFQ holding its lines is published or later,
move it `sourcing_in_progress → sourced` through a new `requisitions.service.mark_sourced(conn,
scope, requisition_id, actor_id)`. That function owns the rule and the check, and is audited as a
requisition status change. The reverse (a draft RFQ line added later) never happens: a `sourced`
requisition has no open quantity.

## Acceptance

- [ ] State machine: every valid and invalid pair.
- [ ] Publish refusals list every problem at once; publish needs no approval even when an `rfq` workflow exists.
- [ ] Amend: v2 has a diff with `was`/`now`; v1 is unchanged (a raw UPDATE raises); each invitee contact gets one outbox row for v2; a retried amend request (same Idempotency-Key) creates no second version.
- [ ] Extend earlier → 422; later → new version and emails.
- [ ] Close job: an RFQ past its deadline closes once; running the tick twice changes nothing more.
- [ ] `mark_sourced`: a requisition with all lines on published RFQs → `sourced`; one line still on a draft RFQ → stays.
- [ ] No email is sent from a request handler (the outbox assertion).
- [ ] TEN-010 and authorization per role on every route.
- [ ] `flo check` green.

## Plants

1. Edit the published row in place on amend: the immutability test fails.
2. Send email in the handler: the outbox assertion fails.
3. Let the deadline move earlier: the 422 test fails.
