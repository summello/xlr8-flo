# E12-S21 — Comparison engine follow-up: selection totals, amount to spare, late override, counts

**Epic** E12 · **M3** · **engine/M** · after **E12-S06** · tags: `money` (Opus review)

> **Why (operator, 27 Oct 2026, E12-S10 `## Decisions`):** E12-S10's page computes no figure, and
> E12-S06's response lacks figures the page shows. This story adds them to the server; it changes no
> existing field and no existing figure.
> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.
> **Spec for the values:** `design-system/pages/rfq-comparison.md` §2 (late, exceptions), §3 (scope
> pill, not-lowest line, requirements line), §4 (`In This Selection`), §5 (`Show Only Differences`).
> Back end only; no migration; no new route; no permission change.

## Requirements (inlined)

- **SRC-009** — The comparison dashboard must normalize and compare total cost, unit cost, tax, freight, lead time, compliance, vendor score, and configured criteria.
- **SRC-008** — A late bid is marked and included only through an audited override.
- **SRC-014** — A non-lowest-price award must require an explicit justification when configured.
- **SRC-016** — Award totals must not exceed approved requisition scope or available reserved funds without an approved amendment.

## Rules (all `Decimal`; rounding through `kernel/money.quantize`, as `comparison.py` already does)

All in `modules/sourcing/comparison.py`, inside `compute()` and `ComparisonService`; only
`ComparisonRead` gains fields. `SealedComparisonRead` is unchanged (`{sealed: true}` only).

1. **`VendorFigures`** gains:
   - `unmet: int` = `met_of − met`.
   - `late: BidLate | None` — the existing `BidLate` schema (`modules/sourcing/schemas.py:497`),
     filled from `bid.late_accepted_by`/`late_accepted_at`/`late_reason` exactly as
     `BidService._late` (`bids.py:217`) does; `null` for a bid on time. Read those columns in
     `_current_bids` (`comparison.py:435`). A submitted late bid always has an override (E12-S05), so
     `late` non-null ⇔ late and accepted.
   - `exceptions_count: int` = the number of non-blank lines in `bid.exceptions` (`str.splitlines()`,
     a line counts when `strip()` is non-empty); 0 when `exceptions` is null or blank. Planner
     rule, 27 Oct 2026: exceptions are free text and the page counts them (§2).
     `# ponytail: line count of free text; a structured exceptions list replaces it if vendors ever key one`.
2. **`Basis`** gains (both bases):
   - `to_spare: str | None` = `max(0, approved_scope − total)`, quantized like `over_by`; `null`
     when `total` is null. Exactly one of `over_by` and `to_spare` is non-zero, or both are zero.
   - `vendors: list[BasisVendor]`, `BasisVendor = {vendor_id, total: str, lines: list[UUID]}`, in
     `sent_at, id` order: each vendor in the selection with the lines it wins and its `In This
     Selection` total. Lowest Cost Supplier: per vendor, Σ `landed(line)` over the lines it wins
     (the same values `lcs_total` sums, `comparison.py:358`). Best Average Cost: the one vendor, with
     `total = best_priced.total` (unallocated freight included, as the basis total is). **Invariant:
     Σ `vendors[].total` = `total`, to the cent, for both bases** (no separate rounding).
   - `not_lowest_lines: list[UUID]` and `not_lowest_count: int`: the lines in the selection where
     the selected vendor's `landed(line)` is **strictly greater** than that line's lowest (the vendor
     `LineRow.lowest` names). A tie at the lowest is not "not lowest" (E12-S08 handles ties with
     `tie_override_reason`). For Lowest Cost Supplier this is empty by construction.
3. **`ComparisonRead`** gains:
   - `identical_lines: int` = the number of `LineRow`s with `identical = true`.
   - `identical_measures: list[str]` and `identical_rows: int` (its length): the keys, from the fixed
     list `landed_total, difference_from_lowest, price, tax, freight, lead_time_days, meets_need,
     met, unmet, score, exceptions_count`, whose `VendorFigures` value is equal across every vendor
     with `not_quoted = false`. With fewer than two such vendors, the list is empty.

## Acceptance

- [ ] Engine unit tests (`tests/sourcing/test_comparison_engine.py`), on a hand-built three-line, three-vendor example (one partial bid): for both bases, Σ `vendors[].total` = `total`; `to_spare` and `over_by` hand-computed (one case within scope, one over); `not_lowest_lines` for Best Average Cost lists exactly the lines where another vendor is strictly cheaper, and a tie at the lowest is not listed.
- [ ] `unmet`, `exceptions_count` (null, blank, three lines with one blank → 2), `identical_lines`, `identical_measures` (two vendors identical on `lead_time_days` only → `["lead_time_days"]`, `identical_rows = 1`).
- [ ] Service test (`tests/sourcing/test_comparison.py`, real Postgres): a late bid accepted by override shows `late` with the accepting person's name, time and reason; an on-time bid shows `late: null`.
- [ ] Sealed: before the deadline the response is still exactly `{sealed: true}` (none of the new fields leaks).
- [ ] Existing comparison tests pass unchanged (no existing field changes value).
- [ ] TEN-010: the existing foreign-RFQ 404 case still covers the route (no new route).
- [ ] `flo check` green, with the regenerated API client (`apps/web/src/api/generated/`).
