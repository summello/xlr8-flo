## Requirement (inlined)

- **SUP-005** — Administrator and operator documentation must be updated in the same PR as the feature it describes.

## Why

The live supervisor is Omnissiah's `flo-fleet` (state in `~/.claude/omnissiah/state/xlr8flo/`). `flo-monitor` already
reads fleet chatter and notifies sessions, but nothing counts repeat failure classes over time or records whether a
proposed fix was ever applied. Failures already seen by hand: four Opus reviews for one E11-S16 round, CI-fix commits
that marked verdicts stale and re-ran reviews, one step relaunched tick after tick. This story adds the counting and the
record, deterministically. A free-model summariser reads the digest later (a separate story); it is out of scope here.

## Inputs (read-only; never write under the state dir)

State dir default `~/.claude/omnissiah/state/xlr8flo`, overridable with `--state DIR`.

- `tick.log`: one line per tick,
  `YYYY-MM-DD HH:MM:SS paused=<bool> actions=[('E13-S08', 'review', 'codex'), ...] needs=<int> notes=[...]`.
  Parse `actions` with `ast.literal_eval` on the bracketed text; skip a line that does not parse and count it as `skipped`.
- `runs/<STORY>.<step>[.<reviewer>].json` and `.exit`: run records (`story`, `step`, `reviewer`, `started`, `attempt`);
  the `.exit` file holds the exit code. Records are overwritten per step, so they are evidence for the latest run only.

## Design

New `agents/scripts/flo_watch.py`, stdlib only, `python3 agents/scripts/flo_watch.py <command>`.

### 1. Detectors (pure functions over parsed ticks, each returns findings)

| id | flags | rule |
|---|---|---|
| `dup_review` | a reviewer launched twice for one story with no author/round step between | same `(story, 'review', reviewer)` in two ticks and no `resume`, `round`, `fix` or `submit` action for that story in between |
| `repeat_step` | one step relaunched tick after tick | same `(story, step)` in `>= 3` consecutive ticks |
| `repeat_note` | the same note on many ticks | note text with digits collapsed to `#` appears in `>= 5` ticks |

Each finding: `{detector, story (or null), first_tick, last_tick, count, evidence}` with `evidence` the first two raw tick lines.
Thresholds are module constants, not flags.

### 2. `digest [--state DIR] [--day YYYY-MM-DD] [--out DIR]`

Runs the detectors on ticks of that day (default today), writes `<out>/<day>.md` (default out `.scratch/watch`, created if
missing): totals (ticks, skipped lines, actions by step), then one section per detector with its findings, or `none`.
Idempotent: a re-run for the same day rewrites the file. A day with no ticks writes a digest saying so; it is not an error.

### 3. Proposals log: `.scratch/watch/proposals.jsonl` (append-only)

- `propose "<text>" --detector <id> [--story S]` appends `{id, ts, text, detector, story, status: "open"}`; ids are `P1`, `P2`, ...
- `resolve <id> accepted|rejected [--reason "..."]` appends a `{id, ts, status, reason}` row; rows are never edited.
- `stats` prints, per detector: proposals, accepted, rejected, open, acceptance rate (accepted / resolved; `n/a` when none resolved).
  The current status of an id is its latest row. `resolve` of an unknown id or an invalid status exits 2 with a message and writes nothing.

## Invariants

- Nothing under the state dir, `fleet.toml`, `agents/roadmap.yaml` or any story file is ever written or modified.
- No network and no model call. A malformed tick line never raises.
- `proposals.jsonl` is only appended to.

## Acceptance criteria

- [ ] A fixture `tick.log` with two `review codex` actions for one story and nothing between flags `dup_review`; the same
      pair with a `round` action between them does not.
- [ ] Three consecutive ticks with the same `(story, step)` flag `repeat_step`; two ticks, or three non-consecutive, do not.
- [ ] Five ticks with the same note differing only in digits flag `repeat_note`; four do not.
- [ ] A clean fixture yields `none` in every digest section.
- [ ] A malformed line is counted as `skipped` and the digest still renders.
- [ ] `digest --day` for a day with no ticks writes a digest that says so, exit 0.
- [ ] `digest` run twice writes identical content.
- [ ] `propose` then `resolve ... accepted` then `stats` shows acceptance rate 1.0 for that detector; `resolve` of an unknown id exits 2 and appends nothing.
- [ ] A test asserts the state-dir fixture is byte-identical before and after `digest`.
- [ ] `docs/ops/fleet-tooling.md` documents the three commands, the detector table and how to read `stats`.
- [ ] `flo check --light` green.

## Plants (prove each guard fails)

- Drop the "nothing between" condition from `dup_review`: the `round`-between fixture is flagged and the test fails.
- Make `repeat_step` ignore consecutiveness: the non-consecutive fixture is flagged and the test fails.
- Compare notes without collapsing digits: the digits-differ fixture is not flagged and the test fails.
- Let `digest` open `tick.log` for append: the byte-identical test fails.
- Let `resolve` rewrite an earlier row: a test that checks earlier rows are unchanged fails.
