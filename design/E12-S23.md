# E12-S23 — No zero-value lines: bids refuse them at the source, and the zero-price special cases go

**Epic** E12 · **M3** · **engine/M** · after **E13-S02** · before **E13-S05** · tags: `money`, `migration` (Opus review)

> **Why (operator, 28 Oct 2026, from the E13-S05 pre-flight):** a line with no quantity or no price means
> nothing on a purchase order, and storing one lets tax and freight proration drift. Every quantity is
> already `CHECK > 0` on requisition, RFQ, bid, award and PO lines, and a requisition line's unit price is
> `CHECK > 0`. The only way in is a **bid line marked quoted with unit price 0** (`bid_line.unit_price`
> is `CHECK >= 0`, and `_write_lines` only checks that a quoted line has a price). Stop it there, and the
> zero-price special cases downstream are dead.
> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.
> Back end only. No new route. One migration. Not in scope: the "No priced quote" reason and
> auto-cancel (E12-S24).

## Requirements (inlined)

- **SRC-006** — Vendor responses must capture line prices, currency, tax, freight, lead time, validity, exceptions, attachments, and submission timestamp. *(A captured line price must be a real price; a line not priced is recorded as not quoted.)*
- **FIN-009** — One rounding rule: amounts quantize per line through `kernel/money.quantize`.
- **Operator ruling (28 Oct 2026)** — A zero-value line (zero quantity, zero price, or an amount that rounds to zero) is never listed, stored or shown on a PO. A bid is refused gracefully, with the field named and the input kept.

## Design

1. **A quoted line must price above zero** (`sourcing/bids.py` `_write_lines`, ~151). For each quoted line, with `price = Decimal(unit_price)` and the bid's `currency`:
   - `price <= 0` → `ProblemFieldError(field=f"lines/{rfq_line_id}", message="Enter a unit price above 0, or leave this line not quoted.")`.
   - `quantize(price * quantity, currency) == 0` (the line rounds to 0.00 on this quantity; `quantity` is the answered RFQ version's, as `_quantities` returns) → `ProblemFieldError(..., message="This price rounds to 0 on this quantity. Enter a higher price, or leave this line not quoted.")`.
   Both collect into the existing `errors` list and raise through `_fail(errors)` (422 `invalid_bid`, one entry per line, all lines reported at once, nothing written, so the client keeps what the buyer typed). Only `patch` writes lines (`BidPatch.lines`, `bids.py` ~452 calls `_write_lines`): `capture` (`BidCreate` has no lines) and `replace` (it copies every line as **unquoted**) write none, so they need no price check; a replacement bid is priced through `patch` before it can be submitted, and rule 2 refuses it until it quotes a line.
2. **A bid must quote at least one line to be submitted** (`_before_submit`, ~113, and `replace`): no row of the bid has `quoted` → 422 `invalid_bid`, `ProblemFieldError(field="lines", message="Quote at least one line before submitting.")`. A draft may hold none.
3. **Migration** (reversible; the next revision at story start, renumbered at merge). `bid_line` carries append-only triggers (`bid_line_immutable`), so **no data is rewritten**, and the constraint is **validated**, so no zero-price row can survive to hit the allocation code removed in rule 4 (`Money.allocate` rejects an all-zero ratio list, `kernel/money.py` ~103):
   ```sql
   ALTER TABLE bid_line ADD CONSTRAINT bid_line_quoted_price_positive
     CHECK (NOT quoted OR unit_price > 0);
   ```
   A plain `ADD CONSTRAINT` validates every existing row and **aborts the upgrade** if one has `quoted` with a price of 0, with a clear error, rather than leaving a row that breaks the award later. Bids arrive in migration 0071 and are not on `main` (the latest there is 0055), so no production row exists; a development database holding such a row is reset (`flo db reset`). Downgrade: `ALTER TABLE bid_line DROP CONSTRAINT bid_line_quoted_price_positive;`.
4. **Delete the zero-price special cases** (each exists only because a zero price could arrive):
   - `sourcing/awards.py` `_quotes` (~301): the `if not any(ratios): ratios = [1] * len(lines)` branch.
   - `sourcing/comparison.py` (~244): the `if bid.quotes and not any(ratios)` equal-split branch and the `if any(ratios)` guard beside it. **Keep** the one-token `pct = ... if low else None` guard (~438: it only avoids a `ZeroDivisionError`, and a quoted vendor's total is now always above 0); **delete** `test_difference_pct_is_null_when_the_lower_total_is_zero` (`test_comparison_engine.py` ~225), which can no longer build its zero-price bid.
   - `purchasing/pricing.py` `spread` (~58): the all-zero equal split.
   After this, every ratio is `> 0`; keep `Money.allocate`'s own handling and add nothing in its place.
5. **A PO line cannot round to zero either**, on **both** pricing paths: creation (`purchasing/service.py` ~495, `landed(...)` for each chosen award line; an ordered quantity below the quoted one can round the line to 0) and the draft quantity edit (~657, `landed` again after the rescale): after the rescale, a line with `price = quantize(unit_price × quantity, currency) == 0` is refused 422 `validation-failed`, field `lines/{line_no}/quantity`, "This quantity is too small to price." (A quantity of 0 is already refused by `CHECK (quantity > 0)`; make sure that surfaces as the same 422, not a 500, and add the test.)

## Acceptance

- [ ] On `patch` (the only route that writes lines): a quoted line at price `0` and a quoted line whose `quantize(price × quantity)` is `0` (USD, price `0.001`, quantity `1`; and a JPY or 3-decimal currency case) each return 422 `invalid_bid` with the right field and message, nothing written; two bad lines report both. A `replace`d bid is all-unquoted and cannot be submitted until patched (rule 2).
- [ ] A line left `quoted = false` is accepted; a bid with no quoted line saves as a draft and is refused at submit with `lines` named.
- [ ] Direct SQL inserting `quoted = true, unit_price = 0` into `bid_line` fails the CHECK.
- [ ] Migration test (`tests/kernel/test_migrate.py`, up, down, data preservation, and the refusal): with a clean database the upgrade keeps a quoted row at price `1.0000` and an unquoted row untouched, a new quoted row at `0` then fails, and the downgrade lets it in again; with a quoted row at `0.0000` inserted **before** the upgrade the upgrade aborts (the database stays at the previous revision).
- [ ] The awards, comparison and `spread` tests built on zero-price bids are rewritten to positive prices (`test_comparison_engine.py` the zero-price line in scene C and `test_every_line_at_zero_price_splits_the_bid_freight_equally_over_the_quoted_lines`; `test_pricing.py` the all-zero `spread` case and `test_a_zero_price_bid_keeps_its_freight_through_the_award_to_the_po`); every other test fixture that keys a zero price is moved to a positive one. Each rewrite keeps its original intent (freight still shared pro rata by price; the award total still includes it).
- [ ] The three removed branches are gone (grep for the old comments finds nothing) and `flo check --light` is green with `mypy --strict`.
- [ ] PO **creation** from an award with an ordered quantity that rounds a line to 0 → 422 with the field, nothing written; PO **draft** quantity edit that rounds the line to 0 → 422 with the field; a quantity of `0` on either → 422 (not 500). Three separate tests.
- [ ] TEN-010: the existing foreign-RFQ 404 cases still cover the routes (no new route). Authorization unchanged.

## Plants

1. Remove the `price <= 0` check: the zero-price test fails.
2. Compare `price * quantity` without `quantize`: the rounds-to-zero test fails.
3. Drop the `_before_submit` quoted-line check: the empty-bid submit test fails.
4. Drop the CHECK from the migration: the direct-SQL test fails.
5. Skip the rounds-to-zero check on the creation path only: the creation test fails.
