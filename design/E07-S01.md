# E07-S01 — Ledger schema, append-only triggers, entry types, partitioning, source linkage

**Epic** E07 · **M1** · **migration/L** · after **E03-S01**, **E03-S04** · tags: `money`, `migration`

> **Conventions:** read `docs/m1-conventions.md` (authorization outcomes, scope targets, wire formats). It applies unless this packet says otherwise.

## Requirements

- **FIN-004** — Posted financial entries must be append-only; corrections use reversal and replacement entries.
- **FIN-007** — Each financial event must record organization, BU/OU, project, department, ledger account, source document, amount, currency, effective date, actor, and timestamp where applicable.
- **BUD-005** — The ledger must list allocations, reservations, commitments, actuals, releases, reversals, transfers, and adjustments.
- **BUD-006** — Every ledger entry must link to its source document or authorized manual action.
- **ARCH-003** — The budget ledger, stock movement history, audit trail, and approval decisions are append-only records.

## Design decisions (confirm on review)

- **D-M1-9 Every entry names the balance bucket it moves.** The plan's table gives `entry_type` and a signed `amount` "determined by entry_type". That makes the balance recompute a CASE expression that every future writer and the nightly job must keep in sync. Instead each row carries `bucket` (`allocated|reserved|committed|actual`) and a signed `amount`, so **balances are exactly `SUM(amount) GROUP BY bucket`** and the drift job (E07-S09) is one query. `entry_type` stays as the business meaning. Mapping, enforced by a CHECK:

  | entry_type | bucket | sign of amount |
  |---|---|---|
  | allocation | allocated | + (a reduction is an `adjustment`) |
  | transfer | allocated | + receiving leg, − giving leg |
  | adjustment | allocated | ±, `reason` mandatory |
  | reservation | reserved | + |
  | commitment | committed | + |
  | actual | actual | + |
  | release | reserved or committed | − |
  | reversal | the reversed entry's bucket | the negation of the reversed amount |

  `available = allocated − reserved − committed − actual` (E07-S02).
- **D-M1-10 No table partitioning in M1.** The roadmap title says "partitioning", but a partitioned table cannot carry a unique `(org_id, idempotency_key)` across partitions (the partition key must be in every unique index), which would break FIN-012. At the reference load (plan §2.3) and Neon's 512 MB cap an unpartitioned ledger is correct, and `audit_log` archival to R2 is the storage lever. Leave a `# ponytail:` comment on the table naming the ceiling (about 5M rows) and the upgrade path (partition by `effective_date` with a separate `ledger_idempotency` table).

## Contract

Migration (reversible): the next revision after the current head at story start (revision id `20260826_<next 4-digit number>`, `down_revision` = the head `python -m flo.kernel.migrate --check` validates today); stories merge one at a time, so there is no gap or fork:

```sql
CREATE TYPE ledger_type AS ENUM ('allocation','reservation','commitment','actual',
                                 'release','reversal','transfer','adjustment');
CREATE TYPE ledger_bucket AS ENUM ('allocated','reserved','committed','actual');
CREATE TABLE ledger_entry (
  id                BIGSERIAL PRIMARY KEY,
  org_id            uuid NOT NULL,
  bu_id             uuid NOT NULL REFERENCES org_unit(id),
  project_id        uuid NOT NULL REFERENCES project(id),
  entry_type        ledger_type   NOT NULL,
  bucket            ledger_bucket NOT NULL,
  amount            numeric(18,4) NOT NULL CHECK (amount <> 0),
  currency          char(3)       NOT NULL,
  source_type       text NOT NULL CHECK (source_type IN ('requisition','purchase_order','manual','transfer','import','system')),
  source_id         uuid,
  transfer_group_id uuid,
  reverses_entry_id bigint REFERENCES ledger_entry(id),
  department_code   text, ledger_account_code text,
  effective_date    date NOT NULL,
  posted_at         timestamptz NOT NULL DEFAULT now(),
  actor_id          uuid NOT NULL,
  reason            text,
  idempotency_key   text,
  UNIQUE (org_id, idempotency_key)
);
```

Table CHECKs (names matter, tests assert them by name):
- `ledger_type_bucket_ok` — the mapping table above (release → `reserved` or `committed` only; reversal → any bucket).
- `ledger_sign_ok` — allocation/reservation/commitment/actual `amount > 0`; release `amount < 0`; transfer and adjustment any sign.
- `ledger_source_link` — `source_type IN ('requisition','purchase_order','transfer','import')` requires `source_id IS NOT NULL`; `manual` requires `reason IS NOT NULL` (BUD-006: every entry links to a source document or an authorized manual action).
- `ledger_transfer_group` — `entry_type='transfer'` requires `transfer_group_id IS NOT NULL`.
- `ledger_reversal_link` — `entry_type='reversal'` requires `reverses_entry_id IS NOT NULL`; any other type requires it NULL.
- `ledger_adjustment_reason` — `adjustment` requires `reason`.

Triggers: `ledger_entry_append_only` BEFORE UPDATE OR DELETE using the existing `raise_append_only()` (**also BEFORE TRUNCATE**, statement level — a TRUNCATE must fail too). Indexes: `(org_id, project_id, effective_date)`, `(org_id, source_type, source_id)`, `(org_id, transfer_group_id) WHERE transfer_group_id IS NOT NULL`, `(reverses_entry_id) WHERE reverses_entry_id IS NOT NULL`.

Reversal integrity is a trigger, not just a CHECK: `BEFORE INSERT` on a `reversal` row asserts the reversed entry exists in the same org, the new row's `bucket` equals its bucket, `amount = -reversed.amount`, `currency` equal, and **no earlier reversal of the same entry exists** (a unique partial index on `reverses_entry_id` is the enforcement; the trigger gives the readable error). Error codes surface as SQLSTATE `23514`/`23505` mapped to the RFC 9457 problem types in E07-S02.

Permissions inserted into the global `permission` table: `ledger.read`, `budget.allocate`, `budget.adjust`, `budget.transfer`. No role grants in this story.

Python: `modules/budget/models.py` with `LedgerEntry` row dataclass, `LedgerType`, `LedgerBucket` enums (values identical to the SQL), and `modules/budget/ledger_rules.py` exporting `BUCKET_FOR_TYPE` and `expected_sign(entry_type)` — the **single Python mirror** of the CHECK; a test asserts it equals the migration (parse both).

## Behaviour

1. The migration only defines structure. No endpoint is exposed here (writers are E07-S02..S07).
2. The money-float lint scope is extended to `modules/budget/` (it already names it; confirm the path now exists and is scanned).
3. `tenant` guard scripts (`check_tenancy.py`, `unprotected_tenant_tables`) must pass without exemptions.

## Acceptance criteria

- [ ] `UPDATE`, `DELETE` and `TRUNCATE` on `ledger_entry` each fail in the database (three tests, as the owner role too)
- [ ] Each named CHECK rejects a planted violating insert and accepts the minimal valid one (one test per CHECK, by constraint name)
- [ ] A second reversal of the same entry is rejected; a reversal with a mismatched bucket, currency or amount is rejected; a reversal of another tenant's entry is rejected
- [ ] The same `(org_id, idempotency_key)` twice raises `23505`; the same key in two orgs succeeds
- [ ] Cross-tenant: an insert whose `org_id` differs from the session org fails RLS; a SELECT never returns another org's rows (use the existing RLS fixture)
- [ ] `BUCKET_FOR_TYPE`/`expected_sign` equal the migration's CHECK definition
- [ ] Migration up, down, and a data-preservation assertion (a 0017-era row set survives 0018 up/down)
- [ ] `tenant` guard and money-float lint pass unchanged

## Amendments (preflight audit — authoritative, override anything above)

- **Tenant-consistent foreign keys:** use composite FKs `(org_id, project_id, bu_id) REFERENCES project(org_id, id, bu_id)` (this also forces `bu_id` to equal the project's BU) and `(org_id, bu_id) REFERENCES org_unit(org_id, id)`; `org_unit` needs `UNIQUE (org_id, id)` (E05-S01 adds it). Drop the plain single-column FKs shown above.
- **Reversal integrity** also requires the same `project_id` and `bu_id` as the reversed entry (add to the trigger and to the planted tests).
- `department_code` and `ledger_account_code` are **NOT NULL** (FIN-007); every writer takes them from the project when the caller does not supply them and validates through `org.service.assert_usable`.
