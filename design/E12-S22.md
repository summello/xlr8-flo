# E12-S22 — Comparison engine: converted unit price on each cell (SRC-009 unit cost, for E12-S10)

**Epic** E12 · **M3** · **engine/S** · after **E12-S06**, **E12-S21** · tags: `money` (Opus review)

> **Why (operator, 27 Oct 2026, E12-S10 `## Blocked`):** Codex blocked E12-S10 three rounds running
> because `By Line` has no normalized per-unit cost. `Cell.unit_price` is the price as the vendor keyed
> it, in the bid currency; the page may compute no figure. This story adds the converted unit price to
> the server. It changes no existing field and no existing figure.
> **Ruling (operator):** converted at the comparison's frozen rate, quantized to the RFQ currency's
> minor unit through `kernel/money.quantize` (never `round()`), alongside the existing `unit_price`.
> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.
> Back end only; no migration; no new route; no permission change.

## Requirements (inlined)

- **SRC-009** — The comparison dashboard must normalize and compare total cost, unit cost, tax, freight, lead time, compliance, vendor score, and configured criteria.
- **SRC-010** — Currency conversion shows rate, source and effective date, and never alters the bid.

## Rule

All in `apps/api/src/flo/modules/sourcing/comparison.py`.

1. **`Cell`** (`comparison.py:85`) gains `unit_price_converted: str | None`, declared directly after
   `unit_price`. Value: `quantize(quote.unit_price * rate.rate, currency)` where `currency` is the RFQ
   currency and `rate` is the same frozen `Rate` the bid's other components use (`rates[bid.currency]`,
   the one `_price` receives). `null` exactly when `unit_price` is `null` (the vendor did not quote the
   line). An RFQ-currency bid has rate 1 (`source = identity`), so the value is `unit_price`
   quantized to the minor unit.
2. Compute it once per quoted line in `_price` (store it on `_Priced`, e.g. a `units: dict[UUID, Decimal]`)
   and read it where `compute()` builds `Cell`s (`comparison.py:~370`). Do not derive it from
   `price / quantity` (that divides a quantized amount and differs from the rule).
3. It is a display figure. `price`, `landed`, every total, basis, marker and `identical` keep their
   current computation from the exact `unit_price × quantity`; nothing sums `unit_price_converted`.
   `IDENTICAL_MEASURES` is unchanged.
4. `SealedComparisonRead` is unchanged (`{sealed: true}` only).
5. Regenerate the API client: `npm run generate:api` in `apps/web` (updates
   `apps/web/src/api/generated/openapi.json` and `schema.ts`).

## Acceptance

- [ ] Engine unit test (`apps/api/tests/sourcing/test_comparison_engine.py`), hand-computed
      cross-currency example in the test's comment: an RFQ in USD, a EUR bid keying unit price `8.125`
      at rate `1.0837` → `8.805…` → `unit_price_converted == "8.81"` (HALF_UP to 2 places), while
      `unit_price == "8.125"` is unchanged. A JPY-currency RFQ (0 decimals) case shows the quantum
      follows the RFQ currency.
- [ ] Same-currency bid: `unit_price_converted` equals `unit_price` quantized to the minor unit.
- [ ] A not-quoted cell has `unit_price_converted is None`.
- [ ] Every existing figure in `test_three_vendors_four_lines_every_figure` is unchanged (no existing
      test edited except to add assertions on the new field).
- [ ] Sealed: the sealed response is still exactly `{sealed: true}`.
- [ ] TEN-010: the existing foreign-RFQ 404 case still covers the route (no new route).
- [ ] `flo check --light` green, with the regenerated API client.

## Plants

1. Use `round()` / `ROUND_HALF_EVEN` instead of `quantize`: a half-way case (USD bid, unit `2.125`, rate 1 → `"2.13"`; half-even gives `2.12`) fails. Add that case.
2. Convert with the bid's identity instead of the frozen rate (drop `* rate.rate`): the cross-currency test fails.
3. Derive it as `price / quantity`: a case where the two differ (quantity 10, unit `0.0046`, rate 1 → `"0.00"`; `price / quantity` gives `0.01`) fails. Add that case.
