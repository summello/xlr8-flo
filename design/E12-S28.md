# E12-S28 — RFQ change responses carry the caller's edit and approve flags

**Epic** E12 · **M3** · **api/S** · after **E12-S03**, **E12-S27** · tags: none
Origin: ACC-008 automated keyboard run, 21 Nov 2026 (result record on PR #22). Operator, 21 Nov 2026: fix before
the human walkthrough round.

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.

One router file and its tests. No migration, no schema change, no service change, no frontend change.

## Requirements (inlined)

- **SRC-002** — An RFQ must contain items/services, quantities, specifications, delivery requirements, response
  deadline, terms, attachments, and invited vendors.
- **UX-005** — Errors must state what happened, what was preserved, and how the user can recover.
- **ACC-008** — A complete project-to-PO workflow is operable without a mouse.

## The defect

`RfqRead.can_edit` and `can_approve` (`modules/sourcing/schemas.py` ~198) default to `False`. Only
`GET /rfqs/{id}` (`api/sourcing.py` ~175-188) fills them. Every route that returns the RFQ after a change —
`_done` (~194-196) and its 14 callers, plus `create_rfq` (~130) and `patch_rfq_lines` (~143) — returns both as
`False`. The web replaces its RFQ with that response:

- `components/sourcing/editor/Editor.tsx` ~28 then shows "You cannot change this RFQ" and **discards every field
  the user had typed** after Invite Selected, Save Draft or any other editor change (the save itself succeeded);
- `routes/sourcing/rfqs/detail.tsx` ~67 and `routes/sourcing/rfqs/comparison.tsx` ~70 hide Edit, Amend, Extend
  Deadline, Record Bid, Start Evaluation and Refresh Rate after any change until a reload.

The server authorizes every one of these routes itself (`EditContext`/`ApproveContext`), so this is a wrong answer,
not an access hole.

## Fix

In `api/sourcing.py` only. `_done` becomes
`_done(rfq: RfqRead, response: Response, request: Request, connection: Connection) -> RfqRead` and sets, before
returning, exactly what `get_rfq` sets:

```python
target = rfq_target(rfq.id, connection)
rfq.can_edit = permits(request, "rfq.edit", target)
rfq.can_approve = permits(request, "rfq.approve", target)
```

`get_rfq` calls `_done` too (one place sets the flags). Every route returning `RfqRead` routes through `_done`,
including `create_rfq` and `patch_rfq_lines`; add `request: Request` to each signature that lacks it. Nothing else
changes: the ETag header, the service calls, the status codes.

A route that returns `RfqRead` and does not go through `_done` is the defect again. Enforce it with a test (below),
not by review.

## Acceptance

- [ ] **Editor change keeps the flags:** with `rfq.edit` and `rfq.approve` on the RFQ's unit, `PATCH /rfqs/{id}`,
      `POST /rfqs/{id}/invitees`, `POST /rfqs/{id}/extend-deadline` (published RFQ) and `POST /rfqs` each answer with
      `can_edit: true, can_approve: true`.
- [ ] **Edit without approve:** the same `PATCH` with `rfq.edit` only answers `can_edit: true, can_approve: false`.
- [ ] **Every RfqRead route uses `_done`:** a test walks `app.routes`, takes every `APIRoute` under `/api/v1/sourcing`
      whose `response_model` is `RfqRead`, and asserts its endpoint's source (`inspect.getsource`) contains `_done(`.
      Today 17 routes (`get_rfq`, `create_rfq`, `patch_rfq_lines` and the 14 `_done` callers); the test asserts it
      found at least 17, so a rename that empties the list fails.
- [ ] Existing sourcing route tests stay green unchanged (`tests/sourcing/`).
- [ ] TEN-010: no new endpoint. `flo check --light` green.

## Plants

1. In `_done`, drop the two flag lines: the editor-change acceptance fails.
2. Make `extend_rfq_deadline` return the service result directly instead of `_done(...)`: the route-walk test fails.
3. Compute `can_approve` with `"rfq.edit"`: the edit-without-approve case fails.
