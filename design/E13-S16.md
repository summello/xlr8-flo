## Requirements (inlined)

- **PO-004** — Phase 1 must send approved POs by email and record recipient, time, delivery result, and the exact document version.
- **PO-015** — Failed email/API/cXML transmissions must be visible, retryable, and auditable without duplicating the PO.
- **EML-002** — Bounces and complaints must be ingested, stored against the vendor contact, and surfaced on the PO transmission record.
- **EML-003** — A hard-bounced or complained address must enter a suppression list and must not be retried silently; the PO must show as undelivered and be actionable (PO-015).

(EML-006's provider id, recipient and template are shown here because the read carries them; EML-006 itself was closed by E13-S10 and is not cited by this story.)

## Design

### 1. Shared resend hook (extract, do not duplicate)
Move the resend logic out of `issue.tsx:68-86` into `components/purchasing/transmissions/useResend.ts`: `useResend(poId, onSent: (rows) => void)` → `{ resend(), busy, refusal, clearRefusal }`, same body `{}`, same key handling. `issue.tsx` uses it with its existing `sent` callback; its behaviour and `po-issue.spec.ts` stay unchanged.

### 2. `currentSend` takes the template
`currentSend(rows, id, template = "po-issued-v1")`. Export the two template ids as `ISSUE_EMAIL` and `CANCEL_EMAIL = "po-cancelled-v1"`. Existing callers keep the default.

### 3. Detail page owns the list
`detail.tsx` loads `GET …/transmissions` once with `useLoad` and passes the loaded value to the card and to the header recovery, so a resend from either updates both (`load.set(rows)`).

### 4. Header recovery (pages/purchase-orders.md §4.4)
Only when the PO's status is `issued` (template `ISSUE_EMAIL`) or `cancelled` (template `CANCEL_EMAIL`): `plan = recovery(currentSend(rows, p.id, template), p.vendor_status !== null)`. When `plan` is non-null, render `plan.actions` in that order inside `vendor-head-actions` — `Resend` (button, `useResend`) and `<ChangeRecipient poId vendorId onSent>`. Under them, when `Resend` is shown: "Sends the same version again. Nothing more is committed." Any refusal from either renders as `role="alert"` beside the actions. **No autofocus on the detail page** (that is the issue moment's job, not a page load). Any other status (draft, approval_pending, approved, superseded, closed) shows no recovery; the log is read-only there (the server would 409 `not_resendable`).

### 5. Transmissions card (replaces `TransmissionsCard`, new file `transmissions/TransmissionsCard.tsx`)
- Title `Transmissions`, loading/error from `Card`. Empty: "Nothing has been sent to the vendor yet."
- **Sent to Vendor** summary: the rows of `currentSend` for the status's template (issue email when not cancelled), one `Signal` per recipient with `Person`.
- If a row of that summary is `bounced`, `complained` or `address_suppressed`: one line in words naming the address and what happens — bounced: "{email} does not accept mail. It is on the suppression list and is never retried silently."; complained: "{email} reported this email as spam. It is on the suppression list and is never retried silently."; address_suppressed: "{email} is on the suppression list, so this email was not sent to it. It is never retried silently." Then once: "An organization administrator can remove an address under Administration, Sending Domain." (plain text, no link: E13-S21 is not built). The PO's status pill is untouched: a bounce leaves the PO `Issued`.
- **Send log**: a `<table className="po-lines">` with a `<caption>` "Every email sent for this purchase order", columns `Time` (`formatDateTime(created_at)`), `Recipient` (`Person`), `Version` (`v{revision + 1}`, as `VersionControl.tsx:33`), `Template` (`Purchase Order` for `po-issued-v1`, `Cancellation Notice` for `po-cancelled-v1`, else the raw id), `Result` (`<Signal {...sentSignal(row)} why={row.result_reason && <p className="sig-why">{row.result_reason}</p>} />`), and a last cell with a `Details` button whose accessible name is `Details for {recipient_email}, attempt {attempt}`. Rows in server order; no client sort.
- A `Refresh` button in the card reloads the list (results arrive after the provider reports; no polling on the detail).

### 6. Send sheet (new file `transmissions/TransmissionSheet.tsx`)
Opened by `Details`, mounted only while open, VendorCopySheet's pattern (Radix Dialog, `appr-scrim`, `appr-sheet`, title "Email to {recipient_email}", `Dialog.Close` labelled `Close`, `onCloseAutoFocus` → `restoreFocus(opener)`). A `<dl>` with: Recipient (`Person`), Version (`v{revision+1}`), Template (the words, then the raw `template_version` in `req-sub`), Attempt, Queued (`formatDateTime(created_at)`), Result (`Signal` with `result_reason`), Result at (`formatDateTime(result_at)` or "Not reported yet"), Provider Message ID (`provider_message_id` in the mono face, or "Not assigned yet"). No actions in the sheet: recovery lives in the header.

### 7. Suppressed contacts in Change Recipient
In `ChangeRecipient.tsx:60`, after the contact's type, a contact with `suppressed: true` shows `<span className="req-sub">Suppressed: never sent</span>` (words, no colour-only marker). It stays selectable; choosing it produces an `address_suppressed` row, which the log shows. Add to the dialog description: "A suppressed address is never sent to."

### Styling
Reuse the classes above. Any new rule goes in `apps/web/src/styles/purchase-orders.css` using only `var(--…)` tokens that exist in `tokens.css` (e.g. `--space-*`, `--fg-secondary`, `--text-body-dense`, `--font-mono` — check the name before use). No literal colour, size, radius or duration.
