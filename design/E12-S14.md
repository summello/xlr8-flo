## Requirements (inlined)

- **SRC-006** — Vendor responses must capture line prices, currency, tax, freight, lead time, validity, exceptions, attachments, and submission timestamp.
- **SRC-008** — Late bids must be blocked or explicitly marked and accepted only through an audited override.
- **SRC-010** — the original bid is never altered.

## Design

A wide side sheet opened from `Record Bid` on the Invitees card. It shows the vendor snapshot, the
version answered, `Vendor Sent It On` (date field + 24-hour time field + the evidence file, all
required), and `Keyed By Us` (the server's `keyed_at`, read-only). Lines are in the **vendor's
currency** with `Not Quoted` per line, plus validity, freight, lead time, terms, warranty and
exceptions. Compliance requirements are each answered `Met` or `Not Met` with a note.

**`Vendor Sent It On` is entered in the RFQ's deadline zone** (operator, 25 Oct 2026): the zone is
shown as text beside the time field (`Europe/London`, from `RfqRead.deadline_tz`), and the pair is
converted with the existing `instantIn(date, time, zone)` in `apps/web/src/components/sourcing/api.ts`
(null → field error `Enter a real date and a time as HH:MM.`), sent as an ISO instant with offset
(`BidCreate.sent_at` / `BidPatch.sent_at` / `BidReplace.sent_at` are `AwareDatetime`). Read back,
`sent_at` is shown in the same zone. Lateness compares like with like against the deadline the
vendor was given.

**Tax per line** (SRC-006): each quoted line has a required `Tax` amount input in the vendor's
currency beside `Unit Price` (`BidLineIn.tax`, an amount, not a rate). Blank on a quoted line is a
field error (`Enter the tax on this line, or 0 if none.`); the form never sends a default — `0` is
sent only when the user typed it. A `Not Quoted` line has neither input and sends `tax: "0"`.

**Totals** (operator, 25 Oct 2026): the server returns them, the page computes nothing. Add to
`BidRead` (`modules/sourcing/schemas.py`) `totals: BidTotals | None` with
`BidTotals { lines: str, tax: str, freight: str, total: str }`, all in `bid.currency`:
`lines = Σ line_total` and `tax = Σ tax` over quoted lines, `freight = quantize(bid.freight,
bid.currency)`, `total = lines + tax + freight`, all `Decimal`, each quantized through
`kernel/money.quantize`. Computed in `BidService` where `BidRead` is built (`bids.py` ~`:255`);
`SealedBidRead` never carries it. The sheet shows four rows `Lines`, `Tax`, `Freight`, `Total`,
each with the currency code, refreshed from each save's response. No conversion here.

**Late** (decision 155, escape path ruled by the operator, 25 Oct 2026): when submit answers 409
`late_bid`, one callout explains (the vendor sent it after the deadline, by `Vendor Sent It On`,
never `Keyed By Us`).
- For an `rfq.approve` holder (`RfqRead.can_approve`) the footer action becomes `Accept Late Bid
  and Save` with a required reason (1–500 characters), sent as `BidSubmit.accept_late_reason`.
- Anyone else sees: `Ask a sourcing lead to open this draft and accept it.` The draft stays saved.
- **Backend change:** `BidService.submit` (`bids.py:479`) currently calls `_own_draft`, so only the
  keyer may submit (`bids.py:79`). Change it so a non-keyer may submit a draft **only** when
  `may_accept_late` is true **and** `accept_late_reason` is present **and** the bid is late; any
  other non-keyer submit stays 403. The draft must still be a draft (409 `not_draft`). `keyed_by`
  is unchanged (the buyer); `late_accepted_by` is the lead; `bid.submit` and `bid.late_override`
  are both audited, as now. `PATCH` stays keyer-only. A lead finds the draft through `list_bids`
  (`rfq.approve` already lists every bid, `api/sourcing.py:343`) and opens it from the Invitees
  card, which shows `Draft, Late — Waiting for a Lead` to everyone.
- An accepted late bid shows `Late, Accepted By Override` with who, when and why (`BidRead.late`).

**Submitted bid:** opens read-only. Before the deadline (`RfqRead` deadline not passed) it offers
`Replace`, which opens a small form with a new `Vendor Sent It On` (same zone rule) and a required
`Reason for Replacing` (1–500), posting `BidReplace {reason, sent_at}`; the response is the new
draft, which the sheet then opens for keying (every price and answer re-keyed, as the server
copies structure only). After the deadline `Replace` is not shown, and the sheet says `Bids can
no longer be replaced after the bidding stop time.` (the server's 409 `deadline_passed` is
mapped to the same text). A replaced bid shows `Replaced By` linking the replacement.

**`bids_received`** (inherited from E12-S11): add `bids_received: int` to `RfqListRow` and to
`RfqRead`, computed in the list query (`modules/sourcing/service.py:165`) and the detail read as
the count of **current** bids — `status = 'submitted'` and not replaced by a submitted bid (the
rule behind `BidRead.current`, `bids.py:202`, `:269`), so a vendor counts once and drafts never
count. It is a count, not a bid figure, so it is visible before the deadline (SRC-007 allows it;
the sealed DOM assertion still holds for amounts).

## Acceptance

- [ ] Late path, per role: a buyer's submit is blocked with the callout and no accept action; a lead opens the same draft, accepts with a reason, and it is marked `Late, Accepted By Override` everywhere. - [ ] Replace: before the deadline it needs a reason and a sent time; after the deadline the action is absent and the server's 409 is mapped.
- [ ] `bids_received` counts a replaced vendor once and excludes drafts (API test).
- [ ] Amounts are typed in the user's locale and sent canonical; the currency code is visible beside every amount.
- [ ] Focus: the sheet traps, Escape returns focus to `Record Bid`.
- [ ] axe in both themes; keyboard-only path.
- [ ] MASTER §8 checklist; tokens only.
- [ ] TEN-010: a foreign tenant's bid submit is 404.
- [ ] `flo check` green, with the regenerated API client.
