## Requirements (inlined)

- **SRC-006** — Vendor responses must capture line prices, currency, tax, freight, lead time, validity, exceptions, attachments, and submission timestamp.
- **SRC-008** — Late bids must be blocked or explicitly marked and accepted only through an audited override.
- **SRC-010** — the original bid is never altered.

## Design

A wide side sheet opened from `Record Bid` on the Invitees card. It shows the vendor snapshot, the
version answered, `Vendor Sent It On` (date field + 24-hour time field + the evidence file, all
required), and `Keyed By Us` (the server's time, read-only). Lines are in the **vendor's currency**
with `Not Quoted` per line, plus validity, freight, lead time, terms, warranty and exceptions.
Compliance requirements are each answered `Met` or `Not Met` with a note. Totals come from the
server in the vendor's currency only; there is no conversion here.

**Late:** when the server answers 409 `late_bid`, one callout explains (vendor sent it after the
deadline) and, for `rfq.approve` holders only, the footer action becomes `Accept Late Bid and Save`
with a required reason (decision 155). Others see what to do (ask the sourcing lead). An accepted
late bid shows `Late, Accepted By Override` with who, when and why.

A submitted bid opens read-only with `Replace` (a new draft).

## Blocked

Codex pre-flight 25 Oct 2026 (`.scratch/E12-S14.preflight.log`) — 7 packet defects against the real
code, for the planner to fix:

1. **Line 27's late-bid escape hatch doesn't work.** Telling a blocked buyer to "ask a lead to
   accept the existing late bid" fails both ways: submission is restricted to the draft's original
   keyer (`bids.py:79`, `:488`), and a lead can't create a second draft either — `draft_exists`
   blocks it (`bids.py:344`). Decide the actual escape path.
2. **Submission (POST) also needs `If-Match`, not just PATCH/PUT/DELETE** (line 9). Bid submit is a
   POST that requires it too (`api/sourcing.py:386`, `bids.py:488`); omitting it returns 400
   (`service.py:596`). Fix the convention note.
3. **`Replace` (line 32) is incomplete.** The API requires both a new `sent_at` and an audited
   reason (`schemas.py:441`), and only permits replacement before the deadline (`bids.py:545`). The
   packet's form/flow for Replace needs both.
4. **No bid-total field exists** (line 24 says totals come from the server). `BidRead` only exposes
   per-line `line_total`, `tax`, `freight` (`schemas.py:455`, `:477`) — no aggregate. Either add a
   total to the schema or have the packet compute/display per-line only; also undecided: does the
   displayed total include line tax and freight.
5. **Tax is required (line 14) but the form (line 20) has no tax input or rule.** Tax is modeled
   per-line (`schemas.py:372`); silently defaulting to `"0"` would record wrong money. Add the
   field and its rule.
6. **`sent_at` timezone is undecided** (line 21). The API requires an aware instant
   (`schemas.py:364`) and the conversion helper requires an explicit zone (`api.ts:39`). This choice
   can flip whether a bid reads as late — needs a ruling, not a default.
7. **`bids_received` (line 53) has no server source.** File scope lists only web files, but no such
   value exists in the current model or list query (`schemas.py:179`, `service.py:165`). Also
   undecided: do replacements/drafts count, or only current submitted vendor bids.
