## Requirements (inlined)

- **PO-007** — The lifecycle should support Draft, Approval Pending, Approved, Issued, Partially Delivered, Delivered, Accepted, Closed, Cancelled, and Superseded.

## State machine

`status` CHECK in exactly `draft`, `approval_pending`, `approved`, `issued`, `partially_delivered`,
`delivered`, `accepted`, `closed`, `cancelled` and `superseded`.

| From | Action | Owner story | To |
|---|---|---|---|
| `draft` | submit | E13-S04 | `approval_pending` |
| `approval_pending` | approve / reject / withdraw | E13-S04 | `approved` / `draft` / `draft` |
| `approved` | issue | E13-S05 | `issued` |
| `issued` | change order approved | E13-S06 | `superseded` (old version) + new version `issued` |
| `draft`, `approval_pending`, `approved` | cancel | E13-S07 | `cancelled` |
| `issued` | cancel (whole) | E13-S07 | `cancelled` |
| `issued` | close (manual, reason) | this story | `closed` |
| `issued` → `partially_delivered` → `delivered` → `accepted` | goods receipt | **M4 (E14)** | not reachable in M3 |

This story builds **one transition function** in `purchasing/lifecycle.py`:
`transition(conn, scope, po_id, action, actor_id, reason=None)`. It locks the PO `FOR UPDATE`,
checks the table, writes the status and an audit row (`purchase_order.<action>`), and is the only
writer of `purchase_order.status`. Other stories call it. It also delivers `close` (`purchase_order.close`
permission, reason required) and `delete` of a draft (it delegates to E22-S02's soft delete if
merged; otherwise 409 is left as a follow-up).

`partially_delivered`, `delivered` and `accepted` exist in the CHECK and the enum but **no action
reaches them in M3**. A test asserts every M3 action's target set excludes them.

## Acceptance

- [ ] Every valid and invalid (from, action) pair, parametrized.
- [ ] A raw `UPDATE purchase_order SET status` outside `lifecycle.py` is caught by a test that greps `src/` for status writes (only `lifecycle.py` may write it).
- [ ] Close needs a reason and `purchase_order.close`; audited.
- [ ] TEN-010 on the close route; `flo check` green.

## Plants

1. Add a second status writer in the router: the grep test fails.
2. Allow `approved → closed`: the invalid-pair test fails.
