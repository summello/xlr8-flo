# E02-S01 — IdentityProvider port + LocalIdentityProvider, argon2id, NIST password policy

**Epic** E02 Identity & access · **M0** · **security/L** · after **E01-S02** · tags: `auth`, `security`

## Requirements

- **AUTH-003** — Password behavior must follow current NIST guidance: allow long passphrases and password-manager paste, block common/compromised values, and avoid arbitrary composition or periodic-rotation rules.
- **AUTH-004** — When used as the only factor, a password must be at least 15 characters; an 8-character minimum may apply when it is part of MFA.
- **AUTH-005** — Passwords must be salted and hashed with an approved, adaptively costly password-hashing scheme.
- **AUTH-007** — Authentication errors must not reveal whether an account exists.
- **D-05** (decision log) — In-app auth behind an `IdentityProvider` port. Keycloak is a ~1 GB always-on JVM, incompatible with every scale-to-zero free tier. The port keeps AUTH-012 cheap: Phase 2 SSO swaps the adapter, business authorization never moves.

## Deliverable

The authentication boundary. **The port is the point of this story** — it is what makes the Phase-2 SSO migration a new adapter rather than a rewrite.

## Contract

```python
class IdentityProvider(Protocol):
    def authenticate(self, email: str, password: str) -> AuthResult: ...
    def create_identity(self, email: str, password: str) -> IdentityId: ...
    def change_password(self, identity_id: IdentityId, new: str) -> None: ...
    def verify_password_policy(self, password: str) -> PolicyResult: ...
```

`LocalIdentityProvider` is the only implementation in Phase 1. **Nothing outside `kernel/identity/` may import it by name** — callers depend on the protocol. This is enforced by `lint-imports`.

Business authorization (roles, BU scope, project permissions) stays in XLR8 FLO and never moves into the provider, whatever the provider becomes.

## Behaviour

1. **Hashing** — argon2id via `argon2-cffi`. Parameters in config, defaults `time_cost=3, memory_cost=64MiB, parallelism=4`, tuned so a hash takes 250–500 ms on Cloud Run's CPU allocation. The stored hash carries its own parameters so cost can be raised later; on successful login with a below-current-cost hash, transparently rehash.
2. **Policy (AUTH-003, AUTH-004)** — minimum **15 characters** when password is the only factor, 8 when MFA is enrolled. Maximum 256 (a DoS bound, not a security control). **No composition rules** — no required symbol, digit, or mixed case. **No periodic rotation.** Unicode accepted, normalized NFKC. Leading and trailing whitespace preserved, never trimmed.
3. **Breach blocklist** — reject passwords in a bundled top-100k compromised list (k-anonymity prefix lookup against a local dataset; no external call, because the free tier must work offline and sending password prefixes to a third party is a needless disclosure).
4. **No enumeration (AUTH-007)** — a wrong email and a wrong password return the **same** error body and the same HTTP status. They must also take the same time: on unknown email, perform a dummy argon2 verify against a fixed hash so the timing signal is flat.
5. Password fields must permit paste and work with password managers (`autocomplete="current-password"`), never `onpaste="return false"`.

## Acceptance criteria

- [ ] A 15-character all-lowercase passphrase is accepted; a 14-character one is rejected
- [ ] A password from the blocklist is rejected regardless of length
- [ ] No composition rule is enforced anywhere — `"correct horse battery staple!"` and `"aaaaaaaaaaaaaaaa"` both pass length, the latter fails only if blocklisted
- [ ] Wrong email and wrong password produce byte-identical responses and status codes
- [ ] **Timing test**: median response time for unknown-email vs wrong-password differs by less than 10 % over 100 trials
- [ ] Stored hashes are argon2id and contain their parameters
- [ ] Raising `time_cost` in config causes transparent rehash on next successful login
- [ ] No module outside `kernel/identity/` imports `LocalIdentityProvider` — `lint-imports` proves it
- [ ] Passwords never appear in a log, an error body, or an audit record
