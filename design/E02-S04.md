# E02-S04 — TOTP MFA, mandatory for privileged roles, step-up re-auth for high-risk actions

**Epic** E02 · **M0** · **security/L** · after **E02-S02** · tags: `auth`, `security`

## Requirements

- **AUTH-006** — MFA must be available and should be mandatory for privileged users; phishing-resistant methods should be preferred.
- **SEC-009** — High-risk actions must support step-up authentication or recent-authentication checks.

## Contract

```
POST /api/v1/auth/mfa/enroll        → 200 {secret, otpauth_uri, recovery_codes[10]}
POST /api/v1/auth/mfa/confirm       {code} → 204, activates
POST /api/v1/auth/mfa/verify        {code} → 204, completes login or step-up
DELETE /api/v1/auth/mfa             {code|recovery} → 204, requires current factor
```

## Behaviour

1. **TOTP** (RFC 6238) via `pyotp`: SHA-1, 6 digits, 30 s step, ±1 step drift window. SHA-1 here is the algorithm every authenticator app implements; it is not a hash-security decision.
2. **Replay prevention** — a consumed `(identity_id, time_step)` is recorded and refused for the rest of its validity. Without this a shoulder-surfed code is reusable for 30 seconds.
3. **Recovery codes** — 10 single-use codes, shown once at enrollment, stored only as argon2id hashes. Using one consumes it and warns when 3 or fewer remain.
4. **Enrollment** requires the current password. The secret is not active until `confirm` proves a working code — otherwise a mis-scanned QR locks the user out.
5. **Mandatory for privileged roles** (AUTH-006) — an identity holding Organization Administrator or Auditor **cannot complete login** without MFA enrolled. On first login after being granted such a role, they are forced into enrollment before any other action.
6. **Step-up (SEC-009)** — a `@requires_recent_auth(max_age=timedelta(minutes=15))` decorator. If the session's `last_auth_at` is older, respond **403 with `WWW-Authenticate: step-up`** and a problem-details body naming what is required. The client re-prompts, `verify` refreshes `last_auth_at`, and the original request is retried. Applied to: changing a password, changing MFA, changing roles or scope, issuing a PO, approving above threshold, and exporting sensitive data.
7. Failed attempts are rate-limited and audited. Brute force locks the factor, not the account, to avoid a denial-of-service on the user.
8. The port keeps this local-only; a Phase-2 OIDC provider may supply MFA instead, and `requires_recent_auth` must keep working against whatever the provider reports.

## Acceptance criteria

- [ ] A valid code authenticates; the **same code fails on reuse** within its window
- [ ] A code from the previous and next step is accepted; two steps away is rejected
- [ ] Enrollment does not activate until `confirm` succeeds with a real code
- [ ] An Organization Administrator without MFA cannot reach any authenticated endpoint except enrollment
- [ ] A recovery code works once, then never again; a warning appears at 3 remaining
- [ ] A step-up-protected endpoint returns 403 with `WWW-Authenticate: step-up` when `last_auth_at` is older than 15 minutes, and succeeds after re-verification
- [ ] The TOTP secret and recovery codes never appear in a log or audit record
- [ ] Repeated failures lock the factor and write an audit event
