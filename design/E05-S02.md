# E05-S02 — Bill To / Ship To addresses with effective dates

**Epic** E05 · **M1** · **crud/S** · after **E05-S01** · tags: 

## Requirements

- **ORG-005** — Each BU/OU must maintain Bill To and Ship To addresses with effective dates.

## Contract

Migration (reversible): the next revision after the current head at story start (revision id `20260826_<next 4-digit number>`, `down_revision` = the head `python -m flo.kernel.migrate --check` validates today); stories merge one at a time, so there is no gap or fork: `org_address(id uuid pk, org_id, unit_id uuid not null fk org_unit, kind text check in ('bill_to','ship_to'), line1, line2, city, region, postal_code, country char(2), effective_from date not null, effective_to date null, created_by, created_at)`; RLS; `CHECK (effective_to IS NULL OR effective_to >= effective_from)`; **no two rows of the same (unit_id, kind) may overlap in effective range** — enforce with an `EXCLUDE USING gist (unit_id WITH =, kind WITH =, daterange(effective_from, effective_to, '[]') WITH &&)` (needs `btree_gist`; create the extension in the migration if absent).

- `POST /api/v1/org/units/{unit_id}/addresses` (Idempotency-Key) → 201 | 409 `address_overlap` | 404
- `GET /api/v1/org/units/{unit_id}/addresses?kind=&as_of=YYYY-MM-DD` → 200 list; `as_of` defaults to today in the org's timezone-free sense (date from `kernel.clock`)
- `PATCH /api/v1/org/units/{unit_id}/addresses/{id}` may only set `effective_to` (closing an address) — history is never edited in place → 200 | 409 if it would create an overlap

Permissions: `org.unit.manage` (write), `org.unit.read` (read).

## Behaviour

1. Addresses are history: a new address for an existing (unit, kind) must start after the previous one's `effective_to`; the service closes nothing implicitly — overlap is a 409 telling the caller which existing row conflicts.
2. `as_of` returns the single row effective that day or an empty list.
3. Audit `org_address.create|close`.

## Acceptance criteria

- [ ] Overlapping ranges for the same unit and kind are rejected by the database even if the service check is bypassed (test inserts directly)
- [ ] Adjacent ranges (`2026-01-01..2026-06-30` then `2026-07-01..`) succeed
- [ ] `as_of` boundary days (first and last day of a range) return the right row
- [ ] Foreign-tenant unit or address id → 404 (COVERED entries added to the isolation route-coverage gate)
- [ ] Migration up/down and data preservation
