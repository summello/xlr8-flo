# E01-S02 — Local stack: Postgres 17 + MinIO + Mailpit via one command

**Epic** E01 · **M0** · **chore/M** · after **E01-S01**

## Requirements

- **OPS-007** — A single command must reproduce the full stack locally (Postgres, MinIO, mail catcher) with no cloud account.

## Deliverable

`compose.yaml` plus `flo up`, giving every agent an identical local environment. This is what makes the concurrency and isolation suites runnable on a laptop.

## Behaviour

1. `compose.yaml` defines three services, pinned by digest, not `:latest`:
   - `postgres:17` — port 5432, db `flo_dev`, healthcheck `pg_isready`
   - `minio` — the R2 stand-in, S3 API on 9000, console 9001, bucket `flo-attachments` created by an init container
   - `mailpit` — SMTP 1025, web UI 8025
2. `flo up` runs `podman compose up -d` and blocks until every healthcheck passes, then prints the four URLs.
3. `.env.example` lists every variable the stack needs, with local defaults. `.env` is gitignored and never committed.
4. A second database `flo_test` is created at startup so the test suite never touches dev data.
5. `flo down` stops the stack; `flo up --reset` destroys volumes first.

## Acceptance criteria

- [ ] `flo up` on a machine with no cloud credentials brings all three services healthy
- [ ] `psql "$DATABASE_URL" -c 'select 1'` succeeds after `flo up` returns
- [ ] The S3 client can put and get an object in `flo-attachments` against MinIO
- [ ] An SMTP send to `localhost:1025` appears in the Mailpit UI
- [ ] `flo up` is idempotent — running it twice leaves one healthy stack, not two
- [ ] `flo up --reset` produces an empty database

## Files

`compose.yaml`, `.env.example`, `scripts/db-init.sql`, `agents/scripts/flo` (`cmd_up`, `cmd_down`)

## Out of scope

Neon, R2 and Resend wiring (E01-S06) · migrations (E03-S01 onward).
