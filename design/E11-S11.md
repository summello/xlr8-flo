## Requirements (inlined)

- **VEN-012** — A vendor that is inactive, suspended, expired, or not approved must not be invited or selected unless policy explicitly permits an authorized override.

## Server rule

`vendors.service.eligibility(vendor_ids, unit_id, on: date) -> dict[UUID, Eligibility]`, batched
for list pages, where `Eligibility = {eligible: bool, reasons: list[Reason]}` and
`Reason = {code, text, document_type?, date?}`. Reasons are in this order; every failing check
adds one:

1. `status` — status is not `active`: `Vendor is Suspended` / `Inactive` / `Rejected` / `Draft` / `Pending Approval`
2. `not_available` — not `available_in(unit)` (E11-S01): `Not available in Plant 4`
3. `disabled_here` — a global vendor locally disabled in this unit or an ancestor: `Disabled in Plant 4 by a@x.com`
4. `document_missing` — a required type missing: `Insurance Certificate missing`
5. `document_rejected` — `Insurance Certificate rejected`
6. `document_expired` — `Insurance Certificate expired 2 Oct`

`eligible = (no reasons)`. `expiring` and `unverified` **do not** make a vendor ineligible. They
come back as `warnings` (same shape), so the UI can show `Expiring in 12 Days`. **The vendor's
status is never changed by this function** (decision 123). Dates are formatted by the server in the
caller's locale (UX-007) and also returned raw.

Expose `GET /vendors/{id}/eligibility?unit_id=` and include `eligibility` for `available_in` (or
the caller's default unit) on each row of `GET /vendors`. This is the **only** implementation.
E12 (invitation) and E13 (PO vendor) call `vendors.service.eligibility`. The **override** (MASTER
§7.14: `rfq.approve` on the unit, a reason, audited) belongs to those consuming stories, not here.

## Web component

`apps/web/src/components/vendors/Eligibility.tsx`, implementing the `.sig` / `.sig-why` / `.elig`
contract of MASTER §7.14 with tokens only:
- `variant="cell"`: icon plus words (`Eligible Here` / `Not Eligible`), first reason on the next line, `and N more`.
- `variant="header"`: the `.elig` form, `Not Eligible In Plant 4`, with every reason listed.
- `variant="picker"` / `"field"`: as `cell`, for E12 and E13 to reuse.
- One `Signal` primitive (`components/ui/Signal.tsx`) carries the icon-plus-words rule for every signal (eligibility, document state, weight total). Icons come from the §2.3 set via the status package (Phosphor, one weight).
- The component computes nothing: it renders the server's `eligible`, `reasons` and `warnings`.

## Acceptance

- [ ] Rule: a parametrized test per reason, plus combinations, checks the order; an expired document leaves `status` unchanged; expiring and unverified are warnings only; a restricted vendor in a child OU of an allowed BU is eligible.
- [ ] Batch: 50 vendors in one call issue a bounded number of queries (assert ≤ 6), not one per vendor.
- [ ] TEN-010: another tenant's vendor id → 404 on the eligibility route; in the batch it is absent, never reported as ineligible.
- [ ] Component: vitest for each variant; the greyscale test (render both states with the colour tokens stripped and assert the accessible names differ by words and the icons differ); no colour literal (lint).
- [ ] The vendor list row carries `eligibility` (API contract test), and the generated client is regenerated.
- [ ] `flo check` green.

## Plants

1. Make an expired document set the status to `inactive`: the "status unchanged" test fails.
2. Compute `eligible` in the component from `reasons.length`: the test that passes `eligible: false` with no reasons, and expects `Not Eligible`, fails.
3. Drop the icon: the greyscale test fails.
