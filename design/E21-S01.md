# E21-S01 — Delivery status from git: six story states, one snapshot, release runbook tab

**Epic** E21 Delivery visibility · MT Delivery tooling (standalone: a pull request to `main`, no milestone branch) · kind `chore`, size L · tags: none · after: nothing.

> **Why.** `board.html` was rendered by whichever checkout ran `flo done`, from that checkout's own `agents/roadmap.yaml`. The M2 runner works in its own checkout, so the board the operator opened never saw its merges, a milestone merged to `main` kept showing as in flight, and Mission Control (which reads `agents/roadmap.yaml` from its session's directory) stayed on M1. The operator was blind and had to ask for progress.

**Requirements:** **SUP-005** — operator documentation is updated in the same change. **OBS-003** — runbooks are reachable from the operating surface (the board's Release steps tab).

## Contract

Every fact comes from refs and worktrees, which all checkouts share. `flo board` writes one snapshot, `<primary checkout>/.flo/status.json` (gitignored), and renders `board.html` from it.

| Story state | Rule (first match wins) |
|---|---|
| **Deployed** | its `E00-S00:` commit is reachable from `origin/main` |
| **Merged** | its commit is on a milestone branch (`flo done`) |
| **Committed** | a story worktree has commits ahead of the milestone **and** the review floor is met (an approving, test-running review; Opus's too when `opus_final`) |
| **In Progress** | a story worktree exists, or the roadmap says `in_progress` / `review` |
| **Ready** | `design/<ID>.md` exists on any milestone, docs or main ref |
| **To Do** | otherwise |

| Epic / milestone state | Rule |
|---|---|
| **Deployed** | every story Deployed |
| **Ready to Merge** | every story Merged or Deployed **and** the milestone branch's CI is green (`gh run list`, newest push) |
| **On Train** | any story past Ready; also all-merged with CI not green (the note says why) |
| **To Do** | otherwise |

`status.json` carries `stories`, `epics`, `milestones` (with `ci` and `pr`), `counts` and `generated_at`. Mission Control and the board both read it.

## Behaviour

1. `flo board [--watch [S]] [--no-gh] [--no-fetch]` gathers, writes `status.json` (atomically), renders `board.html`. It runs from any checkout and always writes to the primary one. It fetches `origin` at most every 120 s.
2. **It is not part of coding tasks.** `flo done` no longer renders the board. Mission Control's handler runs `flo board` every minute and after `flo`/`git`/`gh` shell calls; `flo board --watch` does the same from a plain terminal.
3. `board.html` is a complete document (doctype, charset, viewport), has an inline SVG favicon, a **Delivery** tab (the existing views, now with the six story states and the four group states) and a **Release steps** tab, shows "updated N min ago" (turns into a warning after 10 min) and reloads itself each minute keeping tab and scroll.
4. **Release steps** is the operator's checklist: confirm ready, release reviews, Neon staging rehearsal, decisions, mark ready, merge, watch the deploy, smoke test, tell Claude, roll back. Every command has a copy button; the pull-request number and branch are filled from `status.json`.
5. The Neon step mirrors the `neondb-staging-rehearse` skill and `infra/SETUP.md` ("Rehearse on a staging branch first").

## Acceptance criteria

- [ ] Each of the six states is derived from a real repository fixture; the answer is identical whichever checkout asks.
- [ ] A story on a milestone branch but not on `main` is Merged, never Deployed; a milestone with all stories merged and CI not green is On Train with a note.
- [ ] A story with commits ahead but no approving review is In Progress, not Committed.
- [ ] `status.json` is gitignored and written atomically; `flo board` run from a story worktree writes to the primary checkout.
- [ ] The page is valid HTML with a favicon; the Release tab shows the live PR number and has a copy button on every command.
- [ ] `flo done` does not render the board; `flo board --watch` exists.
- [ ] `docs/ops/delivery-status.md` documents states, files, refresh and troubleshooting.

## Plants

1. Make `group_state` ignore CI (`if True:`): the red-CI and pending-CI cases fail.
2. Treat commits-ahead as Committed without checking reviews: the in-progress-without-review case fails.
3. Resolve `main_root` to the checkout instead of the common git dir: the checkout-independence test fails.
