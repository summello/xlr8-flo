## Requirements

- **REQ-015** — The system must show requested, sourced, awarded, ordered, remaining, and cancelled quantities/amounts per line.
- **UX-003** — Unsaved changes must be detected before accidental navigation.
- **UX-004** — Loading states must distinguish initial loading, incremental loading, empty results, and failure.
- Also served (from the page specs): REQ-001, 003, 005, 006, 007, 010, 011, 013; **canvas decision 33 / D-M2-15** (over-funds blocks submit, with no override); A11Y-004 (colour never alone), A11Y-006 (forms), UX-005 (errors), UX-007 (locale), PERF-005 (server-side grids).

## Contract — screens and the API each uses (generated client only; regenerate, never hand-write a type)

| Route | Screen | API |
|---|---|---|
| `/requisitions` | List | `GET /requisitions` (E09-S01) |
| `/requisitions/new` | Create | `POST /requisitions`, `PUT …/lines` (E09-S02), lookups (E09-S03), catalogue (E09-S03), `GET …/submission-check` (E09-S04/S05), `POST …/transitions` (E09-S05), attachments (E09-S10) |
| `/requisitions/<uuid>/edit` | Edit a draft, including a returned one | as Create, plus `PATCH /requisitions/{id}` |
| `/requisitions/<uuid>` | Detail | `GET /requisitions/{id}`, `…/lines`, `…/links` (E09-S09), `…/transitions/available`, `…/revisions` (E09-S08), approval instance and decisions (E10-S05/S06) for the trail and the returned banner |

- **Routing:** add `REQUISITION_PATH` and `REQUISITION_EDIT_PATH` regexes to `routes/__root.tsx` beside `PROJECT_PATH`; `/requisitions/new` is an exact entry matched first; register in `route-paths.ts`; list tabs are `?tab=mine|drafts|submitted|all` (the E06-S07 amendment-2 pattern).
- **List** uses the shared `DataGrid` with a `loadPage` adapter (E06-S07 amendment 2). The `Mine`, `Drafts`, `Submitted` and `All` tabs map to `requester=me`, `status=draft&requester=me`, `status=approval_pending&requester=me`, and none. The total row and the pager are as the page spec draws them.
- **Money:** `lib/money.ts` `formatMoney` and decimal strings end to end; line arithmetic uses the existing BigInt decimal helpers (`components/dashboard/decimal.ts`; move them to `lib/decimal.ts` if two features now import them, and keep their tests). **No `Number`, `parseFloat` or float on money.** A vitest proves `3 × 0.10 = 0.30` and `2.5 × 19.99 = 49.98`, matching the server's HALF_UP (E09-S02).
- **Status:** extend `components/status/map.ts` and `labels.ts` for requisitions with `rejected: "danger"` and `expired: "danger"` (MASTER §2.3 names both as danger), and `withdrawn: "neutral"` (MASTER has no entry; neutral is the closest meaning). Record the MASTER map gap in `notes.followup`. Icon and words always.
- **Buttons (MASTER 7.13):** Submit is the one primary. `Withdraw requisition` and `Cancel requisition` are destructive (danger text, icon, verb). The danger fill appears only on the withdraw dialog's confirm button, and the safe button takes focus. **7.13's dark-mode values are not yet contrast-measured** (DECISIONS 112). If `tokens.css` has no destructive-button tokens when this story starts, use the secondary style for those buttons with the destructive icon and verb, and record it in `notes.followup`. Do not invent a value.

## Behaviour

1. **Create and edit** (`requisition-create.md` §2–7, verbatim copy): the radio for project versus standalone; selects fed by `GET /requisitions/lookups/{kind}`, with a requisition-generated project listed disabled with its note (canvas 48); the required-field marks of MASTER 7.11 (the `Required`/`Done` tag, the rail, the action-bar line) with the lint gate's markup; lines as one table with an explicit type, stacked cards below 660 px card width, `aria-label` per cell ("Quantity, line 3"); catalogue suggestions (`Add` appends quantity 1 and the last price); the Funding Check card; the Attachments card, which reads "Save the draft to attach files" until the draft exists, then uploads through E09-S10 with scan pills (`Clean`, `Scanning`, `Quarantined`, icon and text) and refuses to open an unreadable file, saying why.
2. **Save draft:** `POST` (first time) or `PATCH`, then `PUT …/lines` (atomic), each with the `If-Match` the previous response returned. Toast "Draft saved. Nothing is reserved until you submit." Status line `Draft saved 14:06` (`role=status`).
3. **Submit** (never disabled to signal an error, MASTER 7.11): save, then `POST …/transitions {to: "approval_pending"}` with an Idempotency-Key that is generated once per click and reused on retry. On 422 `submission_invalid`, the summary at the top (`role=alert`, focus moves to it), titled "Fix N things before you submit" with the line "Nothing was submitted. Everything you entered is kept." It holds one `Category: link` item per `errors[]` entry: the category comes from the field's first segment (E09-S04), and the link focuses the control or line. Field and line errors are shown inline (`aria-invalid`, `aria-describedby`). On 409 (`no_workflow`, `stale_version`, and so on) the summary shows the server's `detail`. On success, the confirmation card per the page spec, with the reserved figure and the route taken from the response and the instance. While submitting, the button reads `Submitting`, is disabled and `aria-busy` (the only time it is disabled).
4. **Unsaved changes (UX-003):** a dirty form prompts before in-app navigation (the root router's navigation hook) and sets `beforeunload` for tab close. Saving or discarding clears it. A Playwright test covers both.
5. **Detail** (`requisitions.md` §2): the lifecycle stepper (`aria-current="step"`, ", done" and ", not yet" in hidden text, terminal states shown in words); the Request, Reservation (the reserved figure equals the reservation ledger node from `…/links`; the released figure; project available), History (status events and decisions, newest first, system steps attributed to `System`), Linked Records (E09-S09 nodes as a list, tone pills, the "Nothing Linked Yet" empty state) and Lines (requested, sourced, awarded, ordered, cancelled, remaining; remaining from the server, REQ-015) cards, following the dashboard layout rule (DECISIONS 4–6, 15: a table card takes no hover outline).
6. **Returned banner** (`ReqDetailReturned`): approver, time and comment from the RETURNED decision. "The reservation is held while you amend." `Edit and Resubmit` (primary) goes to `/requisitions/<id>/edit`. Submitting from there is the resubmit (E09-S08), whose `409 nothing_changed` shows "Not resubmitted. Nothing has changed." **The resubmit diff screen (`RequisitionResubmit`) and the amendment screens are E09-S12**, which adds its own entry-point buttons ("Review and Resubmit" on a returned draft, "Amend" on an approved requisition) to these screens.
7. **Withdraw dialog** (`approval-inbox.md` §3, boards `WdDialog*`): `alertdialog` (Radix dialog), focus on **Keep Requisition**, Tab trapped, Escape closes except while busy. It states what stops, what is released (the server's reserved figure, "exactly once") and what follows, with an optional reason. Its outcomes are success, failure ("Not withdrawn", nothing changed, reason kept, `Try Again`) and already approved (`409 invalid_transition` once the requisition moved on: "Already Approved … nothing was released", Close only). A draft holding no reservation discards **without** a dialog. A returned draft that holds one **gets** the dialog.
8. **States everywhere** (UX-004): loading (skeletons at final height), empty, no match, error (what happened, what was kept, reference id, `Try again`), and partial (one card fails alone), as drawn.
9. **Tests are API-stubbed** (`page.route`, the E06-S07 amendment-2 §9 pattern). The real-Postgres proof of "two concurrent submissions against the last funds, exactly one succeeds" is **E09-S05's** ACC-001 test. Cite it in the PR. This story proves the UI renders the server's `funds` problem and offers no bypass.

## Acceptance criteria

- [ ] Happy path (stubbed): create a project-linked requisition with an item line and a catalogue line, save, submit, see "Submitted", then the detail shows `Approval Pending`, the reserved figure and the route.
- [ ] Empty submit lists every problem with its category, focuses the summary, and each link focuses its control or line. Every message in `requisition-create.md` §6 renders from a stubbed 422.
- [ ] **Over funds:** the Funding Check shows the shortfall in parentheses, signed, coloured and with the word `Exceeds`. Submit still posts and renders the server's `Funds` entry. No control anywhere submits anyway. Reducing a quantity clears the shortfall.
- [ ] A requisition-generated project is visible but disabled in the Project select, with its note.
- [ ] Cents: `3 × 0.10` shows `0.30`; the estimate equals the sum of line totals; the Funding Check's "This Requisition" equals the estimate (a three-way agreement test).
- [ ] UX-003: editing and then clicking a sidebar link prompts, cancelling stays, confirming leaves. `beforeunload` is registered only while dirty.
- [ ] Detail: exactly one `aria-current="step"` per status, including terminal ones; remaining equals the server's figure on every line; a split award stub shows awarded above ordered.
- [ ] Withdraw dialog: initial focus on Keep Requisition, Tab trapped, Escape returns focus to the trigger, busy state ignores Escape, and the three outcomes render as drawn. A non-requester sees no Withdraw button.
- [ ] Returned banner renders the approver's words, and `Edit and Resubmit` opens the edit route.
- [ ] Keyboard-only: create, add lines (Add item line, type, remove by keyboard), submit, open detail, withdraw, all with visible focus.
- [ ] `@axe-core/playwright` clean on `/requisitions`, `/requisitions/new`, a detail route, and the open withdraw dialog, in **both themes**.
- [ ] 375 px: no horizontal page scroll, lines stack, targets ≥ 44 px. Lines never overflow their card at 1024, 1100 and 1280.
- [ ] MASTER §8 checklist ticked in the PR body, including the required-field lint (`requiredMarkViolations`-equivalent in the app's lint, or the canvas rule ported) and tokens only.
- [ ] `tsc`, `eslint`, `vitest`, Playwright and the colour gate pass.

## Plants

1. Disable Submit while the form has errors: the never-disabled test fails.
2. Compute a line total with `Number()`: the cents vitest fails, and so does the lint rule if one exists.
3. Remove the `beforeunload` registration: the UX-003 test fails.
4. Hide the generated project instead of disabling it: its test fails.
5. Focus Withdraw instead of Keep Requisition: the dialog focus test fails.
