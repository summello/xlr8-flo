## Why

Revalidated by the planner on `9a53605` (23 Oct 2026, local load 24–31 during the incidents):

1. `flo check --light` adds changed Playwright specs as one `story e2e` command and `run_check()` fails on
   its first non-zero result. It has no selective retry or flake evidence.
2. E22-S07 reached test 24 of 85 before Playwright timed out; E11-S13 and E11-S16 also failed only on
   30-second `page.goto`/`locator.fill` or test timeouts under load. E11-S13's latest log shows 26 passing
   tests followed by the dark restricted-state test at 31.4 seconds. Each became
   `submit failed on this commit`, although an isolated retry could distinguish load from a defect.
3. Retrying every Playwright failure would hide real regressions. Assertion/expect failures and axe violations
   are deterministic evidence and must remain red without retry.

## Design

### 1. Classify the failed `story e2e` run

- Capture the Playwright output for `story e2e` without changing output shown on final failure.
- A retry is eligible only when every failed test is reported as a Playwright timeout (`Test timeout ...
  exceeded`, action timeout such as `page.goto`/`locator.fill`, or the equivalent structured timeout text).
- Any assertion/`expect()` mismatch, axe violation, explicit test failure, setup/compile error, crash, or
  unclassified failure is immediately red. Mixed timeout plus non-timeout failures are not retried.
- Full `e2e+axe` is unchanged; only the light profile's `story e2e` step is eligible.

### 2. Retry only the failed specs once

- For an eligible first failure, run Playwright once with `--last-failed --workers=1` from `apps/web`, using
  the same configuration and environment as the original story command. Do not rerun passed specs.
- If that retry passes, the `story e2e` step is green and prints
  `flaky under load: <specs>` with the failed spec paths parsed from the first run.
- If the retry fails for any reason, the step is red and prints both first-run and retry evidence. There is no
  third attempt and no retry of the whole light check.

### 3. Persist the distinction

- A pass-on-retry evidence step records `flaky: true`, the spec paths and `attempts: 2` in `task.json`; a
  first-pass success records no flake. Keep the existing clean tree/profile cache semantics.
- `submit.sh` logs the `flaky under load` line through its existing check output. The story is submitted because
  the targeted retry passed; hosted CI remains the independent full-suite judge.
- Document the retry boundary and how operators find the recorded specs.

## Invariants

- An assertion, axe/accessibility violation or unknown Playwright failure can never become green by retry.
- At most one retry occurs, with one worker, and only failed specs run.
- Hosted story CI and the full local `e2e+axe` profile do not gain retry behaviour.
- A pass on retry is visible in both the submit log and task evidence; it is never reported as an ordinary
  first-pass success.

## Acceptance criteria

- [ ] A fake `story e2e` timeout failure runs exactly one second command containing `--last-failed --workers=1`;
      a passing retry makes `run_check(..., "light")` green.
- [ ] Pass-on-retry prints `flaky under load: <specs>` and task evidence records those specs, `flaky: true`
      and two attempts.
- [ ] A second timeout failure remains red and no third Playwright command runs.
- [ ] An assertion/`expect()` failure runs no retry and remains red.
- [ ] An axe violation runs no retry and remains red, even if its text also contains a timeout elsewhere.
- [ ] A mixed timeout and assertion failure runs no retry.
- [ ] The full-profile `e2e+axe` command remains single-attempt.
- [ ] Existing `test_light_profile_skips_full_suites_and_runs_the_story_tests` remains green.
- [ ] `docs/ops/fleet-tooling.md` documents the one-retry rule and evidence fields.

## Plants (prove each guard fails)

- Retry every non-zero `story e2e`: the assertion plant observes a second command and fails.
- Retry the original command instead of `--last-failed`: the selective-command test fails.
- Permit a second retry: the attempt-count test observes three commands and fails.
- Omit persistent flake evidence: the task/log evidence test fails.
