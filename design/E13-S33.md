## Requirements (inlined)

- **A11Y-002** — All functions must be operable by keyboard with visible, unobscured focus and logical focus order.
- **ACC-008** — A complete project-to-PO workflow is operable without a mouse.
- **MASTER §8** — Focus never falls to the page body. When an action removes or replaces the focused control (a
  dialog that closes on success, a button that unmounts, a form swapped for a result), focus moves to the element
  that reports the result, or to the next surviving control.

## The rule, applied

The target is either an element that already exists or one given `tabIndex={-1}` (never a positive tabindex, never
a new focusable control). Move focus after the DOM has the target: a ref plus
`requestAnimationFrame(() => ref.current?.focus())`, as `lib/focus.ts` `useFocusOnRouteChange` does. If three or
more sites end up with the same few lines, put one helper in `lib/focus.ts`; otherwise none. Focus moved this way
shows the `:focus-visible` ring (MASTER §3.5); if a `tabIndex={-1}` target does not show it in Chromium, add the
target to the existing `:focus-visible` selector, do not invent a style.

## Acceptance

Each case is a Playwright test in the existing spec for that screen (the fixture style already there; keyboard
only: `page.keyboard`, no `.click()`), asserting after the action that
`document.activeElement !== document.body` **and** that the focused element is the named target
(`toBeFocused()` on its locator):

- [ ] 1 `tests/e2e/sign-in.spec.ts` or `shell.spec.ts`: sign in by keyboard → `main#main-content` focused.
- [ ] 2 `shell.spec.ts`: Account menu → Sign out by keyboard → sign-in `h1` focused; one Tab → Email.
- [ ] 3 `projects.spec.ts`: add a sponsor with Enter → search input focused.
- [ ] 4 `projects.spec.ts`: press Approval pending → status element focused.
- [ ] 5 `requisitions.spec.ts`: Save draft → "Draft saved" status focused.
- [ ] 6 `sourcing-rfq-editor.spec.ts`: Invite Selected → `#rfq-invitees` focused; then Save Draft → the saved status focused.
- [ ] 7 `sourcing-bids.spec.ts`: Save Draft → the Save Draft button focused; then Submit Bid → the read-only Status value focused.
- [ ] 8 `sourcing-award.spec.ts`: Submit for Approval → the approval-pending status focused.
- [ ] 9 `po-close.spec.ts`: Close Order → PO status focused; Escape on the open dialog → **Close Purchase Order** focused.
- [ ] `@axe-core/playwright` clean on each touched route (existing a11y runs stay green).
- [ ] MASTER §8 checklist in the PR body, both themes for the focus ring on a `tabIndex={-1}` target.
- [ ] `flo check --light` green.

## Plants

1. Remove the focus call for case 8: its test fails on `document.body`.
2. In case 1, drop the `document.activeElement` guard and focus `main` unconditionally on the first route: the
   deep-link test that already focuses a control fails. The sign-in screens render `Screens`, not `AppShell`
   (`routes/__root.tsx` ~446, ~479), so they cannot exercise this guard: use an authorized shell route whose child
   focuses a surviving control on mount (add the e2e deep link if none exists).
3. In case 9, `preventDefault` the return-focus on Cancel too: the Escape assertion fails.
