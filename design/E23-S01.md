# E23-S01 — Stage durations in the scorecard record, with a `flo score --durations` report

**Epic** E23 · **MT** · **chore/S** · tags: none · backlog item T8 (`docs/fleet-throughput-backlog-2026-10-22.md`) · land first: S04, S06 and S10 cannot be measured without it

> **No new dependency** (AGENTS.md §0.6).

## Requirements (inlined)

- **SUP-005** — Administrator and operator documentation must be updated in the same PR as the feature it describes (UX-010).
- **OBS-002** — Monitoring must cover availability, latency, errors, saturation, job backlog/failures, database health, storage, email/integration delivery, and backup results.

## Pre-flight findings (Opus, 22 Oct 2026, traced against `799797d`)

- `agents/scorecard.json` records (106) carry `kind, size, tags, author, reviewers, rounds, gate_failures, opus_final, escapes, review, substitutions, sessions, recap, title`. There is **no timestamp or duration field**, and `task.json` (built in `cmd_start`, `agents/scripts/flo` ~line 346) has none either.
- The scorecard is "one immutable record per story" (`note` field). Existing 106 records cannot be backfilled honestly: a duration derived from git commit times would include waiting, not working. **Do not backfill.**
- Review launch time is not recorded anywhere. A verdict file's mtime gives the end only.
- `flo check` is cached per tree (`run_check once per tree`, ~line 2047), so a gate that hits the cache is fast. `gate_s` therefore measures the gate as run, not the cost of the checks.

## Design

### 1. Capture raw timestamps in `task.json` (the only mutable place)

ISO-8601 with offset, the format `cmd_codex_usage` already writes (`time.strftime("%Y-%m-%dT%H:%M:%S%z")`):

| Field | Written by | When |
|---|---|---|
| `started_at` | `cmd_start` | when the packet dict is built |
| `submitted_at` | `cmd_submit` | the **first** successful submit only; a later submit appends its time to `resubmitted_at` (list) and leaves `submitted_at` alone |
| `gate_seconds` | `cmd_gate` | wall time of the gate invocation, integer seconds |
| `done_at` | `cmd_done` | immediately before `record_score` |

Review launch: `agents/scripts/review.sh` writes one line, the epoch seconds, to `.scratch/<STORY>.<REVIEWER>.started` just before it launches the reviewer. It is overwritten on each round, so it always describes the **last** round.

### 2. Derive durations inside `record_score`

`record_score` (called from `cmd_done`, ~line 926) adds one key to the new record:

```json
"durations": {
  "wall_s": 0,
  "author_s": 0,
  "review_s": {"codex": 0},
  "gate_s": 0
}
```

- `wall_s = done_at - started_at`. `author_s = submitted_at - started_at` (first submit; review rounds are inside `wall_s` and not in `author_s`).
- `review_s[reviewer] = verdict file mtime - .started epoch`, last round only.
- **A missing input omits its key.** Never write `0`, `null` or a negative number: a zero would pull every median down and a negative means clock skew, which `record_score` reports on stderr (`warning: <story>: <key>: end is before start, not recorded`) and does not record.
- Pure function `durations_from(packet, verdict_mtimes, review_starts) -> dict` so the test needs no git, no clock and no filesystem.

### 3. `flo score --durations`

Prints to stdout only. It does **not** write `SCORECARD.md`, so the "scorecard drifts" CI check is untouched and old records stay immutable.

- Tables by `kind` and by `author`: `n`, median `wall_s`, median `author_s`, median `review_s` (per reviewer), median `gate_s`, max `wall_s`. Minutes, one decimal.
- Reuse the scorecard's `min_sample` (3): a cell with fewer samples prints `—`.
- Records without `durations` are skipped and counted: the last line states `N of 106 records carry durations`.

## Acceptance criteria

- [ ] `cmd_start`, `cmd_submit`, `cmd_gate`, `cmd_done` write the four task.json fields above; `review.sh` writes the `.started` marker.
- [ ] A story merged after this lands has a `durations` object in its scorecard record; a story missing `submitted_at` has no `author_s` key (not `0`).
- [ ] `flo score --durations` renders both tables and the coverage line; a cell with fewer than `min_sample` records prints `—`.
- [ ] `flo score` (no flag) output and `agents/SCORECARD.md` are byte-identical before and after this change on the committed `scorecard.json` (CI's drift check stays green).
- [ ] `agents/scorecard.json` existing records are not modified.
- [ ] Usage text at the top of `agents/scripts/flo` lists `--durations`; `docs/ops/fleet-tooling.md` has the section.

## Plants

1. Delete `submitted_at` from a fixture packet: `durations_from` must return a dict **without** `author_s`. A version that defaults to `0` fails the test.
2. Give a fixture `done_at` earlier than `started_at`: the function returns no `wall_s` and calls `warn`. A version that records the negative number fails.
3. Five fixture records, one without `durations`: the report's coverage line says `4 of 5`; a cell with one sample prints a dash.
