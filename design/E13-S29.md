# E13-S29 — ACC-008 evidence: the project-to-PO flow, keyboard only, end to end

**Epic** E13 · **M3** · **test/L** · after **E13-S27** · tags: `ui` · **status: blocked (operator)**
Origin: M3 Opus milestone review (finding 1, 8 Nov 2026). ACC-008 is an M3 exit criterion.

## Requirements (inlined)

- **ACC-008** — A complete project-to-PO workflow is operable without a mouse. (M3 exit criterion, docs/claude-plan.md §4:
  "a complete project→requisition→RFQ→award→PO→email flow is operable without a mouse".)

## Finding

Every M3 screen has its own keyboard-only Playwright path, but all 41 e2e specs stub the API per screen
(`page.route`). Nothing drives the chain project → requisition → submit/approve → RFQ → bid → award → PO →
issue → transmission log as one flow, so a broken hand-off between screens (a redirect that drops focus, a
create that lands where the next step has no keyboard route, the missing Close control now E13-S27) passes
every spec. The CI `frontend-e2e` job has no API and no database; the `backend` job has Postgres 17.

## Blocked

**Question for the operator: what counts as ACC-008 evidence for the M3 release?**

- (a) **A full-stack spec (this story, size L).** CI gains a job that starts Postgres, migrates and seeds one
  tenant, runs the API and the built SPA behind the Vite preview proxy, and runs one keyboard-only Playwright
  spec (`apps/web/tests/e2e-live/acc-008.spec.ts`, no `page.route`, no `.click()`) through the whole chain with
  axe on each landing page. Email is captured by the local mail stand-in. Adds a few minutes to every CI run.
- (b) **A recorded manual walkthrough** by the operator on the local stack (`flo up`) or staging, keyboard only, following a
  checklist this story writes (`docs/ops/acc-008-walkthrough.md`), with the result linked from the PR. No CI
  cost; not repeatable automatically.
- (c) **A chained stubbed spec**: one spec that walks all the screens in sequence against the existing stubs.
  Cheap, proves the hand-offs in the browser, not against the real API.

The planner recommends (a) before the first paying customer and (b) for this release if time matters.
