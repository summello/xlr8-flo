# E09-S02 — Item and service lines with explicit type tagging and quantity/amount tracking

**Epic** E09 · **M2** · **crud/M** · after **E09-S01** · tags: `money`, `migration`

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md` (G–O) and `docs/author-traps.md`. Decisions: `docs/m2-decisions.md`. Screens are E09-S11 (`design-system/pages/requisition-create.md` §4 is the consumer of this API; read it for the field list).

## Requirements

- **REQ-006** — Requisitions must support explicitly tagged item and service lines.
- **REQ-015** — The system must show requested, sourced, awarded, ordered, remaining, and cancelled quantities/amounts per line. *(The columns and their invariants land here; M3 stories write sourced/awarded/ordered/cancelled.)*
- **REQ-014** (guard only) — Split sourcing and partial awards must be supported without exceeding approved quantity or amount. *(Database CHECKs here so M3 cannot overshoot.)*
- **XFN-009** — Foreign-key fields such as department, ledger account, vendor, project, and item must use scoped dropdown/type-ahead selection rather than free text. *(Unit and category are master codes, never free text.)*
- **Money rules (AGENTS.md 3.1):** `Decimal` end to end, `NUMERIC(18,4)`, rounding through `kernel/money.py`, decimal strings on the wire (a JSON number is a 422).

## Design decisions (this packet)

- **Quantities are decimals** (`NUMERIC(18,4)`, > 0), so `2.5 m` and `0.75 kg` work; the canvas sample uses whole numbers only because it is a sample (closes `requisition-create.md` open question 5). **The unit is a `uom` master code** (XFN-009, closes the same question), required on every line.
- **Category** is optional: an `item_category` code on an item line, a `service_category` code on a service line; the wrong kind is a 422.
- **Line amount** = `kernel.money.quantize(quantity × unit_price, currency)` (currency exponent, `ROUND_HALF_UP`). `3 × 0.10 = 0.30` exactly. The client never sends `amount`.
- **The estimate is the sum of line amounts**, recomputed in the same transaction as every line write; it is never written any other way.
- **Every line write bumps the requisition's `version`** and requires `If-Match` with the requisition's version (convention O), so a line edit and a header edit cannot silently overwrite each other (DATA-002).
- **`line_no` is stable**: assigned `max+1` on insert, never renumbered on delete (the screen says "Remove line N", and E09-S08's diff needs stable identities).
- **At most 500 lines** per requisition (422 beyond).

## Contract

Routes in `api/requisitions.py`. All are draft-only (409 `not_editable` otherwise), target the requisition record (E09-S01's `requisition_target`), need `requisition.edit` for writes and `requisition.view` for reads.

| Route | Success | Errors |
|---|---|---|
| `GET /api/v1/requisitions/{id}/lines` | 200 `{rows: [LineRead], estimate, currency, version}` | 404 |
| `POST /api/v1/requisitions/{id}/lines` (Idempotency-Key, `If-Match`) | 201 `LineWriteResult`, `ETag` = new requisition version | 400 no `If-Match`; 409 `stale_version`; 409 `not_editable`; 422 |
| `PUT /api/v1/requisitions/{id}/lines/{line_id}` (`If-Match`) | 200 `LineWriteResult` | as above; 404 unknown line |
| `DELETE /api/v1/requisitions/{id}/lines/{line_id}` (`If-Match`) | 200 `LineWriteResult` (`line: null`) | as above; deleting an absent line is 404 (the version check makes a blind repeat stale anyway) |

- **`PUT /api/v1/requisitions/{id}/lines`** (`If-Match`) body `{lines: [LineCreate & {line_id?: uuid}]}` (0..500): **replaces the whole line set atomically**, the way the create form saves. A line with `line_id` updates that line, one without adds a line, and an existing line left out is deleted. One version bump, one audit row per changed line, 200 `{rows, estimate, currency, version}`. An unknown `line_id` → 422 on `lines/<index>/line_id`. The per-line routes stay for single edits.
- **`LineCreate` / `LinePut`** (`extra="forbid"`): `line_type` (`"item"|"service"`), `description` (1..500), `quantity` (decimal string, > 0, ≤ 14 integer digits, ≤ 4 dp), `uom_code`, `unit_price` (decimal string, > 0, ≤ 4 dp), `category_code` (optional). `amount`, `currency`, `line_no` in a body → 422 `derived_field`.
- **`LineRead`**: `id, line_no, line_type, description, quantity, uom_code, unit_price, amount, currency, category_code, requested_qty (= quantity), sourced_qty, awarded_qty, ordered_qty, cancelled_qty, remaining_qty (= quantity − ordered_qty − cancelled_qty)` — every number a decimal string.
- **`LineWriteResult`**: `{line: LineRead | null, estimate, currency, version}`.
- `uom_code` and `category_code` are checked with `org.service.assert_usable(conn, scope, kind, code, today)` (422 with the reason: `unknown`, `inactive`, `not_effective`).

## Behaviour

1. **Migration** (reversible; next revision at story start): `requisition_line(id uuid PK, org_id uuid NOT NULL, requisition_id uuid NOT NULL, line_no int NOT NULL, line_type text NOT NULL CHECK (line_type IN ('item','service')), description text NOT NULL, quantity NUMERIC(18,4) NOT NULL CHECK (quantity > 0), uom_code text NOT NULL, unit_price NUMERIC(18,4) NOT NULL CHECK (unit_price > 0), amount NUMERIC(18,4) NOT NULL CHECK (amount >= 0), currency char(3) NOT NULL, category_code text, sourced_qty NUMERIC(18,4) NOT NULL DEFAULT 0, awarded_qty NUMERIC(18,4) NOT NULL DEFAULT 0, ordered_qty NUMERIC(18,4) NOT NULL DEFAULT 0, cancelled_qty NUMERIC(18,4) NOT NULL DEFAULT 0, created_at, updated_at)`; `FOREIGN KEY (org_id, requisition_id) REFERENCES requisition(org_id, id) ON DELETE RESTRICT`; `UNIQUE (requisition_id, line_no)`; CHECKs `sourced_qty >= 0 AND awarded_qty >= 0 AND ordered_qty >= 0 AND cancelled_qty >= 0`, `awarded_qty <= quantity`, `ordered_qty + cancelled_qty <= quantity` (REQ-014 guard). RLS as every tenant table.
2. **A write** (one `tenant_transaction`): lock the requisition row `FOR UPDATE`; check `If-Match` against `version`; check `status = 'draft'`; validate; write the line; `UPDATE requisition SET estimate = (SELECT COALESCE(SUM(amount), 0) FROM requisition_line WHERE requisition_id = ...), version = version + 1, updated_at = now()`; audit `requisition.line.create|update|delete` with the line's before/after and the estimate before/after. A line's `currency` is copied from the requisition, and a line whose currency differs from its requisition is impossible: assert it in the write path, and add a test that tries.
3. **No `float` anywhere** in `modules/requisitions/` (enforced by `scripts/check_money_floats.py`, which already lists `requisitions`).
4. New routes get `COVERED` entries with real foreign-tenant tests.

## Acceptance criteria

- [ ] `quantity "3"`, `unit_price "0.10"` gives `amount "0.3000"` (stored) and estimate `"0.3000"`; `"2.5" × "19.99"` gives `"49.98"` (HALF_UP of 49.975) in USD.
- [ ] Adding, editing and deleting lines keeps `estimate == SUM(amount)` after each step (property-style, seeded RNG, 200 random operations).
- [ ] A JSON number for `quantity` or `unit_price` → 422; `quantity "0"` or a negative → 422; 5 decimal places → 422.
- [ ] `line_type` other than item/service → 422; a service line with an `item_category` code → 422; an inactive `uom` → 422 with reason `inactive`.
- [ ] Stale `If-Match` → 409 `stale_version`, nothing written; missing → 400; non-draft requisition → 409 `not_editable`.
- [ ] Two concurrent line inserts with the same `If-Match`: exactly one succeeds, the estimate equals the surviving line set.
- [ ] `line_no` is never reused after a delete within a requisition.
- [ ] Replace-all with one updated line, one new line and one omitted line: one version bump, the omitted line deleted, the estimate right. An invalid fourth line → 422 and **nothing** changes (atomic).
- [ ] Direct SQL setting `awarded_qty > quantity`, or `ordered_qty + cancelled_qty > quantity`, fails on the CHECK.
- [ ] `LineRead.remaining_qty` equals `quantity − ordered − cancelled` for planted values.
- [ ] Foreign-tenant requisition or line → 404 on every route; no grant → 404; view-only grant on a write → 403.
- [ ] Migration up/down/up preserves lines.

## Plants

1. Compute the amount with `float(quantity) * float(unit_price)`: the float checker fails CI and the `49.98` test fails.
2. Recompute the estimate before the line write instead of after: the property test fails.
3. Drop the `FOR UPDATE` on the requisition row: the concurrent-insert test fails (run it 20 times).
4. Remove the `awarded_qty <= quantity` CHECK: its SQL test fails.

## Pre-flight amendments (11 Oct 2026, Opus; binding, they override anything above)

Each item below was found by reading the code this story touches. A block on any of them is a packet defect, not an author failure.

1. **Overflow is a 500 unless guarded.** `quantity` allows 14 integer digits and `unit_price` allows 14, so the product can need 28 digits and the SUM can exceed `NUMERIC(18,4)`; Postgres then raises `NumericValueOutOfRange` and the client sees a 500. Reject in the service before any write: the computed `amount` must fit 14 integer digits and 4 decimals, and so must the new estimate. 422 on `lines/<index>/quantity` (or `/unit_price`, whichever the amount came from), `checks.problem = "amount_too_large"`. Add an acceptance case: `quantity "99999999999999"` × `unit_price "99999999999999"` → 422, nothing written.
2. **`kernel.money.quantize(amount, currency)`** is the only rounding (it uses the currency exponent). A currency with exponent 0 (JPY) stores `49.0000`; the 4-dp column does not change that. Test one zero-exponent currency so a hardcoded `.quantize(Decimal("0.01"))` fails.
3. `scripts/check_money_floats.py` already lists `requisitions` (`MONEY_MODULES`); do not edit it. Plant 1 relies on it.
4. **A currency change is refused while lines exist (11 Oct 2026, runner's block; binding).** E09-S01's header PATCH can move a draft to another project in the same `bu_id` and re-derive `currency` from it; ProjectCreate allows non-base currencies (D-M2-7 follow-up). This packet has no repricing rule and invents none: lines are priced in the requisition's currency and are never converted. Therefore `RequisitionService.update` (edit authorized, `modules/requisitions/service.py`) must, in the same transaction and after taking the requisition row lock, reject a PATCH whose re-derived currency differs from the stored one **while at least one line exists**: `422 currency_change_blocked`, `checks.problem = "currency_change_blocked"`, `ProblemFieldError` on `project_id`: "This request has lines priced in <CUR>. Remove the lines or choose a project in <CUR>." A move to a project with the same currency is unchanged, and a currency change on a draft with **no** lines proceeds as in E09-S01 (the estimate is 0). No FX conversion, no rounding recompute, no `kernel/money` call is added for this case. Tests: (a) same-currency move with lines succeeds and the estimate is unchanged; (b) USD to JPY move with a line is 422 and leaves `project_id`, `currency`, version, every line and the estimate unchanged; (c) USD to JPY move with no lines succeeds and `currency` re-derives; (d) the guard is under the requisition lock: a concurrent line add and a currency-changing PATCH leave either (lines in the old currency, old project) or (project moved, no lines), never lines in a currency other than the header's (real-Postgres, convention R lock order). Plant: remove the lines-exist check, and test (b) fails.
   Add `modules/requisitions/service.py` to this story's Files (it already ships from E09-S01; this is the one authorized edit).
