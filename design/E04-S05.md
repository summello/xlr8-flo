# E04-S05 — StatusPill primitive: closed per-document-type tone map, icon always, never author-coloured

**Epic** E04 · **M0** · **ui/M** · after **E04-S01** · tags: `ui`

## Requirements

- **TAG-001** — Every transactional and budget document must display a status badge drawn from a closed, per-document-type vocabulary mapped to one of five semantic tones (neutral, info, success, warning, danger).
- **TAG-002** — Status tone must be derived from status, never authored. A tenant, administrator or user must not be able to recolour a status or add a status value without a code change and a workflow-version bump.
- **TAG-003** — A status badge must always render tone colour **and** an icon **and** text. It must never be a bare coloured dot.
- **A11Y-004** — Color must not be the only way to communicate status, risk, validation, or financial direction.

## Deliverable

The primitive that makes every red pill in the product trustworthy. It ships in M0, before any document exists, because retrofitting strictness after eleven modules have each invented their own badge is impossible.

## Contract

```tsx
<StatusPill docType="purchase_order" status="issued" />
// tone, icon and label are all derived. There is no `color` or `icon` prop.
```

```ts
export const STATUS: Record<DocType, Record<string, StatusTone>> = {
  project:        { draft:'neutral', approval_pending:'info', active:'success',
                    deferred:'warning', completed:'neutral', abandoned:'danger' },
  requisition:    { draft:'neutral', approval_pending:'info', sourcing_in_progress:'info',
                    sourced:'info', awarded:'success', open_for_purchase:'info',
                    completed:'success', cancelled:'danger' },
  purchase_order: { draft:'neutral', approval_pending:'info', approved:'info',
                    issued:'success', partially_fulfilled:'info', fulfilled:'success',
                    closed:'neutral', cancelled:'danger', superseded:'warning' },
  rfq:            { draft:'neutral', published:'info', closed:'neutral',
                    under_evaluation:'info', awarded:'success', cancelled:'danger' },
  vendor:         { pending:'info', active:'success', suspended:'warning',
                    expired:'danger', inactive:'neutral' },
  budget:         { within:'success', nearing:'warning', exceeded:'danger' },
}
```

## Behaviour

1. **The map is the only source of tone (TAG-002).** The component takes no colour prop and no icon prop. There is no override, no `className` that can reach the tone colour, and no tenant configuration path. Adding a status requires editing this file.
2. **A status not present in the map does not render** — it throws in development and renders a neutral "Unknown status" pill in production rather than silently inventing a colour. Silent fallback is how a wrong status becomes invisible.
3. **Icon is mandatory (TAG-003, A11Y-004)**: `Circle`, `ArrowsClockwise`, `CheckCircle`, `Warning`, `XCircle` from Phosphor, one per tone. The icon is decorative to a screen reader (`aria-hidden`) because the text label already carries the meaning.
4. Geometry per `design-system/MASTER.md` §7.1: height 22, radius **6** (square-ish), padding 0 8, gap 5, label 12/560, filled tint background. **Deliberately not a pill** — that shape belongs to tags (E16-S09), and the distinction must survive greyscale.
5. Labels come from an i18n map, not from `status.replace('_',' ')`. `open_for_purchase` reads "Open for purchase", and a future locale can change it.
6. In a grid, the status column is fixed-width and left-aligned so the eye scans one ragged edge.
7. A Storybook-style route renders every `(docType, status)` combination for visual review and for the greyscale test.

## Acceptance criteria

- [ ] `<StatusPill>` accepts no colour or icon prop — asserted at the type level
- [ ] Every status in the map renders tone + icon + text
- [ ] An unmapped status throws in dev and renders a neutral unknown pill in prod
- [ ] Adding a status to a document type requires only a map edit, and immediately renders correctly
- [ ] **Greyscale test**: with `filter: saturate(0)`, every status is still identifiable by icon and text
- [ ] Contrast of every tone on its tint passes 4.5:1 in **both** themes — asserted by the E04-S01 contrast test extended to pills
- [ ] Radius is 6, not 999 — a snapshot test guards the distinction from tags
- [ ] Screen reader announces the label once, not twice (icon is `aria-hidden`)
- [ ] No component outside `StatusPill` renders a status colour — CI grep proves it
