# E15-S01 — Governed KPI registry: one definition per KPI, shared by executive and operational views

**Epic** E15 · **M4** · **engine/M** · after **E07-S06** · tags: `money` (Opus review)

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.
> Back end only. Dashboards that render these are E15-S06; read models and materialized refresh
> are E15-S02; row/field authorization at query time is E15-S03; time analysis for units and the
> organization is E15-S05.

## Requirements (inlined)

- **RPT-001** — Executive and operational reporting must be clearly separated while sharing governed definitions.
- **RPT-006** — Every KPI must have a documented definition, source, calculation, time basis, currency basis, and refresh time.
- Context, not closed here: **RPT-003** — project reporting shows allocation, reservation, commitment, actual, available balance, variance and consumption percentage (already served per project by E07-S06's `BalanceQueryRead`).

## Why

Today each screen computes its own figures (`components/dashboard/Kpis.tsx` derives variance and
consumption in the browser). A governed registry means one definition per KPI, in code, versioned and
reviewed, that every dashboard reads, so an executive card and an operational card can never
disagree about what "Committed" means.

## Design

**Registry in code, not in the database.** Definitions are governed by code review and versioned in
git; there is no endpoint that edits them (an admin-editable calculation is a reporting injection
surface and would defeat "governed"). New module `modules/reporting/`:

```python
@dataclass(frozen=True)
class KpiDefinition:
    code: str                    # "budget.committed", stable forever
    version: int                 # bumped on any change to the text fields or the calculation
    name: str                    # "Committed"
    definition: str              # plain language, one or two sentences
    source: str                  # "ledger_entry via project_balance (budget module)"
    calculation: str             # "SUM(amount) WHERE bucket = 'committed'"
    time_basis: Mapping[ScopeKind, tuple[Period, ...]]   # ScopeKind = "organization" | "unit" | "project"
    currency_basis: str          # see below
    refresh: Literal["live"]     # E15-S02 adds "materialized"
    audiences: frozenset[Literal["executive", "operational"]]
    unit: Literal["money", "percent"]
    evaluate: Callable[..., list[KpiValue]]               # private to the module

REGISTRY: Mapping[str, KpiDefinition]   # in modules/reporting/kpis.py
```

**The six KPIs in this story** (every one `audiences = {executive, operational}`; `currency_basis =
"Per currency. Amounts in different currencies are never added or converted; one value per
currency."`, the existing `budget_summary` and `aggregate_balance` rule):

| Code | Calculation | Source call |
|---|---|---|
| `budget.allocated` | Σ allocated | org/unit: `budget.service.budget_summary(conn, scope, unit_id)` `.totals` (abandoned Project Requests excluded, D-M2-22); project: `budget.service.balance_query(conn, scope, project_id, period, as_of, start, end)` |
| `budget.reserved` | Σ reserved | same |
| `budget.committed` | Σ committed | same |
| `budget.actual` | Σ actual | same |
| `budget.available` | allocated − (reserved + committed + actual) | same (`available` field) |
| `budget.utilization` | (reserved + committed + actual) / allocated, 2 places, half-up; `null` when allocated = 0 | the project path's `consumption_pct`; org/unit computed with **`consumption_ratio`**, which this story re-exports from `budget/service.py` `__all__` (it lives in `budget/queries.py`; never re-implement it) |

`time_basis`: project → `mtd, qtd, ytd, fiscal_year, life, range` (what `balance_query` supports);
organization and unit → `life` only (current balances from `project_balance`). Anything else → 422
`unsupported_period` naming the supported list. E15-S05 widens unit/organization.

No `float` anywhere: add `"reporting"` to `MONEY_MODULES` in `apps/api/scripts/check_money_floats.py`.

## API (`api/reporting.py`, prefix `/api/v1/reporting/kpis`)

| Method and path | Guard | Response |
|---|---|---|
| `GET /` | `report.view` at the organization | `?audience=executive|operational` (optional). 200 `[KpiDefinitionRead{code, version, name, definition, source, calculation, time_basis, currency_basis, refresh, audiences, unit}]` sorted by code. |
| `GET /{code}/values` | `report.view` at the target: organization when neither id is given, the BU/OU for `unit_id`, the project for `project_id` | `?unit_id=|project_id=&period=life&as_of=&from=&to=` → 200 `KpiValuesRead{code, version, scope:{kind, id}, period, range:{from, to}, as_of, refreshed_at, refresh, values:[{currency, value}]}`. Unknown code 404. Both ids 422. Unsupported period 422. Values are decimal **strings** (`"12.34"` for percent). |

**Why `report.view`, not `ledger.read`:** the role table in `docs/requirements.md` §3.1 gives the
Executive/Viewer role "Read dashboards and reports within authorized scope", and the seeded
`executive-viewer` role holds `report.view` and `budget.view`, not `ledger.read`. A KPI is an
aggregate at a scope the caller is granted; the drill-down to entries stays on E07-S06's
`ledger.read` routes. The target resolvers are the existing ones: `organization_target()`, the BU
target via `OrgService.get_unit` (404 foreign), the project target as in `api/budget.py`
`project_target`.

`refreshed_at` = the database `now()` of the read for `live` KPIs (one statement per call; the
underlying service calls already read one snapshot). `as_of` echoes the requested date or today.

## Governance gate

`tests/reporting/kpi_registry.lock.json` (committed) holds, per code, `version` and a SHA-256 of
`name|definition|source|calculation|currency_basis|time_basis|audiences|unit` plus the
`evaluate` function's source text (`inspect.getsource`). The test fails when a hash changes and the
version did not increase, when a code disappears (codes are never removed; retire with a later
`retired` flag if ever needed), or when any text field is empty. Regenerate with
`python -m flo.modules.reporting.kpis --lock` (prints the JSON; the author commits it).

## Acceptance

- [ ] `GET /` returns six definitions with every RPT-006 field non-empty; `audience=executive` and `audience=operational` both return all six (shared definitions, RPT-001).
- [ ] Hand-computed fixture (two currencies, one abandoned Project Request, a sub-project): organization, unit and project values equal the figures in the test's golden table, one value per currency, the abandoned project excluded.
- [ ] Project `period=ytd` with a fiscal year starting in April returns the E07-S06 golden figure; organization `period=ytd` → 422 `unsupported_period`.
- [ ] `utilization` is `null` when allocated is zero and `"0.50"` for 50 of 100.
- [ ] Concurrency (real Postgres): `reporting.service.values(conn, scope, codes, target, …)` evaluates several codes from **one** underlying service read. While a second connection posts 50 allocations and reservations, 50 calls for all five bucket KPIs each satisfy `available = allocated − (reserved + committed + actual)` per currency. No call sees a torn state.
- [ ] Authorization (convention A): executive-viewer with an org grant 200 on all three scopes; a requestor (no `report.view`) with a grant at the unit → 403; no grant covering the project → 404; foreign-tenant project or unit → 404.
- [ ] Money lint covers `modules/reporting` (plant below).
- [ ] TEN-010 entries in `test_route_coverage.py::COVERED`; generated client regenerated; `flo check --light` green.

## Tests (AGENTS.md §3.5, money)

`flo.api.health.app`, isolation entries.

## Plants

1. Change `budget.committed`'s `definition` text without bumping `version`: the lock test fails.
2. Return `float(value)` in one `evaluate`: `check_money_floats.py` fails on `modules/reporting` (name the rule in the report).
3. Drop the `report.view` guard on `/values` (use `require_member`): the 403 test fails.
