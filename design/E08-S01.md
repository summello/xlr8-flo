# E08-S01 — Import framework: template versioning, column mapping, type and reference validation

**Epic** E08 · **M1** · **engine/L** · after **E03-S06** · tags: `security`

## Requirements

- **IMP-001** — The system must support robust Excel and CSV imports aligned to the application’s data model.
- **IMP-002** — Import templates must declare required columns, data types, accepted codes, examples, and template version.
- **IMP-003** — A mapping step must allow source columns to map to fields, including approved custom fields.
- **IMP-004** — Imports must validate file structure, formulas/macros policy, types, references, permissions, duplicates, and business rules before commit.

## Design decisions (confirm on review)

- **D-M1-19 Import framework scope.** Files are CSV or XLSX. **Formulas and macros policy (IMP-004): any formula cell, any `.xlsm`, any macro-bearing or externally-linked workbook is rejected at upload** (cells are read as cached values only if the file contains no formulas; one formula → whole file rejected with the cell addresses). XLSX is parsed with the standard library (`zipfile` + `xml.etree.ElementTree`) — **no new dependency** — with ZIP bomb limits (uncompressed size cap 50 MiB, member count cap 100, ratio cap 100:1) and `<!DOCTYPE`/`<!ENTITY` rejected before parsing. Upload size cap 10 MiB, 50,000 rows.
- Templates are **code**, not data: `modules/imports/templates/<name>.py` registers a `Template(name, version, columns=[Column(name, type, required, accepted_codes_source, example)], key_columns)`; a version bump is a code change reviewed like any other. Custom-field mapping (IMP-003 "approved custom fields") is an extension point that lists none until M4.

## Contract

Migration (reversible): the next revision after the current head at story start (revision id `20260826_<next 4-digit number>`, `down_revision` = the head `python -m flo.kernel.migrate --check` validates today); stories merge one at a time, so there is no gap or fork: `import_batch(id uuid pk, org_id, template text not null, template_version int not null, uploader_id uuid not null, file_name text, file_sha256 char(64) not null, file_size int, status text not null default 'uploaded' check in ('uploaded','validated','failed_validation','committing','committed','failed','cancelled'), mapping jsonb, counts jsonb, created_at, validated_at, committed_at)`; the file bytes are stored in the private storage port (R2/MinIO) under `imports/<org_id>/<batch_id>`, never in Postgres. RLS forced. Permissions `import.run`, `import.read`.

- `GET /api/v1/imports/templates` → 200 list `{name, version, columns:[{name,type,required,example,accepted_codes_url?}]}` (IMP-002); `GET /api/v1/imports/templates/{name}/file?format=csv|xlsx` → 200 a template file with header row and an example row, and the template version in a `X-Template-Version` header and in the file
- `POST /api/v1/imports` multipart `{template, file}`, `Idempotency-Key` → 201 `ImportBatchRead` (status `uploaded`, detected headers, row count) | 413 | 415 | 422 (formula/macro/structure, with cell addresses) 
- `PUT /api/v1/imports/{id}/mapping` body `{mapping: {template_column: source_header}}` → 200 (IMP-003); missing a required column → 422 naming it

Validation of rows is E08-S02; this story delivers upload, structure checks, templates and mapping only.

## Behaviour

1. Structure validation (IMP-004, the structural part): header row present, no duplicate headers, headers map to template columns, type-parsable columns, required columns present, row cap, formula/macro rejection.
2. Type parsers (shared with S02): `text`, `integer`, `decimal` (accepts `1234.56` only, **never** thousands separators, never floats: parsed with `Decimal`), `date` (ISO 8601 only), `code` (resolved against master data, S02), `enum`.
3. `file_sha256` is computed while streaming; the stored object name is the batch id, never the client file name; the client name is stored as display text only and output-encoded.
4. All endpoints scoped to the org; a foreign batch id is 404.

## Acceptance criteria

- [ ] A valid CSV and a valid XLSX both reach `uploaded` with correct headers and row counts (XLSX fixture generated in the test)
- [ ] An XLSX with a formula cell → 422 with the cell address; an `.xlsm` or a workbook with `vbaProject.bin` → 422; a ZIP bomb fixture (ratio > 100:1) → 422 without exhausting memory; an XLSX with `<!ENTITY` → 422
- [ ] Duplicate header, missing required template column, unknown column → 422 with field-level detail
- [ ] A 10 MiB + 1 byte upload → 413; a wrong content type or a `.exe` → 415
- [ ] Template download round-trips: uploading the downloaded template with its example row reaches `uploaded`
- [ ] Mapping missing a required column → 422; a valid mapping is stored and returned
- [ ] The file bytes exist only in storage, the DB row holds only the checksum; the checksum equals `sha256` of the bytes
- [ ] Foreign-tenant batch id → 404 on GET/PUT (isolation gate entries); `import.run` required (403 otherwise)
- [ ] Replayed `Idempotency-Key` → same batch, one stored object
- [ ] Migration up/down/data-preservation
