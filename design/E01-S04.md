# E01-S04 — CI: lint, types, tests, gitleaks, import-linter, roadmap drift check

**Epic** E01 · **M0** · **chore/L** · after **E01-S03** · tags: `security`

## Requirements

- **SEC-012** — Dependency scanning, secret scanning, static analysis, dynamic testing, and an SBOM must be part of release controls.

## Deliverable

`.github/workflows/ci.yml` already exists in the repository. This story **activates** it against real code and adds the two controls SEC-012 names that are still missing: dependency scanning results as an artifact, and an SBOM.

## Behaviour

1. Verify the existing job graph runs end to end now that `apps/api` and `apps/web` exist. The `detect` job publishes `api`/`web` path outputs; `backend` and `frontend` gate on them. **Do not reintroduce `hashFiles()` in a job-level `if:`** — it evaluates before checkout and silently disables the job.
2. Add SBOM generation (`syft` or `cyclonedx-py` + `cyclonedx-npm`) uploaded as a build artifact per run, for both the Python and Node dependency trees.
3. Trivy already runs pinned at `@0.28.0` with `severity: CRITICAL,HIGH` and `exit-code: 1`. Add `--format sarif` upload so findings surface in the Security tab.
4. Confirm every existing gate fires. Each must be proven by a deliberately broken commit that is then reverted:
   | Gate | Break it with |
   |---|---|
   | `ruff` / `mypy --strict` | an untyped function |
   | `lint-imports` | `flo.modules.a` importing `flo.modules.b` |
   | float ban | `def f(x: float)` in `modules/budget` |
   | hardcoded colour | `color: #ff0000` in a `.tsx` outside `tokens.css` |
   | roadmap drift | edit `docs/claude-plan.md` §5 by hand |
   | scorecard drift | edit `agents/SCORECARD.md` by hand |
   | story-id commit | a commit message without `Enn-Snn:` |
   | gitleaks | a fake `sk-ant-` string |
5. CI must stay under ~15 minutes and within the 2,000 free minutes/month (OPS-001). Cache pip and npm.

## Acceptance criteria

- [ ] A PR with all gates satisfied goes green
- [ ] Each of the eight gates above fails CI when deliberately broken, and passes when reverted — evidence linked in the PR body
- [ ] SBOMs for both dependency trees are attached to the run
- [ ] Trivy findings appear as SARIF in the Security tab
- [ ] Full run completes in under 15 minutes on a cold cache

## Files

`.github/workflows/ci.yml`, `apps/api/pyproject.toml` (coverage config), `docs/ops/ci-gates.md` (the evidence table)

## Branch-protection follow-up (part of this story's done criteria)

`apps/api` and `apps/web` come into existence with E01-S01, which is what makes three
gates start reporting. Until then they report `skipped`, and GitHub counts a skipped
required check as **passing** — so requiring them early silently enforces nothing.

When this story completes, update the `Protect main` ruleset to require:

| Add | Why it can be required now |
|---|---|
| `backend` | `apps/api/pyproject.toml` exists, so the job runs |
| `frontend` | `apps/web/package.json` exists, so the job runs |
| `analyze (python)` · `analyze (javascript-typescript)` | CodeQL has source to analyze |

Never require `deploy` — it runs on push to `main` only and can never report on a PR.

Re-add the `code_scanning` rule (CodeQL, `high_or_higher`) only **after** the first
analysis has completed on `main`. Requiring it before it has ever run blocks every PR.

## Out of scope

Deployment (E01-S05) · penetration testing and DAST (E19-S02).
