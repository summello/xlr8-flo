# E23-S03 — The nemotron launcher reads its model from `agents.yaml` and records what it launched

**Epic** E23 · **MT** · **chore/S** · tags: none · backlog item T3 · no dependency, can run beside E23-S01 and E23-S02

> MT stories ship by a pull request to `main`, as E21-S01 did (PR #18).
> **No new dependency** (AGENTS.md §0.6).

## Requirement (inlined)

- **SUP-005** — Administrator and operator documentation must be updated in the same PR as the feature it describes (UX-010).

## Why

`agents/agents.yaml` says which model each agent runs. The launcher ignores it. A config edit, even a typo fix, silently changes nothing, and a deliberate swap in the launcher silently changes the model behind a scorecard row. E23-S04 reorders authors on the strength of nemotron's scorecard history, so that history must stay attributable to one known model.

## Pre-flight findings (Opus, 22 Oct 2026, traced against `799797d`)

- `agents/scripts/author.sh` line 57 hardcodes `openrouter/nvidia/nemotron-3-ultra-550b-a55b:free`. `agents.yaml` `opencode-nemotron.model` is `nvidia/nemotron-3-ultra-550b-a55b:free`. They agree today; nothing keeps them agreeing.
- **The same pattern is in `agents/scripts/review.sh` lines 12 to 14**: qwen, kimi and deepseek model ids are hardcoded in a `case`. Reviewer blocker-precision numbers drive routing (`agents/claude.md` §5), so a silent reviewer-model change corrupts them the same way.
- `author.sh` passes `--effort medium` to Sonnet (lines 42 and 44), while `agents.yaml` says `reasoning: high  # passed as --effort`. That is a **value** disagreement, not a missing-mechanism one. See Design decisions.
- The scorecard record already carries a `sessions` object per agent (`agent`, `id`, `source`). A launched model fits there without a schema change.
- Nemotron's `sessions` entry in the existing records reads `id: null, source: "unavailable: no opencode session ..."`: the launcher never recorded anything for it.
- Privacy note, so it is not rediscovered: OpenRouter's free-tier notice says NVIDIA logs usage for security and product improvement. Irrelevant here because this lane never takes a gated (money, auth, security, migration, concurrency) story: `avoid_tags` keeps it off them. If that ever changes, revisit.

## Design decisions (confirm on review)

1. **Include `review.sh`'s OpenRouter reviewers.** The backlog names only the nemotron author launcher. The reviewer case statement is the same defect with the same fix and the same test, three lines. Recommended: include. If the reviewer rejects the extra scope, drop the `review.sh` change and keep the rest.
2. **Do not touch Sonnet's `--effort medium`.** Reading it from config would flip a running value from medium to high (cost and speed change) or force `agents.yaml` to be edited to `medium` (only the planner edits that file, `agents/claude.md` §5). Record the disagreement in `notes.followup` for the planner. Claude aliases (`sonnet`, `opus`) are aliases, not pinned ids; out of scope.

## Design

### 1. `flo launch-model <STORY_ID> [--reviewer NAME]`

New subcommand in `agents/scripts/flo`. It resolves the model, **records it**, and prints it, so the recorded value is by construction the string that was used.

- Author (no flag): agent = `task.json` `author`. Reviewer: agent = NAME.
- Model = `load_yaml(FLEET)["agents"][agent]["model"]`. A missing agent or missing `model` key exits non-zero with a message naming the agent. **Never fall back to a default model.**
- Record into `task.json`: `sessions[agent]["model"] = <model>`, merging into the existing record; if none exists, create `{"agent": agent, "id": null, "source": "launch-model", "model": <model>}`. Do not overwrite `id`, `account` or `source` of an existing record.
- Print the model id exactly as configured (no `openrouter/` prefix); the shell adds the prefix.

### 2. `agents/scripts/author.sh`

In the `opencode-nemotron` branch, compute `M="$("$W/apps/api/.venv/bin/python" "$R/agents/scripts/flo" launch-model "$S")"` (the same interpreter pattern the sonnet branch uses for `flo account`) before the `nohup`, and pass `-m "openrouter/$M"`. If the command fails the launch aborts (`set -e` is already on); do not launch with an empty model.

### 3. `agents/scripts/review.sh` (decision 1)

Replace the `qwen`/`kimi`/`deepseek` `case` model literals with `M="openrouter/$(... flo launch-model "$S" --reviewer "$A")"`. Keep the `case` only for anything that is not a model id.

### 4. Operator docs (SUP-005)

One paragraph where the fleet commands are documented (find with `grep -rn "flo account" docs/ agents/`) saying the launchers read `agents.yaml` and what `sessions[agent].model` means. Update the usage text at the top of `flo`.

## Acceptance criteria

- [ ] `author.sh` and `review.sh` contain none of the strings `nemotron-3-ultra`, `qwen3`, `kimi-k2`, `deepseek-v4`.
- [ ] `flo launch-model E23-SXX` against a fixture config prints the configured model and writes `sessions.<agent>.model` without altering `id`/`account`/`source`.
- [ ] Changing `agents.<agent>.model` in a fixture `agents.yaml` changes the printed value. This proves the config change reaches the launch command.
- [ ] An agent with no `model` key makes the command exit non-zero and print the agent name; `author.sh` then does not launch.
- [ ] The next scorecard record for a nemotron-authored story carries `sessions.opencode-nemotron.model`.
- [ ] `notes.followup` records the Sonnet `--effort` disagreement.

## Plants

1. Re-insert the literal `nemotron-3-ultra-550b-a55b` into a copy of `author.sh` content in the test: the no-literal test must fail.
2. Remove `model` from the fixture agent: the command must fail, not print a default.
3. Change the fixture model string: the printed value must change. A launcher that ignores config fails this.
