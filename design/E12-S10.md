## Requirements (inlined)

- **SRC-009** — The comparison dashboard must normalize and compare total cost, unit cost, tax, freight, lead time, compliance, vendor score, and configured criteria.
- **SRC-010** — conversion shows rate, source and effective date, and never alters the bid.
- **SRC-007 / SRC-008** — sealed until the deadline; a late bid is marked and included only through an audited override.
- **A11Y-009 / RPT-013** — every chart ships an accessible data table.
- **A11Y-003 / A11Y-004** — no drag-only paths; colour never alone.

## Scope

Route `/sourcing/rfqs/:id/comparison`, as specified in `pages/rfq-comparison.md` §1 to §7: the award
basis cards with insight, scope pill and justification notice; the verdict strip; the matrix with
groups, `Show Only Differences`, sticky header and narrow two-vendor mode; the tabs `Overview`,
`By Line`, `Cost Breakdown` (bar chart **and** its `Table` tab) and `Scoring`; the bid sheet; the
sticky award bar with **`Start Award`** (a hand-off to `/sourcing/rfqs/:id/award` with the basis;
until E12-S16 exists, the route registry hides the button and records a follow-up). The states are
sealed, no bids, scores not available, stale rate with `Refresh Rate`, over scope, and all five widths.

**Pre-flight 26 Oct 2026 (Codex, fail 6), settled here:**
- **Sealed count:** `SealedComparisonRead` is only `{sealed: true}`; the count comes from the RFQ read
  (`RfqRead.bids_received`, `modules/sourcing/schemas.py`), which the page already loads for its header.
- **Bid sheet contents follow the server.** The sheet always shows what E12-S06's `VendorFigures`
  carries. The per-requirement answers, `delivery_terms`, warranty, exceptions and override note (`BidRead` has no separate `terms` field) come from the bid read
  (`GET` bid, `modules/sourcing/bids.py:350`), which the server refuses to a user without `rfq.approve`
  who did not key that bid; on a refusal those sections are omitted, not shown empty or as an error.
  The page grants nothing the server refuses.
- **`Refresh Rate`** is shown only when the user holds `rfq.edit` on the RFQ's unit, which is what the
  route enforces (`api/sourcing.py:456`). Decision 117 ("any sourcing role") disagrees with the server:
  record it in `notes.followup` for the operator; do not change the server here.
- **Sheet width:** `--sheet-w` from `tokens.css`. The page spec's 640px is not a registered exception
  and MASTER has the token, so 640px is stale (record it in `notes.followup`).
- **Container cutoffs:** the page spec's 1000px and 560px are content-width container-query cutoffs,
  which MASTER has no token for (MASTER §breakpoints are viewport widths), so the page file's values
  stand (AGENTS.md, UI authority 2).

## Blocked

Second pre-flight 26 Oct 2026 (Codex, fail 6). These are scope or rule decisions for the operator,
because the server is out of scope here and the page computes no figure:

- **B1 (scope):** the page spec needs figures E12-S06 does not return: per-vendor `In This Selection`
  totals and the amount to spare (`Basis` has only total, `within_scope`, `over_by`,
  `sourcing/comparison.py:99`), and the `Late` marker with its override note (`VendorFigures` has
  neither, `comparison.py:51`). Either a server follow-up to E12-S06 adds them before this story, or
  this screen drops them.
- **B2 (authorization):** evaluator declarations on the Scoring tab come back only to `rfq.edit`
  (`sourcing/evaluation.py:377`), and the bid read refuses evaluators who did not key the bid
  (`bids.py:350`); the page spec shows both to evaluators. Which is right: the server, or the spec?
- **B3 (money, page §8.1):** how a split award interacts with a vendor's minimum order value. Still
  open since 10 Oct; the engine computes nothing for it.

Markers are icon plus words inside their cell. The three colour jobs come from tokens only (decision
120), and there is a colour key. Money is tabular, right-aligned, with the currency code; negatives
are parenthesised and signed.
