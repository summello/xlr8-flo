# E06-S02 — Five-level hierarchy with recursive CTE traversal and depth guard

**Epic** E06 · **M1** · **engine/L** · after **E06-S01** · tags: 

## Requirements

- **PROJ-004** — Sub-projects must be creatable manually or automatically from a requisition.
- **PROJ-005** — A project hierarchy must support up to five levels.

## Contract

Migration `20260826_0025` (down `…_0024`): add `project.depth smallint not null default 1 check (depth between 1 and 5)` and `project.root_id uuid`, backfilled for existing rows (a data-preservation test covers a pre-existing 3-level tree). A BEFORE INSERT trigger sets `depth = parent.depth + 1` and `root_id = parent.root_id` (or the row's own id for a root), rejecting a parent in another org or a parent whose `depth` is already 5 (`23514`, mapped to 422 `ProjectDepthExceeded`). `parent_id` and `org_id` are immutable (trigger rejects UPDATE of those columns) — D-M1-15.

Service API (`projects.service`, imported by budget via `service` only):

- `ancestors(project_id) -> list[ProjectRef]` (nearest first) — one recursive CTE, depth-guarded (`WHERE depth_guard < 6`)
- `descendants(project_id, include_self=True) -> list[ProjectRef]` — one recursive CTE with the same guard
- `lowest_common_ancestor(a, b) -> ProjectRef | None`
- `path_between(a, b) -> PathRead{up: [ids a→LCA exclusive], lca, down: [ids LCA exclusive→b]}` (used by E07-S08); two projects in different root trees have no LCA → returns `lca=None` and the transfer service rejects with `TransferNotEligible`
- `depth_of(project_id)`

Endpoints (permission `project.read`):
- `GET /api/v1/projects/{id}/children?cursor=&page_size<=50` → 200
- `GET /api/v1/projects/{id}/tree?max_depth=5` → 200 nested `{id, number, name, status, depth, children[]}` capped at 500 nodes with `truncated: true` when exceeded
- `POST /api/v1/projects` (from E06-S01) now accepts `parent_id` and enforces depth

## Behaviour

1. Sub-projects may be created manually here (PROJ-004); the requisition-generated path calls the same service in M2.
2. A child must be in the same org; it may be in a different BU/OU than its parent only if the caller holds `project.create` on the child's BU/OU **and** `project.read` on the parent.
3. Every traversal is a single recursive CTE; none loads the whole table or loops per level in Python. A test asserts a tree of 5 levels is fetched in one query (count statements).
4. The CTE is depth-guarded so a corrupt cycle (planted by a superuser insert) terminates instead of looping.

## Acceptance criteria

- [ ] A sixth level is rejected by the service **and** by the database trigger when inserted directly
- [ ] Changing `parent_id` or `org_id` on an existing project fails in the database
- [ ] `ancestors`, `descendants`, `lowest_common_ancestor` and `path_between` return the hand-computed answers on a planted 5-level tree with two branches (golden test), each in one SQL statement
- [ ] A planted cycle (inserted with triggers disabled in the test) does not hang `ancestors`/`descendants`
- [ ] `tree` truncates at 500 nodes and says so; `max_depth` filters
- [ ] Foreign-tenant project id → 404 on children/tree (isolation gate entries); a child under a foreign-tenant parent → 404
- [ ] Migration up/down/data-preservation
