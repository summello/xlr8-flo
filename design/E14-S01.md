# E14-S01 — Warehouses: owning BU/OU, locations, custodians, active status, supported categories

**Epic** E14 · **M4** · **crud/M** · after **E05-S01** · tags: none (ungated)

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`.
> Back end only. The warehouse screens are a registered **GAP** (`docs/ui-screen-inventory.md` §3.8;
> canvas-2 page 3.8, undrawn). Stock is E14-S02.
> **Writes:** every `PATCH`/`PUT`/`DELETE` on an editable resource follows `docs/m2-conventions.md` §O (`If-Match` with the integer version, `ETag` on reads, 400 when missing, 409 `stale_version` on mismatch). `Idempotency-Key` protects **POST** commands only (the middleware ignores other methods).
> **RLS:** every new tenant table gets literal `ALTER TABLE <t> ENABLE ROW LEVEL SECURITY; … FORCE …; CREATE POLICY tenant_isolation ON <t> …` statements in the migration text, one block per table, never generated by a helper or f-string (the static gate in `tests/isolation/test_ci_guards.py` reads the text; the light check runs it).

## Requirements (inlined)

- **AST-001** — Each BU/OU may create warehouses for unassigned fixed assets and basic stock counts.
- **AST-002** — Warehouses must record locations, custodians, active status, and supported item categories.
- **ORG-007** — Each BU/OU may contain multiple warehouses.

## Why

E14-S02 (stock movements), E14-S03/S04 (assignment, valuation) and E14-S05 (the asset register's
`location`) all hang off a warehouse and its locations. This story gives them a stable row to
reference, authorized at the owning BU/OU.

## Reuse (verified 23 Oct 2026)

- Permissions already exist: `asset.view`, `asset.create`, `asset.edit` in
  `modules/identity/models.py` `PERMISSION_CODES`, granted to `warehouse-asset-user` and
  `organization-administrator`; `auditor` gets `asset.view` by construction. **No new permission,
  no permissions migration.**
- Categories are the existing master kind `item_category` (`modules/org/master_kinds.py` `RULES`).
  Validate with `org.service.assert_usable(conn, scope, "item_category", code, today)`; it raises
  `MasterCodeUnusable` (`reason` unknown / inactive / not_effective) → 422 on `category_codes[i]`.
- Units: `org.service.OrgService(conn, scope).get_unit(unit_id)` (404 for foreign/absent).
- Custodians: `identity.service.user_exists(conn, scope, user_id)` (the `projects/risks.py` precedent).
- Display: `identity.service.emails_by_id` for `custodians[].email` (and the sibling
  `custodians[].name` from `identity.display_name` if E22-S07 has merged; it has a schema test
  that will demand it).
- List authorization: `kernel.authz.require_granted("asset.view")` → `GrantedScopes`; filter
  `unit_id = ANY(bu_ids)` unless `org_wide` (the `api/projects.py` list precedent). `bu_ids` already
  covers descendants.

## Data (new module `modules/assets/`, one migration, all four tables RLS)

`warehouse`: `id uuid`, `org_id`, `unit_id uuid NOT NULL` (FK `org_unit`), `code text NOT NULL`
(stored upper-case, `CHECK (code ~ '^[A-Z0-9][A-Z0-9_-]{0,29}$')`), `name text NOT NULL`
(1..200 after trim), `active bool NOT NULL DEFAULT true`, `row_version int NOT NULL DEFAULT 1`,
`created_by`, `created_at`, `updated_at`. `UNIQUE (org_id, code)`.

`warehouse_location`: `id`, `org_id`, `warehouse_id` (FK), `code` (same CHECK), `name` (1..200),
`active bool DEFAULT true`. `UNIQUE (org_id, warehouse_id, code)`. Never deleted (stock will point
at it).

`warehouse_custodian`: `org_id`, `warehouse_id`, `user_id uuid`, `added_by`, `added_at`.
`PRIMARY KEY (org_id, warehouse_id, user_id)`.

`warehouse_category`: `org_id`, `warehouse_id`, `category_code text`. `PRIMARY KEY (org_id, warehouse_id, category_code)`.

`unit_id` and `code` are **immutable** after create (moving a warehouse between units would move
its authorization; a new warehouse is the answer).

## API (`api/assets.py`, prefix `/api/v1/warehouses`)

| Method and path | Guard | Behaviour |
|---|---|---|
| `POST /` (Idempotency-Key) | `asset.create` at `body.unit_id` (BU target; 404 for a foreign unit, before authorization, like `api/projects.py` `create_target`) | Body `{unit_id, code, name, custodian_ids: uuid[0..20], category_codes: str[0..100], locations: [{code, name}] 0..200}`. 201 `WarehouseRead`. Unit inactive → 409 `unit_inactive`. Duplicate code → 409 `duplicate_code`. Unknown custodian → 422 `custodian_ids[i]`. Bad category → 422 `category_codes[i]`. Duplicate location code in the body → 422. |
| `GET /` | `require_granted("asset.view")` | `?unit_id=&active=&q=&cursor=&page_size` (1..50, default 50). Keyset on `(code, id)`. `q` matches a case-insensitive prefix of code or name. Rows outside the caller's granted units never appear. |
| `GET /{id}` | `asset.view` at the warehouse's unit | `WarehouseRead` with `ETag: "<row_version>"`. |
| `PATCH /{id}` | `asset.edit` at the unit | `If-Match`. Fields: `name`, `active`, `custodian_ids` (replaces the set), `category_codes` (replaces the set). `unit_id` or `code` in the body → 422 naming the field. Bumps `row_version`. |
| `POST /{id}/locations` (Idempotency-Key) | `asset.edit` | `If-Match` (warehouse version). `{code, name}` → 201 `WarehouseRead`. Duplicate → 409 `duplicate_code`. Bumps `row_version`. |
| `PATCH /{id}/locations/{location_id}` | `asset.edit` | `If-Match` (warehouse version). `{name?, active?}`; `code` → 422. Bumps `row_version`. |

`WarehouseRead`: `id, unit_id, unit_code, code, name, active, row_version, custodians: [{user_id, email}], category_codes: str[] (sorted), locations: [{id, code, name, active}] (sorted by code), created_at, updated_at`.

Each write runs in one `tenant_transaction`: lock the warehouse row `FOR UPDATE`, compare
`row_version`, write, audit. Audit actions: `warehouse.create`, `warehouse.update`,
`warehouse.deactivate` (when `active` goes true → false), `warehouse.reactivate`,
`warehouse.location.create`, `warehouse.location.update`. `after` carries the changed fields,
custodian ids and category codes (no emails in the audit).

**Deactivation in this story** is unconditional. E14-S02 adds "no deactivation while stock is on
hand" and "no removal of a category that has stock"; do not stub it here.

## Invariants

- `org_id` from the session only; no route accepts it.
- Foreign tenant on any `{id}` or `location_id` → 404; a location of another warehouse → 404.
- No hard delete of a warehouse or location anywhere (no `DELETE` route).
