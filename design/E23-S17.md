# E23-S17 — Recoverable execution records: write before launch, process identity, transient-error retries

**Epic** E23 · **MT** · **chore/M** · **priority P0** (operator, 23 Oct 2026) · **after E23-S14 and E23-S15**

> MT stories start from and merge into the checked-out milestone (d9ba9c3). **No new dependency** (AGENTS.md §0.6).
> **Review: Codex only.** Operator, 23 Oct 2026: every Opus planner and reviewer sleeps until the E23 flo fixes
> (S14 to S18) are on the milestone PR and its CI is green. Codex must plant every violation listed below.

## Requirement (inlined)

- **SUP-005** — Administrator and operator documentation must be updated in the same PR as the feature it describes.

## Why

Revalidated by the planner on `9a53605` (23 Oct 2026; Codex assessment finding 4):

1. `agents/fleet/fleet.py::launch()` calls `subprocess.Popen` before writing the JSON run record. A crash,
   power loss or exception in that gap leaves a live process the supervisor cannot see, so the next tick may
   launch the same step again.
2. `records()` decides liveness with pid alone. macOS can reuse a pid; an unrelated process then makes a dead
   run look busy indefinitely.
3. `flo_facts.py` classifies `ENOTFOUND` and `ECONNRESET` as usage limits. A transient network failure then
   waits for a quota-reset schedule that does not apply, while a real quota limit and a network outage need
   different recovery policy.
4. The supervisor retries from its last record without first reconciling external state. A submit may already
   have pushed, a finish may already have merged into the milestone, or an author may still be live even when
   a wrapper died before recording success.

## Design

### 1. Atomic, pre-launch run records

- For every run identity delivered by E23-S14, atomically write `<run>.json.tmp` then `os.replace()` it onto
  `<run>.json` **before** `Popen`. The pre-launch record contains story, step, reviewer, command, head,
  attempt, start timestamp and state `launching`, with pid/start identity null.
- After `Popen`, read the process start time with `ps -o lstart= -p <pid>` and atomically replace the record
  with state `running`, pid and normalised start identity. If the second write fails, the visible `launching`
  record remains recoverable rather than disappearing.
- A `launching` record with no pid is not blindly relaunched: the next tick runs step-specific reconciliation,
  then either records success, finds a live matching process, or marks the attempt dead before retry policy.
- All JSON writes use a same-directory temporary file and `os.replace`; readers never see partial JSON.

### 2. Process identity, not pid alone

- A running record is live only when its pid exists **and** `ps -o lstart=` matches the recorded start identity.
  Whitespace/locale normalisation is shared by writer and reader.
- A missing pid, failed `ps`, or mismatched start time is dead. Never signal or wait for the mismatched process.
- Old records without start identity remain readable but are treated as dead/reconcilable, not permanently busy.

### 3. Separate transient network failures from limits

- `flo_facts.author_result()` distinguishes `network` from `limit`; `ENOTFOUND` and `ECONNRESET` are network.
  Existing last-600-characters and last-exit rules remain, so product prose cannot trigger the classifier.
- For the same story/step/head, network failure retries use bounded backoff after the failed attempt:
  1 minute, then 5 minutes, then 15 minutes. After three retries, emit an operator need instead of looping.
- A quota/session limit continues to wait for the reported reset/capacity signal. Do not change `capacity()`'s
  operator-approved policy that unknown telemetry allows work.
- Store retry kind, attempt and `retry_at` in the run record so a restart preserves the schedule.

### 4. Reconcile before retry

- **submit:** fetch/read origin and succeed without rerunning when `origin/<story branch>` already equals the
  story worktree HEAD; update the ordinary submit evidence/task state if needed.
- **finish:** succeed without rerunning when the milestone already contains the story squash commit, using the
  existing `merged_in(<STORY>, <milestone head>)` rule.
- **resume/author:** do not launch while E23-S15's live-author guard says an author process is live.
- Reconciliation is read-only until it can prove the prior external effect happened. Uncertain state remains a
  need or a scheduled retry; it never guesses success.

## Invariants

- No process is intentionally launched before a durable record names the intended action.
- A reused pid never keeps a run busy and is never killed as if it were the recorded process.
- Retry count and backoff survive supervisor ticks and restarts.
- Submit and finish are idempotently reconciled before repetition; no force-push or merge to `main` is added.
- Unknown capacity telemetry still allows work, exactly as today.

## Acceptance criteria

- [ ] Patch `Popen` to raise: a complete `launching` JSON record already exists and parses; no partial `.tmp`
      is consumed by `records()`.
- [ ] Crash between `Popen` and the second record write: the next tick reconciles before any duplicate launch.
- [ ] A live pid with matching recorded `lstart` is busy; the same pid with a different start identity is dead.
- [ ] An old record without process identity is reconciled and cannot block a story forever.
- [ ] `ENOTFOUND` and `ECONNRESET` classify as network; session/quota messages still classify as limit.
- [ ] Fake time proves network retries at 1, 5 and 15 minutes, with no early launch and an operator need after
      the third retry; a quota limit does not use this schedule.
- [ ] Submit reconciliation does not rerun a check/push when origin story ref equals HEAD.
- [ ] Finish reconciliation does not rerun when the milestone contains the story commit.
- [ ] Resume reconciliation launches nothing while a matching live author exists.
- [ ] `docs/ops/fleet-tooling.md` documents record states, process identity, backoff and reconciliation.

## Plants (prove each guard fails)

- Move the first record write after `Popen`: the raised-`Popen` ordering test fails.
- Compare pid only: the reused-pid/start-time test stays busy and fails.
- Put network errors back in the quota regex: the classifier/backoff test fails.
- Retry submit before checking the remote ref: the reconciliation test observes the command launch.
