# E07-S06 — Balance query API: MTD/QTD/YTD/fiscal/life-to-date/range, reconcile to entries

**Epic** E07 · **M1** · **api/M** · after **E07-S05** · tags: `money`

> **Conventions:** read `docs/m1-conventions.md` (authorization outcomes, scope targets, wire formats). It applies unless this packet says otherwise.

## Requirements

- **BUD-009** — Balances must support MTD, QTD, YTD, fiscal-year, life-to-date, and selected ranges.
- **BUD-011** — A user must be able to reconcile a displayed balance to its component entries.
- **ACC-003** — Every dashboard balance drills down to a ledger that recalculates to the same value.

## Contract

Permission `ledger.read` on the project's scope.

- `GET /api/v1/projects/{project_id}/balance?period=mtd|qtd|ytd|fiscal_year|life|range&as_of=YYYY-MM-DD&from=&to=` → 200 `BalanceRead{project_id, currency, as_of, range:{from,to}, allocated, reserved, committed, actual, available, consumption_pct, variance, reconciles: bool}` (all amounts decimal **strings**; `consumption_pct` a decimal string with 2 places; `variance = allocated - (reserved+committed+actual)` i.e. equals `available`; keep both for RPT-003) | 404 | 422 (bad period/range)
- `GET /api/v1/projects/{project_id}/ledger?bucket=&entry_type=&from=&to=&cursor=&page_size<=50` → 200 keyset-paged entries ordered `(effective_date, id)`; each entry includes `source_type`, `source_id`, `reverses_entry_id`, `releases_entry_id`, actor, reason (BUD-011 drill-down).
- `GET /api/v1/projects/{project_id}/balance/reconcile?...same params` → 200 `{balance, entries_total_by_bucket, difference_by_bucket}` where each difference must be `"0.0000"`.

Period math lives in `fiscal.service.range_for` (E05-S04): `mtd` = first of the month of `as_of` to `as_of`; `qtd` = first day of the **fiscal** quarter containing `as_of` (quarters are fiscal periods 1-3, 4-6, ...); `ytd` and `fiscal_year` = fiscal year start to `as_of` / to fiscal year end; `life` = no lower bound; `range` = explicit `from`/`to`, `to >= from`, max span 20 years.

## Behaviour

1. **Period balances are computed from the ledger**, not from `project_balance` (the rollup is life-to-date only): `SUM(amount) GROUP BY bucket WHERE effective_date BETWEEN from AND to`. `life` also reads the rollup and sets `reconciles` by comparing it to the summed entries (ACC-003).
2. Amount formatting comes from `Decimal`; no float on the read path. Percent: `consumption = (reserved+committed+actual)/allocated`, quantized with `kernel/money.py`; `allocated = 0` → `consumption_pct = null`.
3. The ledger list is read-only and keyset-paged; it never loads a full project ledger.
4. Reads use the tenant-scoped repository; a foreign-tenant project is 404.

## Acceptance criteria

- [ ] For a planted ledger spanning two fiscal years, each of `mtd, qtd, ytd, fiscal_year, life, range` returns the hand-computed figures (golden table in the test, fiscal year starting in April to prove it is not calendar-year)
- [ ] `reconcile` differences are `0.0000` for every bucket after a mixed sequence, and non-zero when a test inserts a row bypassing the service (planted drift) — proving the check bites
- [ ] The ledger endpoint pages with `page_size=50` over 2,000 entries without returning more than 50 per page and never repeats or skips an id across pages
- [ ] `period=range` with `to < from` or a 21-year span → 422
- [ ] 403 without `ledger.read`; foreign-tenant project id → 404 on all three endpoints (isolation gate entries)
- [ ] Money fields are strings in the OpenAPI schema (no `number` type on any amount); the generated client is regenerated and committed
