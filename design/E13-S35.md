## The corrections

1. **PO lifecycle stepper after Close** (`components/purchasing/PoCards.tsx` ~25-35, `api.ts` `LIFECYCLE`,
   `FUTURE_STATES` ~26-30). Closing an issued PO draws Partially Delivered, Delivered and Accepted as done although
   receiving does not exist until M4. Rule: a `FUTURE_STATES` step is **never** drawn done; on a closed PO it is drawn
   as skipped (the future style plus the text "Not tracked yet", so colour does not carry it), and Closed is done.
2. **Comparison insight copy** (`components/sourcing/comparison/BasisCards.tsx` ~8, ~19-21). With one vendor it reads
   "Splitting the award is 0.00 USD (0.00%) cheaper … and uses 1 vendors instead of one." Rule: render the insight
   only when `insight.difference` is greater than zero; in the split sentence use "vendor"/"vendors" by count.
3. **Project people by name** (`routes/projects/detail.tsx` ~72 lists `owner_id` and `sponsor_id` raw). Add to
   `ProjectRead` (`modules/projects/schemas.py` ~116-150) `owner_name`, `owner_email` and
   `sponsors: list[{id, name, email}]` filled the way `modules/sourcing/schemas.py` ~182 fills `owner_name` (find its
   source and reuse it; do not write a new people query if one exists). The overview shows Owner and Sponsors with
   `<Person>` and drops the raw `owner_id`/`sponsor_id` rows. Regenerate `openapi.json` and `schema.ts`.
4. **Project approvals show the budget asked** (`modules/projects/approval.py` ~84 passes `amount=None`, so the inbox
   and decision panel read "Not applicable"). Pass the project's `requested_budget` in the project's currency as the
   summary `Money` when it is set (through `kernel/money.py`, never `float`); `None` stays "Not applicable".
5. **Business unit field shows the unit, not its id** (`components/projects/ProjectForm.tsx` ~16, ~50-58 feeds the
   shared `components/form/Combobox.tsx` ~43-49 `<datalist>` options with `value: u.id, label: u.name`, so choosing
   "Operations" leaves an id in the box; the other Combobox fields carry codes, which is fine). Replace the Business
   unit field only (leave `Combobox` itself unchanged)
   with a native `<select>` of the caller's units from `GET /org/units` (E22-S14 narrows them), option text
   `"<code> <name>"`, value the id, required, with the existing field help and error wiring. Keyboard: arrows and
   type-ahead, as every select on the requisition form.
6. **Project status focus target has a name** (E13-S33 delta minor; `routes/projects/detail.tsx`, the
   `<span ref={statusRef} tabIndex={-1}>`): add `aria-label={"Project status: " + <the status label>}`.
