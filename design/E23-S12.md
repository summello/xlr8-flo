# E23-S12 — Sonnet's effort comes from `agents.yaml`, which now says `medium`

**Epic** E23 · **MT** · **chore/S** · tags: none · new story (operator approval, 22 Oct 2026) · follow-up of E23-S03

> MT stories ship by a pull request to `main`, as E21-S01 did (PR #18).
> **No new dependency** (AGENTS.md §0.6). **No change in what runs**: Sonnet stays at `medium`.

## Requirement (inlined)

- **SUP-005** — Administrator and operator documentation must be updated in the same PR as the feature it describes (UX-010).

## Why

`agents/agents.yaml` says Sonnet runs at `reasoning: high  # passed as --effort`. `author.sh` passes `--effort medium` (two places). The launcher is right: commit `5ba2460` (13 Oct 2026) records "Operator decision 13 Oct 2026: claude-sonnet-5-5 at medium, not high, for new and resumed worker sessions". The config line was written earlier the same day and never updated. A stale config is how a later session "corrects" the launcher back to `high` without knowing it reverses a decision, and effort is not recorded per story, so a scorecard row cannot say which effort produced it.

## Pre-flight findings (Opus, 22 Oct 2026)

- `author.sh`: `claude -p --model sonnet --effort medium --session-id ...` (new) and `claude -p --model sonnet --effort medium --resume ...` (resume).
- `agents.yaml` `sonnet`: `model: sonnet` and `reasoning: high`. Codex has `reasoning: high` for authoring and `review_reasoning: medium` for reviews; neither is touched here.
- E23-S03 added `flo launch-model`, which prints an agent's `model` and records it in `task.json` `sessions.<agent>.model`. The same mechanism extends to effort.
- Only the planner edits `agents/agents.yaml` (`agents/claude.md` §5).

## Design

### Planner hunk (the author does not edit it)

In `agents/agents.yaml`, `sonnet.reasoning` becomes `medium`, with a comment: `# operator decision 13 Oct 2026 (5ba2460); passed as --effort`. Add the dated entry to the "Fleet routing changes" section of `agents/project-memory.md`: the value did not change, only the config now agrees with the launcher.

### `flo launch-model <STORY> --effort`

New flag. It prints the agent's `reasoning` value instead of the model, and records it as `sessions.<agent>.effort`, merging into the existing session record without altering `id`, `account`, `source` or `model`. A missing `reasoning` stops the launch (exit non-zero, naming the agent); there is no default effort. It works for any agent that has a `reasoning` key.

### `agents/scripts/author.sh` (sonnet branch)

Compute `M` (model) and `E` (effort) from `flo launch-model` before building `RUN`, and use `--model $M --effort $E` in both the new-session and the resume commands. If either call fails the launch aborts (`set -e`).

## Acceptance criteria

- [ ] `author.sh` contains no `--effort medium` and no `--model sonnet` literal.
- [ ] `flo launch-model <story> --effort` prints the configured `reasoning` and records `sessions.sonnet.effort`, leaving `id`, `account`, `source` and `model` unchanged.
- [ ] Changing `reasoning` in a fixture config changes the printed value.
- [ ] An agent with no `reasoning` fails and prints nothing.
- [ ] `agents.yaml` says `medium` for Sonnet and the memory entry exists.
- [ ] Docs paragraph updated (extends the "Launch models" section of `docs/ops/fleet-tooling.md`).

## Plants

1. Put `--effort medium` back into `author.sh`: the no-literal test must fail.
2. Remove `reasoning` from the fixture agent: the command must fail, not print a default.
3. Change the fixture value: the printed value must change (a launcher that ignores config fails this).
4. Revert the committed `agents.yaml` to `high`: a test that reads the committed file for Sonnet's `reasoning` must fail.
