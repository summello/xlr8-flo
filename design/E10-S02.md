# E10-S02 — Condition evaluator over any document attribute including amount and custom fields

**Epic** E10 · **M2** · **engine/L** · after **E10-S01** · tags: `money`

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md` and `docs/author-traps.md`. Decisions: `docs/m2-decisions.md` (D-M2-4).

## Requirements

- **APR-005** — Conditions must support any approved document attribute, including name, department, ledger account, amount, currency, category, risk, and custom fields.
- **APR-010** — Amount thresholds and threshold bands are required in Phase 2. **D-M2-4:** amount *conditions* ship now; the named "threshold band" administration feature does not.

## Contract

Service only, no route: `modules/approvals/conditions.py`, re-exported through `approvals/service.py`.

```python
def evaluate(expression: Condition, attributes: Mapping[str, AttributeValue]) -> Evaluation
def field_catalog(document_type: str) -> Mapping[str, FieldType]
def register_attribute_provider(provider: AttributeProvider) -> None   # hook for custom fields (E16)
```

- `AttributeValue` = `str | Decimal | date | bool | None | tuple[str, ...] | Money` (`kernel.money.Money`). **Never `float`**; an `int` from a provider is converted to `Decimal` at the boundary.
- `FieldType` = `text | code | decimal | date | boolean | money | code_list`.
- `Evaluation` = `{result: bool, trace: tuple[LeafTrace, ...]}`, where `LeafTrace` = `{field, op, expected, actual, result}` with values rendered as strings. E10-S09 shows it; this story builds it.

**Condition grammar** (the JSON E10-S01 stores in `edges[].when`; Pydantic models, `extra="forbid"`):

```json
{"all": [ <cond>, ... ]}          // 1..20 children
{"any": [ <cond>, ... ]}          // 1..20 children
{"not": <cond>}
{"field": "amount", "op": "gt", "value": {"amount": "250000.00", "currency": "USD"}}
{"field": "department_code", "op": "in", "value": ["ENG", "OPS"]}
{"field": "risk_level", "op": "is_null"}
```

| `op` | Field types | `value` |
|---|---|---|
| `eq`, `ne` | all except `code_list` | same type as the field |
| `lt`, `le`, `gt`, `ge` | `decimal`, `date`, `money` | same type |
| `in`, `not_in` | `text`, `code` | list of 1..100 strings |
| `contains` | `text` (case-insensitive substring), `code_list` (membership) | string |
| `is_null`, `not_null` | all | absent |

Nesting depth at most 6, at most 50 leaves per expression; deeper or larger is invalid.

## Behaviour

1. **Field catalog per document type.** Each M2 adapter (convention H) declares `fields() -> Mapping[str, FieldType]` alongside `snapshot()`; `field_catalog(document_type)` merges it with every registered attribute provider. Add `fields` to the `DocumentAdapter` protocol here. The requisition catalog (implemented by E09-S05 when it writes the adapter; listed here so E10-S03 can validate against it) is: `name` text, `justification` text, `department_code` code, `ledger_account_code` code, `bu_id` code, `project_id` code, `amount` money (the estimate), `currency` code, `category_codes` code_list (all line categories), `line_types` code_list, `standalone` boolean, `needed_by` date, `risk_level` code (null until a risk story supplies it).
2. **Custom fields (APR-005) without a custom-field system.** Custom fields arrive in M4 (E16). Names prefixed `custom.` resolve only through a registered `AttributeProvider` (`prefix`, `fields(document_type)`, `values(conn, scope, document_type, document_id)`); M2 registers none. A condition naming an unknown `custom.*` field is therefore *invalid* (E10-S03 rejects it at publish), never silently false. Add a test provider in the test suite to prove the hook works end to end.
3. **Evaluation semantics:**
   - A leaf whose field is absent from `attributes`, or is `None`, is `false` for every op except `is_null` (true) and `ne` (true).
   - **Money:** both sides must carry the same currency. A mismatch raises `ConditionError("currency_mismatch", field, expected_currency, actual_currency)`; it is never coerced or converted. Requisitions carry the base currency (D-M2-7), so a correctly built workflow never hits it; E10-S05 turns the error into a blocked route with a WF-006 message.
   - **Decimals** are compared exactly (`Decimal("250000.00") == Decimal("250000.0000")` is equal). Amount strings in `value` must match `^-?[0-9]{1,14}(\.[0-9]{1,4})?$`.
   - **Dates** are ISO `YYYY-MM-DD`. Text equality is exact; `contains` is case-folded.
   - `all` and `any` short-circuit for the result, but the trace still records every leaf it evaluated, in order.
4. Pure functions only: no database access in `evaluate`. Providers are called by the instance code (E10-S05), not here.

## Acceptance criteria

- [ ] Every op times every field type it allows, true and false case, from a table-driven test.
- [ ] `{"field":"amount","op":"gt","value":{"amount":"250000.00","currency":"USD"}}` is true for `Money(Decimal("250000.01"),"USD")` and false for exactly 250000.
- [ ] A money comparison across currencies raises `ConditionError` with code `currency_mismatch`.
- [ ] A float anywhere (in `value` or in `attributes`) is rejected: the parser refuses a JSON number for a money or decimal value (strings only), and `evaluate` raises `TypeError` on a `float` attribute.
- [ ] Missing and null attributes follow rule 3 exactly.
- [ ] Depth 7, or 51 leaves, is rejected by the parser with a JSON-pointer location.
- [ ] A registered test provider's `custom.cost_center` field appears in `field_catalog` and evaluates; with no provider it is absent.
- [ ] The trace lists each evaluated leaf with field, op, expected, actual and result.

## Required tests

`apps/api/tests/approvals/test_conditions.py` (pure unit tests, no database), table-driven, one case per acceptance criterion.

## Plants

1. Compare money by `float(amount)`: the float-rejection test and the exact-boundary test fail.
2. Drop the currency check: the `currency_mismatch` test fails.
3. Make a missing attribute raise instead of returning false: the missing-attribute test fails.
4. Let the parser accept a JSON number for money: the float-rejection test fails.
