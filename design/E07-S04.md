# E07-S04 — Reservation and release primitives, exactly-once release guarantee

**Epic** E07 · **M1** · **ledger/L** · after **E07-S02** · tags: `money`, `concurrency`

## Requirements

- **FIN-011** — Failed, rejected, cancelled, expired, or reduced transactions must release unused reservations and commitments exactly once.
- **FIN-012** — Retries and duplicate submissions must not create duplicate financial effects.
- **BUD-008** — Outgoing changes must not reduce available budget below zero unless an authorized negative-budget policy applies.
- **ACC-001** — Two concurrent requisitions cannot reserve more than the same project’s available budget.
- **ACC-006** — Cancelling a requisition or PO releases only its unused funds, once.

## Contract

Service-only primitives (no endpoint; M2 requisitions and M3 POs call them in the same transaction as their document transition):

- `reserve(conn, scope, *, project_id, amount, currency, source_type, source_id, effective_date, actor_id, department_code, ledger_account_code, idempotency_key) -> LedgerEntry` — `entry_type=reservation`, `bucket=reserved`.
- `release_reservation(conn, scope, *, reservation_entry_id, amount: Decimal|None, actor_id, effective_date, reason, idempotency_key) -> LedgerEntry|None` — `entry_type=release`, `bucket=reserved`, `amount = -x`.

Migration `20260826_0021` (down `…_0020`), reversible:

1. `ALTER TABLE ledger_entry ADD COLUMN releases_entry_id bigint REFERENCES ledger_entry(id)` — adding a column is allowed on an append-only table (the trigger only blocks row UPDATE/DELETE/TRUNCATE). Add `CHECK ((entry_type = 'release') = (releases_entry_id IS NOT NULL))` as `NOT VALID`, then `VALIDATE CONSTRAINT`, plus an index on `releases_entry_id`.
2. A view `reservation_remaining(reservation_entry_id, org_id, reserved_amount, released_amount, remaining)`: the reservation's amount plus the sum of the `release` rows that point at it (releases are negative, so `remaining = reserved_amount + SUM(release.amount)`).

## Behaviour (FIN-011, FIN-012, ACC-001, ACC-006, BUD-008)

1. `reserve` = `post_entry(reservation)`; fails with `InsufficientBudget` per E07-S02 (this *is* ACC-001's atomic overspend guard).
2. `release_reservation`: lock `project_balance` FOR UPDATE first, then read `remaining` for the target reservation **inside the lock**. `amount=None` releases the full remaining; an explicit amount greater than remaining is a 409 `ReleaseExceedsReservation`; remaining of zero returns `None` (idempotent no-op, not an error) — **exactly-once release is "remaining can never go below zero" plus idempotency keys**.
3. A release must reference a reservation whose `project_id` and `currency` match; a reservation from another tenant is a 404.
4. A release of a **reversed** reservation is rejected (409): nothing remains to release.
5. Release never fails because of the availability rule (it only frees funds) and is allowed in a closed period **only** if the original reservation's period is closed too? **D-M1-12: releases ignore period closure** (a cancellation in January must be able to free funds posted in December); the entry carries today's `effective_date` by default. Document this choice in the module docstring.

## Acceptance criteria

- [ ] Two concurrent releases of the same full reservation: exactly one ledger release row, balance `reserved` reduced once, the other returns `None`
- [ ] Partial release 40 then full release releases exactly the remaining 60; a third returns `None`
- [ ] Release of 61 against remaining 60 → `ReleaseExceedsReservation`, nothing written
- [ ] The same `idempotency_key` replayed returns the first release entry with no balance change
- [ ] `project_balance.reserved` equals the sum over `reservation_remaining.remaining` for the project after a mixed sequence (property-style, seeded RNG)
- [ ] Reserving more than available fails; with two concurrent reserves of 60 against 100, exactly one succeeds (reuses E07-S02's concurrency harness)
- [ ] Release against a foreign-tenant reservation id → not found, no write
- [ ] Release is accepted when the reservation's fiscal period is closed
- [ ] Migration up/down/data-preservation; the column add does not break the append-only trigger tests
