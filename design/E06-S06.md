## Requirements

- **PROJ-016** — Projects must maintain risks with likelihood, impact, owner, mitigation, due date, and status.

## Contract

Migration (reversible): the next revision after the current head at story start (revision id `20260826_<next 4-digit number>`, `down_revision` = the head `python -m flo.kernel.migrate --check` validates today); stories merge one at a time, so there is no gap or fork, RLS forced: `project_risk(id uuid pk, org_id, project_id fk, title text not null, description text, likelihood smallint not null check 1..5, impact smallint not null check 1..5, score smallint generated always as (likelihood * impact) stored, owner_id uuid not null, mitigation text, due_date date, status text not null default 'open' check (status in ('open','mitigating','closed','accepted')), closed_reason text, created_by, created_at, updated_at, version bigint not null default 1)`.

Permissions `project.update`, `project.read`.

- `POST /api/v1/projects/{id}/risks` (Idempotency-Key) → 201 | 404 | 422
- `GET /api/v1/projects/{id}/risks?status=&min_score=&cursor=&page_size<=50` → 200 ordered by `score desc, due_date`
- `PATCH /api/v1/projects/{id}/risks/{risk_id}` with `If-Match` → 200 | 409 `StaleVersion`; closing requires `closed_reason`
- No DELETE: a mistaken risk is `closed` with a reason (history is retained and audited).

## Behaviour (PROJ-016)

1. `likelihood`/`impact` are integers 1 to 5; `score` is computed by the database (no float).
2. `owner_id` must be a user in the same org (validated through the identity service, never trusting the client).
3. Overdue = `due_date < today` and status in `open|mitigating`; returned as a boolean `overdue` field computed from `kernel.clock` (the clock is injected so tests are deterministic).
4. Completed/abandoned projects reject new risks (409).
5. Audit create/update/close; risk text fields are plain text, length-capped (title 200, description 4,000, mitigation 4,000) and returned with output encoding left to the client (no HTML).

## Acceptance criteria

- [ ] Create, list ordered by score, update with `If-Match`, close with reason; closing without a reason → 422
- [ ] `likelihood` 0 or 6 → 422 and rejected by the CHECK if inserted directly
- [ ] `score` equals `likelihood * impact` for every row; filter `min_score` works server-side
- [ ] `overdue` is true only for open/mitigating risks past due (clock-injected test)
- [ ] An owner from another tenant → 422; foreign-tenant project or risk id → 404 (isolation gate entries)
- [ ] Concurrent updates with the same `If-Match` → one wins, one 409
- [ ] There is no DELETE route (test fails if one appears)
- [ ] Migration up/down/data-preservation
