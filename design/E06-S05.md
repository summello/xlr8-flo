## Requirements

- **PROJ-011** — Projects may be divided into phased sub-projects with planned items/services for each phase.
- **PROJ-015** — Projects must track planned/actual dates, milestones, owner, sponsor, health, and percent complete.

- `PATCH /api/v1/projects/{id}` extended (E06-S01) with `health`, `percent_complete`, `actual_start`, `actual_end`, `owner_id`, `sponsor_id`

## Behaviour (PROJ-011, PROJ-015)

1. `planned_end >= planned_start` and `actual_end >= actual_start` enforced by CHECK and service; milestone `due_date` must fall within the project's planned window when that window is set (422 otherwise).
2. PROJ-011 asks for phased sub-projects "with planned items/services for each phase". Planned items/services are catalog data that does not exist until M2/M4. **In M1 a phase is a schedule container and may reference one child project** via `project_phase.sub_project_id uuid null fk project` (same org, child of the same parent, validated). Planned items arrive with requisitions; record that in `notes.followup`.
3. A project's `percent_complete` is a manual value; it is **not** derived from phases in M1 (derivation rule undecided, so it is not guessed). Health is manual too; the computed risk indicator is E06-S08.
4. Variance helpers are read-only: `schedule_variance_days = actual_end|today - planned_end` returned on GET.
5. Audit every write. Completed/abandoned projects reject new phases and milestones (409).

## Acceptance criteria

- [ ] CRUD happy path for phases and milestones; `sequence` collisions → 409
- [ ] Date-order CHECKs reject inverted ranges at the database even when the service is bypassed
- [ ] Milestone outside the project's planned window → 422
- [ ] A phase can reference a valid child sub-project; a project from another tree or org → 422/404
- [ ] Owner/sponsor/health/percent changes are audited and visible on GET
- [ ] `percent_complete` outside 0..100 → 422
- [ ] Foreign-tenant ids → 404 on every route (isolation gate entries); writes without `project.update` → 403
- [ ] Migration up/down/data-preservation
