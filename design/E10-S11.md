# E10-S11 — Visual workflow builder: drag-and-drop canvas and its outline equivalent, in one story

**Epic** E10 · **M2** · **ui/L** · after **E10-S03**, **E04-S02** (and E10-S04 for the approver picker) · tags: `ui`

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md`, `docs/author-traps.md`. **UI authority, in order:** `design-system/MASTER.md` and `tokens.css`, then `design-system/pages/approval-workflow-builder.md` (§2 builder, §3 inspector, §4 check and publish, §6 states), then canvas boards `ApprovalWorkflows`, `Wf*` for layout and copy only.
>
> **AGENTS.md invariant 8: drag-and-drop ships its keyboard equivalent in the same story.** This story ships the canvas *and* the Outline (the spec puts both here). E10-S12 is the list, version history and route preview, not the keyboard editor.

## Requirements

- **APR-001** — Authorized administrators must be able to design approvals in a flowchart-style drag-and-drop builder.
- **APR-002** — An accessible non-drag method must provide the same workflow-building operations.
- **A11Y-003** — Drag-and-drop interactions must have an equivalent non-drag control.
- **APR-007**, **APR-008**, **APR-012**, **APR-006** — surfaced from E10-S03's validation (texts there).
- **A11Y-006**, **UX-004**, **UX-005** — forms, states, recoverable errors.

## Contract

Route `/admin/approval-workflows/:id` (the spec's path; register in `__root.tsx` like `PROJECT_PATH`, E06-S07). It uses E10-S01 to E10-S04's API only: `GET`/`PUT .../versions/{v}` with `If-Match`, `POST .../versions` (create a draft from the published version when none exists), `GET .../versions/{v}/validation`, `POST .../versions/{v}/publish` with `acknowledge_warnings`, and `GET /api/v1/approvals/eligible-approvers?document_type=…`. The spec's `/approval-workflows/...` API paths are illustrative; **the packets' routes win**. No new backend in this story, apart from the regenerated client.

## Behaviour

1. **One graph model, three editors.** The canvas, the Outline and the inspector edit one in-memory graph (E10-S01's JSON, `layout` included) through one reducer of operations: `addNode(kind)`, `connect(from, output, to)`, `disconnect`, `move(node, x, y)` (canvas only, presentation), `update(node, fields)`, `delete(node)`. The canvas and the Outline only dispatch operations. **Vitest proves that the same operation sequence issued through the canvas, the keyboard and the Outline yields an identical graph.**
2. **Canvas (APR-001):** a board that scrolls inside its own box on a dot grid (spacing from a token; no canvas value). Nodes are `<button aria-pressed>` with kind word, icon, name and summary; a problem marker uses an icon and words. Lines are SVG paths with arrowheads; condition outputs carry labelled chips.
   - **Pointer:** drag a node to move it (snap to grid); drag from an output port to a node to connect. Use pointer events; **no new dependency**, and no drag-and-drop library.
   - **Keyboard on the canvas itself:** arrow keys move the selected node one grid step (Shift: five); `C` (or the node's context menu button) opens "Connect output to…" listing reachable targets; Delete removes; Tab moves between nodes in route order. Every canvas action has a keyboard path, as well as the Outline.
3. **Outline (APR-002):** the table from spec §2: node, type, summary, `Goes To` selects per output, `Edit` (focuses the inspector title), `Delete`. It is the default view below 768px. The inspector also has `Goes To` selects.
4. **Cycles are prevented** (APR-007): a connect operation that would close a loop is refused **before** it reaches the reducer: `Not connected. That would make a loop.` (`role=alert`, focus, names both nodes), graph unchanged. E10-S03 still reports cycles in older or imported graphs.
5. **Inspector** (spec §3): Start, Condition and Approval Step panels.
   - **Condition `Attribute` offers exactly the catalogue the server exposes.** In M2 that is Estimate only (D-M2-4, canvas 83). Do not hardcode the spec's "any attribute, including custom fields"; read the catalogue from the server. Add `GET /api/v1/workflows/catalog?document_type=` (`workflow.read`), backed by `approvals.service.field_catalog` (E10-S02): the one backend addition this story makes, with a `COVERED` entry.
   - **Approval Step:** approvers as a checkbox group from `eligible-approvers` (eligible people only, APR-004); `Group Rule` radios Any one, All, Quorum (with Approvals Needed); `An approver here may also approve at an earlier step` maps to `allow_repeat` (canvas 82); Due After, Escalate After and Escalate To map to E10-S01's node fields.
   - If the approver list fails, only that field fails (spec §3).
6. **Check and Publish** (spec §4): `Check` saves the draft (`PUT`, If-Match) and reads `/validation`; problems list with kind, sentence and `Go to Node`, and the same markers on the nodes. `Publish` with errors opens Problems and focuses the summary; with warnings only, the dialog shows them and sends `acknowledge_warnings: true` when the admin confirms; with none, the publish dialog (focus on `Keep Editing`) says new submissions use the new version and in-flight documents keep theirs (ACC-007).
7. **Stale spec copy, overridden** (record each in `notes.followup`):
   - The Start node's "funds are reserved at submission" is **current** (D-M2-15) for project-linked requests; add the spec's standalone wording "Funding is assigned when a standalone request is approved" (D-M2-5).
   - "Membership is snapshotted when each task is created" becomes "Approvers are checked when each decision is made" (D-M2-2).
   - "Depth limit 25 steps" becomes the organization's `approval.max_depth`, shown from the server (D-M2-3).
8. Saving uses `If-Match`; a 409 `stale_version` (another administrator saved) shows "Someone else changed this draft. Reload it." and keeps the local graph in memory until the admin chooses to reload (DATA-002, spec open question 3).

## Acceptance criteria

- [ ] Add, connect, move, update and delete by pointer, by canvas keyboard and by Outline produce identical graphs (vitest on the reducer, and Playwright on two flows).
- [ ] A keyboard-only Playwright path builds Start → Condition → Approval → End, connects both condition outputs, checks, and publishes.
- [ ] A loop-closing connect is refused with the alert and the graph unchanged.
- [ ] The Attribute select offers only what `/workflows/catalog` returns (Estimate in M2).
- [ ] Publish with errors focuses the summary; with warnings it needs explicit acknowledgement; with none it shows the dialog with the in-flight count.
- [ ] Axe passes on the builder with canvas, Outline, inspector and problems open, in light and dark.
- [ ] No new npm dependency.

## Plants

1. Let the canvas mutate the graph directly instead of dispatching: the three-editors equivalence test fails.
2. Remove the loop check from `connect`: the cycle-prevention test fails.
3. Hardcode an attribute list: the catalogue test fails.
4. Make a canvas-only action (move) the only way to connect: the keyboard-only path fails.
