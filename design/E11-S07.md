## Requirements (inlined)

- **VEN-007** — Vendor performance must be measurable across quality, pricing, delivery/time adherence, service, and configurable categories.
- **VEN-015** — Performance scores must retain source transaction, scorer, period, rationale, and any dispute/adjustment history.

## Design

**Categories:** a master kind `vendor_score_category`, seeded per org on first use with `quality`,
`pricing`, `delivery` and `service` (these four cannot be deactivated). Further codes are the
"configurable categories". Per-vendor-category scoring sets are open (§7.4, parked in E11-S08):
every category applies to every vendor in M3.

**Scores are append-only.** Table `vendor_score` (RLS): `id`, `org_id`, `vendor_id`, `category_code`,
`score int` (1..5), `period date` (the first day of the month scored), `source_type text`
CHECK in `po` and `manual`, `source_ref text NOT NULL` (the PO number while E13 does not exist;
E13-S03 adds an FK column `source_po_id` and backfills by number in its own migration),
`rationale text NOT NULL` (1..1000), `scored_by`, `scored_at`, and `supersedes uuid NULL`
(an adjustment points at the row it replaces). Add `vendor_score` to the **append-only trigger set**
(the same trigger function as `ledger_entry`): UPDATE and DELETE raise.

**Disputes are rows too:** `vendor_score_dispute`: `id`, `org_id`, `score_id`, `raised_by`,
`raised_at`, `reason`, `resolution` CHECK in `upheld`, `dismissed` or NULL, `resolved_by`,
`resolved_at`, `resolution_note`. It is append-only except for resolving: allow exactly one UPDATE
that sets the resolution fields while they are NULL (a trigger enforces it). An **upheld** dispute
must come with an adjustment, which is a new `vendor_score` with `supersedes = <original>`. The
original stays, shown struck through. Both are written in one transaction.

**Current score:** a score row is current when no other row supersedes it. A vendor's category
average over a period window uses current rows only. `GET /vendors/{id}/performance?from=&to=`
returns per-category averages as `Decimal` strings to one place, the overall mean of the category
averages, and the row count. No figure is computed in the browser.

## API

| Method and path | Permission | Behaviour |
|---|---|---|
| `GET /vendors/{id}/scores?category=&from=&to=&cursor=` | `vendor.view` | Rows with scorer email (D-M2-16), source, rationale, disputes, and `superseded_by`. |
| `POST /vendors/{id}/scores` (Idempotency-Key) | `purchase_order.view` **and** `vendor.view` (purchasing users) | Category, score, period, `source_ref`, rationale; all required (422 per field). Duplicate (vendor, category, period, source_ref) while current → 409 `already_scored`. |
| `POST /vendors/{id}/scores/{sid}/disputes` (Idempotency-Key) | `vendor.edit` | Reason required; one open dispute per score (409). |
| `POST /vendors/{id}/scores/{sid}/disputes/{did}/resolve` (Idempotency-Key) | `vendor.approve` | `{resolution, note, adjusted_score?, adjusted_rationale?}`: `upheld` requires both adjusted fields. One transaction. The person who raised the dispute cannot resolve it (409 `separation_of_duty`). |
| `GET /vendors/{id}/performance` | `vendor.view` | As above. |

All writes are audited (`vendor.score.add`, `vendor.score.dispute`, `vendor.score.resolve`).

## Acceptance

- [ ] Migration up, down and data preservation; the triggers are installed and removed.
- [ ] A raw UPDATE or DELETE on `vendor_score` raises (trigger); a second resolution of a dispute raises.
- [ ] An upheld dispute leaves the original row, adds the adjustment with `supersedes`, and the average uses the adjustment only; dismissed changes nothing.
- [ ] Averages: a worked example with three categories over two periods gives the hand-computed `Decimal` strings.
- [ ] `already_scored` and one-open-dispute rules; separation of duty on resolve.
- [ ] TEN-010 on every route, plus an authorization test per role (sourcing-specialist cannot score; purchasing-user can).
- [ ] `flo check` green.

## Plants

1. Drop `vendor_score` from the append-only trigger: the raw-UPDATE test fails.
2. Average including superseded rows: the adjustment test fails.
