# E04-S01 — Design tokens, Tailwind v4 setup, light/dark, neutral chrome palette

**Epic** E04 Design system & shell · **M0** · **ui/M** · after **E01-S01** · tags: `ui`

## Requirements

- **UX-006** — Light and dark modes must be supported without weakening semantic color or contrast.
- **A11Y-005** — Text, controls, focus indicators, and non-text UI must meet applicable contrast requirements.

## Deliverable

`design-system/MASTER.md` §2 made executable. Every token in this story is **already computed and contrast-verified** in that document — this is transcription plus a test that keeps it honest, not a colour-picking exercise. Do not invent a value.

## Behaviour

1. `apps/web/src/styles/tokens.css` is the **only** file in the repository allowed to contain a colour literal. CI already fails any raw hex or `oklch()` elsewhere under `apps/web/src`.
2. Three theme states, exactly as `design-system/MASTER.md` §2.1 specifies:
   - bare `:root` carries the **complete** light palette
   - `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { … } }` for the un-stamped default
   - `:root[data-theme="dark"] { … }` so an explicit toggle wins in both directions

   **No component style may live inside a media or `[data-theme]` block** — only token redefinitions. A colour whose sole definition sits behind `[data-theme]` never applies in the un-stamped state, which is the classic unreadable-page bug.
3. Tokens transcribed: chrome surfaces and text, four phase accents, five status tones with tints, 14 tag swatches, tinted shadow scale, lit edge, radii, spacing, motion durations and easings.
4. `body` sets an explicit `background: var(--canvas)`. A transparent body borrows the host's ground.
5. Theme preference persists in `localStorage`, wrapped in `try/catch` — a private window or blocked site data must render correctly with no stored value.
6. **A contrast test is committed with the tokens.** It parses `tokens.css`, converts OKLCH to sRGB, and asserts every documented pair: text ≥4.5:1, UI glyphs and chart marks ≥3:1, in both themes. Changing a token to a failing value must fail CI. This is what stops the palette drifting out of compliance six months from now.

## Acceptance criteria

- [ ] `tokens.css` is the only file with a colour literal; CI proves it
- [ ] All three theme states resolve correctly, including the un-stamped default under a dark OS
- [ ] `data-theme="light"` on a dark OS renders light; `data-theme="dark"` on a light OS renders dark
- [ ] No component style appears inside a media or `[data-theme]` block
- [ ] `body` paints an explicit token background
- [ ] Theme persists across reload and degrades silently when `localStorage` throws
- [ ] The committed contrast test passes on all 46 documented pairs in both themes
- [ ] Deliberately lowering one token's lightness fails the contrast test; reverting passes
- [ ] Every token in `design-system/MASTER.md` §2 exists in `tokens.css` with the identical value
