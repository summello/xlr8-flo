# E23-S06 — `flo reassign`: capacity-aware, liveness-checked, per-story locked author reassignment

**Epic** E23 · **MT** · **concurrency/M** · tags: `concurrency` (Opus final review required) · backlog item T4 · **after E23-S04** (hard dependency, see below)

> MT stories ship by a pull request to `main`, as E21-S01 did (PR #18).
> **No new dependency** (AGENTS.md §0.6). Gated: a fresh Opus session reviews this story, and the gate refuses to merge it without that review.

## Requirement (inlined)

- **SUP-005** — Administrator and operator documentation must be updated in the same PR as the feature it describes (UX-010).

## Why

A story assigned to an author who has hit a limit waits; nothing moves it. The supervisor only waits when an author reports a limit. A reassignment path exists only if it is safe: moving a story out from under a worker that is still running produces two authors on one branch, and moving it to an agent `flo assign` would never have chosen breaks the routing rules.

## Pre-flight findings (Opus, 22 Oct 2026, traced against `799797d`)

- **The supervisor is not in this repository.** `~/.claude/fleet/fleet.py` (with its `decide()` and tests) is user-scoped; `agents/fleet.toml` is the only tracked piece. The backlog describes a change to `decide()`. **That change cannot be made or tested from here.** This story delivers the in-repo primitive, `flo reassign`, which the planner can run by hand today and the supervisor can adopt later. Record the adoption as `notes.followup`.
- A worker's launch writes its PID to `.scratch/<STORY>.author.pid` (`author.sh`, last lines), and `flo` already has `_alive(pidfile)` (~line 2084, `os.kill(pid, 0)`). `task.json` and `reviews/*.json` are gitignored, so a clean `git status` says nothing about a running worker. Reuse `_alive`; do not write a second liveness check.
- `$!` in `author.sh` is the PID of the `nohup sh -c ...` wrapper. A reused PID makes `_alive` return true for an unrelated process. That errs toward **refusing** a reassignment, which is the safe direction. Document it; do not "fix" it.
- A crashed worker leaves a stale pidfile whose process is gone (`_alive` false) and a log with no final `exit N`. That is reassignable: the process is not running.
- The repo's lock convention is an atomic `mkdir` lock with a `ponytail:` comment: `finish.sh` and `submit.sh` use `until mkdir "$R/.scratch/finish.lock"`, with `trap 'rmdir ...' EXIT`. `fcntl`/`flock(1)` are not used (macOS has no `flock(1)`; the fleet runs on macOS). **Use `mkdir`.**
- `cmd_assign` (~line 143) mixes eligibility and ranking in one function with nested `can_author` and `rank`. Reusing "the complete filter" means extracting them. **`cmd_assign` has zero test coverage today**; that is why this story depends on E23-S04, which adds `test_flo_assign.py`. Refactoring an untested function that decides who authors gated stories is the risk this dependency removes. The backlog's "depends on nothing" is overridden here.
- `worker_load` counts a sonnet account slot from `task.json` authors of `design`/`in_progress` stories, so changing `task.json.author` frees the slot automatically.

## Design

### 1. Extract eligibility from `cmd_assign` (behaviour-preserving)

Move `can_author`, `rank` and the reviewer selection into a module-level function, for example `assignment_for(epic, st, fleet, spend, exclude=())`, returning `{"author", "reviewers", "opus_final"}`. `cmd_assign` calls it with `exclude=()` and prints the same JSON. **Its output for every input must be byte-identical before and after**; the S04 tests are the proof. The milestone-override branch (step 0) stays where it is and is reused unchanged.

### 2. `flo reassign <STORY_ID> [--reason TEXT]`

Run from the parent repo. In order, holding the per-story lock for steps 2 to 6:

1. Require `st` in `{design, in_progress}` and a `task.json` in the story worktree. Refuse a `review` or `done` story.
2. **Lock** `.scratch/<STORY>.lock` with `mkdir`; if it exists, exit non-zero "another reassign or launch holds the lock". Remove with a `try/finally` (and say in a `ponytail:` comment that a crash leaves a stale lock to remove by hand).
3. **Liveness:** refuse if `_alive(.scratch/<STORY>.author.pid)`.
4. **Clean worktree:** refuse unless `git -C <worktree> status --porcelain` is empty **and** `git -C <worktree> rev-list --count <milestone_branch>..HEAD` is `0`. (Commits that are only the milestone merged in are reachable from the milestone branch and do not count.)
5. **Full eligibility re-check:** call `assignment_for(..., exclude={current_author})`. If it raises or finds no candidate, refuse and print why. The new author is whatever `flo assign` would pick without the current one, never a chosen agent.
6. **Write:** set `task.json` `author` and `reviewers` from that result; set `opus_final` from the story **tags** (never from the author); append to `substitutions` `{"from": <old>, "to": <new>, "reason": <--reason or "reassign">}`; keep the old agent's `sessions` entry. Print old author, new author, reviewers, `opus_final`.

### 3. `author.sh` takes the same lock

Without this, a launch that has read `task.json` can race a reassignment and start a second author. In `author.sh`, wrap the section from reading `author` from `task.json` through writing the pid file in the same `mkdir` lock (`until mkdir ...; do sleep 1; done`, `trap ... EXIT`), with a short bounded wait (for example 30 s, then exit non-zero), so a stuck lock cannot hang a launch.

## Invariants

- A gated story keeps `opus_final: true` and a reviewer other than its author after a reassignment. Reassignment changes who authors; it never changes review depth.
- The new author is always an agent `flo assign` would have accepted for this story. An override that makes a milestone sole-author is respected (the reassign refuses because no other candidate exists).
- Exactly one of two simultaneous `flo reassign` calls on one story succeeds.

## Acceptance criteria

- [ ] `flo assign` prints byte-identical JSON for a fixed set of fixture stories before and after the extraction (the S04 tests pass unmodified).
- [ ] `flo reassign` on a story whose worker pid is alive is refused; the same story with a dead pid and a clean tree is reassigned.
- [ ] A dirty tree, an untracked file, or one commit past the milestone branch each cause a refusal.
- [ ] A gated story (money tag) reassigned from Sonnet to Codex has `opus_final: true`, and a reviewer other than Codex, in `task.json`.
- [ ] A story whose only other eligible candidate is excluded by `avoid_tags` or `max_author_size` is refused, not given to that agent.
- [ ] **Two reassign calls started together on one eligible story: exactly one writes, the other exits non-zero** (a real two-process test, not a mock).
- [ ] The substitution is recorded and the old author's session entry is kept.
- [ ] `author.sh` holds the lock around its read-and-launch section and gives up after the bounded wait.
- [ ] Usage text and one docs paragraph updated.

## Plants (AGENTS.md §2.2: prove each guard fails)

1. Comment out the liveness check: the live-pid test must fail.
2. Comment out the `rev-list --count` check: the one-commit test must fail.
3. Drop the lock: the two-process test must fail (both succeed or the file is corrupt).
4. Compute `opus_final` from the new author instead of the tags: the gated test must fail.
5. Pass `exclude=()` in step 5: the "does not hand it back to the same agent" test must fail.
