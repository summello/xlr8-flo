# E23-S09 — Build the SPA bundle once in CI and deploy the same artifact

**Epic** E23 · **MT** · **chore/S** · tags: none · backlog item T10 · **after E22-S12** (hard dependency: both stories edit `.github/workflows/ci.yml`'s frontend jobs, and S12 is in flight)

> MT stories ship by a pull request to `main`, as E21-S01 did (PR #18).
> **No new dependency** (AGENTS.md §0.6): `actions/upload-artifact` and `actions/download-artifact` are already used in this workflow, at pinned SHAs.

## Pre-flight findings (Opus, 22 Oct 2026, traced against `799797d`)

- `frontend-e2e` (`ci.yml` ~line 339) runs `npm --prefix apps/web ci`, installs Chromium and runs Playwright with `--shard`. `frontend-static` (~line 283) runs `npm ci` and static checks. **Neither builds `apps/web/dist`.** Only `deploy` does, inside its "Deploy single-origin Worker route and SPA" step (~lines 561 to 604): `npm --prefix apps/web ci`, `npm --prefix apps/web run build`, four `grep` guards on `apps/web/dist`, then `npx wrangler deploy` and `npx wrangler pages deploy apps/web/dist`.
- Two of the guards need values only the deploy job holds: `$GCP_PROJECT` (a secret) and `$cloud_run_host` (from `vars.CLOUD_RUN_ORIGIN`). **The guards must stay in `deploy`**, run against the downloaded bundle.
- The step first asserts `apps/web/.env.production` has `VITE_API_BASE_URL=/api`. That belongs before the build, so it moves to the build job.
- `wrangler` is not in `apps/web/package.json`; it runs through `npx wrangler` and is fetched from npm at deploy time, **unpinned**. That is the case today and removing `npm ci` from deploy does not change it. It is a supply-chain item for `notes.followup`, out of scope here.
- `deploy` has no `setup-node` step; it uses the runner's Node. `deploy` runs only for pushes to `main` and for `workflow_dispatch` on `main` or `milestone/*`, and it applies the SPA step only when `needs.detect.outputs.web == 'true'`.
- **Honest sizing.** The saving is one `npm ci` plus one `vite build` taken off the deploy critical path, because the build runs in parallel with `backend`, `frontend` and `security`. That is an estimate of one to two minutes, unmeasured; read it from the Actions run logs before and after. The backlog's "deduplicate" framing overstates it: until the E2E shards also consume this artifact there is nothing deduplicated, only moved. Feeding the shards from it is a follow-up that touches E22-S12's `playwright.config.ts`, so it is out of scope here.

## Design

### 1. New job `frontend-build`

- `needs: [detect]`; `if:` the same event condition `deploy` uses (main push, or `workflow_dispatch` on `main` or `milestone/*`) **and** `needs.detect.outputs.web == 'true'`. It must not run on pull requests: it would add a build to every PR for nothing.
- Steps: checkout; `setup-node@v5` with `node-version: ${{ env.NODE_VERSION }}` and the npm cache (as `frontend-e2e`); the `VITE_API_BASE_URL=/api` assertion (moved from deploy); `npm --prefix apps/web ci`; `npm --prefix apps/web run build`.
- Manifest: from `apps/web/dist`, write `dist.sha256` (`find dist -type f -print0 | sort -z | xargs -0 sha256sum`) beside it.
- Upload artifact `web-dist` containing `apps/web/dist` and `apps/web/dist.sha256`, `if-no-files-found: error`, `retention-days: 1`. Use the same pinned `upload-artifact` SHA the workflow already uses.

### 2. `deploy`

- Add `frontend-build` to `needs`. Keep `if: always() && !failure() && !cancelled()` semantics: a skipped `frontend-build` (web untouched) must not skip deploy, as the existing comment says for `backend` and `frontend`.
- In the SPA step: remove the `npm ci` and `npm run build` lines and the `.env.production` assertion; add, guarded by `needs.detect.outputs.web == 'true'`, an `actions/download-artifact` step (pinned SHA already in the workflow) and `sha256sum --check` on the manifest, failing the job on any mismatch.
- The four `grep` guards, `wrangler deploy` and `wrangler pages deploy apps/web/dist` stay as they are, now reading the downloaded `apps/web/dist`.
- Trivy, SBOM and digest steps are untouched (they handle the API image only).

### 3. Docs

The CI note in `infra/SETUP.md` (find with `grep -n "deploy" infra/SETUP.md`): the SPA is built once by `frontend-build` and deployed from the artifact; the guards run in `deploy`.

## Design decisions (confirm on review)

1. **Manifest check.** Deploy no longer builds what it ships, so an integrity check between build and ship is added (two shell lines). Recommended; it is a small control for a real boundary change.
2. **Not on pull requests.** Keeps PR CI time unchanged. The cost is that a build-breaking change is still caught by `frontend-static` and the E2E shards (S12 makes them build), not by this job.
3. **Same-run artifact only.** `download-artifact` without `run-id` is scoped to the current run. Do not add a cross-run download.

## Acceptance criteria

- [ ] `ci.yml` has a `frontend-build` job that does not run on `pull_request`.
- [ ] `deploy` runs no `npm ci` and no `vite build`; it downloads `web-dist` and verifies its manifest.
- [ ] The four bundle `grep` guards are unchanged and still run in `deploy` against the downloaded bundle.
- [ ] A `workflow_dispatch` rehearsal on a `milestone/*` branch (the planner runs it; the author has no network) shows `frontend-build` green, `deploy` downloading the artifact, and the guards passing. Record both run durations and the deploy job's critical path before and after in the PR body.
- [ ] `actionlint` (or the repo's existing workflow lint, if one runs in CI) passes.
- [ ] `infra/SETUP.md` updated.

## Plants (the planner pushes these on a throwaway branch; the author has no network)

1. Alter one byte of a file in the downloaded bundle before `sha256sum --check`: deploy must fail at the check.
2. Put a string matching `sk-` plus 20 key characters into a built file before upload: deploy's guard must still fail. This proves the guard reads the downloaded bytes.
3. Set `VITE_API_BASE_URL` to an absolute URL in a copy of `.env.production`: `frontend-build` must fail before building.
4. Make `frontend-build` fail: `deploy` must not deploy (it must not run with a missing bundle).
