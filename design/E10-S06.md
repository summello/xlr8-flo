# E10-S06 — Decisions: approve, reject, return, comment, withdraw; full attribution recorded

**Epic** E10 · **M2** · **engine/M** · after **E10-S05** · tags: `security`

> **Conventions:** `docs/m1-conventions.md`, `docs/m2-conventions.md` (H, I, K) and `docs/author-traps.md`. Decisions: D-M2-1, D-M2-2, D-M2-9; canvas `DECISIONS.md` 82.

## Requirements

- **APR-013** — Approval actions must include approve, reject, return for changes, comment, and—where authorized—withdraw.
- **APR-014** — Every decision must record actor, acting authority/delegation, timestamp, outcome, comment/rationale, and document version.
- **AUD-001** — … approval, rejection … events must be audited.
- **COL-003** (rationale clause) — notes used as approval rationale must be immutable: **a decision's comment is its rationale and lives in an append-only row.**

## Contract

| Route | Who | Success | Body |
|---|---|---|---|
| `POST /api/v1/approvals/tasks/{task_id}/decisions` (Idempotency-Key, replayed) | a current member of the task (convention K) | 200 `DecisionResult = {decision, instance}` | `{outcome: "approve"\|"reject"\|"return"\|"comment", reject_mode?: "return_to_draft"\|"permanent", comment?: str, document_version: int, assign_project_id?: uuid}` |
| `POST /api/v1/approvals/instances/{id}/withdraw` (Idempotency-Key) | the instance's requester, while it is `running` | 200 `InstanceRead` | `{comment?: str}` |
| `GET /api/v1/approvals/instances/{id}/decisions` | anyone who can read the document (adapter `can_read`) | 200 `[DecisionRead]`, oldest first | |

Validation (422 `VALIDATION_FAILED`, field-level): `reject_mode` is **required** with `reject` and forbidden otherwise (D-M2-1: the approver chooses every time); `comment` 1..4000 characters, **required** for `reject`, `return` and `comment`; `assign_project_id` only with `approve`, only when the adapter has `accepts_project_assignment`, and only on the instance's final approval step (otherwise 422 naming the field).

`document_version` must equal the document's current version (from `adapter.snapshot`); the stale case is E10-S07's 409. This story reads and records it.

## Behaviour

1. **Table `approval_decision`** (one of the four append-only tables named in AGENTS.md 3.1): `id uuid PK, org_id, instance_id, task_id uuid NULL (NULL for withdraw), actor_id uuid NOT NULL, on_behalf_of uuid NULL, authority text NOT NULL CHECK (authority IN ('member','delegate','admin','requester')), outcome text NOT NULL CHECK (outcome IN ('approve','reject','return','comment','withdraw')), reject_mode text NULL, comment text NULL, document_version int NOT NULL, members_at_decision jsonb NOT NULL, decided_at timestamptz NOT NULL DEFAULT now()`. Append-only triggers (`raise_append_only()`, the audit/ledger precedent) for UPDATE, DELETE and TRUNCATE. RLS. `on_behalf_of` and the `delegate`/`admin` authorities are written by E10-S08; this story always writes `member` (or `requester` for withdraw) with `on_behalf_of = NULL`.
2. **Order of operations for a decision**, in one transaction:
   1. Lock `approval_instance` `FOR UPDATE` (E10-S05 rule 5); re-read the task. A task that is not `open`, or an instance that is not `running`: 409 `CONFLICT`, `checks.problem = "task_closed"`.
   2. Compute the current members (E10-S04, live, D-M2-2). Actor not a member: a user who cannot read the document gets **404**; one who can read it but is not a member gets **403**, with detail "You are not an approver for this step." (convention A).
   3. Insert the decision row with `members_at_decision` = the member list just computed (convention K).
   4. `comment` does not change state. `approve` asks `step_complete` (E10-S05 rule 3); on completion the engine advances, and reaching `end` calls `on_outcome(APPROVED, context)`. `reject` ends the instance as `rejected` and calls `on_outcome(REJECTED, context with reject_mode)`. `return` ends it as `returned` and calls `on_outcome(RETURNED, ...)`. Remaining open tasks become `cancelled`.
   5. Audit (AUD-001) and outbox notification to the requester for `approved`, `rejected` and `returned` (`OutboxStore.add_email`, template `approval-outcome-v1`, idempotency key `approval:<instance_id>:<outcome>`, context without any document amount or comment text, only the document type, number and outcome; the link goes to the document).
3. `on_outcome` runs inside this transaction (convention H). If it raises (for example a requisition's reservation fails `InsufficientBudget`), the decision row, the task change and the instance change all roll back and the response is that problem (WF-003: never a recorded approval without its financial effect).
4. **Withdraw** (APR-013, "where authorized"). One service function, frozen for document modules:
   ```python
   def withdraw(conn, scope, *, document_type, document_id, actor_id, reason: str) -> InstanceRead
   ```
   It locks the running instance `FOR UPDATE` (no running instance: 409 `CONFLICT`, `checks.problem = "task_closed"`), cancels its open tasks, writes a `withdraw` decision (`authority = 'requester'` when `actor_id` is the instance's requester, otherwise `'admin'`; `comment = reason`), sets the instance `withdrawn`, and calls `on_outcome(WITHDRAWN, context)`, all in the caller's transaction. **The caller has already authorized the actor**: a requisition's withdraw (requester) or cancel (holder of `requisition.cancel`) transition calls it, and the requisition decides which terminal status it reaches. The route `POST /api/v1/approvals/instances/{id}/withdraw` calls the same function but authorizes only the instance's requester (anyone else 403, or 404 without document read). Document modules should use their own transition, not this route.
5. **Idempotency:** the decision route goes through the idempotency middleware with replay (the same key and body returns the first response; a different body is 422 `IDEMPOTENCY_KEY_REUSED`).

## Acceptance criteria

- [ ] Each outcome (`approve`, `reject` with each mode, `return`, `comment`, `withdraw`) writes exactly one `approval_decision` with actor, authority, outcome, comment, document version, `members_at_decision` and timestamp (APR-014).
- [ ] `reject` without `reject_mode` is 422 on `reject_mode`; `approve` with `reject_mode` is 422.
- [ ] `UPDATE`, `DELETE` and `TRUNCATE` on `approval_decision` fail in the database, as the application role.
- [ ] An `on_outcome` that raises leaves no decision row, the task open and the instance `running` (a fake adapter in the test raises `InsufficientBudget`).
- [ ] Non-member with document read: 403; without document read: 404; foreign tenant: 404.
- [ ] The final approval on a requisition-type fake adapter passes `assign_project_id` through `OutcomeContext`; on a non-final step, or an adapter without `accepts_project_assignment`, it is 422.
- [ ] A replayed `Idempotency-Key` returns the first response and writes nothing.
- [ ] Withdraw by the requester ends the instance; by anyone else, 403; on a finished instance, 409 `task_closed`.
- [ ] The outbox email holds no amount and no comment text.

## Plants

1. Remove the append-only trigger: the immutability test fails.
2. Call `on_outcome` after committing the decision: the rollback test fails.
3. Check membership before locking the instance: a concurrency test with a member removed mid-decision fails (add one).
4. Default `reject_mode` silently to `return_to_draft`: the required-mode test fails.
