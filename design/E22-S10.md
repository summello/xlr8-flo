## Requirements (inlined)

- **APR-004** — Approvers must be selectable only from eligible users in the relevant organization/BU/OU scope.
- **APR-014** — Every decision must record actor, acting authority/delegation, timestamp, outcome, comment/rationale, and document version.
- **APR-017** — Delegation, out-of-office coverage, reminders, due dates, and escalations should be configurable, without changing historical attribution.
- **APR-019** — A user must be prevented from approving their own request where separation-of-duty policy applies.
- **A11Y-006** — Forms must have programmatic labels, instructions, field-level errors, an error summary, and preserved input after validation failure.

## The API (exists; do not change it)

All under `/api/v1/approvals`, generated client only:

| Call | Use |
|---|---|
| `POST /delegations` | Save Out-of-Office (`delegate_id`, `starts_at`, `ends_at`, `document_types` or null for all, `reason`). 201, or 422 field errors, 409 on overlap |
| `GET /delegations/eligible-delegates?document_types=` | `Pass Approvals To` options (APR-004; the server re-checks on save) |
| `GET /delegations?view=mine` / `?view=organization` | `My Delegations` / `Organization` tab (organization is 403 for non-administrators: hide the tab **and** handle the 403) |
| `POST /delegations/{id}/revoke` | Revoke (owner, or an approval administrator from the Organization tab) |
| `GET /delegations/decided-on-my-behalf` | `Decided on Your Behalf` list |

## Design

Route `/approvals/availability`, linked from the Approval Inbox header and the user menu
(`Approval Availability`). Build it as §5 says: the Out-of-Office form, `Your Delegations` table,
the revoke `alertdialog` (focus starts on `Keep Delegation`; the text says new approvals stop,
undecided tasks come back to you, and decisions already made stay recorded as made by the delegate
for you), `Decided on Your Behalf`, and the three side cards. `Covers` maps `All my approvals` →
`document_types: null` and `Purchase orders only` → `["purchase_order"]`. Dates are inclusive and in
the organisation's time zone; send what the API expects and show the period in the user's locale.
People render with the shared `Person` component if E22-S09 has merged, otherwise by email.

States per §5: loading, empty (`No Delegations`), error (`Could not load your delegations`, typed
values kept), form errors (summary with `role=alert` that takes focus, each item links to its field,
inline `aria-invalid`), and the 409 overlap shown as the `Overlap` item.

## Acceptance

- [ ] Playwright happy path: create a delegation, see it `Upcoming` or `Active`, revoke it through the dialog, see `Revoked` and `Kept in the record`.
- [ ] Keyboard-only path through the whole form, the table's `Revoke` and the dialog (focus on `Keep Delegation`, Escape closes, focus returns to the row's button).
- [ ] Error summary: submit empty → `Not saved. 3 problems.` focused, each link focuses its field, typed values kept; an overlapping range → the `Overlap` item from the 409.
- [ ] `Pass Approvals To` lists only `eligible-delegates` results; the Organization tab is absent for a non-administrator, and a forced `?view=organization` shows the error state, not data.
- [ ] axe clean on `/approvals/availability` and the open dialog in light and dark; MASTER §8 checklist.
- [ ] Tokens only; status uses the §2.3 map; `flo check` green.

## Plants

1. Show every user in `Pass Approvals To` instead of the eligible list: the eligibility e2e fails.
2. Move initial focus to `Revoke` in the dialog: the keyboard test fails.
